## Context

Текущий поток второй вершины в инструменте «Стена» (`src/main.ts`):

```
pointermove -> snapWallCursor(raw)
   snapVertex(raw, walls, R, GRID, t, ortho ? chainStart : undefined)   wall-snap.ts
      1. кандидаты-стены -> есть -> RETURN (орто не применяется)
      2. орто по осям экрана от orthoFrom, подвижная координата по сетке
      3. сетка
   cursorV = lockedDirection(chainStart, v, walls) ?? v                  geometry.ts
redraw -> previewPoint(): cursor, или typedLength вдоль (cursor - start)  <- не cursorV
commit -> typedLength вдоль cursorV, иначе cursor                         <- расходится с превью
```

Наблюдаемые дефекты (см. proposal): прилипание к стене отменяет орто; `lockedDirection`
действует при выключенном орто, отличается от превью и выбирает первую касающуюся стену
массива. Начало цепочки хранится только точкой (`chainStart: Point`): результат прилипания
начала (`VertexSnap` с неперечислимой `normal`) после клика теряется, и вид примыкания
(грань или торец) нигде не фиксируется.

`main.ts` (1114 строк) тестами не покрыт; юнит-тесты `vitest` есть только для чистых
функций. Утверждённые тесты фиксируют контракт `snapVertex(p, walls, R, GRID, t, orthoFrom?)`
с результатом `{point, source}` и неперечислимой `normal`.

## Goals / Non-Goals

**Goals:**
- Одна чистая функция вычисляет сегмент построения (конец, направление, результат
  привязки конца, угол) из начала, его опоры, курсора, флага орто, введённых угла и длины;
  её используют и превью, и фиксация — расхождение превью/фиксации исключено по
  построению.
- Опора начала (стена примыкания и вид примыкания) берётся из результата прилипания
  первого клика.
- Угол, орто-направления и разбор введённого угла — чистые функции, проверяемые
  юнит-тестами.
- Сохранить контракт `snapVertex` для привязки без заданного направления и для
  орто по осям экрана без стен.

**Non-Goals:**
- Перетаскивание конца выделенной стены и перенос группы (`snap` в `geometry.ts`) — не
  меняются.
- Форма стыка новой стены с гранью при подходе под углом — вопрос wall-joints.
- Автотесты DOM (поле угла, фокус, Tab) — в проекте нет DOM-тестов; проверка вручную в
  браузере (tasks).

## Decisions

### D1. Новый модуль `src/wall-angle.ts` — геометрия угла и направлений

Чистые функции без зависимостей от DOM:

```ts
type StartRef = { kind: "face" | "cap"; normal: Point }   // normal — наружу от стены примыкания

startRefOf(snap: VertexSnap): StartRef | null              // null для source "grid"
wallAngleDeg(ref: StartRef, dir: Point): number            // наименьший угол, cap 0..180, face 0..90
angleReferenceRay(ref, dir): Point                          // луч, от которого отсчитан угол (для дуги)
orthoDirection(ref: StartRef | null, v: Point): Point | null // притянутое направление или null
typedDirection(ref: StartRef, deg: number, v: Point): Point | null // null вне диапазона
parseAngleDeg(text: string): number | null                  // запятая = точка; нечисловое -> null
```

- Аргумент `v` у `orthoDirection` и `typedDirection` — ненулевой вектор от начала к
  курсору, не обязательно единичный; результат — единичный вектор.
- Опорные направления орто: `cap` → `normal` (180°) и `±perp(normal)` (90°); `face` →
  `normal` (90°); `null` (свободное начало) → `±x`, `±y`. Допуск — `|угол| <= 15°`
  включительно, проверка в форме `|cross(v, d)| <= ORTHO_TAN · dot(v, d)` с `dot > 0`
  (как сейчас), чтобы граница ровно 15° была устойчива.
- Угол: `cap` — `acos(dot(dir, −normal))`; `face` — `min(acos(dot(dir, t)), acos(dot(dir, −t)))`,
  `t = perp(normal)`. Перевод в градусы и округление до целого — у потребителя
  (отображение), функция возвращает точное значение.
- `typedDirection`: `cap` — поворот `−normal` на `±deg`; `face` — поворот `normal` на
  `±(90 − deg)`. Знак — по стороне курсора: `sign(cross(axis, v))`, где `axis` — `−normal`
  для `cap` и `normal` для `face`; при `cross = 0` — по спеке: поворот против часовой
  стрелки на экране от луча отсчёта, проходящий через свободную сторону. Для `cap` луч
  отсчёта — `−normal`; для `face` — тот из лучей `±perp(normal)`, от которого поворот
  против часовой на экране идёт через сторону `normal` (для normal (0,1) это (−1,0), и
  результат при 60° — (−cos60°, sin60°)). Экран y вниз: «против часовой на экране» —
  отрицательный математический угол в мировых координатах. Фиксируется TYPED-TIE-1. Диапазоны: `cap` `(0, 180]`, `face` `(0, 90]`.

Альтернатива — расширить `geometry.ts`: отклонена, файл уже смешивает размеры, перенос и
устаревшую привязку; новая доменная тема заслуживает отдельного модуля.

### D2. Вид примыкания передаётся в результате привязки неперечислимым полем `target`

`Candidate` в `wall-snap.ts` получает `kind: "face" | "cap"`; `snapVertex` кладёт его в
результат так же, как `normal` — `Object.defineProperty(..., { enumerable: false })`.
Утверждённые тесты с `toEqual({point, source})` и `Object.keys` не затрагиваются.

Альтернатива — определять вид по геометрии (нормаль параллельна оси стены → торец):
отклонена, требует снова искать стену по точке, то есть повторяет дефект
`lockedDirection`.

### D3. `snapOnRay` в `wall-snap.ts` — конец при заданном направлении

```ts
snapOnRay(p, walls, radiusCm, gridStepCm, newThicknessCm, start, dir): VertexSnap
```

- Кандидаты — для каждой невырожденной стены: две грани и два торца. Для грани берётся
  сторона, через которую луч входит в тело (`dot(dir, sideNormal) < 0`); пересечение луча
  `start + s·dir, s > 0` с линией грани; точка должна лежать в одном из
  `openIntervals(scene, line, len)` (без сжатия). Для торца — только свободный
  (`capCandidate`), пересечение с плоскостью торца в пределах его отрезка.
- Принимается кандидат на расстоянии от курсора `<= max(radiusCm, newHalf)`, чей квадрат
  установки `squareOnSide(point, normal, t)` не налагается на тела (`overlapsBodies`).
  Ближайший к курсору; при равенстве — стена раньше в массиве (тот же цикл, что в
  `snapVertex`).
- Иначе — сетка на луче: если `dir` параллелен оси экрана (`|dir.x|` или `|dir.y|` равен 1
  с допуском 1e-12), неподвижная координата = координата `start`, подвижная — `round` к
  шагу; иначе длина `round(dot(p − start, dir) / step) · step`. В обоих случаях, если
  `dot(end − start, dir) < 0`, конец = `start` (нулевая длина, спека «Привязка к сетке»).
- Результат — `VertexSnap` с неперечислимыми `normal`/`target` при прилипании.

### D4. Орто по осям экрана в `snapVertex` переводится на `snapOnRay`

Сигнатура `snapVertex(p, walls, R, GRID, t, orthoFrom?)` сохраняется. Новая семантика
`orthoFrom` — «свободное начало, орто включено»: `dir = orthoDirection(null, p − orthoFrom)`;
если направление есть — `snapOnRay(p, …, orthoFrom, dir)`, иначе прежний путь
стены → сетка. Без `orthoFrom` поведение не меняется.

Следствие: при сработавшем орто стена больше не перехватывает направление — это и есть
изменение спеки «Приоритет привязки к стенам». Утверждённые тесты, проверявшие старое
правило, перечислены в D8.

### D5. `chainSegment` — единый расчёт сегмента (`src/wall-chain.ts`)

```ts
interface ChainInput {
  start: Point; ref: StartRef | null; raw: Point; walls: Wall[]
  radiusCm: number; gridStepCm: number; thicknessCm: number
  ortho: boolean; typedAngleDeg: number | null; typedLengthCm: number | null
}
interface ChainSegment {
  end: Point; dir: Point | null; snap: VertexSnap; angleDeg: number | null; refRay: Point | null
}
chainSegment(input): ChainSegment
```

Порядок:
1. `v = unit(raw − start)` (null при нулевой длине).
2. Направление: `typedDirection(ref, typedAngle, v)` если угол введён и допустим →
   иначе при `ortho`: `orthoDirection(ref, v)` → иначе нет заданного направления.
3. Конец: направление задано → `snapOnRay(raw, …, start, dir)`; иначе `snapVertex(raw, …)`
   без `orthoFrom`. `dir` сегмента = заданное направление или `unit(snap.point − start)`.
4. Введённая длина: `end = start + dir · typedLength`; иначе `end = snap.point`.
5. `angleDeg = ref && dir ? wallAngleDeg(ref, dir) : null`, `refRay` — для дуги.

`main.ts` хранит `chainRef: StartRef | null` рядом с `chainStart` (из `cursorSnap` на
первом клике), вызывает `chainSegment` в `snapWallCursor` и при фиксации; `previewPoint`,
`cursorV` и ветка точной длины в `commitPoint` заменяются результатом `chainSegment`.
`lockedDirection` удаляется из `geometry.ts` (единственный потребитель — `main.ts`).

Слои: `wall-angle.ts`, `wall-snap.ts` — домен; `wall-chain.ts` — прикладной расчёт без
DOM; `main.ts` — тонкая привязка к событиям и полям.

### D6. Отображение угла

`RenderOptions` получает `angle?: { at: Point; from: Point; to: Point; deg: number } | null`
(`from` — `refRay`, `to` — `dir`). `drawScene` рисует отрезок луча отсчёта и дугу радиусом
56 px экрана (не зависит от масштаба; при толщине 20 см и масштабе 1 полоса превью — 40 px,
дуга выходит за неё) линией 2 px в секторе от `from` к `to` по кратчайшему пути, и подпись
`${round(deg)}°` полужирным шрифтом на белой подложке у середины дуги. `main.ts` заполняет `angle`, только если `chainRef` есть и длина превью > 0.

### D7. Поле угла

`index.html`: `<label id="angle-label">Угол<input id="angle" …>°</label>` сразу после поля
длины (порядок Tab). `main.ts`:
- `angleInput.disabled = !(tool === "wall" && chainStart && chainRef)`; при отключении —
  значение пустое, `angleDirty = false`.
- Живое значение — `Math.round(angleDeg)`, выделено целиком, пока `!angleDirty`
  (зеркально `updateLengthBox`).
- Круговой Tab, пока поле угла активно: `keydown` Tab (без Shift) в поле угла и Shift+Tab в
  поле длины — `preventDefault` и фокус на другое поле; при неактивном поле угла обработчик
  ничего не делает (обычный порядок страницы).
- `input` → `angleDirty = true`, пересчёт сегмента; `Enter` → `commitPoint()`;
  `Esc`, фиксация, смена инструмента — очистка как у длины.
- Разбор — `parseAngleDeg`; диапазон проверяет `typedDirection`.

## Risks / Trade-offs

- [Обратная совместимость сохранённых чертежей] → данные стен не меняются; угол не
  хранится. Миграция не нужна.
- [Сетка на наклонном луче даёт концы вне узлов сетки] → осознанно (спека); на осевом
  луче концы по-прежнему на линиях сетки.
- [Пересечение луча с гранью почти параллельно грани уходит далеко] → ограничено зоной
  прилипания от курсора.
- [`snapOnRay` проверяет 4 цели на стену с построением контура сцены] → контур строится
  лениво один раз за вызов, как в `snapVertex`; сложность того же порядка.
- [Знак «против часовой» при y вниз легко перепутать] → зафиксировать тестом на
  конкретных координатах.
- [main.ts остаётся большим] → новая логика вынесена в `wall-angle.ts`/`wall-chain.ts`;
  в `main.ts` только связывание.
