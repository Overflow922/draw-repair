## Context

Мотивация — в `proposal.md`, поведение — в `specs/`. Что есть (после `add-switching-plan`):

- `src/switching/`: сцена (`switchingScene`: подложка, предметы, объекты освещения), рабочий набор, отрисовка слоёв, поле `Drawing.switching` с выносками и примечаниями.
- `src/ceiling/`: `light-symbol.ts` (знаки и зона клика `lightHitRadiusPx`), `ceiling-tool.ts` и `ceiling-label` — образец инструмента с панелью, подписи постоянного экранного размера и правки на месте.
- `src/anchor-label.ts` (`anchorLabelBox`) — рамка подписи с привязкой к точке.

## Goals / Non-Goals

**Goals:**
- Метка линии как отдельный объект плана «Группы включения», не меняющий плана «Потолки и освещение».
- Имя линии — единственный ключ связи: выключатели (`add-light-switch`) и вытяжка (`add-exhaust-fan`) ссылаются на линию по имени.

**Non-Goals:**
- Выключатели, вытяжка, проверки целостности схемы (линия без ключа, ключ без линии).
- Столбец «Количество» в легенде.

## Decisions

### D1. Модель и хранение
```
LightLine { id: string; targetId: string; name: string }   // name = "L" + целое > 0
SwitchingContent.lines?: LightLine[]
```
`targetId` — идентификатор объекта-носителя метки (сейчас светильник из `Drawing.ceiling.lights`). Поле названо общим словом, потому что `add-exhaust-fan` добавит вторую категорию носителей; идентификаторы объектов уникальны во всех списках чертежа. Метка принадлежит плану «Группы включения», а не светильнику: так `ceiling-lighting` не меняется и объекты освещения остаются чистыми точками плана потолков.

Группа включения — не объект, а все метки с одним именем; реестра линий нет. Линия без меток исчезает сама.

Отклонённые альтернативы:
- Поле `line` в `LightFixture`. Затрагивает `ceiling-lighting`, его хранение, историю и проверки.
- Реестр линий (`Line { id, name }`) и ссылки светильников на него. Лишний уровень, пока у линии нет собственных свойств; при необходимости (цвет, комментарий) вводится позже.

### D2. Имя линии
`parseLineName(text): string | null` принимает `3`, `L3`, `l3` (пробелы по краям игнорируются), возвращает `"L3"`; ноль, дробь, отрицательное, пустая строка, прочие буквы — `null`. Одна функция для панели, правки на месте и проверки при загрузке (при загрузке допускается только каноническая форма `L<n>`).

### D3. Кто может нести метку
Точечный светильник, люстра, бра, электровывод. ДПС — нет: датчик пожарной сигнализации питается отдельно и не коммутируется выключателем. Это решение дизайна, не слова пользователя; если выключаемый ДПС нужен, правило меняется одной проверкой в `canCarryLine`.

### D4. Инструмент и панель
Новый `Tool` `"lightLine"`. Инструмент работает как «Натяжной потолок» по схеме «панель значения + клик»:
- значение `n` для новых меток — состояние сеанса `main.ts` (по умолчанию 1), поле панели — целое число, как поле опускания потолка;
- клик в зоне светильника (круг не меньше 8 px, как выделение освещения) ставит или меняет метку, один шаг истории; повторный клик с тем же именем шага не создаёт;
- при наведении светильник подсвечивается цветом выделения;
- метка выделяется кликом по подписи без инструмента; выделенная метка показывает имя в панели, правка панели меняет её одним шагом; на месте имя правится кликом по подписи (поле по образцу подписи потолка).

### D5. Положение метки
Левый нижний угол текста — центр светильника плюс (8 px, −8 px) на экране и (2 мм, −2 мм) на бумаге: правее и выше знака, как в примере пользователя. Текст всегда горизонтален и не зависит от направления бра. Кегль постоянный (как у подписи «ДПС» на «Потолках и освещении»), цвет — красный цвет освещения схемы. Метки соседних светильников могут перекрываться; пользователь двигает светильник на «Потолках и освещении».

```
 вид сверху, схематично, не в масштабе: пять светильников одной линии

        L3                      L3
       (+)                     (+)
    L3                 L3
   (+)                (+)
              L3
             (+)
```

### D6. Образец вида
Знаки освещения сделаны по `references/lighting.png`. Метка линии — подпись красным курсивом, образец в примере пользователя; `references/` картинки подписи нет. Перед реализацией (`/opsx:apply`) пользователь кладёт картинку (например `references/lines.png`) или подтверждает описание из спеки; в `design` реализации называется картинка (правило `references`).

### D7. История, PDF, легенда
Запись истории `switchingPlan` — снимок списков `lines`, `callouts`, `notes` до операции (по образцу `recordCeilingPlan`). PDF рисует метки тем же кодом, что холст, кеглем в миллиметрах. Запись легенды `{ kind: "light-line" }` стоит после записей видов освещения; образец — подпись «L1» тем же шрифтом и цветом.

## Risks / Trade-offs

- [Метки перекрываются в плотной сетке светильников] → без раскладки, как у чисел расстояний на «Потолках»; решается правкой положения светильников. Отдельное изменение, если понадобится.
- [Метка висит на светильнике, который удалён на другом плане] → хранится и не показывается; удаление записи вручную невозможно, пока светильника нет. Принято, как у размеров на отсутствующую стену.
- [Имя `L<n>` без ограничения числа] → опечатка `L300` видна сразу; верхней границы нет, как у опускания потолка.
