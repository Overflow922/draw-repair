## Context

Мотивация — в `proposal.md`, поведение — в `specs/`. Что в коде уже есть для этого плана:

- Каталог планов и наборы инструментов — `src/plans.ts` (`PLANS`, `PLAN_TOOLS`). Переключатель, страницы PDF и ключи истории строятся по каталогу.
- План «Потолки и освещение» (`src/ceiling/`): `ceilingScene` (подложка `reconstructionScene`, предметы «Мебели», помещения, потолки), `openCeiling` / `storedCeiling` (рабочий набор), `renderCeiling` (слои, одна функция для холста и PDF), `light-symbol.ts` (условные знаки).
- Объекты освещения лежат в `Drawing.ceiling.lights` вместе с потолками плана «Потолки и освещение».
- План «Сантехника» (`src/plumbing/`) — образец плана-оболочки: сцена, рабочий набор с объектами только для чтения, отрисовка.
- Выноски и примечания хранятся по плану через `callout-store.ts` и `notes-store.ts`; PDF — `pagesOf` (`src/export/pdf.ts`), легенда — `src/export/legend.ts`.

## Goals / Non-Goals

**Goals:**
- Девятый план с подложкой «Потолки и освещение» без потолков и расстояний, с общими инструментами плана (выноска, линейка, примечания, ластик), страницей PDF, историей и хранением.
- Следующие изменения («Линия освещения», «Выключатель», «Вытяжка») добавляют объекты в поле плана без перестройки сцены и хранения.

**Non-Goals:**
- Выключатели, линии освещения, вытяжка, их счётчики в легенде.
- Изменение плана «Потолки и освещение» и объектов освещения.
- Разделение `main.ts` на модули.

## Decisions

### D1. План в каталоге
`{ id: "switching", label: "Группы включения" }` встаёт последним в `PLANS`. Новых значений `Tool` нет. `PLAN_TOOLS.switching = ["callout", "ruler", "notes", "eraser"]`, по умолчанию — первый («Выноска»). Название выбрано коротким, чтобы переключатель из девяти сегментов умещался; идентификатор `switching` — по образцу `ceiling`.

### D2. Модель и хранение
```
SwitchingContent { callouts?: Callout[]; notes?: string[] }
Drawing.switching?: SwitchingContent
```
Поле необязательное, при загрузке не дописывается, версия документа 3 не меняется — как у `plumbing`. Собственных объектов у плана пока нет; будущие изменения добавляют в `SwitchingContent` списки линий, выключателей и вытяжек. Объекты освещения НЕ копируются в `switching`: линия освещения будет ссылаться на светильник по идентификатору (это забота следующего изменения).

### D3. Сцена и подложка
`src/switching/switching-scene.ts`:

```
switchingScene(drawing, base = reconstructionScene(drawing)) -> {
  base,                                  // подложка «Мебели»
  items:  drawing.furniture.items (копии, все виды)
  lights: drawing.ceiling.lights (копии)
}
```
Помещений и потолков в сцене нет: план показывает объекты освещения как есть, а привязка потолков к помещениям ему не нужна. Сцена — чистая функция, чертёж не мутируется. Рабочий набор `openSwitching` / `storedSwitching` (`src/switching/switching-workspace.ts`) — по образцу `ceiling-workspace.ts`: стены и предметы — `readOnlyIds`, хранимое — выноски и примечания.

Отклонённая альтернатива: строить план на `ceilingScene` и скрывать потолки при рисовании. Тогда сцена считала бы помещения и действующие потолки без пользы, а будущие изменения зависели бы от структуры чужого плана.

### D4. Отрисовка
`src/switching/switching-render.ts` рисует слои: подложка (`drawReconstructionScene`, как на «Потолках и освещении»), предметы серыми линиями без габаритов (`itemDrawingInPlan`, `traceLines`), знаки освещения (`drawLightSymbol`), выноски и примечания. Размерных линий и чисел освещения нет, поэтому `lightBodies` не передаются. Если `renderCeiling` не позволяет показать знаки без расстояний и без потолков, слой «предметы + знаки» выделяется общей функцией из `ceiling-render.ts` без изменения её поведения (тесты `ceiling-render*.test.ts` — контракт, не правятся). Функция одна для холста и PDF.

Цвета знаков — как на «Потолках и освещении» (`light-symbol.ts`, `theme.ts`); новых цветов нет.

### D5. Ластик, выделение, горячие клавиши
Объекты освещения, предметы и стены — `readOnlyIds`; ластик удаляет только выноски (по образцу ластика «Сантехники»). Delete и стрелки на плане не действуют на подложку. Инструмент «Освещение» на плане недоступен, как и на других планах, кроме «Потолков и освещения».

### D6. История
Своя история по ключу `historyKey(drawingId, "switching")`. Записи — только `callouts` и `notes`, как у «Мебели» и «Сантехники». Запись плана-оболочки без собственных объектов отдельного вида не вводит; следующие изменения добавят вид записи с их списками.

### D7. PDF и легенда
`pagesOf` даёт девятую страницу по каталогу; отрисовка повторяет D4 в миллиметрах листа. Габариты страницы — объединение габаритов подложки, предметов, центров объектов освещения и выносок.

Легенда: правило страницы описано отдельным требованием `pdf-export` «Легенда страницы «Группы включения»», а не правкой требования `Легенда на странице PDF`: оно перечисляет страницы в десятках сценариев, и его перепись сильно раздула бы дельту. Требование задаёт набор записей страницы (без «Натяжного потолка» и видов мебели) и ссылается на общие правила порядка и образцов. В реализации `legendEntries` для страницы `switching` берёт записи как для `ceiling`, кроме `{ kind: "ceiling" }`. При следующей правке легенды перечисления страниц в общем требовании приводятся к девяти.

### D8. Порядок изменений
1. Каталог, модель, проверка, хранение, история.
2. Сцена, рабочий набор, отрисовка, `main.ts`.
3. PDF и легенда.
4. Следующие изменения (не здесь): «Линия освещения» → «Выключатель» → «Вытяжка».

## Risks / Trade-offs

- [Слой «предметы + знаки» дублирует часть `renderCeiling`] → общие шаги выносятся функцией, поведение «Потолков и освещения» закрыто его тестами.
- [Формулировки перечней страниц в `Легенда на странице PDF` остаются на восемь страниц] → новое требование их уточняет; расхождение записано в `TODO.md` для следующего изменения легенды.
- [Нет собственных объектов, кроме выносок] → осознанно: проверяем оболочку отдельно, выключатели идут следующим изменением.
- [Подписи линий `L1…` на светильниках понадобятся в следующих изменениях] → место в модели не занято: `SwitchingContent` расширяется необязательными списками.
