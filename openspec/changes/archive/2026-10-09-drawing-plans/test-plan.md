# Test Plan

## Scope

Поведение изменения `drawing-plans` (спецификации `drawing-plans`, дельты `drawing-storage`, `drawing-history`, `pdf-export`; решения D1–D7 в `design.md`).

Автоматизируются чистые модули — в проекте нет DOM-стенда (см. `TODO.md`):

- `src/plans.ts` — каталог, `isPlanId`, `activePlanOf`, `historyKey`;
- `src/storage.ts` — чтение/запись необязательного поля `activePlan`;
- `src/history.ts` — `planHistory`;
- `src/export/pdf.ts` — `pagesOf`, `availableFormatsForPages`, `buildPdfPages`, `exportPages`.

Переключатель планов (`main.ts`, `index.html`, `style.css`) проверяется вручную в браузере (раздел «Ручные проверки»), без автотестов.

Регрессия: весь существующий набор тестов остаётся зелёным без правок; он защищает требование «поведение для единственного плана не меняется» (обёртки `buildPdf`, `availableFormats`, `exportDrawing`, неизменность формата хранилища и истории).

Новые тесты — отдельные файлы (existing tests не правятся): `src/plans.test.ts`, `src/storage-plans.test.ts`, `src/history-plans.test.ts`, `src/export/pdf-pages.test.ts`.

## Boundary Cases

| Case | Input | Expected |
|---|---|---|
| Пустое/неподходящее значение плана | `activePlan`: `""`, `"Measure"` (регистр), `" measure"` | читается как `measure`, поле отбрасывается (ST-02) |
| Нестроковые значения | `activePlan`: `5`, `null`, `true`, `{}`, `["measure"]` | чертёж загружается, стены на месте, план `measure` (ST-02) |
| Ключ истории | `historyKey("a", "measure")` | ровно `"a"` без суффикса (PL-05) |
| Ключ истории пустой/длинный id | `historyKey("", "measure")` | `""` (PL-05) |
| Одна страница | `buildPdfPages([p])` | ровно 1 страница (PG-02) |
| Ноль страниц | `availableFormatsForPages([], 100)` | все форматы A4–A0 (PG-12) |
| Три страницы, средняя пустая | `[A, пустая, B]` | 3 страницы, у каждой рамка и надпись (PG-09) |
| Граница области A4 на второй странице | страница 1 мала; страница 2 ровно 272×145 мм на бумаге / +0,1 мм | A4 доступен / отсутствует (PG-11) |
| Только пустые страницы | `[пустая, пустая]` | все форматы (PG-12) |

| Case | Expected behavior |

## Invariants

- `activePlanOf` всегда возвращает идентификатор из каталога.
- Для любого чертежа и любого плана каталога `planHistory(h, id, p)` возвращает ту же историю, что и повторный вызов (идентичность объекта), а для `measure` — ту же, что `drawingHistory(h, id)`.
- Число страниц PDF равно числу переданных страниц; порядок страниц = порядок входа; страница i содержит геометрию только `pages[i]`.
- Масштаб листа точный на каждой странице: 1 см чертежа = 10/X мм независимо от номера страницы.
- Каждая страница PDF имеет рамку и основную надпись с одним и тем же именем, масштабом и датой.
- `availableFormatsForPages` не зависит от порядка страниц и равна пересечению `availableFormats` каждой непустой страницы; для одной страницы совпадает с `availableFormats` этой страницы.
- Формат документа хранилища (`version: 3`) и документа истории (`version: 2`) не меняются.

## Integration Cases

- Хранилище: `serializeStore` → `parseStore` с чертежом, содержащим стены, размеры, проёмы и `activePlan` (ST-03, ST-04).
- История: `record` через `planHistory` → `undoEntry`/`redoEntry` → `serializeHistory`/`parseHistory` (HI-02, HI-06).
- PDF: `pagesOf(drawing)` → `buildPdfPages` → разбор операторов страницы теми же утилитами, что `sheet-pdf.test.ts` (`pdf-ops.test-utils`) (PG-01 … PG-06).
- Совместимость: прежние вызовы `buildPdf`/`availableFormats`/`exportDrawing` дают прежний результат — существующие тесты без правок.

## Mutation Targets

Проект не имеет инструмента мутационного тестирования; валидатор проверяет вручную (ручные мутации):

- `activePlanOf` возвращает значение без проверки по каталогу (неизвестный/нестроковый идентификатор проходит) — ST-02, PL-04.
- `parseStore` добавляет `activePlan: "measure"` всем чертежам или отбрасывает валидное поле — ST-01, ST-03, ST-06.
- `parseStore` считает неизвестный `activePlan` повреждённым документом и сбрасывает хранилище — ST-02.
- `historyKey` для `measure` возвращает `drawingId + ":measure"` — PL-05, HI-01, HI-03.
- `planHistory` создаёт новую историю при каждом вызове — HI-02 (запись должна быть видна при втором вызове).
- `buildPdfPages` строит только первую страницу / дублирует первую / меняет порядок — PG-03, PG-04, PG-05.
- Страницы после первой без рамки или основной надписи, либо с другим именем/масштабом/датой — PG-06.
- Размещение второй страницы вычислено по габаритам первой (общий bbox) — PG-05.
- `availableFormatsForPages` берёт только первую страницу / только последнюю / объединение вместо пересечения / считает пустую страницу ограничивающей — PG-10, PG-11, PG-12.
- `>=` вместо `>` на границе области — PG-11 (граница на второй странице).
- `pagesOf` мутирует чертёж или подставляет `undefined` вместо `[]` для отсутствующих проёмов — PG-01.
- `pagesOf` зависит от `activePlan` — PG-07.
