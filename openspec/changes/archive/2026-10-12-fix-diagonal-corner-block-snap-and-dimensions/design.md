## Context

Блок диагонального углового стыка строится в `displayPolygons` (`src/wall-geometry.ts`, `diagonalCornerBlock`) как отдельный кусок тела поздней стены. Контур сцены для привязки (`sceneContour` в `src/wall-snap.ts`) собирается из `displayPolygons`, поэтому кромка блока уже входит в открытые участки граней: нижняя грань A и кромка блока сливаются в один участок (`openIntervals`). Но:

- зона прилипания к грани в `wallCandidates` задаётся по оси стены: `s >= -reach && s <= len + reach`;
- свободность торца для авторазмеров (`wallEndOccupied` в `src/geometry.ts`) проверяется по осям и `wallShape`, где блока нет.

## Goals / Non-Goals

**Goals:**
- Прилипание к грани доходит до края участка, продолженного блоком, плюс зона прилипания.
- Торцы, закрытые блоком, не получают размера толщины.

**Non-Goals:**
- Размеры длины граней (в том числе по контуру с блоком) не меняются.
- Правила построения блока и порядок стен не меняются.
- Диагональное прилипание (`cornerCandidate`) не меняется.

## Decisions

**D1. Зона вдоль грани — по открытому участку, а не по оси.** В ветке «вне полосы» `wallCandidates` условие по `s` заменяется расстоянием от `s` до ближайшего открытого участка грани (тот же набор интервалов, что `faceCandidate` получает из `openIntervals`). Для грани без блока интервал совпадает с `[0, len]`, поэтому условие равносильно прежнему. Альтернатива — отдельный кандидат «торец блока» у стены B: отвергнута, так как кромка блока коллинеарна грани A и новая цель дублировала бы существующую, усложнив выбор ближайшего.

**D2. Зажим вершины не меняется.** `faceCandidate` уже зажимает вершину в `[lo, hi]` с учётом `endShrink`; при продолжении участка блоком `hi` естественно доходит до кромки блока. Менять нужно только отбор «попадает ли курсор в зону».

**D3. Свободный торец — через отображаемую форму.** Признак «торец занят» для авторазмеров дополняется проверкой: плоскость торца полностью закрыта отображаемым телом сцены (включая блок), либо ось торца лежит внутри блока. Реализация использует уже существующие `displayPolygons`, а не дублирует условия диагонального стыка. Размеры нужно только для авторазмеров: `wallEndOccupied` используется и перемещением стен (`followingEnds`), поэтому его поведение не меняется: добавляется отдельная проверка в `thicknessDimension`.

**D4. Конец продолжения в `diagonalCornerBlock`.** Проверка «других концов в пороге» (оба цикла по концам сцены) пропускает конец q стены t, если выполнены условия требования «Диагональный угловой стык»: q в пределах 1 см по каждой оси от центра дальней стороны блока F (для стены B — `v + outC·толщина A`, для стены A — `E + outW·толщина B`), направление t от q совпадает с направлением от конца стены за блок в пределах `RIGHT_SIN`, и такой конец у данной стены пары один. Остальные концы отменяют блок, как прежде. Вычисление F использует величины, которые функция уже имеет (`E`, `v`, `outW`, `outC`, толщины). Альтернатива — не отменять блок по любым концам, лежащим на границе блока: отвергнута, так как пропустила бы перпендикулярные примыкания (сценарий «Другой конец в пороге»).

**D5. Остальные формы стыков не меняются.** `partnerEndOf`/`faceCornerAt` для пары (A или B, C) не должны срабатывать на конце продолжения. Это проверяется тестами итоговой формы (покрытие полосы без просвета и без наложения); если у C появятся клинья или доращивание от A, их нужно исключить в `faceCornerAt` по тому же признаку продолжения.

**D6. Выбор пары при симметричном Т.** В сцене A, B, C стена A образует диагональный стык и с B, и с C (концы B и C равноудалены от конца A, оси B и C совпадают). Кандидаты, оси которых совпадают в пределах допуска прямого угла, а концы лежат в допуске продолжения друг друга, не должны давать «двух соседей» (`if (match) return null`): пара выбирается по порядку в массиве — первым берётся кандидат, ранее стоящий в массиве; второй считается концом продолжения. Результат (объединение закрытых областей) от выбора не зависит, меняется только владелец блока.

## Risks / Trade-offs

- Конец продолжения затрагивает общий путь `diagonalCornerBlock`, которым пользуются отображение, привязка и размеры; регрессии ловят существующие тесты `wall-geometry-diagonal-corner*.test.ts`.

- Зона по открытому участку меняет `wallCandidates` для всех граней; риск регрессии в чужих сценах. Смягчение: для граней без блока интервал равен `[0, len]`, прежние тесты зоны остаются без изменений.
- Закрытие торцов блоком убирает уже созданные размеры при пересчёте стены. Это допустимо (размеры вычисляемые, метка `auto`); ручные размеры не затрагиваются.
- Размеры длины на внешних гранях у блока на момент установки B могут отсутствовать (контурные вершины блока не якорятся в `anchorAt`). Это известное расхождение вне объёма изменения; требуется отдельное решение.
