## Context

Свободный конец стены после первого клика вычисляется одной функцией `chainSegment` (`src/wall-chain.ts`); её результат используют и превью, и фиксация (`segment.end` в `src/main.ts`). Внутри:

- направление не задано: `snapVertex` — стена (грань/торец), иначе узел сетки;
- направление задано (орто/угол): `snapOnRay` — пересечение луча со стеной, иначе сетка по длине на луче;
- введённая длина: конец = начало + dir · длина.

`VertexSnap` (`{point, source: "wall" | "grid"}`) — замороженный контракт существующих тестов; `chainEndSquare` строит квадрат установки только для `source === "wall"` и совпадающей точки, иначе — последний блок вдоль сегмента. Отрисовка превью получает дополнительные элементы через `RenderOptions` (`src/render.ts`), как это сделано для дуги угла.

## Goals / Non-Goals

**Goals:**
- Трекинг по узлам как отдельный чистый модуль, без зависимостей от DOM и состояния.
- Встраивание в `chainSegment` между прилипанием к стенам и сеткой, без изменения `snapVertex`/`snapOnRay` и контракта `VertexSnap`.
- Единый результат для превью, фиксации и отрисовки линий.

**Non-Goals:**
- Трекинг при перетаскивании конца выделенной стены (отдельное изменение; модуль должен быть пригоден для повторного использования там).
- Трекинг до первого клика, узлы помимо концов осей стен.
- Кэширование узлов между событиями указателя (сцены малы, см. Risks).

## Decisions

### D1. Модуль `src/wall-tracking.ts`

Чистые функции, вход — только данные:

- `trackingNodes(walls, start)`: концы осей стен ненулевой длины в порядке массива, у стены — `a`, затем `b`. Исключаются точки, совпадающие (в пределах `EPS` проекта) с концом оси другой стены, и точка, совпадающая с `start`. Порядок задаёт детерминированный выбор при равенстве.
- `trackFree(raw, nodes, radiusCm)`: независимый выбор лучшей вертикали и лучшей горизонтали; результат — `{ x: TrackHit | null; y: TrackHit | null }`, где `TrackHit = { node: Point; value: number }`. Выбор — минимальное `|raw.x − node.x|` (соответственно `y`) при `≤ radiusCm`; строго меньше, чтобы при равенстве побеждал более ранний узел.
- `trackOnRay(raw, nodes, radiusCm, start, dir)`: для каждой сработавшей линии узла (расстояние от курсора до линии `≤ radiusCm`), не параллельной лучу (`|dir.x| > AXIS_TOL` для вертикали, `|dir.y| > AXIS_TOL` для горизонтали), — пересечение с прямой луча при параметре `s > EPS`. Выбирается пересечение с минимальным расстоянием до `raw`; при равенстве — более ранний узел. Результат — `{ point: Point; line: TrackLine } | null`.

Равенство расстояний (в обеих функциях) понимается с допуском `EPS = 1e-9` см, как в `wall-snap.ts`: кандидат заменяет текущего лучшего, только если его расстояние меньше на величину больше `EPS`. Это делает правило «при равенстве — более ранний узел» устойчивым к погрешностям вычислений, в том числе на наклонном луче, где вертикаль одного узла и горизонталь другого могут пересекать луч в одной точке, а вычисленные расстояния различаются на ~1e-14. Порядок кандидатов при этом — порядок узлов (стена в массиве, затем `a` перед `b`); для одного узла вертикаль рассматривается раньше горизонтали.

`TrackLine = { from: Point; to: Point }` — отрезок от узла до конца (дискриминант не нужен: ориентация следует из координат).

Альтернатива — встроить трекинг в `snapVertex`/`snapOnRay`: отвергнута, так как эти функции используются и до первого клика, и при перетаскивании, а их контракт заморожен тестами.

### D2. Встраивание в `chainSegment`

Порядок внутри `chainSegment` после вычисления `snap` (`snapVertex` или `snapOnRay`, как сейчас):

```
snap.source === "wall"         -> как сейчас, tracks = []
typedLengthCm !== null         -> как сейчас (направление от start к snap.point или fixed), tracks = []
fixed (направление задано)     -> hit = trackOnRay(...); hit ? end = hit.point, tracks = [hit.line]
                                                         : как сейчас
не задано                      -> t = trackFree(...);
                                  end = { x: t.x?.value ?? snap.point.x, y: t.y?.value ?? snap.point.y }
                                  dir = unit(end − start); tracks = линии сработавших осей
```

В свободном режиме координата без трекинга берётся из `snap.point`, который в этой ветке — узел сетки, что даёт «одна ось — трекинг, другая — сетка» без отдельного расчёта.

`ChainSegment` получает поле `tracks: TrackLine[]` (0..2 элемента). `snap` остаётся результатом привязки к стене/сетке и не подменяется: при трекинге `snap.source === "grid"`, поэтому `chainEndSquare` строит последний блок вдоль сегмента, как требует спека. Узлы считаются через `trackingNodes(walls, start)` внутри `chainSegment`; вход `ChainInput` не меняется.

### D3. Отрисовка

`RenderOptions` получает `tracks?: TrackLine[] | null`. `render.ts` рисует их пунктиром в экранных координатах с постоянной экранной толщиной и отдельным контрастным цветом (по аналогии с `drawAngle`). `main.ts` передаёт `segment.tracks`, только пока цепочка начата; после фиксации/Esc `segment` сбрасывается, и линии исчезают. В модель `Wall` и хранилище ничего не добавляется.

### D4. Слои

Модуль трекинга — доменная логика привязки (чистые функции над `Point`/`Wall`), `wall-chain.ts` — оркестрация расчёта сегмента, `render.ts`/`main.ts` — представление и состояние. Направление зависимостей не меняется.

## Risks / Trade-offs

- **Производительность.** Узлы пересчитываются на каждое движение указателя: O(n²) для проверки совпадения концов. Для планов квартир (десятки стен) это пренебрежимо мало; при необходимости — сортировка/хэш по квантованным координатам без изменения поведения.
- **Конец трекинга внутри тела стены.** Если курсор вне зоны прилипания к стене, но линия узла уводит конец внутрь тела другой стены, превью покажет наложение — так же, как это сейчас возможно с узлом сетки. Спека этого не запрещает; при необходимости — отдельное изменение.
- **Почти совпадающие концы (легаси).** Концы осей, близкие, но не совпадающие (в пределах допуска стыка старой модели), остаются двумя узлами. Это сознательное решение: исключаются только точно совпадающие точки.
- **Шум линий.** В плотных сценах линии могут срабатывать часто; радиус ограничен 12 px экрана, поэтому линия появляется лишь при почти точном совпадении координаты.
- **Совместимость.** Данные чертежей и хранилище не меняются, миграция не нужна. Существующие тесты `chainSegment` сравнивают поля результата; новое поле `tracks` может потребовать проверки, что эти тесты не используют точное сравнение всего объекта (см. test-plan).
