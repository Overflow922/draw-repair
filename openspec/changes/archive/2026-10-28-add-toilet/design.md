## Context

Предмет мебели сегодня — один тип `FurnitureItem` (центр, ширина, длина, угол, `kind`); вид задаёт запись каталога `FURNITURE_KINDS`, а пересечения, выделение, габариты (два числа), панель (три поля), история и хранение от вида не зависят. Скилл `add-furniture-kind` прямо исключает предметы с другими полями или формой: унитаз — такой случай (четыре размера и форма из двух прямоугольников). Мотивация — `proposal.md`.

Источник рисунка — `references/toilet.png` (копия `img.png`): вид сверху, стена справа, нос чаши слева; на картинке подписаны 380 (ширина чаши) и 700 (ширина блока). Числа картинки сняты по пикселям на глаз (масштаб 0,595 px/мм по размеру 380); картинка содержит и ёршик, который в change не входит.

```

   картинка (стена справа)                 рисунок вида (угол 0: блок сверху)
   +-----------+--+------------+           +--------------------------+
  /   сиденье   |ш |  блок      |           |  блок  X (диагонали)     |

   ё  <- ёршик не рисуем                         \__________/
```

## Goals / Non-Goals

**Goals:**
- Унитаз как один предмет с четырьмя размерами; на «Мебели» и как прибор на «Сантехнике».
- Блок может лежать в гипсокартоне без ложного пересечения; чаша и «уши» прямоугольника — по честной форме.

**Non-Goals:**
- Ёршик, бачок отдельным предметом, ванна, душ, бойлер, выводы ХВС/ГВС/К (остаются в `TODO.md`).
- Общая модель «предмет произвольной формы»: форма вводится только для пересечений унитаза.
- Рисование самого гипсокартона вокруг блока: стена гипсокартона ставится на «Реконструкции» как обычно.

## Decisions

**D1. Четыре размера — в предмете, ширина и длина предмета выводятся.** `FurnitureItem` получает необязательное поле `toilet: ToiletSizes` (`bowlWidthCm`, `bowlLengthCm`, `blockWidthCm`, `blockDepthCm`), заполненное только у унитаза; при чтении из документа оно обязательно для вида «Унитаз» и отбрасывается у остальных видов. `widthCm` и `lengthCm` остаются в предмете и всегда равны ширине блока и сумме «длина чаши + глубина блока»; их выставляет единая функция правки унитаза, так что `itemCorners`, `hitItem`, `itemPointAt`, выделение, рамка, центровка и точки замера размеров работают без изменений по прямоугольнику 70 × 72. Альтернатива — хранить только четыре числа и выводить прямоугольник на лету — заставила бы менять все потребители `widthCm/lengthCm`.

**D2. Форма для пересечений — `footprint`.** Пересечения (`src/furniture/overlap.ts`) сейчас отсекают препятствия прямоугольником предмета (`clipByRect`). Для унитаза отсекаем двумя прямоугольниками (блок и чаша) и объединяем области. Выбрано пользователем: ложные пересечения «ушей» в тесных санузлах недопустимы. Выделение, перетаскивание и ластик остаются по прямоугольнику (вариант проще и достаточен). Пересечение «унитаз × унитаз» считается по формам обоих (на практике — по области наложения прямоугольников формы каждого).

**D3. Исключение «зона блока × гипсокартон».** В структуре исключений добавляется третье измерение — зона предмета × вид препятствия: у вида «Унитаз» область блока не пересекается с препятствиями вида `drywall`. Реализуется на этапе сбора областей: область «блок × гипсокартон» отбрасывается, «чаша × гипсокартон» остаётся. Если область лежит и на гипсокартоне, и на другом объекте, остаётся только другой (по аналогии с исключением кухонных пар). Существующие исключения пар видов (`overlapExemptions`) не меняются.

**D4. Четыре габарита вместо двух.** `item-size-layout.ts` сейчас раскладывает два числа (ширина, длина). Для унитаза раскладываются четыре числа по тем же правилам «внутри/снаружи», каждое отдельно: поперёк чаши, вдоль чаши, вдоль блока, поперёк блока. Раскладка вычисляется, в документе не хранится; на «Сантехнике» — те же числа только для чтения. Правка на месте — по существующей схеме `item-number-edit`: четыре ключа вместо двух. Места сжатия (число ширины блока и ширины чаши рядом) решаются при реализации тестом с реальным размером 70 / 38; если числа налезают, у чаши линия сдвигается к носу (решение в рамках раскладки, не требует новой спеки).

**D5. Якорь при правке — центр.** Как у остальных видов (`furniture-plan` «Правка габаритов на месте»): размер меняется при неподвижном центре и угле. Недостаток: изменение глубины блока сдвигает его заднюю сторону относительно стены. Принято ради единообразия; пользователь возвращает блок к стене перемещением. Если это окажется неудобным — отдельный change.

**D6. Рисунок по картинке.** `unitazDrawing(w, l, bw, bl, bd)` — функция, возвращающая `ItemDrawing` из восьми линий (см. спеку «Унитаз»). Числа сняты с картинки на глаз; перед архивом они сверяются с картинкой в браузере на светлой и тёмной схеме. Не воспроизводятся: ступенчатые «плечи» крышки у задней стороны чаши и полоса фурнитуры на лице блока (3 см со вставками), пометки и размеры самой картинки. Деталям даётся масштаб `k = min(1, bw / 38, bl / 52)`.

**D7. Хранение.** Поля унитаза добавляются в предмет документа; версия документа не меняется; проверка при чтении отбрасывает битый унитаз (нет поля, не положительное, чаша шире блока). Предметы других видов не получают новых полей.

**D8. Сантехника.** Вид получает `water: true`; план «Сантехника» уже рисует приборы по записи каталога. Новый для плана — только четыре габарита вместо двух; расстановка и подсветка как были (подсветки на «Сантехнике» нет вообще).

## Risks / Trade-offs

- [Числа рисунка сняты на глаз] → сверка с картинкой в браузере; числа в спеке правятся до архива.
- [Форма из двух прямоугольников — первая форма, отличная от прямоугольника] → `footprint` вводится узко, только как список прямоугольников предмета; другие виды возвращают один прямоугольник, поведение не меняется (проверяется всем существующим набором тестов).
- [Правка размера при неподвижном центре сдвигает заднюю сторону блока] → D5, зафиксировано; решение пользователя при необходимости.
- [Легенда PDF: добавляется 24-й вид; высотный предел страницы «Мебель» (`furniture-pdf.test.ts` FP-414, 15 записей на A3)] → проверить; если предел превышен — решение уровня `pdf-export`, остановиться и спросить.

## Migration Plan

Формат документа не меняется, миграции нет: старые чертежи не содержат унитазов. Откат — удаление записи каталога и полей предмета; сохранённые унитазы при этом считались бы предметами с неизвестным видом и отбрасывались.
