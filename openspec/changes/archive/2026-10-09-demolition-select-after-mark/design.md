## Context

`createDemolitionTool` (`src/demolition/demolition-tool.ts`): `up(p, px): void` разбирает жест и через `commit` меняет пометки; выделение (`selected`) задаётся только `select`. `main.ts` вызывает `demolitionTool.up(...)` в `pointerup`; `leavePlacing` проёмов (`main.ts`) — образец: инструмент снимается без сброса выделения (`tool = "none"`, `syncToolUI`, `redraw`).

## Decisions

### D1. `up` возвращает идентификатор поставленной пометки

`up(p, px): string | null` — идентификатор пометки, которая получилась после постановки (создана или слита; результат `addMark`), иначе `null`. Снятие пометки, отклонённая и ничего не изменившая операция возвращают `null`. Перед `commit` инструмент выбирает результат постановки: пометка с тем же идентификатором, что вернул бы слитый участок; для этого определяется идентификатор пометки, содержащей участок `[from, to]` в новом списке (по диапазону от конца `a`, допуск `EPS_CM`), как в `editNumber`. Если постановка изменила список, `selected` = этот идентификатор (до `commit`, чтобы перерисовка видела выделение). Снятие пометки, совпадающей с `selected`, сбрасывает выделение.

### D2. `main.ts` снимает инструмент

В `pointerup` плана «Демонтаж»: `if (demolitionTool.up(...) !== null) leaveDemolitionTool()`, где `leaveDemolitionTool` ставит `tool = "none"`, `syncToolUI()`, `redraw()` — без `resetDemolition()` (выделение сохраняется). Через `setTool` нельзя: он сбрасывает выделение.

## Risks / Trade-offs

- Следующую стену нужно метить, снова выбрав инструмент (как проёмы).
- `up` теперь имеет возвращаемое значение; существующие вызовы в тестах его игнорируют.
