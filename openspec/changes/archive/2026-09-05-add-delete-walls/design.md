## Context

Приложение неявно всегда находится в режиме «стена»: клик по пустому холсту начинает цепочку, клик по стене выделяет её (`selectedWall`), кнопка `#tool-wall` — лишь переключатель панели толщины/материала, а не инструмента. Вводимых состояний инструментов нет. История построена на снимках массива стен (`record` до мутации), undo/redo подменяют массив целиком — удаление укладывается в этот механизм без изменений `history.ts`. Соединения стен держатся на равенстве значений точек (`pointsEqual`), ссылок между стенами нет: после удаления соседние стены корректно отрисовываются с плоскими торцами (`jointAt` возвращает `null`). Обработчик `keydown` на `window` сейчас не проверяет источник события — прямая ловушка для Delete при фокусе в полях ввода.

## Goals / Non-Goals

**Goals:**

- Явное состояние инструмента: `wall | eraser | none` (стартовое — `wall`, текущее поведение сохранено).
- Удаление выделенной стены по Delete с защитой от input-фокуса.
- Ластик: серийное удаление кликом, красная hover-подсветка, свой курсор, Escape → `none` (не `wall`).

**Non-Goals:**

- Мультивыделение и групповое удаление (остаётся одна стена за раз).
- Backspace как синоним Delete — только клавиша Delete (решение пользователя).
- Изменение механики undo/redo, модели данных, экспорта PDF.
- Одноразовый (single-shot) ластик — инструмент остаётся активным до переключения (решение пользователя).

## Decisions

**D1. Трёхпозиционное состояние инструмента вместо булева флага.**
`tool: "wall" | "eraser" | "none"` —Escape из ластика переводит в `none`, а не обратно в `wall` (решение пользователя: «отменять ластик, но не возвращаться в режим стен»). В `none` клик по пустому месту ничего не делает, но выделение и перетаскивание работают — выделение не привязано к инструменту. Альтернатива: бинарный переключатель wall/eraser с авто-возвратом — отклонена, противоречит решению по Escape.

Семантика кликов по состояниям:

```
                 | клик по пустому      | клик по стене
  ---------------+----------------------+--------------------
  wall           | цепочка (как сегодня)| выделить
  eraser         | ничего               | удалить
  none           | ничего               | выделить
```

**D2. Общая точка входа удаления.**
Оба сценария сходятся в одну функцию: `record(drawingHistory(...), walls)` → `walls.splice(indexOf(w), 1)` → сброс `selectedWall` если удаляли её → `dirty = true` → `redraw()`. Undo/redo покрываются существующими снимками массива стен, `history.ts` не трогается. Альтернатива (дельта-запись об удалении в истории) — отклонена: избыточна при имеющемся snapshot-механизме.

**D3. Delete — в глобальном `keydown` с guard на input.**
Проверка `(e.target as HTMLElement).tagName === "INPUT"` отсекает поле длины, толщины и динамическое поле переименования вкладки (`.tab-rename`). Только `e.key === "Delete"` (без Backspace). Попутный известный риск: существующий обработчик Ctrl+Z тоже не имеет такого guard — вне скоупа, не усугубляем.

**D4. Hover-подсветка ластика через существующий рендер.**
`render()` уже получает `selected: Wall | null`; добавляется аналогичное поле `hover` в `RenderOptions` — рисуется тем же `drawOutline`, но красным (`rgba(220, 38, 38, 0.5)` вместо teal `rgba(8, 145, 178, 0.5)`). Значение вычисляется при каждой перерисовке (`redraw`) при `tool === "eraser"` через существующий `hitWall(cursor, walls, SNAP_RADIUS_PX / (PX_PER_CM * view.zoom))` — тот же hit-test, что и для клика, поэтому подсветка и удаление всегда согласованы; пересчёт на кадр не оставляет устаревшей подсветки при панораме или undo. Дешёво: `cursor` уже трекается и `redraw()` уже вызывается на каждый `pointermove`.

**D5. Переключение инструмента — централизованный `setTool`.**
Единая функция: присваивает `tool`, гасит `chainStart` (аналог `endChain`), сбрасывает `selectedWall`, закрывает `wallPanel` при уходе из `wall`, синхронизирует классы `.active` кнопок и класс курсора на канвасе. Активация `wall` закрывает панель (панель открывается повторным нажатием — текущее поведение кнопки сохраняется). `activate(id)` (переключение вкладок) сбрасывает `tool` в `wall` — стартовое состояние на вкладке; undo/redo (`resetEditing()`) инструмент НЕ переключают: спека требует сброс только при открытии приложения и активации вкладки, а сброс при отмене ломал бы серию удалений ластиком.

**D6. Курсор ластика — CSS-класс на канвасе.**
Класс (например `.tool-eraser`) переключается в `setTool`; сам курсор — `crosshair` либо inline-SVG data-URI. Деталь реализации, на спеки не влияет.

**D7. Точка вставки кнопки.**
Вторая кнопка `.tool` в `#toolbar` рядом с `#tool-wall`; CSS `.tool.active` уже существует. Панель параметров остаётся popover-ом якоря «Стена» (`:has(.tool-panel.open)` вёрстку не ломает — панель открывается только в `wall`).

## Risks / Trade-offs

- [Delete при фокусе в динамическом input переименования вкладки] → guard по `tagName === "INPUT"` покрывает `.tab-rename`, отдельной логики не нужно.
- [Undo после удаления заменяет массив стен — ссылки в `selectedWall`/drag-состоянии становятся висячими] → существующие `resetEditing()`/`activate()` уже сбрасывают выделение при undo/redo; удаление не добавляет новых состояний.
- [Подсветка расходится с кликом, если hit-test посчитать дважды по-разному] → одно значение вычисляется в `pointermove`, клик переиспользует `hitWall` с теми же параметрами в момент клика; расхождение возможно только при смене геометрии между событиями, что в пределах одного указателя не воспроизводимо.
- [Ластик активен, пользователь начинает цепочку через Delete-сценарий…] → цепочка в `eraser` не начинается по определению (клик по пустому месту игнорируется), конфликт невозможен.

## Migration Plan

Без миграции данных: модель `Drawing`, стор и формат истории не меняются. Раскатывается одной сборкой; откат — обратный коммит.

## Open Questions

Нет — все развилки закрыты решениями пользователя (активность ластика, красная подсветка, Escape → `none`, без Backspace, смена курсора).
