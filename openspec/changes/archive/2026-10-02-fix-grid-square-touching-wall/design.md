## Context

Привязка начальной вершины живёт в `src/wall-snap.ts`:

- `snapVertex(p, walls, radiusCm, gridStepCm, newWallThicknessCm, orthoFrom?)` —
  кандидаты на гранях и свободных торцах в зоне `reach = max(radius, newHalf)`
  от курсора, проверка неналожения квадрата (`overlapsBodies`, касание
  допустимо), ближайший кандидат; иначе — узел сетки `{source: "grid"}`.
- `placementSquare(snap, size)` — для сеточного результата квадрат по осям
  экрана с центром в вершине.

Одна и та же `snapVertex` вызывается в трёх местах:

1. `src/main.ts` `snapWallCursor` — до первого клика (превью квадрата и вершина,
   которую фиксирует `commitPoint`);
2. `src/main.ts` обработчик `click` — `wallClickAction(raw, snapVertex(...))`
   решает «выделить или рисовать»;
3. `src/wall-chain.ts` `chainSegment` — свободный конец без заданного
   направления.

По спецификации меняется только начальная вершина (1, 2); свободный конец (3)
сохраняет прежнее поведение. Все функции привязки чистые, тесты обращаются к ним
напрямую; `main.ts` модульными тестами не покрыт.

Инструментов форматирования, линтинга и мутационного тестирования в проекте нет;
есть `tsc` (strict) и `vitest`.

## Goals / Non-Goals

**Goals:**

- Начальная вершина: квадрат по сетке никогда не касается тел стен и не
  налагается на них, кроме случая «цели нет» (spec: «Квадрат по сетке не
  касается стен»).
- Превью и клик по-прежнему используют один и тот же результат привязки.
- `snapVertex`, `snapOnRay`, `chainSegment` и их утверждённые тесты не меняются.

**Non-Goals:**

- Свободный конец сегмента, орто-луч, трекинг.
- Изменение формы квадрата по сетке (остаётся центрированным).
- Формат данных, отрисовка, история.

## Decisions

### D1. Новая функция `snapStartVertex` поверх `snapVertex`

В `src/wall-snap.ts` добавляется экспорт

```
snapStartVertex(p, walls, radiusCm, gridStepCm, newWallThicknessCm): VertexSnap
```

с той же формой результата, что у `snapVertex` (`{point, source}`, `normal` и
`target` неперечислимы — через существующий `wallSnap`).

Алгоритм:

1. `r = snapVertex(p, walls, radiusCm, gridStepCm, newWallThicknessCm)`; если
   `r.source === "wall"` — вернуть `r`.
2. Построить квадрат по сетке `placementSquare(r, newWallThicknessCm)` и найти
   стены, тело которых (`displayPolygons(w, walls)`) имеет с ним общую точку
   (D2). Нет таких — вернуть `r`.
3. Для каждой касаемой стены собрать кандидатов по тем же правилам, что в
   цикле `snapVertex` (в полосе: за концом — свободный торец, в пределах длины —
   ближняя грань, запасная — дальняя; вне полосы — грань той стороны, где
   курсор), но **без ограничений зоны** (`reach`) для этой стены. Кандидаты
   проходят ту же проверку неналожения квадрата на тела.
4. Ближайший к курсору принятый кандидат (строго меньше, при равенстве — стена
   раньше в массиве) → `wallSnap`; нет кандидатов — вернуть `r` (сетка).

Альтернативы:

- *Флаг `start` в `snapVertex`* — меняет сигнатуру функции, которую дергает
  `chainSegment` и десятки утверждённых тестов; отдельная функция изолирует
  изменение.
- *Расширить `reach` на полшага сетки* — не закрывает наложение при грани вне
  линий сетки и делает зону зависимой от сетки, вопреки спецификации («зона
  зависит только от радиуса и размера квадрата»).

### D2. Касание — общая точка с допуском

Квадрат и куски `displayPolygons` выпуклые. Касание определяется теоремой о
разделяющей оси по нормалям рёбер обоих многоугольников: тела не касаются, если
существует ось, на которой зазор между проекциями больше `LINE_TOL` (1e-6).
Иначе — касание или наложение. Касание углом к углу также считается касанием
(spec: «общих точек»).

Существующий `overlapsBodies` не подходит: он намеренно считает касание по
стороне допустимым.

### D3. Перенос цикла кандидатов без дублирования

Тело цикла `snapVertex` по стенам (полоса / торец / грани / вне полосы)
выносится во внутреннюю функцию, принимающую стену, курсор, сцену, `newHalf`,
функцию `accept` и зону `reach` для этой стены. `snapVertex` вызывает её с
`reach = max(radius, newHalf)` для всех стен; `snapStartVertex` — с
`reach = Infinity` только для касаемых стен. Поведение `snapVertex` при этом не
меняется (покрыто существующими тестами).

### D4. Интеграция в `main.ts`

`snapWallCursor` (ветка `!chainStart`) и обработчик `click` (аргумент
`wallClickAction`) вызывают `snapStartVertex` вместо `snapVertex`. Остальная
логика (`commitPoint`, `placementSquare`, `startRefOf`) не меняется: результат
прилипания имеет ту же форму, что и раньше, поэтому опора начала (`target`,
`normal`) работает для новых случаев автоматически.

`wallClickAction` при `source === "wall"` рисует — для расширенной зоны это
верно: клик вне тела по квадрату, прилипшему к стене, начинает стену.

## Risks / Trade-offs

- **Вершина «прыгает» дальше, чем раньше.** В расширенной зоне вершина
  переезжает к грани на расстояние до полутолщины плюс округление к сетке.
  Это и есть ожидаемое поведение — квадрат и так визуально у грани.
- **Касание углом у наружного угла.** Квадрат по сетке, касающийся угла стены
  только вершиной, тоже вызывает прилипание к ближайшей цели этой (касаемой)
  стены; цели некасаемых стен в расширенном проходе не рассматриваются (D1 п. 3). Принято
  спецификацией; если окажется навязчивым — уточнить спецификацию отдельно.
- **Производительность.** Дополнительный расчёт `displayPolygons` по стенам —
  только когда первичный результат сеточный; сцена контура уже кешируется
  лениво. На ручных сценах затраты пренебрежимы.
- **Непокрытая интеграция.** Подмена вызова в `main.ts` тестами не
  проверяется — нужна ручная проверка в браузере (dev-сервер на
  `/draw-repair/`).
- **Совместимость.** Формат чертежей и API `snapVertex` не меняются; миграция
  не требуется.
