## Context

Жесты правки стен живут в `src/main.ts` (обработчики `pointerdown`/`pointermove`/`pointerup`, состояния `groupMove` и `endpointDrag`). На каждом `pointermove` жест восстанавливает снимок начала (`restoreWalls`) и применяет полный вектор от него — итог не зависит от пути указателя.

Сейчас при орто ось выбирается заново на каждом `pointermove` и только в конусе 15°:

- привязка точки — `snapWithSource(cursor, walls, grid, r, orthoFrom)` (`src/geometry.ts`): `orthoLockAxis` возвращает ось, если вектор `cursor − orthoFrom` в пределах 15° от оси, иначе привязка по обеим координатам;
- стены, исключаемые из привязки, — `stretchSnapWalls` (`src/main.ts`) через `orthoDirection(null, …)` с тем же конусом;
- правка с ограничениями — `moveWallsBounded` / `moveEndpointBounded` (`src/wall-edit.ts`) берут ось из `orthoAxisOf` (`src/tee-bounds.ts`, конус 15°, иначе `null`), и при `null` вектор остаётся диагональным;
- `planEdit(…, ortho = true)` (`src/edit-plan.ts`) передаёт этот вектор в `planOrthoStretch` (`src/ortho-stretch.ts`): диагональному вектору не параллельна ни одна стена — каскад на весь связный чертёж.

Тот же `snapWithSource` с `orthoFrom` используется для курсора инструментов с началом цепочки (`toSnappedPoint`, `orthoFrom = chainStart`); это не правка положения стен, и требование к нему не меняется.

## Goals / Non-Goals

**Goals:**

- Ось орто выбирается один раз на жест по направляющему вектору (spec `wall-selection` «Орто без боковой составляющей») и хранится до `pointerup`.
- Вектор, который получают правила следования и ограничители, при орто всегда лежит на оси — диагональный каскад невозможен.
- Ни одного порогового угла в выборе оси правки: только сравнение модулей составляющих.

**Non-Goals:**

- Орто-привязка при рисовании цепочки и курсор `toSnappedPoint` (конус 15° остаётся, `wall-drawing` не меняется).
- Каскад от стены, наклонённой больше `RIGHT_SIN` (0.5°), и перемещение стены вдоль собственной оси (`TODO.md`).
- Ввод длины наклонной стены при орто (`resizeWallBounded`): вектор вдоль наклонной стены диагонален, и `planOrthoStretch` даёт тот же каскад. Требование ввода длины в этой правке не меняется — записано в `TODO.md`.

## Decisions

### D1. Чистый модуль оси жеста `src/ortho-axis.ts`

Одна ответственность — выбор и применение оси:

- `type Axis = "x" | "y"`;
- `dominantAxis(v: Point): Axis | null` — `"x"`, если `|v.x| ≥ |v.y|`, иначе `"y"`; `null` только для нулевого вектора;
- `latchAxis(current: Axis | null, dir: Point): Axis | null` — уже выбранная ось не меняется; иначе `dominantAxis(dir)`;
- `onAxis(v: Point, axis: Axis): Point` — проекция вектора на ось (составляющая поперёк обнуляется).

Модуль без зависимостей от DOM и состояния — тестируется напрямую. Альтернатива — хранить логику в `main.ts`: отвергнута, `main.ts` и так велик, а правило выбора — доменное.

### D2. Шаг орто-жеста — чистый модуль `src/ortho-gesture.ts`

Правила жеста (когда защёлкивается ось, какой направляющий вектор, где точка привязки, какие стены в ней участвуют) — поведение из спецификации, поэтому они живут в тестируемом модуле, а не в обработчиках `main.ts`:

- `type OrthoGesture = { kind: "move" | "end"; press: Point; ref: Point; axis: Axis | null }` — неизменяемое состояние жеста: точка нажатия, опорная точка (опорный конец `baseA` для перемещения, противоположный конец для перетаскивания конца) и защёлкнутая ось;
- `startOrthoGesture(kind, press, ref): OrthoGesture` — ось `null`;
- `orthoGestureStep(g, pointer, walls, seed: StretchSeed, gridStepCm, radiusCm): { gesture: OrthoGesture; target: SnapResult | null }`:
  - ось защёлкивается только при ненулевом смещении `pointer − press`; направляющий вектор — `pointer − press` для перемещения, `pointer − ref` для конца; затем `latchAxis` (D1);
  - пока оси нет — `target = null` (правка не применяется);
  - точка привязки: перемещение — `ref + (pointer − press)`, конец — `pointer`; привязка `snapAlongAxis` (D3) через `ref` по защёлкнутой оси среди стен, не увлекаемых правкой (D4).

`main.ts` остаётся тонким: на `pointerdown` создаёт жест `startOrthoGesture` и хранит его в `groupMove` / `endpointDrag`; на `pointermove` при орто восстанавливает снимок, вызывает `orthoGestureStep`, сохраняет новый жест и при `target ≠ null` вызывает правку с вектором `target.point − ref` (перемещение) или целью `target.point` (конец, если не совпадает с противоположным концом); `pointerup` и сброс жестов удаляют состояние — следующий жест начинается с оси `null`. Режим орто читается из переключателя: он меняется только кнопкой, во время захвата указателя переключить его нельзя.

Выбор направляющего вектора для конца не по смещению указателя, а от противоположного конца: иначе первое смещение поперёк стены развернуло бы её на 90°. Момент выбора — как у перемещения: первое ненулевое смещение от точки нажатия.

Тесты жестов вызывают `startOrthoGesture` / `orthoGestureStep` и правку с ограничениями — ту же последовательность, что `main.ts`. Непокрытой остаётся только обвязка DOM (создание жеста на `pointerdown`, хранение между `pointermove`, удаление на `pointerup`) — ручная проверка в tasks.

### D3. Привязка вдоль заданной оси (`src/geometry.ts`)

Новая экспортируемая функция `snapAlongAxis(cursor, walls, gridStepCm, radiusCm, through: Point, axis: Axis): SnapResult` — обёртка над существующей `snapOnOrthoAxis` с осью через `through`. Жесты правки при орто вызывают её (через `orthoGestureStep`, D2) вместо `snapWithSource(…, orthoFrom)`.

`snapWithSource` и `orthoLockAxis` не меняются: их конус остаётся для курсора цепочки (Non-Goals), поэтому существующие тесты `geometry-ortho-snap.test.ts` (OS-6, OS-6b) остаются верными.

### D4. Исключаемые из привязки стены

В привязке участвуют стены, не попавшие в план `planOrthoStretch(walls, seed, единичный вектор защёлкнутой оси)` (их концы следуют за правкой), невырожденные. Это делает `orthoGestureStep` (D2); `stretchSnapWalls` в `main.ts` с `orthoDirection(null, …)` и конусом 15° удаляется. Знак направления на план не влияет (используется только параллельность).

### D5. Ось в правке с ограничениями (`src/wall-edit.ts`, `src/tee-bounds.ts`)

`orthoAxisOf` перестаёт иметь конус: ось — `dominantAxis` (D1), `null` только для нулевого вектора. Следствия:

- `moveWallsBounded` проецирует любой ненулевой вектор на доминирующую ось; для вектора от жеста (уже на оси) это тождественно, для стрелок — тоже;
- `moveEndpointBounded` ставит конец на ось доминирующей составляющей `target − other`; при цели на защёлкнутой оси это та же ось;
- `projectMove` при орто сравнивает с опорной стеной доминирующую ось вместо оси в конусе.

Правка остаётся корректной и при прямых вызовах с диагональным вектором (тесты, будущие вызывающие): диагональный вектор в `planOrthoStretch` больше не попадает. `ORTHO_TAN` в `tee-bounds.ts` удаляется.

### D6. Конфликт с утверждённым тестом

`src/wall-edit-tee.test.ts` TB-19a («орто не сработало (> 15°) — проекция как без орто») закрепляет удаляемое поведение: при орто и цели `(60, 100)` конец ножки уходит по грани в `(10, 100)`. По новой спецификации ось жеста — вертикаль через второй конец `(110, 200)`, на которой нет допустимого положения примкнутого конца, кроме исходного: ожидается `(10, 200)`. Тест больше не представляет спецификацию; он заменяется на этапе написания тестов как запрос на изменение утверждённого теста (CLAUDE.md, правило 5) с этим обоснованием, а не правкой при реализации.

Остальные тесты с `ORTHO` (TB-16, TB-16a, TB-17, TB-19, `wall-edit-follow`, `wall-collision`) используют векторы, у которых доминирующая ось совпадает с прежней осью в конусе, либо проверяют инварианты, сохраняющиеся при любой оси.

## Risks / Trade-offs

- **Неверная ось от первого подрагивания.** Без мёртвой зоны первое смещение в 1 px решает ось. Принято сознательно: правило без чисел; исправление — отпустить и потянуть заново.
- **Конец стены нельзя развернуть на 90° при орто.** Горизонтальная стена при перетаскивании конца остаётся горизонтальной до конца жеста, и новый жест снова выберет горизонталь. Для поворота нужно выключить орто. Решение можно пересмотреть отдельно (выбор оси без защёлки только для концов).
- **Наклонная стена становится осевой.** Перетаскивание конца стены под 30° при орто делает её горизонтальной или вертикальной — ожидаемое следствие «орто = ось».
- **Совместимость данных.** Формат чертежа и история не меняются; миграция не требуется.
