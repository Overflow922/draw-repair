## Context

Сейчас точка замера резолвится (`dimPointPoint`) как пересечение **бесконечных** линий сырых граней (`edgeLine` через сырые a/b), а снап постановки (`nearestEdgeIntersection`) перебирает все пары таких линий. Нарисованный контур стены с учётом стыков уже умеет строить `wallShape` (митры, примыкание впритык, T-подрезка через `endCap`/`jointAt`) — отрисовка идёт по нему, а размеры — нет. Отсюда фантомные точки снапа и дрейф точек замера при деформации. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**
- Точки замера живут на нарисованном контуре: резолв = пересечение отрезков граней (сторон `wallShape`), включая касание концом.
- Снап постановки предлагает только вершины контура; постановка и резолв — один примитив (WYSIWYG-инвариант).
- Fallback при разошедшемся стыке — прилипание к ближайшей концевой точке отрезков (решение пользователя, вариант «а»).

**Non-Goals:**
- Смена модели данных (`EdgeRef`-пары), формата хранения, undo/redo, `dimLevelSnap`, перетаскивания размерной линии.
- Изменение семантики редактирования стен: деформация цепочки при сохранении стыков — норма (эталон пользователя); «жёсткие цепочки» отклонены.
- Угловые размеры, подписи углов при редактировании, прочие элементы UI эталонной программы.
- Изменения отрисовки стен (`wall-joints`).

## Decisions

1. **Один примитив: пересечение отрезков контура.** Стороны полигона `wallShape` маппятся на грани: `capA.plus→capB.minus` — edge 0, `capB.minus→capB.plus` — edge 3, `capB.plus→capA.minus` — edge 1, `capA.minus→capA.plus` — edge 2. Резолв пары (грань стены A, грань стены B) — пересечение этих отрезков с допуском касания концом (совпадение концов обеспечено построением: подрезки вычисляются теми же `lineIntersect`). Точка = вершина контура. Альтернатива «бесконечные линии + clamp к отрезкам» отклонена: clamped-точка продолжает скользить по грани (сам баг) и даёт точки внутри тела соседней стены.

2. **Вырожденные случаи.** Параллельные или коллинеарно перекрывающиеся отрезки (стык «в линию», пара боковых граней коллинеарных стен) уникальной точки не дают → действует fallback. T-примыкание: подрезанный торец приходит концами ровно на грани сквозной стены — касание концом даёт единственную точку для пар (торец, грань±). Три стены в одной вершине (`jointAt` count>1) → плоские торцы, углы контура = сырые углы, пары резолвятся тем же примитивом.

3. **Fallback (вариант «а»):** если отрезки не соприкасаются, точка = точка первого отрезка, ближайшая ко второму (стандартный closest-point пары отрезков); детерминировано, остаётся на реальной геометрии, размер не исчезает и **скользит по грани вслед за геометрией** — legacy-пары, потерявшие касание, отслеживают движение стен вместо примерзания к статичной вершине. Для параллельных/коллинеарных пар алгоритм вырождается в концевую точку (те же значения, что у первой версии fallback'а).

4. **Снап постановки тем же примитивом.** Кандидаты — все пары нарисованных отрезков всех стен с валидной точкой касания (включая пары граней одной стены — её собственные углы). Победитель — ближайший к клику в радиусе; при равенстве приоритет: (1) обе грани одной стены, (2) точка — конец обоих отрезков (митра), (3) касание концом (примыкание/T). Причина — каноничная атрибуция: пара обязана резолвиться в ту же вершину, пока стык существует, и следовать за стыком, а не за чужой линией. Альтернатива «без приоритетов, первый попавшийся» — так делалось раньше и давало привязку угла к чужой линии.

5. **Значение размера** = расстояние между резолвнутыми вершинами контура. В стыках значения сдвинутся с «сырых» углов на нарисованные (наружная митра, подрезка) — как в эталоне (внутренний/наружный размеры отличаются на толщину). У свободных углов значения не меняются.

6. **Хранилище/история не трогаются:** пары `EdgeRef` сохраняются как есть; старые чертежи резолвятся по новым правилам на лету; снисходящий парсинг не затронут. `dimHitDistance` (ластик/выделение/захват) получает точки из того же резолва — области попадания остаются на видимых углах.

## Risks / Trade-offs

- [Снап на каждом pointermove перебирает O(N²) пар отрезков и строит `wallShape`] → строить `wallShape` по одному разу на стену за проход; сложность того же порядка, что текущая (пары линий); кэшировать только при реальных лагах.
- [Резолв зависит от порядка стен в массиве (сквозная/примыкающая)] → резолв — чистая функция текущего массива, как и отрисовка: WYSIWYG сохраняется; порядок меняется только при реальных правках.
- [Существующие сохранённые размеры в стыках визуально сдвинутся] → принимается как часть исправления; упомянуть в отчёте.
- [Числовой допуск касания] → совпадения концов строятся одними функциями пересечения, достаточно EPS ~1e-6 как в `pointsEqual`; остаточные зазоры уходят в fallback.
- [Поведенческие тесты фикстур] → помнить грабли dimension-snap: edge 2/3 вертикальной стены — горизонтальные торцы; фикстуры стыков собирать из боковых граней (edge 0/1).
