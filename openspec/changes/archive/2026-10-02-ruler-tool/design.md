## Context

- Инструменты переключаются в `src/main.ts` через `type Tool = "wall" | "dimension" | "eraser" | "none"`, `setTool` и `syncToolUI`. Кнопки находятся в `index.html` (`#tool-wall`, `#tool-dimension`, `#tool-eraser`). Esc выключает «Размер» и «Ластик» в `setTool("none")` (`main.ts`, обработчик `keydown`).
- В состоянии «без инструмента» курсор в `pointermove` привязывается к сетке (`toSnappedPoint`). Клик по стене выделяет её через `hitWall` с полосным допуском, рамка запускается в `pointerdown` для любого инструмента, кроме ластика. Обработчика `pointerleave` нет: после ухода с холста `cursor` сохраняет последнее значение.
- `redraw()` пересчитывает всё отображение по текущим `walls` и `cursor` при каждом событии, в том числе после undo/redo и правок. Отдельной инвалидации кэшей нет.
- Отображаемая форма стены — `displayPolygons(wall, walls)` (`src/wall-geometry.ts`). Куски разных стен не перекрываются: поздняя стена вычитается из тела ранних, продолжения и клинья принадлежат одной из стен. Они только соприкасаются по границам.
- Помещения — `findRooms(walls)` (`src/room-area.ts`): `outline` и `holes` по внутренним граням, построенные через объединение форм в целой сетке адаптера clipper (`CLOSE_CM = 0.001`). Вложенные помещения возвращаются отдельными элементами, а остров внешнего помещения — это контур, внутри которого находится вложенное.
- Отрисовка: `drawScene` (`src/render.ts`) принимает `RenderOptions`. Размер рисуется `drawDimensionGeom(geom, text, color, …)`, угол построения — `drawAngle` (кратчайший сектор, луч отсчёта, подпись `Math.round(deg)°` на подложке, цвет `ANGLE_COLOR`). Длина форматируется `formatLength(cm, unit)` в `render.ts`. PDF вызывает `drawScene` со своими опциями (`src/export/pdf.ts`).

## Goals / Non-Goals

**Goals:**
- Выделить расчёт замеров линейки в чистый модуль без DOM и canvas, тестируемый на сценах из стен.
- Переиспользовать существующие формы стен, помещения, формат длины и стиль размеров и угла, не меняя их поведение.
- Ограничить изменения `main.ts` проводкой: новое значение инструмента, курсор без привязки, сброс курсора при уходе с холста, передача замера в отрисовку.

**Non-Goals:**
- Кэширование `displayPolygons` и `findRooms` между кадрами.
- Изменение поведения выделения, рамки и перетаскивания: при линейке они работают как в состоянии «без инструмента».
- Изменение угла построения стены (`drawAngle` для `opts.angle` остаётся прежним).

## Decisions

### D1. Чистый модуль `src/ruler.ts` с размеченным результатом

Модуль экспортирует одну функцию `rulerReading(p: Point, walls: Wall[]): RulerReading` и типы результата:

```text
RulerReading =
  | { kind: "wall"; wall: Wall; from: Point; to: Point; lengthCm: number }
  | { kind: "space"; horizontal: Span | null; vertical: Span | null; angles: RoomAngle[] }

Span      = { from: Point; to: Point; lengthCm: number }
RoomAngle = { at: Point; startDir: Point; sweepDeg: number; deg: number }
```

`kind` разделяет режимы спецификации: курсор над стеной или в пустоте. `angles` пуст вне помещения, `horizontal` и `vertical` равны `null`, если направление не замкнуто стенами. Пустой чертёж даёт `space` с `null`, `null`, `[]`. Модуль зависит только от `types`, `wall-geometry`, `geometry` (`distanceToWall`, D2) и `room-area`, поэтому относится к domain-слою наравне с `room-area.ts` и `wall-angle.ts`.

Альтернатива — считать замеры прямо в `render.ts` или `main.ts`. Её отвергли: логику нельзя было бы проверить без canvas, а `main.ts` и так велик.

### D2. Выбор стены под курсором — собственный отбор, не `hitWall`

Для каждой невырожденной стены берутся куски `displayPolygons(wall, walls)`. Кандидаты — стены, у которых хотя бы один кусок содержит `p` (`pointInPolygon` включает границу). Из кандидатов выбирается стена с наименьшим расстоянием от `p` до отрезка оси, при равенстве — с меньшим индексом в `walls`. Замер — `from = wall.a`, `to = wall.b`, `lengthCm = |b − a|`.

Почему не `hitWall`: у неё полосный допуск по оси (нарушает «вне формы — замера нет»), а среди перекрытий она выбирает позднюю стену, тогда как спецификация требует ближайшую ось, затем раннюю. Куски разных стен не перекрываются, поэтому несколько кандидатов бывает только на общей границе. Правило нужно для детерминированности, а не для частого случая.

Расстояние до отрезка оси: в `wall-geometry` есть приватная `axisDistance`, а в `geometry.ts` — экспортируемая `distanceToWall` (до отрезка `a`–`b`). Используется `distanceToWall`; новой копии функции не появляется.

### D3. Лучи пролёта — пересечение с рёбрами кусков форм

Если стена не найдена, все куски всех стен собираются в один список. Для каждого из четырёх направлений `(±1, 0)` и `(0, ±1)` ищется наименьший параметр `t > 0` пересечения луча `p + t·d` с рёбрами всех кусков. Пересечение с осевым лучом считается аналитически: ребро пересекает горизонталь `y = p.y` (или вертикаль `x = p.x`), берётся координата точки пересечения. Рёбра, лежащие на самой линии луча (коллинеарные), пропускаются: соседнее ребро того же куска даст ту же точку входа.

Так как `p` вне всех форм, первое пересечение — это вход в тело стены, то есть её грань. Пролёт строится, если найдены оба луча направления: `from` — точка влево (вверх), `to` — вправо (вниз), `lengthCm = |to − from|`. Острова (колонны) — тоже стены, поэтому они учитываются без особого случая.

Луч бьёт по формам стен, а не по контуру помещения из `findRooms`. Пролёт определён и вне помещений (П-образный контур, снаружи дома), а контур помещения проходит через целую сетку clipper и дал бы погрешность до `CLOSE_CM`.

### D4. Углы — по внешнему контуру помещения, содержащего курсор

Только в режиме `space`. По `findRooms(walls)` выбирается помещение, для которого `pointInPolygon(p, outline)` истинно и `p` не внутри ни одного из `holes`. Вложенные помещения лежат в островах внешнего, поэтому подходящее помещение не больше одного. Если курсор на границе нескольких — берётся первое в порядке `findRooms`.

Расчёт по `outline`:

1. **Чистка контура.** Контур `findRooms` у стыков стен содержит шум: дубли вершин после целой сетки clipper, а у стыков под почти прямым углом ещё и микрорёбра до ~0,05 см с резкими поворотами и узкие щели (при изломе 0,4° — глубиной ~10 см и шириной ~0,002 см; проверено на текущей геометрии, см. `test-suite.md`). Перед расчётом углов контур упрощается, пока изменения не прекратятся:
   - **Короткое ребро** (длина < `MIN_EDGE_CM = 0.1`) стягивается в одну вершину — пересечение прямых соседних рёбер, если они не почти параллельны; иначе в середину ребра. Так вершина угла остаётся там, где сходятся длинные грани.
   - **Шип** — вершина с внутренним углом < `SPIKE_DEG = 1°` или > `360° − SPIKE_DEG`. Она удаляется: это вырожденная щель или выступ нулевой ширины, а не угол помещения. После удаления соседние вершины проверяются заново.
   - Удаление идёт до неподвижной точки. Контур из менее чем трёх вершин даёт пустой список углов.

   Чистка относится только к расчёту углов. Контур помещения, его заливка и площадь (`room-areas`) не меняются. Пороги выбраны так, чтобы не задеть реальную геометрию: рёбра комнаты короче 1 мм и углы острее 1° на плане квартиры не встречаются. Альтернатива — исправить стыки в `wall-joints`, чтобы щель не возникала. Это отдельное изменение с другой спецификацией, и линейка всё равно должна быть устойчива к шуму целой сетки.
2. **Ориентация.** Знак ориентированной площади контура `s` (обход в мировых координатах с осью y вниз).
3. **Внутренний угол вершины.** Для вершины `v` с соседями `prev` и `next`: `e1 = v − prev`, `e2 = next − v`, поворот `τ = atan2(cross(e1, e2), dot(e1, e2))`, внутренний угол `θ = 180° − s·τ` (в градусах, в `(0°, 360°)`). Сумма углов контура равна `(n − 2)·180°`, у входящего угла Г-образной комнаты получается 270°. **Округление до сотых.** θ сразу округляется до 0,01°. Контур проходит через целую сетку clipper (0,001 см), и погрешность направления на ребре длиной в метры даёт угол вида 112,49969° вместо 112,5°. Без округления подпись получила бы «112°» вместо «113°» (спецификация, сценарий «Косой угол»). Погрешность сетки на порядки меньше 0,005°, поэтому округление до сотых возвращает точное значение там, где углы осей заданы точно. Отбор почти прямых вершин (шаг 4) и подпись работают с округлённым значением.
4. **Отбор.** Вершина пропускается, если `|θ − 180°| < 0.5°`. Также пропускается вершина на торце свободного конца стены (спецификация, «Торец перегородки не подписывается»):
   - Конец `E` оси стены свободный, если `E` не лежит ни в одном куске `displayPolygons` других стен (`pointInPolygon` включает границу). Близость к стене без попадания в форму примыканием не считается. В форме соседней стены или на её границе оказываются концы при стыках конец-в-конец, T-примыканиях к оси и к грани, стыках на одной прямой и у упёртой стены углового стыка на грани. У сквозной стены углового стыка на грани конец оси может лежать вне формы партнёра и формально считаться свободным. Это безвредно: углы её торца лежат в теле партнёра, вдали от вершин помещения (в сцене F — не ближе 20 см).
   - Торец свободного конца плоский, его углы — `E ± n·t/2`, где `n` — нормаль оси, `t` — толщина.
   - Вершина контура пропускается, если она ближе `CAP_TOL_CM = 0.05` к углу торца какой-либо свободной стены. Допуск больше сетки clipper (0,001 см) и смещения вершины при чистке, но много меньше толщины стены.
   - Свободные концы считаются по тем же `displayPolygons`, что и выбор стены (D2), один раз за вызов `rulerReading`.
5. **Дуга.** `startDir` — единичный вектор от `v` к `next`, `|sweepDeg| = θ`: сектор поворачивается от `startDir` до направления на `prev` через сторону помещения. Знак `sweepDeg` определяется знаком `s`, то есть ориентацией обхода. `deg = θ`, округление до целых выполняет отрисовка (как у угла построения).

Острова (`holes`) не обходятся. Конкретное направление знака проверяется тестом на Г-образной комнате (дуга входящего угла содержит точку внутри комнаты).

### D5. Отрисовка: опция `ruler` в `RenderOptions`

В `RenderOptions` добавляется `ruler?: RulerReading | null`. `drawScene` рисует её последней перед рамкой, поверх стен, заливки, подписей площади и размеров:

- **Замер стены и пролёты** — через существующую `drawDimensionGeom(dimGeometry(from, to, 0), formatLength(lengthCm, unit), RULER_COLOR, view, m)`. Засечки, число на подложке, экранные размеры и единицы те же, что у размера. Цвет `RULER_COLOR` берётся равным `ANGLE_COLOR` (синий подсказок построения) и отличается от `INK` и `SELECTED_DIM_COLOR`.
- **Углы** — из `drawAngle` выделяется общая часть «дуга + подпись на биссектрисе» с явным началом и знаковым сектором. `drawAngle` вызывает её с кратчайшим сектором и дорисовывает луч отсчёта, а углы линейки — с `startDir`/`sweepDeg` из `RoomAngle` без луча. Поведение угла построения не меняется.

PDF не передаёт `ruler` в `drawScene`, поэтому замеры в экспорт не попадают без отдельной проверки.

### D6. Проводка в `main.ts`

- `Tool` получает значение `"ruler"`, кнопка `#tool-ruler` («Линейка») добавляется в `index.html` после «Размера» без панели; `syncToolUI` переключает её класс `active`.
- В `pointermove` и после окончания сдвига вида при `tool === "ruler"` курсор берётся как `toWorld(e)` (без сетки — замер в точке курсора).
- Добавляется обработчик `pointerleave` на холсте: при линейке `cursor = null` и `redraw()`. Для других инструментов поведение не меняется.
- В `redraw()`: `ruler: tool === "ruler" && cursor && !(marquee || marqueePending || groupMove || endpointDrag || dimDrag || panDrag) ? rulerReading(cursor, walls) : null`. Так замер пересчитывается при каждой перерисовке и после undo/redo следует за стенами.
- Esc: условие `tool === "eraser" || tool === "dimension"` расширяется на `"ruler"`.
- Клик при линейке идёт по ветке состояния «без инструмента» (`hitWall` → `selectWall`, иначе снятие выделения). Ветка `tool !== "wall"` уже даёт это поведение, нужно только убедиться, что `commitPoint` не вызывается.

Состояние линейки не хранится ни в `Drawing`, ни в истории, ни в `localStorage`. Данные чертежа не меняются, миграций нет.

## Risks / Trade-offs

- **Стоимость кадра.** `rulerReading` вызывает `displayPolygons` для всех стен и `findRooms`, а `drawScene` уже вызывает `findRooms` сам — помещения считаются дважды за кадр при каждом движении мыши. На чертежах квартиры (десятки стен) это приемлемо. Если появятся тормоза, `drawScene` можно научить принимать готовые `rooms`. Сейчас кэш не вводится (Non-Goal).
- **Шум контура помещения.** Контур проходит через целую сетку clipper, у стыков бывают микрорёбра и щели. Чистка (D4, шаг 1) стягивает рёбра короче 1 мм и убирает шипы острее 1°. Если реальная комната окажется с ребром короче 1 мм (например, ступенька от неточно поставленной стены), её два угла сольются в один. Это приемлемо для разового замера. Тесты покрывают стыки всех видов (конец-в-конец, угловой на грани, T, почти прямой излом).
- **Щель у почти прямого стыка — дефект `wall-joints`.** Щель в контуре при изломе 0,4°, вероятно, видна и в отрисовке стен. Линейка её маскирует только для углов. Исправление стыков — отдельное изменение.
- **Порог 0,5° против округления.** Угол 180,6° подписывается «181°», а 180,4° не подписывается. Единственный случай подписи «180°» — θ ровно 179,5° (не отбрасывается строгим `<`, `Math.round` даёт 180). Это граница, а не ошибка; тест-план фиксирует её отдельным случаем.
- **Касание лучом вершины.** Луч, проходящий ровно через вершину куска, пересекает два ребра в одной точке — это даёт ту же `t`, на результат не влияет. Коллинеарные с лучом рёбра пропускаются (D3).
- **Курсор ровно на границе формы стены.** `pointInPolygon` включает границу, поэтому на грани показывается замер стены, а не пролёт. Это согласуется со спецификацией («внутри формы»).
- **Совместимость.** Поведение остальных инструментов, сохранение, история и PDF не меняются. Выделение `drawAngle` в общую функцию — рефакторинг внутри `render.ts` с неизменным выводом угла построения, существующие тесты угла должны остаться зелёными.
