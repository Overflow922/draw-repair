## Context

`WALL_TYPES` в `types.ts` несёт id/label/color; `render.ts` рисует стену цветным штрихом (`lineWidth = thicknessCm`), неизвестный тип → fallback `#333`. `storage.ts` валидирует `type` только как строку, поэтому старые чертежи со значениями `partition`/`drywall` загрузятся, но потеряют связь с выбором типа. Спек-дельта `wall-types` из незархивированного `floating-ui` меняет тот же requirement — тексты дельты `gost-walls` написаны с учётом этого; архивировать `floating-ui` раньше.

## Goals / Non-Goals

**Goals:**

- Три категории по несущей способности вместо произвольных типов; корректная миграция сохранённых чертежей.
- Чертёжная монохромная отрисовка: векторная штриховка 45° + вес контура по категории, резкая на любом зуме.
- Данные стиля (плотность/вес) отделены от кода отрисовки — точка расширения для будущих стилей отображения и переключателя.

**Non-Goals:**

- Переключатель стилей отображения, атрибут «материал», паттерны ГОСТ 2.306.
- Изменение геометрии/истории/логики выбора.

## Decisions

- **Категории**: `bearing` «Несущая», `selfbearing` «Самонесущая», `nonbearing` «Ненесущая»; дефолт `nonbearing`; порядок стрелок совпадает с порядком массива. «Несущая» сохраняет id — существующие стены с `bearing` не трогаются.
- **Параметры стиля в данных типа**: каждому типу — `{ hatchSpacingCm, contourPx }`: несущая (8 см, 3px), самонесущая (14 см, 2px), ненесущая (22 см, 1px). Значения стартовые, подгоняются при визуальной проверке. Альтернатива (растровый `createPattern`) отвергнута: мыло при зуме.
- **Векторная штриховка**: полигон стены (4 угла: сегмент ± thickness/2 по перпендикуляру) → `ctx.clip()` → семейство параллельных линий 45° по bbox полигона с шагом `hatchSpacingCm` (в мировых координатах — масштабируется как чертёж), толщина линии штриховки `1/k` (~1px экрана). Контур — stroke того же полигона `contourPx/k` (фиксированные экранные px — читается на любом зуме, как линия на бумаге).
- **Неизвестный тип при отрисовке** → параметры `nonbearing` (fallback вместо `#333`). Покрывает краевой случай: снапшоты в персистентной истории (`draw-repair:history`), записанные до миграции, могут вернуть старое значение при undo — стена останется корректно отрисованной.
- **Миграция**: чистая функция `normalizeWallType(t: string): WallType` в `types.ts` (partition/drywall → nonbearing, bearing → bearing, прочее → nonbearing); применяется в `parseStore` к стенам обоих форматов. Версия хранилища остаётся 1 — значения совместимы, правило «будущая версия → read-only» не затрагивается.
- **Свотчи подпанели**: монохромные мини-штриховки чистым CSS — `repeating-linear-gradient(45deg, …)` с шагом 4/7/10px и рамкой 3/2/1px по категориям; выделение активного образца — как сейчас (синяя рамка + ring).
- **Превью/выделение**: альфа 0.4 у превью и циановая обводка выделения сохраняются поверх штриховки; подписи длин не меняются.

## Risks / Trade-offs

- [Много линий штриховки на длинных стенах при плотном шаге] → Шаг в мировых см, стены короткие; при деградации — caps/адаптивный шаг, не в этом change.
- [Штриховка при малом зуме сливается] → Плотности разнесены (8/14/22 см) + контуры 3/2/1px несут различие даже при сливании штриховки.
- [Undo через персистентную историю возвращает старый тип] → Fallback отрисовки в `nonbearing`-стиль; тип нормализуется при следующем сохранении.
- [Конфликт дельт wall-types с floating-ui] → Текст дельты написан на после-floating-ui контенте; архивировать `floating-ui` строго раньше `gost-walls`.

## Migration Plan

Одно применение: types/storage/render/markup/main.ts + тесты. Хранилище совместимо в обе стороны (старая версия приложения прочитает новые значения `selfbearing`/`nonbearing` как неизвестный тип — вне скоупа). Откат — revert применения.
