## Why

На плане «Мебель» будет много предметов, одинаковых по устройству и разных по назначению (стол, стул, диван). Сейчас стол вшит в код и спеки: тип `Table`, `isTable` в хранилище, запись истории, значения панели, цвет, запись легенды и слово в плашке заданы отдельно для стола в 17 файлах. Каждый новый предмет по этому пути стоил бы около пятнадцати правок и копии требований и сценариев. Нужно сделать предмет мебели данными: одно устройство, а различия вида (название, размеры по умолчанию, цвет, слово в плашке, иконка) — одной записью каталога.

## What Changes

- Предмет мебели плана «Мебель» получает **вид** (`kind`). Стол — первый вид (`table`); устройство предмета (центр, ширина, длина, угол), жесты, перемещение, правка, история, хранение и отрисовка у всех видов общие.
- Каталог видов: для каждого вида задаётся название («Стол»), слово для плашки пересечений, размеры по умолчанию, цвет на светлой и тёмной схеме, иконка кнопки в панели группы. Новый вид добавляется записью каталога.
- Панель группы «Мебель» получает по одной кнопке инструмента на каждый вид каталога; поля «Ширина», «Длина», «Угол» общие для всех видов (значения для новых предметов запоминаются отдельно по каждому виду, начальные берутся из каталога).
- Другие предметы в препятствиях — один вид препятствия «мебель» вместо «стол»; плашка называет предмет по его виду: «Стол пересекается: стена, стол», «Стул пересекается: стол».
- Легенда страницы «Мебель» в PDF содержит запись для каждого вида, чьи предметы есть на странице.
- Вид предмета сохраняется в чертеже; предмет без вида в старых чертежах читается как стол, так что чертежи открываются без потерь.
- **Поведение для пользователя при единственном виде «Стол» не меняется**: все сценарии, описанные для стола, остаются в силе.
- Проектный скилл `add-furniture-kind` для цикла OpenSpec: чек-лист добавления нового вида одним коротким change.
- Тесты перебирают каталог (`it.each`): размеры по умолчанию, различимость цвета, запись легенды, слово плашки; новый вид получает их без новых тестов.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `furniture-plan`: новое требование «Каталог видов мебели»; требование «Пересечения стола» — плашка называет предмет по виду, один вид препятствия для всей мебели.
- `drawing-storage`: новое требование «Вид предмета мебели в документе» — вид сохраняется, у предмета без вида читается «стол».

## Impact

- `src/types.ts` (`Table` → `FurnitureItem` с `kind`), `src/furniture/` (новый `furniture-kinds.ts` — каталог; `table*.ts` переименовываются в `item*.ts`), `src/storage.ts`, `src/history.ts`, `src/export/legend*.ts`, `src/main.ts` и `index.html` (кнопки видов в панели группы), тесты `src/furniture/*.test.ts`.
- Новый файл `.claude/skills/add-furniture-kind/SKILL.md`.
- Формат документа дополняется необязательным полем `kind` у предмета; версия документа не растёт (старые чертежи читаются без миграции).
- Новых зависимостей нет. Форма предмета остаётся прямоугольником; общая функция `footprint` в этот change не входит (решено в обсуждении: выносить, когда появится вид не прямоугольной формы).
