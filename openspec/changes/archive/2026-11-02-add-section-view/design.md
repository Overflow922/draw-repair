## Context

См. `proposal.md` — зачем нужен разрез. Что уже есть:

- План «Реконструкция» хранит собственное содержимое в `Drawing.reconstruction` (`ReconstructionContent`: `walls`, `dimensions`, `callouts`, `notes`). Стена гипсокартона (`DrywallWall`) имеет ось `a`–`b`, толщину и высоту `heightCm`.
- Сцена плана — чистая функция `reconstructionScene(drawing)` (`src/reconstruction/reconstruction-scene.ts`): всё производное вычисляется, ничего не хранится. Рабочий набор `openReconstruction` / `storedReconstruction` (`reconstruction-workspace.ts`) превращает хранимое содержимое в рабочую сцену инструментов и обратно; поля, которые инструменты не правят (выноски, примечания), переносятся как есть.
- Размер (`Dimension`) хранит две точки замера `DimPoint` (`EdgePoint | JambPoint | BatteryCornerPoint | ItemPoint`) и смещение; видимость размера решает `visibleDimensions` по набору существующих целей (`DimensionTargets`).
- Внешний вид — по картинкам `references/`. Для разрезов добавлена `references/sections.png` (контур сечения, штриховка 45°, название «A–A» над фигурой, концевые штрихи, стрелки у штрихов остриём к линии, штриховая линия между штрихами). Конкретные размеры и шаг штриховки берутся из спека; ориентир по форме — эта картинка.

## Goals / Non-Goals

**Goals:**
- Линия разреза и фигура как новые объекты плана «Реконструкция» с сохранением, историей, выбором, удалением, PDF и размерами.
- Фигура — чистая производная от линии и стен; её система координат `(s, z)` с началом в левом конце пола фигуры — единая основа для будущей дорисовки пользовательской геометрии.

**Non-Goals:**
- Пользовательская геометрия на фигуре (полки и т. п.) — следующий change; здесь в хранимых данных для неё нет места.
- Перемещение и растягивание линии, правка вершин после создания.
- Разрез по подложке (нет высот), косые отрезки линии, ломаный разрез с разворачиванием (Г-образная линия).
- Строка в легенде PDF для линии разреза.

## Decisions

### D1. Данные: `sections` в содержимом плана, фигура не хранится

```ts
type SectionView = "up" | "down" | "left" | "right"
interface SectionLine { id: string; label: string; view: SectionView; points: Point[] }
// ReconstructionContent.sections?: SectionLine[]   (поле необязательное, версия документа 3 не повышается)
```

Фигура — `SectionFigure`, значение, которое считает чистая функция по `(SectionLine[], DrywallWall[], габариты плана)`. Поле `sections` переносится в `storedReconstruction` так же, как `callouts` и `notes`: инструменты стен и размеров его не трогают, поэтому в рабочий набор оно не входит; линиями занимается только инструмент «Разрез» (D6) и выбор/удаление (D7).

*Альтернатива:* хранить фигуру вместе с линией. Отвергнуто: она устаревает при каждой правке стены, а для полок позже понадобится отдельная пользовательская часть — её и надо хранить отдельно от вычисляемой.

### D2. Код по возможностям

### D3. Геометрия фигуры

Ось `u` (`up`: `(1,0)`, `down`: `(−1,0)`, `right`: `(0,1)`, `left`: `(0,−1)`) и `s = p·u`. Для каждой стены гипсокартона и каждого рабочего отрезка линии отрезок сечения — это обрезка рабочего отрезка выпуклым четырёхугольником тела стены (алгоритм Кируса–Бека), результат — интервал по `s`; пустой или нулевой интервал — нет сечения. Ступеньки в сечении не участвуют. Стена может быть не по осям (подложка и гипсокартон не обязаны быть ортогональными), поэтому обрезка нужна, а не сравнение координат.

```
 линия A-A со ступенькой, взгляд down (схематично, без масштаба)

  ПЛАН                                     ФИГУРА A-A (ниже плана; s = -x, слева направо обратно плану)

  x:  0       100                          s: -200      -100         0
  A---+  1                                     +----------+-----------+
  |   |  отрезок 1 (рабочий)  ->                \\\ \\\          \\\
  v   +--+ ступенька (ширины нет)               сечение стены 1   сечение стены 2
         |
         +---A  отрезок 3 (рабочий) ->      Ступенька 1->3 в фигуре стыкует рабочие отрезки встык:
             v                              рабочий отрезок 3 начинается там, где кончился отрезок 1
```

Горизонтальное положение рабочего отрезка в фигуре: `s − s_min`, где `s_min` — наименьшее `s` линии; два отрезка ступенчатой линии друг на друга не накладываются, потому что линия не возвращается назад (спек «Линия разреза»).

### D4. Положение фигуры — вычисляемое, без выбора пользователя

Габариты плана: подложка, действующая штукатурка, стены гипсокартона (не сами фигуры, не размеры и не выноски, чтобы фигуры не двигали друг друга). Зазор между габаритами и фигурой — 100 см.

```
 схематично, без масштаба. Плюс у каждой стороны стопка: фигуры упорядочены по букве, каждая следующая дальше

            [A-A up]  <- над планом, по X те же координаты, что у линии
              ^
 [B-B left]<--+ ПЛАН +-->[C-C right]    <- слева/справа: пол фигуры на нижней границе габаритов
              v
            [D-D down] <- под планом, по X те же координаты, зеркально
```

Для `up`/`down` фигура занимает по X тот же диапазон, что линия, для `right`/`left` стоит у боковой границы габаритов. Название — над фигурой всегда. Размер названия на холсте — как у подписи выноски (экранный), в PDF — как у текста выноски; в расчёте стопки считаем только высоту/ширину самой фигуры + зазор 100 см (запаса зазора хватает для названия).

*Альтернатива:* пользователь сам ставит фигуру кликом. Отвергнуто по решению пользователя: положение определяется направлением стрелок.

### D5. Точки замера на фигуре: новый вид `DimPoint`

```ts
interface SectionCornerPoint {
  kind: "section"
  lineId: string
  wallId: string
  segment: number            // номер рабочего отрезка линии (0, 1, 2 … среди рабочих)
  at: { s: "lo" | "hi"; z: "floor" | "top" }
}
// type DimPoint = EdgePoint | JambPoint | BatteryCornerPoint | ItemPoint | SectionCornerPoint
```

Точка резолвится в координаты листа/чертежа через `SectionFigure` (место фигуры + `s`, `z`). `DimensionTargets` получает набор идентификаторов существующих линий разреза; `resolvable` проверяет идентификатор линии, а угол, у которого нет стены или рабочего отрезка (`sectionCornerPosition` даёт `null`), размером не рисуется, но хранится. Размер измеряется по оси `s` или `z` (по большей проекции, при равных — `s`), как у приборов: в фигуре оси ортогональны листу, поэтому размерная линия горизонтальна/вертикальна на листе.

*Альтернатива:* считать фигуру обычными стенами плана и ставить размеры обычными гранями. Отвергнуто: фигура — вид сбоку, а не план, и общая система координат с планом исказила бы выбор снапа и «Линейку».

### D6. Размещение линии — состояние, как у выноски

Инструмент ведёт состояние `idle → vertices → side`:
- `vertices`: каждая новая вершина — проекция курсора на ось текущего отрезка (оси чередуются), с привязкой по правилам «Стены» (сетка, вершины), но без косых; клик, который дал бы нулевой или встречный рабочий отрезок, игнорируется;
- завершение набора допустимо только при нечётном числе отрезков;
- `side`: сторона курсора относительно первого отрезка выбирает `view`; клик создаёт линию.

Правило «оси к ближней» для первого отрезка: после первого клика ось определяется при первом движении курсора (ближе к вертикали или к горизонтали), её нельзя менять до следующего клика. Состояние — чистая функция событий, как у выноски; DOM-обвязка в `src/main.ts` тонкая.

### D7. Выбор, удаление, история, хранение

- Выделение — новый вид элемента выделения плана (`section`), клик по линии, её обозначению, штриховке или названию даёт один и тот же выбор (без активного инструмента); рамка выделения линии не захватывает.
- Правка «не двигать» — линии не входят в перемещение и стрелки; Delete и «Ластик» удаляют.
- История: линии не входят в снимок стен и размеров; у них свой вид записи истории `sections` (как у выносок `callouts`): создание и удаление линии — один шаг, отмена и повтор восстанавливают список целиком; проверка записи истории проверяет каждую линию.
- Хранение: чтение поля `sections` по одной линии; негодная линия отбрасывается (`section-line.ts` — единая проверка и для документа, и для истории, и для создания).
- Размеры на фигурах удалённых линий хранятся и не показываются, как у других отсутствующих целей (`hiddenDimensions`).

### D8. PDF

Страница «Реконструкция» получает линии и фигуры теми же данными (`SectionFigure`); габариты страницы расширяются на фигуры (и название), масштаб подбирается по расширенным габаритам. Выделение не рисуется. Сборщик страницы не знает правил разреза — получает готовую фигуру.

## Risks / Trade-offs

- **Линия только по осям.** Спек требует ортогональных отрезков; ортогональность к осям чертежа — допущение (в спеке «Линия разреза» отрезки параллельны осям чертежа). Для не-ортогональной планировки разрез поперёк косой стены невозможен → подтвердить допущение; снимается отдельным change (общая ось `u`).
- **Стены режутся по отображаемому контуру.** Линия режет стену по тому контуру, который нарисован на плане (`displayPolygons`: достройки в углах и примыканиях), а не по голому прямоугольнику оси, иначе число на фигуре не совпадает с планом. Сечения одной высоты, которые перекрываются или касаются (угол двух стен), сливаются в один прямоугольник; сечение, целиком накрытое более высоким, не показывается. Остаётся двойной контур у угла стен разной высоты (см. `TODO.md`).
- **Концы линии выносятся на свободное место** (`section-free.ts`). Штрих, стрелка и буква не стоят на стенах подложки, штукатурки и гипсокартона, батареях и коммуникациях: конец, который стоит на них, рисуется вынесенным наружу вдоль линии (`SectionEntry.shown`); вершины линии и фигура не меняются. У разрезаемой стены конец выносится так, чтобы поместились штрих полной длины и зазор; штрихи на обоих концах одной длины.
- **Размер названия против зазора 100 см.** Название — в экранных/листовых единицах, зазор — в единицах чертежа: при очень мелком масштабе название может заходить на соседнюю фигуру → зазор выбран с запасом; пересмотрим по результатам проверки на чертеже.
- **Фигуры раздувают габариты PDF.** Далеко стоящая фигура уменьшает масштаб страницы → это прямое следствие «фигура за пределами чертежа»; пользователь регулирует положением и числом линий.
- **Стены подложки в разрезе не участвуют** (нет высот) → линия, пересекающая только подложку, даёт пустую фигуру (только название; линии пола у фигуры нет).

## Migration Plan

Миграции нет: поле `sections` необязательное, версия документа не повышается, старые чертежи и истории читаются без изменений. Откат — удаление поля, остальное остаётся совместимым.
