# Test Plan

## Scope

Проверяется наблюдаемое поведение из спек change `add-battery`: чистые функции и сцены без DOM (`vitest run`, как остальные тесты проекта — `src/battery/*.test.ts` и `*.test-utils.ts`), плюс интеграция через публичные функции модулей. Тесты не знают о внутреннем устройстве (D1–D12 design), только о входах и результатах: координаты прямоугольника батареи, допустимые положения, числа, состав сцены/истории/документа.

Файлы (по областям; ID вида `B-<область>-<n>`):
- `battery-geometry.test.ts` — GEO: данные, прямоугольник, параллельность, углы.
- `battery-face.test.ts` — FACE: грань установки.
- `battery-place.test.ts` — PLC: размещение, участок грани, пересечения, касание, перемещение, стрелки.
- `battery-center.test.ts` — CTR: центровка по окну.
- `battery-numbers.test.ts` — NUM: числа выделенной батареи и их правка, параметры новых батарей.
- `battery-follow.test.ts` — FOL: следование за стеной, каскадное удаление.
- `battery-guard.test.ts` — GRD: двустороннее ограничение (стены, коммуникации, батареи).
- `battery-dimension.test.ts` — DIM: точки замера на углах, направление измерения, следование, удаление.
- `battery-demolition.test.ts` — DEM: снос батареи, ластик, следование метки.
- `battery-mounting.test.ts` — MNT: собственные батареи «Монтажа», видимость старых.
- `battery-storage.test.ts`, `battery-history.test.ts`, `battery-pdf.test.ts` — STO, HIS, PDF.
- `battery-tool.test.ts` — TOOL: кнопка, активация, Esc, призрак, клик.
- `battery-render.test.ts` — RND: отображение.

## Invariants

- I1. Ни одна операция не оставляет прямоугольник батареи пересекающимся (глубина > 0,01 см) с другой батареей, телом другой стены (кроме опорной) или коммуникацией, если до операции пересечения не было; существующее наложение не углубляется. Проверяется свойством над серией операций (B-INV-1, B-INV-2) — случайные последовательности установок, перетаскиваний, правок стен и коммуникаций на фиксированном зерне.
- I2. Батарея всегда параллельна оси опорной стены: после любой правки стены длинные стороны параллельны оси, торцы ей перпендикулярны (B-INV-3).
- I3. Грань, сторона привязки, длина, толщина и отступ не меняются правками стены, перемещением и стрелками (B-INV-4).
- I4. Отменить/повторить — точная инверсия: сцена после `undo(redo(x)) == x` для установки, перемещения, правки числа, удаления, сноса (B-INV-5).
- I5. История обмера, «Демонтажа» и «Монтажа» независимы: операция одного плана не меняет данные и историю другого (B-INV-6).
- I6. Центровка не хранится: после установки список батарей не содержит ссылки на окно (B-INV-7).
- I7. Загрузка → сохранение → загрузка даёт тот же набор батарей (B-STO-9).
- I8. Числа на холсте и в PDF для размера с углом батареи совпадают (B-DIM-10, B-PDF-4).

## Integration Cases

- Комната из четырёх стен с заливкой: установка → внутренняя грань → перемещение стены с батареей → числа пересчитаны (B-INT-1).
- Окно + батарея + размер между углом и откосом: перемещение батареи → число пересчитано, окно двигается → число пересчитано, удаление окна → размер к откосу удалён, размер к углу остался (B-INT-2).
- Обмер → «Демонтаж» (метка батареи) → «Монтаж» (нет) → снять метку «Ластиком» → «Монтаж» (есть) (B-INT-3).
- Снос стены под батареей → батарея на «Монтаже» скрыта; отмена сноса → показана (B-INT-4).
- Собственная батарея «Монтажа» на собственной стене и на остатке: сохранение/загрузка (B-INT-5).
- Две батареи, воздуховод и перегородка на одной стене: каждая операция уважает все препятствия одновременно (B-INT-6).
- Стена с батареей и стояком: перемещение стены останавливается у стояка по батарее (B-INT-7).
- Серия стрелок одной записью истории (`multi-selection`) (B-HIS-4).
- Рамка выделяет батарею и окно, Delete удаляет их с размерами за один шаг (B-INT-8).
- PDF: страницы трёх планов со всеми видами батарей (B-PDF-1..5).

## Mutation Targets

Критичные места, где поверхностно правдоподобная реализация проходит слабые тесты (каждое должно ловиться хотя бы одним тестом из плана):
- знак грани `face` (батарея на другой стороне) — B-GEO-3, B-FACE-1;
- порядок `offsetCm` и стороны привязки (`a`/`b`) — B-GEO-1, B-GEO-2;
- порог глубины наложения `>` против `>=` и 0,01 — B-PLC-3, B-GRD-12;
- касание считается пересечением — B-PLC-3;
- проверка пересечения только с одной стороны — B-GRD-1, B-GRD-7 (двусторонность);
- исключение опорной стены из проверки — B-GRD-5 (иначе батарея не стоит на своей стене) и B-GRD-1 (иначе чужие стены проходят);
- выбор окна по ближайшему центру против первого в списке — B-CTR-5;
- радиус прилипания в пикселях без учёта зума — B-CTR-3 на двух зумах;
- округление `offsetCm` до целого также при центровке — B-CTR-4;
- центровка поверх ограничений — B-CTR-7;
- рост длины от торца привязки, а не от центра — B-NUM-8;
- ввод расстояния меняет сторону привязки — B-NUM-7;
- отступ при утолщении стены пересчитывается — B-FOL-4;
- `end`/`side` углов перепутаны — B-DIM-3;
- направление измерения: большая проекция против первой; равенство → ось — B-DIM-1, B-DIM-2, B-DIM-9;
- «касание = задело» при скрытии на «Монтаже» — B-MNT-8, B-MNT-9, B-MNT-10;
- пометка батареи теряется при удалении/отмене — B-DEM-6, B-HIS-5;
- удаление батареи не удаляет размеры на углах — B-FOL-8;
- запись истории без поля `batteries` затирает список — B-HIS-6.

## Out of Scope

- Высота батареи (не вводится).
- Зона открывания двери как препятствие.
- Смена грани или стены после установки.
- Автоматические проверки DOM-проводки `src/main.ts` (событийный слой): в проекте для неё нет автотестов (см. `TODO.md`, пункт про `main.ts`); проверяется вручную в браузере после реализации. Логика, вынесенная в чистые функции, покрыта этим планом.
- Визуальные снимки: проверяются структурными ассерциями (вызовы отрисовки, список отрезков), а не пикселями — по образцу `window-render.test.ts`.
