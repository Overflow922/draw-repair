## Context

Трекинг узлов (`src/wall-tracking.ts`) вызывается из `chainSegment` (`src/wall-chain.ts`) после привязки к стенам: `tracked()` ищет узлы, выравнивает конец по x/y (свободно) или по пересечению луча (при заданном направлении) и отдаёт `tracks` для отрисовки. `main.ts` передаёт `segment.tracks` в `render.ts`, где `drawTracks` рисует пунктир цветом `palette.track`.

Тот же тип `TrackLine`, `drawTracks` и цвет `track` использует риска центровки батареи (`battery-guide.ts`, `battery-tool.ts`, `main.ts: centerGuideTracks`). Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Конец стены не зависит от концов осей других стен.
- Риска центровки батареи работает и выглядит как прежде.

**Non-Goals:**
- Не менять прилипание к граням, торцам, углам, орто-привязку, угол к стене примыкания и ввод точной длины.
- Не переименовывать цвет `track` в теме и не менять вид риски батареи.

## Decisions

**D1. Удалять трекинг целиком, без флага.** Выключатель оставил бы мёртвую ветку и тесты на неё; пользователь просит убрать. Альтернатива «настройка в панели» отвергнута: новая настройка — новый UI без запроса.

**D2. `chainSegment` без шага трекинга.** Конец = результат привязки (`snap.point`), поле `tracks` в результате сегмента исчезает, `main.ts` передаёт в `render` линии только от риски батареи. Порядок приоритетов остаётся: стена, затем сетка (на луче — длина по сетке).

**D3. Общие типы для риски батареи выносятся из `wall-tracking.ts`.** `TrackLine` нужен батарее, поэтому тип переезжает в модуль рядом с `battery-guide.ts` (`src/battery/`), а `render.ts` и `battery-tool.ts` импортируют его оттуда. Вид риски и `drawTracks` не меняются. Альтернатива «оставить `wall-tracking.ts` ради одного типа» оставила бы мёртвый модуль.

**D4. Тесты.** `wall-tracking.test.ts`, `wall-tracking-render.test.ts`, `wall-tracking.test-utils.ts` проверяют удаляемое требование: удаляются вместе с ним (правило 3 CLAUDE.md выполнено: требование снято на уровне спеки). Остальные тесты с упоминанием трекинга правятся только в тех местах, где они ссылаются на удалённое поведение; ожидаемые значения остальных сценариев не меняются.

## Risks / Trade-offs

- [Скрытая зависимость других тестов от трекинга: ожидаемая точка конца была когда-то получена через узел] → прогнать весь набор до и после; падение теста не лечить правкой ожидания, а разбирать по спеке.
- [Пользователь привык выравнивать стену по оси соседней] → выравнивание остаётся доступным через сетку и прилипание к граням; убрано по явному запросу.
- [Спека `wall-drawing` длинная, в ней много перекрёстных ссылок на трекинг] → дельта правит все упоминания (сетка, квадрат по сетке, прилипание при направлении); после применения проверить `grep трекинг` по `openspec/specs`: остаться должна только риска батареи.
