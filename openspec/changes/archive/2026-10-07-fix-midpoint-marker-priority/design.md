## Context

Цель нажатия левой кнопки выбирается в `pointerdown` (`src/main.ts`) цепочкой встроенных проверок. После
коммита `b30c4d0` порядок такой:

1. число размеров выделенного элемента (`doorwayTool.pressNumber`) — вне ластика;
2. маркер конца одиночной выделенной стены (`endpointAt`) — в любом инструменте;
3. средний маркер одиночной выделенной стены (`midpointAt`) — вне ластика и инструментов «Проём»/«Окно»;
4. размер (`dimHitDistance` ≤ радиуса, первый найденный) — вне ластика;
5. элемент стены (`doorwayTool.pressDoorway` → `hitDoorway`) — вне ластика, цепочки и инструмента «Размер»;
6. тело стены (`hitWall`) — при инструментах «Проём»/«Окно» ничего не делает, иначе при непустом выделении
   стен выделяет стену (если не выделена) и начинает перемещение выделения;
7. пустое место — рамка (вне ластика).

Порядок 2–6 и есть правило приоритета из спецификации, но он живёт в обработчике DOM и не проверяется ни
одним тестом. Похожее решение для ластика уже вынесено в чистую функцию `erasePick` (`src/doorway/doorway-scene.ts`,
change add-doorway design D2, D8: «чистые функции; main.ts только маршрутизирует события»).

## Goals / Non-Goals

**Goals:**
- Вынести выбор цели нажатия (шаги 2–6) в чистую функцию рядом с `erasePick`, чтобы приоритет маркеров над
  элементами, размерами и телом стены проверялся модульными тестами.
- Сохранить наблюдаемое поведение `b30c4d0` без изменений.

**Non-Goals:**
- Числа размеров выделенного элемента (шаг 1) остаются в `doorwayTool`: при выделенной стене элемент не выделен,
  чисел нет, с маркерами они не конкурируют.
- Действие на выбранную цель (запуск `endpointDrag`, `groupMove`, `dimDrag`, перетаскивания элемента, рамки)
  остаётся в `main.ts`.
- Доступность концевых маркеров по инструментам не меняется (в любом инструменте при одиночной выделенной стене).
- Выбор размера при наложении нескольких размеров не меняется (первый в радиусе).

## Decisions

### D1. `pressPick` в `src/doorway/doorway-scene.ts`

Функция рядом с `erasePick`, тем же стилем — дискриминированное объединение результата:

```
PressPick =
  | { kind: "end"; wall; end: "a" | "b" }
  | { kind: "middle"; wall }
  | { kind: "dimension"; dimension }
  | { kind: "doorway"; doorway: WallElement }
  | { kind: "wall"; wall }

pressPick(p, scene: Selection, tolCm, textFactor, options: PressOptions): PressPick | null
PressOptions = { selectedWall: Wall | null; middleMarker: boolean; dimensions: boolean; elements: boolean }
```

- `selectedWall` — одиночная выделенная стена или `null` (нет выделения стен или их больше одной).
- `middleMarker`, `dimensions`, `elements` — доступность целей при текущем инструменте; их вычисляет `main.ts`
  (правила инструментов остаются в обработчике, геометрический приоритет — в функции).
- Порядок: конец `a` → конец `b` → середина → размер → элемент стены → тело стены → `null`.
- Попадания — существующими функциями: `endpointAt`, `midpointAt`, `dimHitDistance`, `hitDoorway`, `hitWall`.

Альтернатива — функция только для маркеров (`markerAt`). Отклонена: тогда приоритет маркера над элементом и
размером по-прежнему задаётся только порядком строк в `main.ts`, и тестом его не проверить.

Альтернатива — отдельный модуль `src/press-pick.ts`. Отклонена: `doorway-scene.ts` уже содержит `erasePick` и
`Selection`, и решение того же рода логично держать рядом.

### D2. Маршрутизация в `main.ts`

`pointerdown` после проверки чисел вызывает `pressPick` и действует по `kind`:
- `end` → `endpointDrag`;
- `middle` → перемещение выделения за эту стену (`startGroupMove`);
- при активном ластике остальные цели игнорируются (как раньше: ластик действует по клику);
- `dimension` → `dimDrag` и выделение размера;
- `doorway` → `doorwayTool.pressDoorway(p)` (выделение и перетаскивание элемента);
- `wall` → при «Проём»/«Окно» ничего; иначе при непустом выделении стен — перемещение выделения;
- `null` → рамка.

Опции: `middleMarker = tool ≠ ластик ∧ не «Проём»/«Окно»`, `dimensions = tool ≠ ластик`,
`elements = tool ≠ ластик ∧ цепочка не рисуется ∧ tool ≠ «Размер»`.

## Risks / Trade-offs

- [`doorwayTool.pressDoorway(p)` заново ищет элемент через `hitDoorway`] → те же аргументы и тот же радиус, что
  в `pressPick`, поэтому результат совпадает; повторный поиск дешёвый.
- [Тесты проверяют функцию, а не обработчик DOM] → маршрутизация в `main.ts` остаётся без автоматической
  проверки; она становится прямым `switch` по `kind`, а ручная проверка в браузере повторяется при реализации.
  Пункт о DOM-тестах жестов уже записан в `TODO.md`.
- Совместимость: формат данных, история и PDF не меняются; миграция не нужна.
