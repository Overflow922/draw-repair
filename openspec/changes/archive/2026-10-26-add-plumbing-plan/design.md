## Context

Мотивация — в `proposal.md`, поведение — в `specs/`. Что в коде уже есть для этого плана:

- Каталог планов и наборы инструментов — `src/plans.ts` (`PLANS`, `PLAN_TOOLS`). Новый план — новая запись; переключатель, страницы PDF и ключи истории строятся по каталогу.
- План «Мебель» устроен как «сцена + рабочий набор»:
  - `furnitureScene` (`src/furniture/furniture-scene.ts`) — подложка «Реконструкции», предметы и видимые размеры;
  - `openFurniture` и `storedFurniture` (`src/furniture/furniture-workspace.ts`) — стены только для чтения, скрытые размеры, хранимое представление.
- Видимость размеров над подложкой — `visibleDimensions` (`src/dimension-visibility.ts`), по множествам идентификаторов стен, элементов и батарей.
- Точки замера — `DimPoint = EdgePoint | JambPoint | BatteryCornerPoint` (`src/types.ts`). Позиция считается в `dimPointPoint`, снап — в `nearestDimAnchor` (`src/geometry.ts`). Правило направления «большая проекция на оси» уже реализовано для углов батареи.
- Рисунки предметов и габариты: `drawFurnitureScene` (`src/furniture/furniture-render.ts`) и `item-size-layout.ts`. Габариты на «Мебели» правятся на месте (`item-number.ts`).
- Выноски и примечания хранятся по плану через `callout-store.ts` и `notes-store.ts` с веткой на каждый план.
- PDF: `pagesOf` (`src/export/pdf.ts`) даёт страницу на каждый план; легенда (`src/export/legend.ts`) берёт виды мебели из `page.furniture.items`.
- `src/main.ts` (около 3600 строк) содержит ветки «на плане „Мебель“» для инструментов, жестов и истории.

Ограничение: изменение `add-furniture-appliances` (вид «Стиральная машина», третий столбец легенды) ещё не реализовано до конца и не заархивировано. Дельта `pdf-export` этого изменения написана поверх его версии требования «Легенда на странице PDF».

## Goals / Non-Goals

**Goals:**
- Новый план собирается из уже существующих частей: подложка «Мебели», рисунки и габариты предметов, движок размеров. Рисование и правка предметов не копируются.
- Приборы не дублируются в данных: в документе прибор есть только в объектах «Мебели», а «Сантехника» хранит только ссылки на него в точках замера размеров.
- Добавить новый водный прибор (унитаз и пр.) можно правкой одной записи каталога видов.

**Non-Goals:**
- Свои объекты-приборы на плане, выводы ХВС/ГВС/К, автоподписи.
- Точки замера предметов на плане «Мебель» и других планах.
- Перенос размеров «Мебели» на «Сантехнику».
- Разделение `main.ts` на модули (за рамками изменения; новые ветки делаются по образцу веток «Мебели»).

## Decisions

### D1. План в каталоге
`{ id: "plumbing", label: "Сантехника" }` встаёт последним в `PLANS`.
`PLAN_TOOLS.plumbing = ["dimension", "callout", "ruler", "notes", "eraser"]`: первый в списке «Размер» и становится инструментом по умолчанию.

Альтернатива — сделать «Линейку» инструментом по умолчанию. Отклонена: план существует ради размеров.

### D2. Какие виды — приборы: признак в записи каталога видов
У `FurnitureKindEntry` появляется необязательное поле `water?: true`; оно ставится у `sink`, `dishwasher` и `washer`. Список приборов — `FURNITURE_KIND_ORDER.filter(k => kindEntry(k).water)`.

Отклонённые альтернативы:
- Отдельный список видов в `src/plumbing/`. Тогда новый водный вид пришлось бы прописывать в двух местах, что ломает правило «вид = запись каталога» (скилл `add-furniture-kind`).
- Признак по `overlapExemptions`. Он ничего не говорит о воде.

### D3. Сцена плана «Сантехника» — производная от сцены «Мебели»
Новый модуль `src/plumbing/plumbing-scene.ts`:

```
plumbingScene(drawing, base = reconstructionScene(drawing)) -> {
  base,                                    // как у furnitureScene
  items:      приборы drawing.furniture.items (по D2), копии
  dimensions: visibleDimensions(drawing.plumbing.dimensions,
                { walls, doorways, batteries, items: id приборов })
}
```

Подложка та же, что у `furnitureScene`. Это одна функция `reconstructionScene`, поэтому две подложки не расходятся.

Рабочий набор `openPlumbing` / `storedPlumbing` (`src/plumbing/plumbing-workspace.ts`) устроен по образцу `furniture-workspace.ts`:
- стены и приборы попадают в `readOnlyIds`;
- в сцене инструментов приборов нет, поэтому выделение, рамка, стрелки, Delete и ластик их не видят;
- хранимое содержимое состоит из размеров (видимых и скрытых), выносок и примечаний.

Отклонённые альтернативы:
- Копировать приборы в план. Тогда «Мебель» и «Сантехника» расходились бы, а пользователь выбрал показ (вариант D в обсуждении).
- Отдавать приборы в сцену «Мебели» с флагом «только чтение». Тогда пришлось бы учить инструменты «Мебели» флагу, а значит менять поведение плана «Мебель».

### D4. Точка замера на приборе — четвёртый вариант `DimPoint`

```ts
export interface ItemPoint {
  kind: "item"
  itemId: string
  at: ItemPointAt
}
export type ItemPointAt =
  | { kind: "center" }
  | { kind: "corner"; u: 1 | -1; v: 1 | -1 } // u — сторона по оси ширины, v — по оси длины
export type DimPoint = EdgePoint | JambPoint | BatteryCornerPoint | ItemPoint
```

Угол записан в системе предмета знаками `u` и `v`, а не абсолютными координатами. Поэтому после поворота или изменения размера на «Мебели» точка остаётся тем же углом (сценарий «Угол остаётся тем же углом»).

```
 система предмета (угол 0), схематично

        u = -1            u = +1
   v=-1  +-------------------+  v=-1
         |         ^ v       |
         |         |   u     |
         |         C ---->   |      C = center (u = v = 0 не хранится,
         |                   |          это отдельный вариант "center")
   v=+1  +-------------------+  v=+1
```

Изменения в коде:
- `dimPointPoint` получает необязательный список предметов. Позиция точки — центр плюс `u·w/2` по оси ширины и `v·l/2` по оси длины, с учётом угла.
- Снап получает список приборов только на плане «Сантехника». Центр перебирается раньше углов, все точки приборов идут после углов батарей: строгое сравнение `d >= bestDist - TIE_CM` в существующем цикле само даёт приоритет по порядку перебора.
- Направление и число берутся из правила батареи: ось задаёт прибор первой точки (ось ширины — направление угла предмета), при равенстве проекций выбирается ось ширины.
- `DimensionTargets` получает множество `items`; `resolvable` проверяет `itemId`.

Отклонённые альтернативы:
- Хранить абсолютную точку. Тогда размер не следовал бы за прибором.
- Хранить номер угла 0..3. Знаки `u` и `v` нагляднее и прямо задают формулу.

### D5. Хранение
`Drawing.plumbing?: PlumbingContent`, где `PlumbingContent = { dimensions: Dimension[]; callouts?: Callout[]; notes?: string[] }`. Поле необязательное, версия документа 3 остаётся.

Проверка `ItemPoint` в `storage.ts` выполняется так:
- нужны строковый `itemId` и корректный `at`;
- точка прибора допустима только в размерах плана «Сантехника». В размерах других планов размер с `kind: "item"` считается некорректным и отбрасывается по одному, так же как прочие битые размеры. Это не даёт точкам предметов попасть туда, где их некому разрешить.

`callout-store.ts` и `notes-store.ts` получают ветку `plumbing`.

### D6. История
У записи истории новый вид `{ kind: "plumbing"; dimensions: Dimension[] }`, ключ — `historyKey(id, "plumbing")`. Проверка записи повторяет проверку записи «Мебели», но без предметов.

Правки приборов на «Мебели» пишутся только в историю «Мебели»: сцена «Сантехники» пересчитывается из чертежа, и размеры к пропавшему прибору просто скрываются (D3, `visibleDimensions`).

### D7. Холст
Отрисовка плана: `drawFurnitureScene` с приборами из сцены, без подсветок, плашки, расстояний и рисок. Затем габариты из `item-size-layout` в режиме «только чтение», то есть без подчёркивания и без зон попадания `item-number`. Затем размеры, выноски и примечания плана, в порядке слоёв по спеке.

Если `drawFurnitureScene` рисует размеры плана до габаритов, порядок вызовов меняется только для «Сантехники» через параметр. Порядок на «Мебели» остаётся прежним.

«Линейка» на плане получает приборы как объекты плана (`ruler-tool`: «объекты, нарисованные на активном плане»).

В `main.ts` появляется предикат `onPlumbing()` и ветки по образцу `onFurniture()`: открыть рабочий набор, записать хранимое, история, сброс при переключении. Инструменты «Мебели» (`itemTool`, правка чисел, центровка) на этом плане не подключаются.

### D8. PDF и легенда
В `pagesOf` появляется `case "plumbing"`: сцена `plumbingScene` поверх той же подложки, что у страницы «Мебель», плюс поле страницы с приборами для рисунка и легенды.

`legend.ts` берёт записи видов из предметов страницы, будь то «Мебель» или «Сантехника». На странице «Сантехника» это только приборы, отдельная логика не нужна.

Цвета подложки, штукатурки и батарей берутся из ветки серой подложки — той же, что у страниц «Реконструкция» и «Мебель».

### D9. Порядок изменений
`add-furniture-appliances` архивируется раньше этого изменения, и дельта легенды здесь написана поверх его версии. Реализация «Сантехники» использует `washer` из каталога, а он уже есть в рабочем дереве.

## Risks / Trade-offs

- **[`main.ts` растёт ещё на одну плановую ветку.]** Логика плана живёт в `src/plumbing/` (сцена, рабочий набор, отрисовка), в `main.ts` остаётся только проводка. Вынос плановых веток в общий реестр записывается в `TODO.md` (Out of scope).
- **[Размер «Сантехники» висит на приборе, который удалили на «Мебели».]** Размер скрыт и не теряется; после отмены на «Мебели» он вернётся. Если прибор удалён навсегда, скрытый размер остаётся в документе. Ластик его не видит, это тот же компромисс, что у размеров на отсутствующую стену.
- **[Правило батареи даёт только большую проекцию]** (от угла `(0, 0)` до центра `(30, 60)` ставится «60», а не «30»). Это выбор пользователя. Меньший размер ставится от другой вершины контура (от соседней стены) или между двумя точками прибора.
- **[Дельта легенды поверх незаархивированного изменения.]** Если `add-furniture-appliances` изменят до архива, дельту легенды здесь нужно перенести вручную. Проверяется `openspec validate` после его архивации.
- **[Признак `water` в каталоге — новое поле записи вида.]** Оно необязательное, существующие записи не меняются, тест каталога проверяет, что признак стоит ровно у трёх видов.

## Migration Plan

Миграции нет: поле `plumbing` необязательное, старые документы и истории читаются без изменений (план пуст).
