## Context

Мотивация и объём — в `proposal.md`, требования — в `specs/drawing-file` и `specs/drawing-storage`.

Сейчас:

- Вкладка = `Drawing` (`src/types.ts`): в одном объекте лежат данные всех планов. Всё, что нужно файлу, уже есть.
- `parseStore` (`src/storage.ts`) читает весь документ и внутри `.map(...)` собирает каждый чертёж из загрузчиков `loadDemolition`, `loadMounting`, `loadFurniture` и др. Проверка структуры — `isDrawing(x, version)`. Эта сборка вшита в `parseStore` и не вызывается отдельно.
- Правки идут в «рабочее» состояние (`loadWorking` / `commitWorking`, `src/main.ts`); перед чтением `current()` другие места (например `activate`) сначала вызывают `commitWorking()`.
- Вкладка добавляется как в `newDrawing()`: `store.drawings.push`, `dirty = true`, `activate(id)`. Шага истории при создании вкладки нет. Имя «Чертёж N» даёт `nextName()`.
- Подтверждение при закрытии вкладки — нативный `confirm()`; своих диалогов в приложении нет.
- Кнопка PDF — `#pdf-export` в `#size-box`; обработчик `pdfExportBtn` в `main.ts`.

## Goals / Non-Goals

**Goals:**
- Один механизм чтения чертежа для хранилища и файла, без изменения поведения хранилища.
- Логика файла (конверт, разбор, имя файла, уникальное имя) — чистые функции с тестами; `main.ts` только подключает кнопки.

**Non-Goals:**
- Экспорт всех вкладок сразу, слияние с существующей вкладкой, перетаскивание файла на холст.
- Запись истории правок и корзины в файл.
- Другие форматы (SVG, DXF, PDF-импорт).

## Decisions

### D1. Конверт файла отдельный от документа хранилища

Файл — `{ "format": "draw-repair-drawing", "version": 1, "drawing": { ... } }`. Поле `drawing` — тот же вид, что элемент `drawings` в хранилище версии 3.

Альтернатива: писать в файл документ хранилища с одним чертежом. Отклонено: такой файл нельзя отличить от копии хранилища, его версия привязана к хранилищу (повышение версии хранилища ломало бы файлы), а при загрузке пришлось бы выбирать «заменить всё или добавить». Отдельный `format` + `version` позволяют отклонять чужие файлы и версии новее поддерживаемой. Для документа хранилища версия 3 остаётся, localStorage не меняется.

```
 файл                                 localStorage
 { format, version:1,                 { version:3, activeId,
   drawing: {...} }                     drawings: [ {...}, {...} ] }
                  \                                   /
                   +--- один и тот же вид Drawing ---+
```

### D2. Выделить чтение одного чертежа из `parseStore`

Тело `.map(...)` в `parseStore` выносится в функцию `readDrawing(d: Drawing): Drawing` (в `src/storage.ts` или соседнем модуле, если файл станет слишком большим). `parseStore` вызывает её для каждого чертежа, файл — для своего. Предусловие то же: структура проверена `isDrawing(x, 3)`.

Альтернатива: скопировать сборку в модуль файла. Отклонено: дубль бизнес-правил (Rule 8) расходится при каждом новом плане; спека требует одинакового чтения.

Рефакторинг покрывается существующими тестами хранилища (они не меняются), `drawing-storage` «Чтение хранилища не изменилось».

### D3. Модуль `src/drawing-file/` с чистыми функциями

- `serializeDrawingFile(drawing: Drawing): string` — конверт в JSON (отступ 2 пробела, чтобы файл можно было просмотреть глазами).
- `parseDrawingFile(raw: string): DrawingFileResult`, где
  `DrawingFileResult = { ok: true; drawing: Drawing } | { ok: false; reason: "not-json" | "not-drawing-file" | "corrupted" | "newer-version" }`
  (дискриминированное объединение; вход — `unknown` после `JSON.parse`, сужение проверками, без `any` и приведений).
- `drawingFileName(name: string): string` — безопасное имя `*.json`.
- `uniqueDrawingName(name: string, used: ReadonlySet<string>): string` — «Кухня» → «Кухня (2)».
- `adoptDrawing(drawing: Drawing, used: ReadonlySet<string>, newId: string): Drawing` — новый `id` и уникальное имя; идентификатор передаётся снаружи, чтобы функция была чистой.

Зависимости: модуль использует `readDrawing` и `isDrawing` из `storage.ts`, но не `localStorage` и не DOM. Скачивание и выбор файла — в `main.ts` (инфраструктура браузера), как и скачивание PDF.

### D4. Идентификатор стен и других объектов сохраняется, идентификатор чертежа новый

Идентификаторы стен/элементов уникальны внутри чертежа (на них ссылаются размеры). Меняется только `drawing.id`, от которого зависят вкладка и история. Так повторная загрузка одного файла даёт независимые вкладки.

### D5. Загрузка добавляет вкладку как `newDrawing()`, без шага истории

Как «+»: `store.drawings.push`, `dirty = true`, `activate(id)`. Закрытие вкладки уже имеет шаг `close` в истории и возвращается отменой; создание вкладки шага не имеет, и загрузка следует тому же правилу (спека: «История пуста»).

### D6. Сохранение сначала фиксирует рабочее состояние

Обработчик «Сохранить в файл» вызывает `commitWorking()` и только потом сериализует `current()`, чтобы в файл попала последняя правка (спека «Последняя правка попадает в файл»). Состояние при этом не меняется.

### D7. Скачивание и выбор файла

Скачивание: `Blob` (`application/json`) + временная ссылка `download`. Загрузка: скрытый `<input type="file" accept=".json,application/json">`, `file.text()`, `parseDrawingFile`. После выбора значение input сбрасывается, чтобы повторный выбор того же файла вызывал событие. Новых зависимостей нет.

### D8. Кнопки и сообщения об ошибках — по образцу существующих

Две кнопки в `#size-box` рядом с `pdf-export`: тот же класс/размер иконок 16x16, `title` вместо подписи, иконки в той же манере (стрелка вниз к линии — «в файл», стрелка вверх от линии — «из файла»; `pdf-export` уже использует стрелку вниз, поэтому для различия иконка файла — лист с загнутым углом и стрелкой). Сообщение об ошибке — нативный `alert()` с текстом причины, как нативный `confirm()` при закрытии вкладки. Своих окон и панелей не добавляется (`ui.md`).

### D9. Имя файла

Недопустимые символы `\ / : * ? " < > |` и управляющие заменяются на `_`, пробелы по краям обрезаются; пустое имя → `Чертёж`. Расширение `.json` (файл открывается любым редактором, без отдельной регистрации типа файла).

## Risks / Trade-offs

- [Рефакторинг `parseStore` может изменить чтение хранилища] → существующие тесты хранилища и миграций остаются неизменными и обязаны проходить; добавляется тест эквивалентности «хранилище и файл читают одинаково».
- [Файл будущей версии формата] → отклоняется с понятным сообщением, данные не повреждаются.
- [Нативный `alert()` блокирующий и некрасивый] → согласуется с нативным `confirm()`; замена на собственную нотификацию потребовала бы нового UI-паттерна, а он требует отдельного согласования.
- [Большие чертежи → большой JSON] → отступ 2 пробела увеличивает размер; приемлемо для чертежей квартиры, при необходимости переключается на компактный вывод без изменения формата.
- [Файл, отредактированный вручную] → защищён теми же проверками, что хранилище; неподходящие элементы отбрасываются.
