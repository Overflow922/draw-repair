## Context

Стены хранятся независимыми отрезками (`Wall { a, b, thicknessCm, type }`), явного графа связей нет. Стыки (вершина стыка, угловой стык на грани, T-стык, клин на непрямом угле) определяются геометрией при каждой отрисовке. Итоговая форма стены, в том числе продолжения торцов и клинья, — это `displayPolygons(wall, walls)` в `src/wall-geometry.ts`: набор выпуклых и невыпуклых кусков, которые касаются кусков соседних стен по общим рёбрам. Поэтому замкнутость контура нельзя определить по совпадению концов осей: у углового стыка на грани концы не совпадают, а отображение закрыто.

В проекте есть только частные операции над полигонами: `clipHalfPlane`, вычитание выпуклых фигур, `polygonArea`, `pointInPolygon`. Объединения произвольных полигонов с дырами нет.

Отрисовка: `drawScene` в `src/render.ts` рисует по порядку сетку, контуры выделения и подсветки, стены, маркеры, дугу угла, размеры. `drawScene` вызывается на каждый `redraw`, в том числе на каждое движение мыши. PDF-экспорт (`buildPdf` в `src/export/pdf.ts`) вызывает ту же `drawScene` на `doc.context2d` из jsPDF с `grid: false` и `PDF_METRICS`.

## Goals / Non-Goals

**Goals:**
- Чистая доменная функция: по стенам возвращает помещения (область, площадь, точку подписи). Её можно проверять юнит-тестами без канваса.
- Устойчивость к погрешности вычислений на стыках: стены, касающиеся по общему ребру, не должны давать ложных щелей, которые соединяют помещения или открывают контур.
- Отрисовка только потребляет результат и не содержит геометрии помещений.
- Место расширения под дверные проёмы: границы помещений задаются набором полигонов-барьеров, а не напрямую стенами.

**Non-Goals:**
- Кэширование между кадрами: только если замер покажет необходимость (см. риски).
- Дверные и оконные проёмы, названия помещений.
- Изменения модели данных, хранилища, истории и попадания курсора.

## Decisions

### D1. Помещения — дыры в объединении форм стен

```
walls --displayPolygons--> куски форм --union + closing--> дерево полигонов
                                                              |
       внешний контур (outer) <- граница чертежа, не помещение
         +-- дыра (hole)       <- кандидат в помещение
               +-- остров (outer внутри дыры) <- вычитается из помещения
                     +-- дыра острова        <- отдельное помещение
```

Помещение — это дыра объединения вместе с непосредственно вложенными островами (как дырами этого помещения). Дыры островов обрабатываются рекурсивно как самостоятельные помещения. Вложенность (квартира и комнаты), разрыв как соединение и открытый контур получаются из определения сами: разрыв соединяет дыры в одну или сливает дыру с внешней областью, и тогда дыры нет. Отдельного алгоритма для вложенности не нужно.

Альтернатива: граф по концам осей и обход граней планарного графа. Отклонена: не видит угловых стыков на грани и T-стыков без отдельной топологической модели и дублирует логику `wall-joints`.

### D2. Библиотека объединения: `clipper2-ts`

Объединение невыпуклых полигонов с общими рёбрами — классический источник ошибок в вычислениях с плавающей точкой. Clipper2 работает в целых координатах, устойчив к совпадающим рёбрам и вершинам, умеет строить дерево вложенности (`PolyTree`) и смещать контуры (`InflatePaths`), что нужно для D3.

| Вариант | За | Против |
|---|---|---|
| `clipper2-ts` (BSL-1.0, TS, без зависимостей, поддерживается) | целые координаты, PolyTree, offset | ~2 МБ в распакованном виде (в бандл идёт только используемое) |
| `polygon-clipping` (MIT, float) | маленькая, простой API | float, известные сбои на почти совпадающих рёбрах; последний релиз 2023 |
| своя реализация | без зависимостей | высокий риск ошибок, объём кода несоразмерен задаче |

Перевод координат: см → целые с шагом 0,001 см (умножение на 1000 и округление). Это ниже любой значимой точности чертежа и далеко от предела целых чисел. Библиотека изолируется в одном адаптере (D4), домен не видит её типов.

### D3. Морфологическое замыкание против ложных щелей

Куски соседних стен касаются по рёбрам, но вершины кусков вычисляются независимо и могут разойтись на ~1e-9 см. Щель на шве T-стыка проходит через всю толщину стены и соединила бы два помещения. Поэтому перед объединением каждый кусок расширяется на δ, а результат объединения сужается на δ (замыкание, `InflatePaths` с острыми углами `Miter`). Щели уже 2δ закрываются, а форма и площадь остальных областей восстанавливаются точно.

Значение: δ = 0,001 см — одна ступень целой сетки из D2. Закрываются только щели уже 0,02 мм: шум независимого вычисления вершин (~1e-9 см) и расхождение на одну ступень при округлении значений, лежащих по разные стороны от границы округления. По спеке любой разрыв, который может создать пользователь, остаётся разрывом. Такой узкий разрыв намеренно не создать: длина вводится с шагом 1 мм, привязки грубее, при максимальном зуме один пиксель примерно 0,5 мм. Сужение после объединения возвращает внутренние грани на место: площадь не смещается на δ × периметр.

### D4. Модули

```
src/room-area.ts            домен, чистые функции
  findRooms(walls: Wall[]): Room[]
  formatArea(areaCm2: number): string          "14,25 м²"
  type Room = { outline: Point[]; holes: Point[][]; areaCm2: number; labelAt: Point }

src/polygon-union.ts        адаптер clipper2-ts
  unionRegions(pieces: Point[][], closeCm: number): Region[]
  type Region = { outer: Point[]; holes: RegionHole[] }   // дерево без типов библиотеки
```

`findRooms` собирает куски форм стен через `displayPolygons(wall, walls)`. Стены берутся только из чертежа, без превью: это требование спеки, превью в `findRooms` не передаётся. Дальше `findRooms` вызывает `unionRegions` и обходит дерево по D1. Площадь равна площади дыры минус площади внешних контуров её островов (`polygonArea`). Области с площадью меньше 1000 см² отбрасываются.

Барьеры отделены от стен на уровне `findRooms`: будущие дверные проёмы добавят свои полигоны-перемычки в тот же набор кусков. Сейчас это только место в коде, а не абстракция: отдельный параметр не вводится.

Отдельный файл `room-area.ts`, а не `wall-geometry.ts`: это отдельная бизнес-возможность (`room-areas`), а `wall-geometry.ts` уже 585 строк.

### D5. Точка подписи — центр масс, иначе polylabel

Полюс недоступности (точка, наиболее удалённая от границы, включая острова) неустойчив в вытянутых помещениях. У прямоугольника 250 × 100 см все точки средней линии длиной 150 см удалены от стен одинаково, на 50 см. Перекос стены на 3 мм переносит максимум к концу этой линии, и подпись уезжает к краю комнаты. Центр масс устойчив к малым изменениям формы, но может лечь вне помещения (Г- и П-образные), в остров или вплотную к стене.

Правило:
1. `pole = polylabel([outline, ...holes], 1)`, `R = pole.distance` — расстояние от полюса до ближайшей границы, включая острова.
2. `c` — центр масс помещения: центр масс `outline` минус центры масс островов, взвешенные по площади.
3. Если `c` внутри `outline`, вне каждого из `holes`, и расстояние от `c` до ближайшего ребра `outline` и `holes` не меньше `R / 2`, то подпись ставится в `c`. Иначе в `pole`.

Расстояние до границы и попадание в многоугольник считаются через `pointInPolygon` и расстояние до отрезка. `pointInPolygon` уже есть в `wall-geometry.ts`, расстояние до отрезка добавляется в `room-area.ts`. Новых зависимостей нет.

Порог `R / 2` выбран по двум требованиям. Во-первых, центр масс должен оставаться в силе для почти выпуклых помещений: у прямоугольника, параллелограмма и трапеции расстояние от центра масс до границы близко к `R`. Во-вторых, его нужно отбрасывать, когда он прижат к стене: например, комната с длинным узким отростком, где центр масс лежит у выхода в отросток.

Альтернатива: среди точек с расстоянием не меньше `0,9 R` выбирать ближайшую к центру масс. Отклонена: нужен собственный поиск по сетке поверх `polylabel`, кода заметно больше, а для типичных планов результат тот же.

### D6. Формат площади

Площадь в см² переводится в целое число сотых долей м²: `Math.round(areaCm2 / 100)`. Затем форматируется целая часть, запятая и две цифры, суффикс « м²». Округление делается в целых, без `toFixed` над дробными м², чтобы избежать ошибок вида 14,255 → «14,25». Функция не зависит от единицы длин и не трогает `formatLength`.

### D7. Встраивание в отрисовку

```
drawScene(walls, preview, ...)
  rooms = findRooms(walls)                 // один раз за кадр, без preview
  1. сетка (если opts.grid)
  2. заливка помещений белым               // только если сетка рисуется
  3. контуры выделения / подсветки
  4. стены, превью, маркеры, квадрат, дуга угла
  5. подписи площадей                      // INK, m.labelPx, по центру labelAt
  6. размеры, рамка выделения, черновик размера
```

- Заливка: путь из `outline` и `holes`, `fill("evenodd")`, `#fff`. Острова внутри помещения не заливаются. Их собственные помещения заливаются как отдельные помещения.
- Заливка рисуется только вместе с сеткой. Без сетки (PDF) заливка белым по белому не наблюдаема. Так мы не зависим от поддержки `evenodd` в `jsPDF.context2d`.
- Подписи рисуются после стен и до размеров: размеры остаются поверх подписей.
- Шрифт подписи — `m.labelPx`/`m.font`, как у размеров. Экранный размер постоянен, в PDF используется `PDF_METRICS` и шрифт PT Sans.
- Попадание курсора (`hitWall`, `dimHitDistance`), привязка и выделение рамкой не меняются. Помещения в них не участвуют, требование «без взаимодействия» выполняется само.

### D8. Совместимость

Модель данных, формат хранилища (`version: 3`), история и загрузка не меняются, миграций нет. Существующие чертежи сразу показывают помещения. Новые зависимости: `clipper2-ts`, `polylabel` (и транзитивно `tinyqueue`), dev-зависимость `@types/polylabel` (у `polylabel` нет встроенных типов).

## Risks / Trade-offs

- **Производительность.** `findRooms` вызывается на каждый кадр, а `displayPolygons` уже O(n²) по стенам. Для типичного плана (десятки стен) объединение занимает миллисекунды. Нужно замерить на плане из ~100 стен. При заметной задержке добавить кэш по ключу данных стен (координаты, толщины, порядок). Ссылка на массив как ключ не подходит: стены меняются на месте при перетаскивании.
- **Точность `clipper2-ts` на числах JS.** При шаге 0,001 см координаты плана в десятки метров — это ~1e7 единиц, а их произведения в векторных операциях подходят к пределу точных целых JS (2^53 ≈ 9e15). Нужно проверить, как порт считает произведения: BigInt, 128-битная эмуляция или `number`. Если `number`, нужно ограничить допустимый размер плана и добавить тест на план 100 × 100 м. Если точности не хватает, крупнее шаг сетки брать нельзя: он увеличит δ. Вместо этого надо сдвигать координаты к началу bbox чертежа. **Итог проверки (задача 1.2):** порт хранит координаты в `number`, а промежуточные произведения считает в `BigInt` и бросает ошибку, если координата выходит за 2^53. При шаге 0,001 см даже 10 км дают ~1e9 единиц, поэтому сдвиг к bbox не нужен. Подтверждено тестами ROOM-FAR-1 и ROOM-BIG-1.
- **Слишком маленький δ.** Если на каком-то стыке шум окажется больше одной ступени, помещения ложно сольются. Это ловится сценариями замкнутого контура по каждому виду стыка (тест-план).
- **Глиф «²» в PDF.** Нужно проверить, что в PT Sans (`src/assets/pt-sans-regular.ttf`) есть U+00B2. Если нет, использовать «м2» с верхним индексом или другой шрифт. Проверяется задачей.
- **Крошечные дыры** от клиньев на непрямых углах отбрасываются порогом 0,1 м², а шум на швах закрывается замыканием.
- **Подпись в узком помещении** может выйти за его границы. Спека этого не запрещает, отдельная обработка не делается.
- **Зависимость от формы стыков.** Помещения наследуют любые ошибки `displayPolygons`: дефект стыка, оставляющий видимую щель, откроет помещение. Это желаемое поведение («что видно, то и считается»), но баги стыков станут заметнее.
