## MODIFIED Requirements

### Requirement: Инструмент «Проём»
Инструмент «Проём» ДОЛЖЕН находиться в группе «Проёмы» (`canvas-app`, «Группа «Проёмы»») — первой кнопкой «Проём» в панели группы; кнопка группы идёт сразу после кнопки «Стена» (порядок групп — `canvas-app` «Группы инструментов»). Панель группы при активном инструменте «Проём» ДОЛЖНА содержать поля «Ширина» и «H» в текущих единицах измерения; по умолчанию ширина 900 мм, высота 2100 мм. Значения полей ДОЛЖНЫ применяться к новым проёмам. Значение, не являющееся положительным числом, НЕ ДОЛЖНО применяться; поле ДОЛЖНО возвращать прежнее значение. Активация инструмента ДОЛЖНА прерывать рисуемую цепочку и незавершённое размещение размера и снимать выделение. Esc при активном инструменте без выделения ДОЛЖЕН деактивировать инструмент, как у ластика.

#### Scenario: Дефолтные параметры
- **WHEN** приложение открыто, единица — мм, и пользователь открыл панель группы «Проёмы» с инструментом «Проём»
- **THEN** поле «Ширина» показывает 900, поле «H» — 2100

#### Scenario: Поля в текущих единицах
- **WHEN** пользователь переключил единицы на сантиметры
- **THEN** поля показывают 90 и 210

#### Scenario: Неверное значение не применяется
- **WHEN** пользователь ввёл в поле «Ширина» 0 или нечисловое значение и покинул поле
- **THEN** поле показывает прежнее значение, новые проёмы ставятся с прежней шириной

### Requirement: Выделение проёма
Вне рисования цепочки, вне активного ластика и вне активного инструмента «Размер» клик по проёму — участку между откосами через всю толщину стены — ДОЛЖЕН выделять проём вместо опорной стены. Клик по размеру выделяет размер (`dimension-selection`). Выделенный проём ДОЛЖЕН отображаться подсветкой выделения по контуру участка проёма. При выделении одного проёма ДОЛЖНА открываться панель группы «Проёмы» с активной кнопкой «Проём» (`canvas-app`, «Группа «Проёмы»»), а её поля ДОЛЖНЫ показывать ширину и высоту выделенного проёма. Изменение поля при выделенном проёме ДОЛЖНО менять этот проём (ширина — по правилам ввода ширины, с ограничением по инварианту) и записываться в историю одним шагом; поля при этом НЕ ДОЛЖНЫ менять параметры новых проёмов.

#### Scenario: Клик по проёму выделяет проём
- **WHEN** активен инструмент «Стена», цепочка не рисуется, и пользователь кликнул внутри участка проёма
- **THEN** выделен проём, стена не выделена, цепочка не начинается, видны размеры проёма

#### Scenario: Выделение проёма открывает панель группы
- **WHEN** текущий инструмент группы «Проёмы» — «Дверь», панель группы закрыта, и пользователь выделил проём кликом
- **THEN** панель группы открыта, выделена кнопка «Проём», поля показывают ширину и высоту проёма

#### Scenario: Высота меняется полем панели
- **WHEN** выделен проём с высотой 210 см, единица — см, и пользователь ввёл в поле «H» 200
- **THEN** подпись проёма показывает «H=200», в истории одна новая запись

### Requirement: Элементы стены
Элемент стены — объект чертежа, который существует только внутри одной опорной стены. Элемент стены ДОЛЖЕН быть одного из видов: проём (эта спецификация), окно (`window`) или дверь (`door`). Каждый элемент ДОЛЖЕН хранить вид и общие данные по требованию «Проём и опорная стена»: постоянный уникальный идентификатор, идентификатор опорной стены, сторону привязки, расстояние привязки и ширину; остальные данные определяет вид (у проёма — высота H). Вид элемента НЕ ДОЛЖЕН меняться ни одной правкой.

Требования этой спецификации и требования других спецификаций, ссылающиеся на проёмы (`wall-collision`, `wall-drawing`, `wall-deletion`, `multi-selection`, `drawing-history`, `drawing-storage`, `room-areas`, `pdf-export`), ДОЛЖНЫ действовать для элемента стены любого вида: слово «проём» в них ДОЛЖНО означать элемент стены, если требование не относится явно к виду «проём». Части этих требований, которые для окон заменены, перечислены в `window` («Окно — элемент стены»), для дверей — в `door` («Дверь — элемент стены»). Элементы разных видов ДОЛЖНЫ обрабатываться вместе: выделение рамкой, удаление, сдвиг стрелками, каскадное удаление со стеной, следование за стеной, ограничение правок стен и рисования.

#### Scenario: Ластик удаляет окно, а не стену
- **WHEN** ластик активен, и пользователь кликнул внутри участка окна
- **THEN** окно удалено, опорная стена осталась

#### Scenario: Рамка и Delete для проёма и окна
- **WHEN** рамкой выделены проём и окно на невыделенных стенах, и пользователь нажал Delete
- **THEN** проём и окно удалены, стены остались; в истории одна запись, одно «Отменить» возвращает оба элемента

#### Scenario: Стрелка сдвигает проём и окно
- **WHEN** выделены только проём и окно на горизонтальных стенах, и пользователь нажал стрелку вправо
- **THEN** каждый из них сдвинут на 10 см в сторону конца своей стены, направление на который образует со стрелкой острый угол

#### Scenario: Удаление стены удаляет её окна
- **WHEN** стена с проёмом и окном удалена клавишей Delete
- **THEN** проём и окно удалены вместе с ней; одно «Отменить» возвращает стену с обоими элементами на прежних местах

#### Scenario: Дверь не пересекается с соседними элементами
- **WHEN** на стене W стоит окно, и пользователь перетаскивает выделенную дверь той же стены на окно
- **THEN** дверь останавливается в касании откосов с окном, участки не налагаются

#### Scenario: Ластик удаляет дверь, а не стену
- **WHEN** ластик активен, и пользователь кликнул внутри участка двери
- **THEN** дверь удалена, опорная стена осталась
