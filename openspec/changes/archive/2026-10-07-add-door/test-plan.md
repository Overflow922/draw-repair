# Test Plan

## Scope

Двери как третий вид элемента стены и группа «Проёмы»: новая возможность `door` и дельты `canvas-app` («Группы инструментов», «Группа «Проёмы»»), `doorway` («Инструмент «Проём»», «Выделение проёма», «Элементы стены»), `window` («Инструмент «Окно»», «Панель выделенного окна»), `drawing-storage`, `drawing-history`, `pdf-export`.

Как и в `add-doorway` / `add-window`, тесты идут в `vitest` без DOM. Поведение проверяется через чистые публичные функции `src/doorway/` (правка, геометрия `doorLeaf`, параметры вида, таблица поворота, переходы группы `openings-group.ts`), `storage.ts`, `history.ts`, через адаптер `createElementTool` с заглушками хоста и панели (как `window-tool.test.ts`) и через `drawScene` / `buildPdf` / `wallsBBox` с записывающим контекстом. Разметка, иконки, фокус и видимость блоков полей — ручные проверки (M-*).

Одобренные тесты `add-doorway`, `add-window` и остальные существующие тесты не меняются и должны остаться зелёными.

### Сцены (см, толщина 20, если не указано)

- **F** — свободная стена W `(0,0)-(500,0)` (`sceneF`).
- **R** — комната (`sceneR`): грань W `y = +10` внутренняя.
- **DR(h, s)** — дверь на W: `a`, 100, ширина 90, H 210, петли `h`, сторона `s` (участок `x` 100…190).
- **DRb** — та же дверь, хранимая как `b`, 310 (тот же участок).
- **FV** — W повёрнута: ось `(0,0)-(0,500)`, дверь `a`, 100, петли `a`, `left`.
- **FW** — F + окно `WA` (`a`, 250, ширина 120: участок 250…370) + DR(a, left).

Константы: `c = cos 95° ≈ −0.08716`, `s = sin 95° ≈ 0.99619`; `90·c ≈ −7.844`, `90·s ≈ 89.657`. Допуски: координаты `toBeCloseTo(x, 3)`.

## Boundary Cases

| Case | Input | Expected |
|---|---|---|
| Ширина двери 1 см | `placeDoor` ширина 1 | полотно длиной 1, дуга радиуса 1, обозначение без NaN |
| Дверь вплотную к углу | R, DR(a, left) с offset 0 (`x` = 10) | петля на грани `y = −10` у `x = 10`, `doorwayHolds` true |
| Дверь во всю свободную длину стены | ширина = длина свободного участка | ставится, полотно длиной w |
| Вертикальная стена | FV | `left` = сторона `x > 0` |
| Ось справа налево | W `(500,0)-(0,0)` | `left` = сторона `y > 0` на экране (нормаль `(d.y, −d.x)` при `d = (−1, 0)` = `(0, 1)`) |
| Наклонная стена | ось `(0,0)-(400,300)` | угол `arcFrom`–`arcTo` = 95°, `arcFrom` на грани, длина полотна w |
| Толщина стены 10 | DR(a, left) на стене 10 см | петля `(100, −5)` |
| Повторный клик по группе | 3 клика подряд при активной двери | панель open → closed → open, `active = door` |

## Negative Cases

| Case | Expected behavior |
|---|---|
| `acceptField("door", "sill", 0)` | false |
| `acceptField("door", "width" / "height", 0 | −1 | NaN | Infinity)` | false |
| `placeDoor` с шириной ≤ 0 или без места на стене | null |
| `rotateDoor` у двери | всегда applied, направление другое; не no-change |
| Поле ширины выделенной двери с неверным значением | дверь не изменена, записей нет |
| Дверь с неизвестной стороной / концом в документе | отброшена, остальные данные целы |
| Дверь с `swing: "up"` в снимке истории | истории пусты, приложение работает |
| Элемент с `kind: "door"` и `sillCm` (лишнее поле) | читается как дверь; сериализация без `sillCm` |
| Клик по полотну / дуге вне стены | дверь не выделяется, не удаляется ластиком |

## Invariants

- Вид элемента и `hinge`/`swing` двери не меняются никакой правкой положения, ширины, высоты, следованием за стеной и сменой стороны привязки; меняет направление только `rotateDoor`.
- `nextDirection` — перестановка 4 направлений одним циклом длины 4 (`nextDirection⁴ = id`, все 4 промежуточных различны).
- Обозначение двери — функция только откосов, толщины и направления (не `anchor`, не направления записи оси при том же физическом смысле `hinge`/`swing`).
- `|hinge − arcFrom| = |hinge − arcTo| = w`; угол между ними 95°; полотно не пересекает сектор открывания (все 4 угла прямоугольника — по одну сторону прямой полотна, противоположную `arcFrom`).
- Дверь участвует в инварианте элементов стены наравне с проёмом и окном (не налагается, `doorwayHolds`).
- Переходы группы — чистые: вход не мутируется; `active` меняется только в `groupButtonClick` / `groupPick`.
- Проём сериализуется без `kind`; одобренные roundtrip-тесты проёма и окна остаются зелёными.

- `moveEndpointBounded` / `moveWallsBounded` с дверью в `EditMode.doorways` (DE-04, DE-05).
- `drawScene` с проёмом, окном и дверью на одной стене: у каждого своё обозначение (DR-01, DR-02).
- `buildPdf` и `wallsBBox` с дверью (DP-*).
- `serializeStore` → `parseStore`, `serializeHistory` → `parseHistory` со смешанными списками проёмов, окон и дверей (DS-*, DH-*).
- Разбор `index.html` как текста/DOMParser-free regex для порядка кнопок панели и панели группы (GR-09, GR-10).

## Mutation Targets

Мутационного инструмента в проекте нет; тест-валидатор проверяет вручную, что каждая мутация ловится:

- Угол 95° → 90° / 85° / в сторону `−n` — DG-01, DG-07.
- Петля на оси (без `±T/2`) или на противоположной грани — DG-01, DG-03.
- `left`/`right` перепутаны (знак `Side`) — DG-01, DG-02, DG-05.
- Конец петель по `anchor`, а не `hinge` — DG-04, DE-02.
- Прямоугольник полотна со стороны сектора — DG-01 (сторона толщины).
- `arcFrom` у петли / радиус ≠ w — DG-07.
- Таблица поворота: пропуск направления, неверный порядок, неполный цикл — DK-03.
- `rotate` без выделения пишет историю / с выделением меняет params — DT-06, DT-07.
- `rotate` при выделенном проёме/окне падает или пишет историю — DT-08.
- Поля двери пишут params проёма (общий объект) — DT-04.
- `hinge`/`swing` теряются в spread правок — DE-03.
- Валидатор хранения пропускает `hinge`/`swing` вне допустимых — DS-03; сериализация теряет направление — DS-01.
- `wallsBBox` не учитывает полотно/дугу — DP-02.
- `groupButtonClick` открывает панель вместо переключения при активном инструменте / не помнит `current` — GR-02, GR-04; `groupSelect` меняет `active` — GR-05.
- Ветка двери в `drawScene` не рисует дугу или рисует оконный блок — DR-01, DR-02; полотно цветом `muted` — DR-01.
- Попадание по полотну выделяет дверь — DC-01.

Примечание для тест-писателя: записывающий контекст `recorder()` фиксирует `arc()` только флагом; для DR-01/DP-01 его можно расширить (тестовая утилита) записью центра, радиуса и углов дуги. Точная геометрия проверяется на `doorLeaf` (DG-*), рендер — на использовании этой геометрии.

## Ручные проверки (браузер)

- M-01: кнопка «Проёмы» с новой иконкой между «Стена» и «Окно»; иконка в стиле остальных; отдельных кнопок «Проём»/«Дверь» на панели нет.
- M-02: клик по «Проёмы» активирует «Проём» и открывает панель с кнопками «Проём» (выделена) и «Дверь» и полями проёма; повторный клик закрывает панель.
- M-03: «Дверь» в панели — поля «Ширина», «H» (мм 900/2100, см 90/210) и кнопка «Повернуть»; выделение проёма/двери переключает панель на его вид, активный инструмент не меняется.
- M-04: призрак двери с полотном и дугой скользит вдоль стены; «Повернуть» без выделения поворачивает призрак по кругу.
- M-05: выделенная дверь — «Повернуть» поворачивает её, «Отменить» возвращает; поля меняют дверь.
- M-06: Esc без выделения деактивирует инструмент «Дверь»; кнопка группы при этом не выделена.
- M-07: PDF с дверью — полотно и дуга на месте, лист вмещает полотно.
