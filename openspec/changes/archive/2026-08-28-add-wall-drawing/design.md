## Context

Репозиторий пуст (кроме openspec-артефактов и макета `design.bmp` / `design_converted.png`). Ограничения: Vanilla TypeScript + Vite без UI-фреймворков и без бэкенда; рисование только стен; макет задал расположение панели инструментов слева. Мотивация — в `proposal.md`.

## Goals / Non-Goals

**Goals:**

- Минимальный каркас приложения, на который позже добавляются новые инструменты.
- Рисование цепочек стен заданной толщины с привязками к сетке и стенам.
- Чистая, тестируемая геометрия привязок без UI-фреймворка.

**Non-Goals:**

- Выделение/перемещение/удаление стен, undo, пан/зум, сохранение, экспорт (см. Non-goals в `proposal.md`).
- Пиксель-перфектное соответствие макету — уточняется по ходу имплементации.

## Decisions

- **Scaffold: `npm create vite@latest` (vanilla-ts), без UI-фреймворков.**
  Альтернатива React — лишние зависимости и код для статической панели; один HTML-файл — нет TS-типов, модулей и HMR при росте проекта.
- **Рендеринг: HTML Canvas 2D, полная перерисовка сцены (сетка → стены → превью) на каждое событие указателя.**
  Альтернатива SVG — DOM-элементы на каждую стену усложняют код; WebGL избыточен. Сотни стен перерисовываются мгновенно; backing store масштабируется на `devicePixelRatio` для чёткости.
- **Модель координат — сантиметры.** Экранное преобразование — константа `PX_PER_CM = 2`; шаг сетки 10 см; толщина стены хранится в стене, вводится в см. Зум/пан отсутствуют, поэтому преобразование фиксированное: `screen = model * PX_PER_CM`.
- **Данные: массив `Wall { a: Point, b: Point, thicknessCm: number }` в памяти** (`Point = { x, y }` в см). Текущая цепочка — точка старта плюс позиция курсора для превью.
- **Привязка — чистая функция `snap(cursor, walls, gridStep, radiusCm) → Point`** с приоритетом: конец стены → проекция на линию стены (в пределах сегмента) → узел сетки; из кандидатов берётся ближайший. Радиус привязки задан в экранных пикселях (12 px) и пересчитывается в см, чтобы ощущался одинаково на любом экране. Чистая функция покрывается unit-тестами (Vitest, только dev-зависимость).
- **Рисование стен: `stroke` сегмента с `lineWidth = thicknessCm * PX_PER_CM`, `lineCap = "square"`** — квадратные торцы визуально закрывают углы и T-стыки лучше, чем `butt`. Превью — полупрозрачный сегмент.
- **Ввод: `pointerdown`/`pointermove` на canvas; Esc и `dblclick` завершают цепочку.** Двойной клик порождает лишний `click` — нулевые по длине сегменты при размещении отбрасываются. Изменение толщины — числовой ввод в панели; некорректные значения игнорируются (последнее валидное остаётся).
- **Структура кода минимальная:** `src/main.ts` (bootstrap, события, панель), `src/render.ts` (отрисовка), `src/geometry.ts` (snap и helpers), `src/types.ts`. Без абстракции «инструмент» до появления второго инструмента.
- **Тесты: Vitest для `geometry.ts`** (приоритеты привязки, проекция на сегмент, сетка, отбраковка нулевых сегментов). UI проверяется вручную через dev-сервер; e2e-фреймворк не вводим.

## Risks / Trade-offs

- [Стыки стен под произвольными углами визуально неидеальны при `lineCap: square`] → достаточно для v1; при необходимости — полигональное объединение позже.
- [`dblclick` генерирует дополнительный `click` с вершиной-дубликатом] → фильтрация сегментов нулевой длины при фиксации вершины.
- [Макет `design.bmp` не просматривается агентом в этой сессии] → раскладка «панель слева + холст» берётся из текста запроса; иконки — простые inline-SVG, стилистика уточняется по макету при имплементации.
- [Плотное расположение стен затрудняет выбор кандидата привязки] → выбор ближайшего кандидата по расстоянию.
