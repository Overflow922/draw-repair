# Design: remove-legacy-wall-geometry

## Context

`src/geometry.ts` (751 строка) содержит ~226 строк экспортов, которые не вызывает ни один продовый файл: `main.ts` и `render.ts` импортируют только живую часть, `wall-geometry.ts` от `geometry.ts` не зависит вообще. Мертвые экспорты держатся на жизни исключительно через импорты в `geometry.test.ts` — так они были законсервированы задачей `2026-09-15-stable-wall-drawing` (Rule 4: реализация не трогает утверждённые тесты). Это изменение снимает консервацию: тесты мертвого кода удаляются в рамках того же изменения, поэтому Rule 4 не нарушается — реализация следует за утверждённым планом тестов этого change, а не правит их задним числом.

Ограничения: поведение приложения не меняется; данные, формат хранения, история и легаси-чертежи не затрагиваются; спецификации не упоминают удаляемые символы (проверено поиском по `openspec/specs/`).

## Goals / Non-Goals

**Goals:**

- Один источник истины для снапа и формы стен — `src/wall-geometry.ts`; `geometry.ts` оставляет только то, что не относится к форме стен (вид, размеры, перемещение, утилиты).
- Удалить мертвые экспорты и пинящие их тестовые блоки атомарно (код и тесты в одном коммите).
- Сохранить 100% поведенческого покрытия: перенести в `wall-geometry.test.ts` единственный непокрытый кейс (hitWall по клину), если он там отсутствует.

**Non-Goals:**

- Рефакторинг живого кода `geometry.ts` (в т.ч. инлайн орто-логики в `snap()`, деэкспорт `wallShape`, дедупликация `hitWall`-тестов между файлами) — отдельные изменения, если понадобятся.
- Введение mutation testing (в проекте нет инструментария; проверка — vitest + tsc).
- Любые изменения `wall-geometry.ts` и его тестов, кроме возможного добавления одного кейса.

## Decisions

### D1. Удаление атомарное: код + его тесты одним изменением

Альтернатива «сначала удалить тесты, потом код отдельным change» отвергнута: промежуточное состояние не имеет смысла, а Rule 4 применяется внутри каждого изменения — здесь план тестов (test-suite) утверждает сам факт удаления, и реализация ему следует.

### D2. Критерий мертвости — отсутствие прод-вызова, подтверждённое вручную

Автоматического knip/ts-prune в проекте нет. Критерий проверялся грепом по `src/*.ts` + разбором внутренних цепочек вызовов `geometry.ts`. Итоговый список (см. proposal) пересчитывается на этапе реализации: перед удалением каждого символа — повторный греп; если нашёлся прод-вызов, символ исключается из удаления и это фиксируется в отчёте задачи.

### D3. Живые «легаси» не трогаются

`lockedDirection` (main.ts:374), цепочка `jointAt`/`wallShape`/`endCap`/`buttCap`/`capOnFaces`/`jointTol`/`jointedWalls`/`bodyGap` (через `wallSegments` кормят `dimPointPoint`/`nearestEdgeIntersection`), реэкспорт `hitWall` — остаются как есть, включая их тесты. Их судьба — возможные будущие изменения, не этот.

### D4. Кейс «клин заливки попадает в позднюю стену»

Тест `geometry.test.ts:528-532` проверяет hitWall по клину поздней стены — поведение из спеки wall-joints. Перед удалением блока «полигоны отрисовки и заливка клина» сверить с describe «hitWall: попадание по отображаемой форме» в `wall-geometry.test.ts:474`. Если эквивалентного кейса нет — добавить туда тот же кейс (та же точка `{ x: 109, y: -9 }`, те же стены) как единственное изменение в этом файле.

### D5. Проверка результата

- `npm test` — все оставшиеся тесты зелёные;
- `tsc` (входит в `npm run build`) — нет ссылок на удалённые символы; `noUnusedLocals` дополнительно поймает забытые импорты;
- греп по `src/` на удалённые имена — 0 вхождений.

## Risks / Trade-offs

- **Риск: символ оказался всё-таки живым** (динамический вызов, будущий код). Митигируется D2 — повторная проверка перед каждым удалением; tsc поймает битые импорты сразу.
- **Риск: потеря покрытия** — принимается только по списку D4; все остальные удаляемые тесты имеют эквиваленты в `wall-geometry.test.ts` (снап-вершины — 5 блоков; moveWall-сценарии — 1:1 в describe `moveWalls`) или пинят код без прод-поведения (subtractCovered, pointInConvex, sameTypeJoint, pointOn, handleAt).
- **Trade-off: `wallShape` остаётся экспортом** только ради тестов, хотя прод зовёт его внутренне. Осознанно: тесты живые, деэкспорт — не-цель этого изменения.

## Migration

Миграции данных и хранилища не требуются — удаляется только вычислительный код, не создающий состояния.
