## Context

Каноническая форма стены строит `displayPolygons` (`src/wall-geometry.ts`); форма каждого конца — `endShape`. Он собирает `endNeighbors` — все концы чужих стен в пределах `jointTol(wall, c) + SLICE` от конца `E` — и разветвляется по их числу:

- `>= 2` — плоский торец, все соседи в `exempt` (не вычитаются из тела);
- `1` — стык двух стен: почти коллинеарный, ранняя/поздняя, доведение до дальней грани или плоский торец с клином на грани;
- `0` — угловой стык на грани, T-примыкание или свободный конец.

Ветка `>= 2` не проверяет, близки ли соседи друг к другу. В данных цепочки (`V.b = (110, 210)`, `H.a = (110, 200)`, толщина 20) новая стена `U.a = (110, 190)` даёт у `H.a` двух соседей на расстоянии ровно 10 = порог, хотя `dist(U.a, V.b) = 20`. Воспроизведено в браузере: снимок совпадает с `img_1.png`.

Форму из `displayPolygons` используют отрисовка, контур, подсветка, попадание курсора, прилипание квадрата установки (`wall-snap.ts`), линейка, площади комнат и границы T-примыканий (`tee-bounds.ts`).

## Goals / Non-Goals

**Goals:**
- Ветка «вершина трёх и более стен» срабатывает только при попарной близости концов.
- Непопарный набор соседей сводится к стыку с ранней из соседних стен по существующим правилам ветки одного соседа.
- Существующие стыки (общая вершина, один сосед, угол на грани, T) отображаются как прежде.

**Non-Goals:**
- Не меняются `faceCornerAt` / `partnerEndOf` (угловой стык на грани) и T-примыкания.
- Не меняется устаревшая форма `wallShape` / `jointAt` в `src/geometry.ts` (используется только для рёбер привязки размеров через `wallSegments`; в требование согласованности формы не входит).
- Не меняются рисование, привязка, данные и история.

## Decisions

### D1. Проверка вершины — попарная близость концов соседей

После сбора `endNeighbors` при числе соседей `>= 2` проверяется, что каждая пара соседних концов `(v_i, v_j)` отстоит не дальше `jointTol(c_i, c_j) + SLICE`. Вместе с близостью каждого соседа к `E` (уже гарантирована сбором) это и есть «все концы попарно в пороге своей пары» из спецификации. Если условие выполнено — прежний плоский торец с `exempt` по всем соседям.

*Альтернатива:* кластеризация (связные компоненты по порогу) — избыточна: решение принимается только для одного конца `E`, и достаточно знать, является ли весь набор кликой.

### D2. Непопарный набор — сведение к одному соседу

Если набор не клика, выбирается сосед с минимальным индексом в `walls` (ранний). Дальше выполняется существующая логика ветки одного соседа, как если бы в `endNeighbors` был только он. Признак `isEarlier` вычисляется относительно выбранного соседа, а не всех соседей: иначе в примере (`V` раньше `H`, `U` позже) `H` не была бы ни ранней, ни поздней по смыслу ветки.

Ветку одного соседа выносим в отдельную функцию, принимающую выбранного соседа, чтобы обе ветки (`1` и непопарный `>= 2`) шли через один код.

Прочие соседи в `exempt` не попадают: поздние стены и так не вычитаются из тела ранней, а ранние должны вычитаться по общему правилу.

### D3. Почти коллинеарная пара в непопарном наборе — плоский торец

Требование «Почти коллинеарный стык» допускает срез по биссектрисе, только если других концов в пороге нет. Поэтому, если выбранная пара почти коллинеарна, возвращается плоский торец (без срезов и без `exempt`), как в спецификации. Это та же проверка угла, что и в ветке одного соседа, но с другим результатом. Проверку выполняет вызывающая сторона до передачи в общую функцию: признак «есть другие концы в пороге» передаётся параметром.

### D4. Превью

Для превью (`isLatest`, `iWall = -1`) выбор ранней соседней работает по индексам `walls` без изменений: превью не входит в массив и всегда позднейшее.

## Risks / Trade-offs

- **Конфигурации из трёх и более соседей, где непопарность вызвана не противоположными гранями** (например, конец со стороны торца и два конца с граней) теперь строятся как стык с ранней соседней вместо плоского торца. По спецификации это ожидаемо; затронуты только наборы, которые раньше давали «плоский» результат. → Тесты на клику (общая вершина) должны остаться зелёными; добавляются тесты на непопарный набор.
- **Граница порога.** В сценарии цепочки расстояния ровно равны порогу (10 = 10); сбор соседей уже использует `+ SLICE`, попарная проверка — тот же допуск, поэтому округление не меняет классификацию.
- **Размеры у узла.** Рёбра привязки размеров строятся по `wallShape` с прежним правилом (`jointAt`, `count > 1`): у узла T из цепочки рёбра для размеров могут не совпадать с отображаемой формой. Это существующее расхождение, вне рамок изменения.
- Миграции данных нет: изменение только в отображении.
