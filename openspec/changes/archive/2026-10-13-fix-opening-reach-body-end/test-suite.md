Падения — ожидаемые причины:

продолжение того же материала), `no-change` у стыка, `invalid` для отрицательного ввода, нарушенные документы и слияние.

## Расхождения и открытые вопросы

1. **Существующий `DS-03` (`src/doorway/doorway-storage.test.ts:45`) противоречит спеке `drawing-storage` в её нынешнем виде.** В нём
   проём `{ …d, id: "neg", offsetCm: -1 }` на свободной стене должен отбрасываться. Спека как написана принимает любое
   конечное расстояние, поэтому после реализации `DS-03` упадёт. Тест не изменён (правило 5). Нужен test-change-request либо
   уточнение спеки. Вариант без изменения `DS-03`: загрузчик принимает отрицательное смещение только если элемент лежит
   в выступе тела (знание стен, как у отбрасывания сирот). Новые тесты хранилища совместимы с обоими вариантами:
   они проверяют отрицательное смещение только на выступе.
2. **Спека `mounting-plan` не говорит, виден ли элемент на выступе.** T-26/T-26b утверждают, что без сноса он виден на остатке
   с тем же смещением (так сейчас ведут себя все элементы целиком на стене). Если решение будет иным, нужна дельта
   `mounting-plan` до реализации; тесты тогда меняются. Поведение при сносе у выступа тестами не закреплено намеренно.
3. **Ввод отрицательного расстояния.** План допускал «ближайшее допустимое значение», существующий `CD-24` требует `invalid`.
   Сохранено `invalid` (T-11f); план в этой строке расходится с действующим поведением.
4. **Расстояние до стыка через число расстояния** (T-24): ожидается 90 до правки (откос `x = 420`, стык `x = 510`).

## Мутационное тестирование

В проекте нет настроенного инструмента мутаций (`package.json` содержит только `vitest run`). Мутанты из плана проверяются
вручную валидатором; тесты, которые должны их убивать: границы `freeIntervals` — T-11, T-12, T-14, T-15, T-16, T-17;
знак `offsetCm` для привязки `b` — T-11, T-13; условие `offsetCm >= 0` — T-17, T-18; порядок стен — T-11 против T-15;
`reattach` — T-25.
