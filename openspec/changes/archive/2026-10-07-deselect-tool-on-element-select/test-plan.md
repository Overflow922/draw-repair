# Test Plan

## Scope

Правило «после выделения существующего элемента стены инструмент установки деактивируется» (`doorway`
«Выделение проёма кликом», `canvas-app` «Панель группы «Проёмы»»): чистая функция перехода `afterElementPress`
(инструмент и состояние группы «Проёмы», design D2a) и `ElementTool.clearGhost` (design D3); цепочка «выделить элемент → клик в
зону направления двери» на уровне домена (`pressDoorway`, `pressZone`, `setDirection`).
Раскладка нажатий в `main.ts` (DOM) модульными тестами не покрывается — см. «Out of Scope» и ручную проверку.

Тесты размещаются в `src/doorway/` рядом с `openings-group.test.ts`, `door-tool.test.ts`, `door-direction.test.ts`;
существующие утверждённые тесты не меняются.

Тесты:

`afterElementPress({ tool, group, selected })` → `{ tool, group }` (design D2a):

- DS-1: `tool: "door"` и `"doorway"`, `selected: true` → `tool: "none"`.
- DS-2: то же для `"window"`.
- DS-3: параметризованно: три инструмента установки × входные `group` (панель открыта/закрыта, `current` —
  `doorway`/`door`) → `tool: "none"`, `group.active: "other"`, `group.panelOpen: false`, `group.current` равен
  входному; повторное применение к результату (с `selected: true`) ничего не меняет.
- DS-4: `"wall"`, `"dimension"`, `"ruler"`, `"eraser"`, `"none"` при `selected: true` → результат равен входу
  (тот же `tool`, `group` равен входному, включая `panelOpen`).
- DS-4b: `selected: false` при каждом инструменте, включая три инструмента установки → результат равен входу
  (нажатие, ничего не выделившее, инструмент не снимает).
- DS-5: функция не мутирует вход; группа результата проходит `groupButtonActive` (`false`), а `groupButtonClick`
  возвращает `active: current`, `panelOpen: true`.
- DS-6: интеграция домена: дверь (петли `a`, `left`) выделена `pressDoorway` из состояния установки;
  `pressZone` в зону `b/right` меняет направление, дверь остаётся выделенной, запись одна (регресс).
- DS-7: `place` по пустому месту стены ставит элемент (регресс).
- DS-8: перетаскивание, начатое `pressDoorway`, переживает `ElementTool.clearGhost` и пишет одну запись;
  без сдвига записи нет; `clearGhost` убирает призрак у всех трёх инструментов (DS-3b).
- DS-9: `clearGhost` не вызывает `inherit` и не пишет историю.

## Boundary Cases

| Case | Input | Expected |
|---|---|---|
| Зона на границе текущего направления | клик в `(120, −60)` после выделения | направление не меняется, записи нет |
| Нажатие точно на откосе элемента | `pressDoorway` на границе участка | как у существующего попадания (`press-pick`), правило деактивации не меняет попадание |
| Деактивация при уже «нет инструмента» | `afterElementPress({tool: "none", …, selected: true})` | `"none"`, группа без изменений, идемпотентно |

## Negative Cases

| Case | Expected behavior |
|---|---|
| Нажатие мимо элементов при инструменте «Дверь» (`selected: false`) | инструмент и группа не меняются (DS-4b); установка — DS-7 |
| Нажатие по телу стены (не по элементу) при инструменте «Дверь» | стену это не выделяет (клик ставит дверь по призраку, DS-7); правило деактивации касается только выделенного элемента стены |
| Выделение элемента при «Стена» | «Стена» остаётся активной (DS-4) |
| Ластик | нажатие по элементу не выделяет и инструмент не меняет (DS-4) |

## Invariants

- Выбор инструмента после выделения не зависит от вида выделенного элемента.
- `current` (память кнопки группы) не меняется выходом из установки.
- Выход из установки не меняет параметры новых элементов и не пишет в историю.
- Функция чистая: тот же вход — тот же результат, входной объект не мутируется.

## Integration Cases

- DS-6: выделение из состояния установки → зона направления → одна запись истории, `inherit` параметров
  (петли) делает их параметрами новых дверей.
- Ручная проверка в браузере (по `memory: browser-manual-checks`): инструмент «Дверь» → клик по двери →
  кнопка группы не выделена, панель закрыта, призрака нет → клик в зону `b/right` → направление изменилось →
  «Отменить» возвращает прежнее.

## Mutation Targets

- Условие «инструмент установки» (убрать `window` или `doorway` из набора → DS-1/DS-2/DS-3 падают).
- Распространение правила на «Стена» и другие (DS-4 падает).
- Потеря или подмена `group.current` при выходе (DS-3 падает).
- `panelOpen` не закрывается (DS-3 падает) или закрывается без деактивации (DS-4 падает).
- Деактивация при `selected: false` (DS-4b падает).
- `clearGhost` равен `reset` (DS-8 падает: перетаскивание сброшено); `clearGhost` — пустая операция (DS-3b падает).
- Мутация входа функцией (DS-5 падает).
- Вызов `setTool("none")` вместо перехода D1 (снятие выделения) и пропуск вызова `afterElementPress` в
  `main.ts` модульными тестами НЕ обнаруживаются — см. «Out of Scope»; закрываются ручной проверкой (Integration
  Cases) и пунктом в `TODO.md`.

## Out of Scope

- DOM-раскладка `pointerdown`/`click` в `main.ts` (нет юнит-тестов на `main.ts`) — проверяется вручную и
  e2e-проверкой, если такая появится; leftover фиксируется в `TODO.md`.
- Ручная деактивация инструмента кнопкой, снимающая выделение (прежнее поведение, осознанно не меняется).
