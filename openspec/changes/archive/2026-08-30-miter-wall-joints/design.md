# Design: miter-wall-joints

## Context

Каждая стена рисуется в `render.ts` как независимый прямоугольник (`wallPolygon`): 4 угла = концы оси ± половина толщины по нормали. Информация о соседях при отрисовке не используется. Стыки возникают потому, что привязка делает концы стен точно совпадающими (`pointsEqual`, цепочка стен + привязка к концам), а T-стыки — потому что `snap` кладёт конец стены точно на ось другой. Оси стен — истина данных; подписи длин (`formatLength`), hit-тест (`hitWall`), ручки и обводка выделения — всё по осям. Мотивация — см. proposal.md.

## Goals / Non-Goals

**Goals:**

- Чистая геометрия стыков при отрисовке: митра / bevel / плоский торец по диапазонам угла, T-подрезка.
- Инварианты: оси, осевые длины, данные, undo/redo — нетронуты; обводка не выходит за грани.
- Непрерывная фаза штриховки одного материала через стыки, без двойной штриховки.

**Non-Goals:**

- Построение общего контура (tracing объединённого полигона) — линия шва на стыке остаётся нарисованной (одна общая линия вместо нынешних двух пересекающихся).
- Митра для 3+ стен в одной вершине.
- Размерные цепочки по граням (отдельная будущая возможность).
- Изменение формата хранения, миграции, истории.

## Decisions

### D1. Стыки — только в отрисовке (presentation-only)

Альтернатива «резать концы в данных» отвергнута: она мутирует осевые длины и сохранённые файлы, требует пересчёта при каждом перемещении и ломает семантику «длина стены = длина оси». Рендер-подход даёт старым чертежам новый вид бесплатно и сохраняет инварианты спеки.

### D2. Чистая функция формы в `geometry.ts`

`wallShape(wall, walls): Point[]` — вместо `wallPolygon`. На каждый рендер строит карту вершин (`pointsEqual`-кластеры) и для каждого конца стены определяет линию среза:

- **Угловой стык (ровно 2 стены в вершине), угол ≥ порога остроты (~30°).** Направления осей от вершины; пересечения наружных и внутренних граней дают общую линию среза (даже при разной толщине обе стены получают один и тот же отрезок — замощение точное). Кап каждого конца в полигоне заменяется с перпендикулярного на эту линию. Верхней границы нет: у лёгких изломов (угол → 180°) срез вырождается в короткий поперечный шов ~1 мм и заполняет угол без щели — плоские торцы здесь оставляли клиновидную щель (feedback пользователя); вырождение |cross| < EPS → плоские торцы.
- **Острые углы (< ~30°): примыкание впритык.** Сквозная стена — нарисованная раньше (меньший индекс в массиве) — отображается полным прямоугольником; примыкающая сохраняет прямоугольный торец, подрезанный по ближней грани сквозной (тот же путь, что T-подрезка). Bevel удалён: он укорачивал видимое тело стены и «отрывал» размеры от стыка, а клиновидные блоки физически неверны (feedback пользователя).
- **T-стык.** Конец стены лежит на оси другой (малый эпсилон, проекция строго внутри): срез = грань сквозной стены со стороны подхода; сквозная не меняется. T-стыки не топологичны (`moveWall` не тянет T-концы), поэтому детект — по факту на оси в момент рендера; разъехался — плоский торец. Подрезка по грани — общий путь для T-стыка и острого примыкания.
- **3+ стены в вершине / численная дегенерация (параллельные грани).** Плоские торцы (fallback).

Константа `MITER_MIN_DEG = 30` — согласована с пользователем, настраиваемая.

Альтернатива «считать стыки один раз на список стен и кэшировать» избыточна: n стен на плане — десятки, O(n²) на кадр незаметно.

### D3. Гарантия «не выйти за грани»

Точки среза определяются как пересечения линий граней → полигон всегда внутри полосы ось ± t/2; вылет угла за конец оси ≤ (t/2)·tg(θ/2) ≤ границе диапазона митры. Отдельной проверки не нужно — инвариант следует из построения.

### D4. Штриховка: якорь фазы от чертежа

`strokeHatch45` начинает линии от `minX+minY` bbox полигона — фаза своя у каждой стены, на стыках линии не продолжаются. Новый якорь: мировая точка (0,0), проведённая через текущий трансформ в экранные координаты; шаг `HATCH_STEP` (экранные мм) не меняется. Так линии приклеены к чертежу при панораме/зуме и одинаковы для всех стен одного материала. Чисто экранная константа отвергнута — штриховка «плыла» бы при панораме.

### D5. Дерево: волокна с запасом

`woodLong` рисует волны только вдоль оси `a→b`; у среза появится пустой клин. Диапазон волн расширяется на толщину в обе стороны за пределы оси; клип полигона обрезает лишнее.

### D6. Превью — плоские торцы

Предварительный сегмент рисуется как сейчас (плоский прямоугольник, alpha 0.4); срез появляется после фиксации вершины. Осознанное поведение: у превью ещё нет соседа.

### D7. Порядок рёбер полигона

Полигон строится упорядоченным путём: боковая грань → кап (возможно срезанный) → боковая грань → кап. Обход не самопересекается при любых диапазонах углов; `drawMaterial` уже клипует по полигону, `tracePolygon` рисует любой замкнутый путь — изменений не требуют.

### D8. Один тип — без линии шва (feedback 2026-08-30)

По референсу AutoCAD стены одного типа (одинаковый материал и толщина) не разделяются в вершине линией среза. Тела стен по-прежнему режутся митрой/подрезкой (замощение точное), но контурный проход пропускает рёбра-торцы: поиск соседа вынесен в `jointAt` (общий для `endCap` и нового экспорта `sameTypeJoint`), а `strokeContour` в рендере рисует контур разомкнутым путём, пропуская слитые торцы; квадратные концы штриха (lineCap square) закрывают микрощели в точках встречи рёбер соседей — на замкнутом контуре lineCap ни на что не влияет. Исключение — острое примыкание (φ < 30°): линия торца там — внешняя граница тела (торец уходит по грани сквозной стены за её конец), пропуск оставил бы дыру в контуре. T-стык одного типа: подрезанный торец лежит на грани сквозной — её собственное ребро уже нарисовано. 3+ стен в вершине — торцы плоские и рисуются (fallback).

### D9. Допуск вершины стыка (feedback 2026-08-30, скриншот «один угол не соединился»)

Снап к оси кладёт конец стены на проекцию, а не на ближний торец: конец оказывается в паре сантиметров от конца соседа (t≈0.003 «строго внутри») → стык классифицировался как T, сквозная оставалась с плоским торцом, у наружного угла была выемка. `jointAt` теперь возвращает `Joint {c, cEnd, vertex, corner}`: угол — когда конец соседа в пределах `max(h)/2` (h — полутолщина пары); вершина каноническая — конец более ранней стены (обе стороны строят одну линию среза, замощение точное); `endCap`/`buttCap` считают кап относительно вершины (тела дорисовываются до среза, полигон остаётся в полосе граней). T действует только дальше порога от концов сквозной — там, где грань реально существует. Три и более концов в пределах порога — плоские торцы (бывший guard «>1 соседа»).

### D10. Разные типы — прямое примыкание вместо митры (feedback 2026-08-30, «не по диагонали»)

Референс AutoCAD: стены разных типов стыкуются прямым перпендикулярным швом. Митра остаётся только для стен одного типа (её линия всё равно не рисуется — она лишь точно замощает тела в углу для штриховки); для разных типов угловой стык идёт по общему пути примыкания: сквозная (ранняя) — полный прямоугольник с прямым торцом, примыкающая — прямоугольный торец, подрезанный по ближней грани сквозной (`buttCap`, тот же путь, что острый угол и T-стык). Все рисуемые линии стыков теперь прямые; диагональ нигде не отображается. Условие в `endCap`: митра при `sameType && phi >= MITER_MIN`, иначе — примыкание.

## Risks / Trade-offs

- [Шов между разными типами остаётся видимой одной общей линией] → приемлемо; полное слияние контура (tracing объединённого полигона) — отдельная будущая возможность (Non-Goals), для одного типа шов убран (D8).
- [Якорь фазы слегка сдвинет существующую штриховку] → визуально то же поле линий; выигрыш — непрерывность через стыки, ГОСТ-подобный вид примыкающих стен.
- [Тело примыкающей стены при остром угле заканчивается на грани сквозной, не доходя по оси до вершины] → физически корректное примыкание впритык; сквозная стена заполняет угол своим прямоугольником, щелей нет.
- [Численные случаи: почти параллельные грани, вырожденные стены] → все fallback-и ведут к плоскому торцу (текущее поведение), регрессий нет.
- [O(n²) кластеризация на кадр] → незаметно для плановых количеств стен; при необходимости — карта по ключу точки, не меняет контракт.

## Migration Plan

Без миграции: данные и хранение не меняются, старые чертежи получают новый вид при отрисовке. Откат — возврат `render.ts` к `wallPolygon`.

## Open Questions

Нет: порог остроты (30°), T-стыки и якорь штриховки согласованы; диапазоны уточнены по feedback пользователя 2026-08-29 (митра без верхней границы, примыкание впритык вместо bevel).
