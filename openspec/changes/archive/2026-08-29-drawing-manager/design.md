## Context

Опирается на `json-storage`: модуль `storage.ts` (шов хранения) и формат документа v1 уже введены, поэтому смена схемы локализована. Всё состояние по-прежнему в модульных переменных `main.ts`; после этого изменения оно становится принадлежностью активного чертежа. Фреймворков нет — UI вкладок строится на статичной разметке `index.html` и обычном DOM. Изменение применяется после архивации `json-storage` (его дельта модифицирует требования `drawing-storage` из того изменения).

## Goals / Non-Goals

**Goals:**

- Несколько независимых чертежей на вкладках с полным автосохранением набора и активной вкладки.
- Минимальный рефакторинг `main.ts`: обработчики переезжают на активный документ без изменения логики черчения.

**Non-Goals:**

- Drag-реордер вкладок, дублирование чертежей.
- Корзина/отмена удаления — подтверждение финально.
- Изменение поведения инструментов черчения.

## Decisions

- **Один ключ хранилища с конвертом `{ version, activeId, drawings }`.** Атомарная запись всего набора, нет рассинхрона «индекс ↔ документы». Альтернатива (ключ на чертёж + индексный ключ) отклонена: два источника правды при том, что объём данных — килобайты.
- **`id` — `crypto.randomUUID()`, имя по умолчанию — «Чертёж N», N = наименьший свободный номер.** После удаления «Чертёж 1» кнопка «+» снова даёт «Чертёж 1» — номер остаётся плотным и очевидно уникальным среди открытых. `id` используется только для активной вкладки в конверте и ключа списка.
- **Чертёж = `{ id, name, walls, view }`; выделение и цепочка рисования — эфемерное состояние сессии.** При переключении/создании/закрытии вкладки цепочка и выделение сбрасываются: их восстановление не требуется сценарием и усложняет модель.
- **Закрытие — нативный `confirm()`, всегда.** Единообразное правило без привязки к содержимому; синхронный диалог проще кастомной модалки и не требует CSS. После подтверждения: удалить из набора, сохранить; если набор пуст — создать новый пустой чертёж.
- **Миграция со схемы `json-storage`:** при загрузке, если документ выглядит по-старому (`version: 1`, есть `walls`, нет `drawings`), он заворачивается в конверт как единственный чертёж с автоматическим именем. Дёшево (десяток строк в `parseStore`) и бережёт данные ранних сборок; без этого первый запуск после обновления выглядел бы как «повреждённые данные».
- **Переименование — инлайн по двойному клику на имени вкладки.** Имя превращается в поле ввода; Enter или потеря фокуса применяют непустое имя, Escape откатывает, пустое имя игнорируется. Без отдельной модалки — минимальный UI; имя живёт в конверте, сохраняется общим dirty-механизмом.

## Risks / Trade-offs

- [Рефакторинг `main.ts` широкий: ~10 обработчиков переезжают на активный документ] → Механическая замена ссылок на `current().walls`/`view`; поведение черчения не меняется, прикрыто тестами геометрии и ручным прогоном сценариев.
- [Атомарная запись всего набора переписывает все чертежи при каждой мутации] → Осознанно: объём — килобайты, запись субмиллисекундная; сложность инкрементальных записей не оправдана.
- [В конверте один `version` на всю схему] → При эволюции схемы чертежа версия поднимается у конверта; парсер читает старые документы целиком по правилам старой версии — стандартный путь, отдельные версии на чертёж не нужны.

## Migration Plan

Порядок: сначала применяется и архивируется `json-storage`, затем это изменение. Миграция данных — см. решение о заворачивании одиночного документа. Откат после архивации не планируется (данные ранних сборок читаются миграцией вперёд).
