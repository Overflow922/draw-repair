# Test Plan

## Scope

Автоподбор масштаба печати и удаление пользовательского выбора масштаба, фильтра форматов и попапа «не влезает» (дельты `drawing-scale`, `pdf-export`, `drawing-storage`, `drawing-plans`, `mounting-plan`).

Тестируется наблюдаемое поведение:

- чистая функция подбора `fitScale(pages, format)` и форматирования `formatScale(x)` (модуль `src/export/fit-scale.ts`, design D1, D7);
- содержимое PDF: масштаб размещения (10/X мм на см мира), графа 25, одинаковый масштаб на всех страницах;
- хранилище: масштаб не пишется, прежний `scale` игнорируется;
- разметка и экран: нет `#pdf-scale`, `#fit-popup`; `#pdf-format` содержит A4–A0 всегда; подпись масштаба рядом с форматом.

Текст подписи масштаба — чистая функция `scaleLabel(pages, format)` (design D4a): T-31…T-33 проверяются unit-тестами без DOM; в `main.ts` проверяется только связка (статически).

Уровни: unit (`fit-scale`, `formatScale`, `storage`), integration (сборка PDF через `buildPdfPages`/`pagesOf`, как в существующих `pdf*.test.ts`), e2e/ручная браузерная проверка (подпись и список форматов в приложении; в vitest DOM-тесты — только если в проекте уже есть подходящий образец).

## Invariants

- `fitScale` возвращает только значения ряда 2, 2.5, 4, 5, 10, 15, 20, 25, 40, 50, 75, 100, 200, 400, 500, 800, 1000 или `null`.
- Максимальность: если `fitScale` вернул X, то при предыдущем (более крупном) члене ряда хотя бы одна страница не помещается (кроме X = 2); при X все непустые страницы помещаются (кроме X = 1000).
- Монотонность по формату: подобранный масштаб для A3 не мельче подобранного для A4, для A2 — не мельче A3 и т. д. (при одном и том же чертеже).
- Один масштаб на все страницы PDF: геометрия каждой страницы размещена с `10/X` мм на см; во всех графах 25 одно и то же значение.
- Подобранный масштаб не зависит от активного плана, выделения, зума и единиц отображения.
- Размер шрифта подписей и размеры рамки/основной надписи/легенды в мм не зависят от масштаба.
- В сохранённом документе у чертежа нет поля `scale`.

## Integration Cases

- Сборка PDF (`buildPdfPages` через `pagesOf`) для чертежа с тремя планами (обмер, демонтаж с пометками и размерами, монтаж с собственными объектами): масштаб определяется самой крупной страницей, во всех трёх графах 25 одинаковое значение, геометрия всех страниц размещена в этом масштабе, ни одна страница не выходит за область чертежа (при X ≠ 1000).
- Цепочка «рисуем стену → габариты растут → масштаб сменился» на уровне чистых функций.
- Загрузка документа версии 1/2/3 со старыми значениями `scale` → чертёж без поля `scale` в модели → PDF этого чертежа собирается.
- Ручная/браузерная проверка (`browser-manual-checks`): нет списка масштаба; подпись рядом с форматом меняется при выборе формата и при рисовании; список A4–A0 неизменен; экспорт и открытие PDF показывают тот же масштаб в графе 25; каждый план — комната, нарисованная по стенам (`check-multi-step-sequences`).

## Mutation Targets

- `fitScale`: порядок перебора ряда (от крупного к мелкому), условие «помещается» (`<=` на границе, мутация на `<`), учёт легенды `legendMm`, учёт всех страниц (`every` → `some`), пропуск пустых страниц, возврат 1:1000 при отсутствии подходящего.
- `formatScale`: запятая вместо точки, целые без дробной части.
- Размещение в `drawPage`/`placeOnPage`: коэффициент `10/X`.
- Граница области в `fitsFormat`.
- Чтение/запись `storage.ts`: игнорирование `scale`, отсутствие отбрасывания чертежа.

Ловушки поверхностно верных реализаций:

- перебор ряда в неверном порядке (первый подходящий от мелкого) — даёт «подходит всё», но не максимально крупно: ловят T-03, T-04, T-46;
- подбор по одной странице (активной или первой) вместо самой крупной — ловят T-11, T-13;
- подбор только по стенам без размеров/подписей/легенды — ловят T-19, T-25, T-27, T-28, T-29;
- масштаб считается по габаритам на бумаге, посчитанным один раз при 1:100 и масштабируемым линейно (запас и подписи в мм ломают это) — ловит T-46 на чертежах с подписями у границы;
- на экране один масштаб, в PDF другой (два независимых пути вычисления) — ловят T-14, T-31 вместе с T-20;
- десятичная точка вместо запятой («1:2.5») — ловят T-02, T-26;
- 1:1000 как «ошибка» вместо экспорта — ловит T-15;
- фильтр форматов оставлен, но «выключен» CSS-классом — ловит T-36.

## Impact on Existing Tests (test-change-request)

Часть утверждённых тестов описывает удалённое поведение или использует удаляемый API (`availableFormats*`, `fitsFormat` со списком, `chooseFormat`, `Drawing.scale`, `isScale`, `DEFAULT_SCALE`, `SCALE_DENOMINATORS`, `buildPdfPages(..., scale, ...)` с произвольным масштабом из старого ряда): `page-format.test.ts`, `sheet-fit.test.ts`, части `pdf.test.ts`, `pdf-pages.test.ts`, `legend-area.test.ts`, `demolition-*-pdf.test.ts`, `mounting-pdf.test.ts`, `sheet-layout.test.ts`, `types.test.ts`, `storage*.test.ts` и фикстуры чертежей с полем `scale`. По Rule 5 реализация их не правит: пересмотр оформляется отдельным test-change-request и повторной валидацией. Полный перечень затронутых тестов и решение «удалить / переписать на подбор масштаба» — задача Test Writer при подготовке `test-suite`.

## Out of Scope

- Менять формат, ориентацию, рамку, основную надпись, легенду, размеры подписей.
- Автоматический выбор формата.
- Подбор масштаба отдельно по планам.
- Мутационное тестирование всего проекта: только цели из раздела «Mutation Targets», если в проекте есть инструмент (на сегодня в `package.json` Stryker нет — прогон мутаций отмечается как невозможный, пока инструмент не добавлен отдельным решением).
- Переименование и правка раздела `## Purpose` у `drawing-scale` и `pdf-export` (делается при синхронизации спек, не тестом).
