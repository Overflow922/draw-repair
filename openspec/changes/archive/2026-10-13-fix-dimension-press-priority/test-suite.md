# Test Suite

Все тесты — в `src/doorway/press-pick-communications.test.ts` (вместе с существующим `press-pick.test.ts`, который не менялся). Запуск: `npx vitest run src/doorway/press-pick-communications.test.ts`.

Контракт интерфейса, который задают тесты (design D1/D2 не фиксирует сигнатуру): `pressPick(p, scene, tolCm, textFactor, options, communications?)`, где `communications?: { items: readonly Communication[]; tolCm: number }` — коммуникации и допуск попадания по их телу; отсутствие аргумента = коммуникации не цель (планы «Демонтаж»/«Монтаж»). Цель-коммуникация — `{ kind: "communication", communication }`. Порядок: маркеры выделенной стены → размер → коммуникация → проём → стена. Существующие вызовы с пятью аргументами не меняются.

## Coverage

### Happy paths

- Размер поверх воздуховода и стояка выбирается как цель (DP-01, DP-02).
- Коммуникация без размера под указателем по-прежнему цель (DP-04, DP-06).

### Boundary cases

- Допуск размера внутри тела: на допуске — размер, на допуск + 0,5 см — воздуховод (DP-09).
- Допуск по телу коммуникации: воздуховод и стояк на допуске — цель, на допуск + 0,5 см — нет (DP-06); допуск по телу не равен радиусу привязки (DP-06b).

### Negative cases

- Без аргумента коммуникаций (планы «Демонтаж», «Монтаж») воздуховод не цель (DP-10).
- Опция `dimensions: false` (активен инструмент): размерная линия не цель, коммуникация — цель (DP-11).

### Invariants

- Размер в допуске всегда главнее коммуникации, в любом порядке списка (DP-12, DP-01, DP-02).
- Порядок целей: маркеры → размер → коммуникация → проём → стена (DP-07, DP-07b, DP-08, DP-08b).
- Ластик выбирает размер раньше всего (DP-05).

### Integration cases

- Комната `sceneR` с размером между внутренними углами и воздуховодом/стояком под линией размера: нажатие на линию и на тело в стороне в одной сцене (DP-01 + DP-04).
- Проём, размер и коммуникация в одной сцене (DP-08, DP-07).

## Unexpected Passes

Новые тесты, прошедшие до реализации (все — регрессионные защиты, они проверяют поведение, которое не должно измениться, и поэтому проходят на текущем коде):

- DP-05: `erasePick` уже ставит размер раньше всего.
- DP-06b: до реализации цели нет, потому что `pressPick` не знает коммуникаций; после реализации тест защищает отдельный допуск по телу.
- DP-07, DP-07b: маркеры выделенной стены уже главнее остального.
- DP-08b, DP-10: поведение без коммуникаций не менялось.
- DP-12 был таким же, но усилен: добавлена проверка выбора коммуникации без размера, теперь он падает до реализации.

Продакшн-код не менялся.

## Tests That Could Not Run

- Диспетчеризация в обработчике `pointerdown` в `src/main.ts` (вызов `communicationTool.pressBody` для цели-коммуникации; перетаскивание размера над воздуховодом меняет только вынос, DP-03): `main.ts` не импортируется в тестах, модульного теста нет. Проверяется вручную в браузере при apply; порядок целей, определяющий результат, покрыт тестами `pressPick`.
- Выбор ластика между размером и коммуникацией в `main.ts` (~817) — та же причина; чистая часть (`erasePick`) покрыта DP-05.
- Типизация: тесты вызывают `pressPick` с шестым аргументом, которого пока нет в сигнатуре, поэтому `tsc` до реализации сообщит ошибку в этом тестовом файле. Это ожидаемо.
