## Context

Мотивация — в `proposal.md`. Сейчас `item-tool.ts` ставит и двигает предмет без привязок: `place(p)` берёт точку клика, `dragTo(p)` сдвигает захваченную группу на вектор указателя, `ghost()` строит призрак в точке наведения. Образец подсказки уже есть у батареи: `centerSnapRadiusCm(zoom)` (`wall-snap.ts`), `TrackLine` (`battery/battery-guide.ts`), `drawTracks` в `render.ts` и канал `tracks` в `RenderOptions`, который `main.ts` собирает в `centerGuideTracks()`.

Подложка плана «Мебель» — `furnitureScene(drawing).base`: `underlay` (стены обмера и «Монтажа» после сноса) и `own` (стены гипсокартона).

## Goals / Non-Goals

**Goals:** прилипание центра предмета к линиям центра стены и центра другого предмета при постановке и перетаскивании; пунктирная риска-подсказка.

**Non-Goals:** привязка к граням, равные промежутки, линии вдоль повёрнутых осей предмета, отключение клавишей, привязка при стрелках и вводе чисел, хранение связи.

## Decisions

### D1. Чистая функция привязки в домене мебели

Новый модуль `src/furniture/center-snap.ts`, без DOM и состояния:

```
snapCenter(center, sources, radiusCm) -> { center, hits }
  Line   = { origin: Point, dir: Point }   // прямая, dir — единичный вектор
  Source = { line: Line, anchor: Point }   // anchor — середина стены / центр предмета
```

Алгоритм: расстояние от центра до каждой линии → ближайшая в радиусе → проекция центра на неё → среди непараллельных линий искать вторую в радиусе уже от проекции → если есть, точка пересечения. `hits` — линии, к которым центр прилип (для рисок). Если нет линий в радиусе, возвращается исходный центр и пустой `hits`.

Источники строятся отдельной функцией `centerSources(sides, items, excludedIds)` (стороны помещения — D4): для каждой стороны — линия через её середину перпендикулярно ей; для каждого предмета вне `excludedIds` — две оси мира (горизонтальная и вертикальная). Параллельные линии из разных источников не сливаются: прилипание идёт к ближайшей.

Почему так: один универсальный механизм «линия + радиус» покрывает и наклонные стены, и оси предметов, без разветвления по видам источников.

### D2. Куда встраивается

`ItemToolHost` получает `walls()` (стены подложки) и `pxPerCm()` (px на см с учётом зума); реализует их `main.ts`. Инструмент сам строит источники через `centerSources` (предметы он знает) и считает радиус как `FURNITURE_SNAP_RADIUS_PX / pxPerCm()` (17,5 px — вдвое меньше `CENTER_SNAP_RADIUS_PX` батареи, который остаётся прежним). Вызовы:

- `ghost()`: центр призрака = `snapCenter(hover, …).center`;
- `place(p)`: тот же центр, что у призрака (клик ставит туда, где стоит призрак);
- `dragTo(p)`: вычисляется сдвиг захваченного предмета с привязкой, остальные выделенные получают тот же вектор (`shiftItems`). Исключаются из источников все выделенные.

Положение захваченного предмета берётся как `base`-центр + сдвиг указателя; снэп применяется к этому центру, итоговый вектор = снэпнутый центр − `base`-центр.

Почему вектор, а не центр каждого: группа сохраняет взаимное расположение (спека «Группа не липнет к своим членам»).

### D3. Риска

`ItemTool` получает `guides(): TrackLine[]`, пока идёт постановка (есть призрак) или перетаскивание; для каждой линии из `hits`: отрезок от `anchor` до центра предмета с выступом `CENTER_GUIDE_OVERSHOOT_PX` (6 px, делится на `k` в мировые см) в обе стороны. `main.ts: centerGuideTracks()` объединяет риску батареи и риски мебели. Рендер не меняется: тот же `drawTracks`. Риска не попадает в `Drawing`, историю и PDF, так как живёт только в состоянии инструмента.

### D4. Стороны помещения вместо стен

Линии центра стены строятся не по осям стен, а по сторонам помещения, в котором стоит предмет (решение пользователя: «стены комнаты, в которой стоит фурнитура»; середина длинной стены может лежать в соседнем помещении).

Новый модуль `src/furniture/room-sides.ts`: `roomSidesAt(walls, p): Side[]`, где `Side = { a: Point, b: Point }`.

- Помещения — `findRooms(walls)` (`room-area.ts`, кэш по значениям стен) от стен плана «Мебель» (`base.underlay` + `base.own`, то есть `walls` в `main.ts`).
- Помещение точки `p` — самое внутреннее, чей `outline` содержит `p` и ни один из `holes` не содержит (`pointInPolygon` из `wall-geometry`). Нет такого — пустой список.
- Стороны — рёбра `outline` и всех `holes` этого помещения после слияния коллинеарных соседних рёбер, длиной не менее `MIN_SIDE_CM = 30` (отсекает уступы на стыках стен разной толщины).
- `centerSources(sides, items, excludedIds)`: середина стороны, перпендикуляр к ней.

Помещение определяется по точке указателя до прилипания; прилипание не перекидывает предмет в другое помещение, поскольку линии лежат внутри своего.

## Risks / Trade-offs

- **Много линий** (много стен и предметов): перебор линейный, сотни линий на кадр наведения — несущественно; индексов не вводим.
- **Прилипание мешает точной постановке рядом с линией:** выход — отвести указатель за радиус 17,5 px; точная правка — стрелками и полями панели (они не липнут).
- **Центровка по стене и «касание» разные вещи:** прилипание касается только центра; грани не выравниваются (в `TODO.md`).
- **Поворот предмета:** линии предмета — оси мира; для предмета под 45° «напротив» понимается по центрам, а не по его осям.
