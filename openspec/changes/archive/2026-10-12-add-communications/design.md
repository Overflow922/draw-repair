## Context

- Проёмы, окна и двери — `WallElement`, опорная стена и расстояния вдоль грани (`src/doorway/`). Защита от нарушений при правке стен — `doorwayGuard` (`src/doorway/doorway-guard.ts`): интерфейс `holds(positions)` подключён в `limit(...)` правок `src/wall-edit.ts` (`EditMode.doorways`), в `thicknessAllowed` (`main.ts`), в фильтр привязки `wall-snap.ts`, в `wall-merge.ts` и `auto-dimensions.ts` через `violatesDoorways`.
- `Wall` проверяется на пересечение тел в `src/wall-collision.ts` (прямоугольник вдоль оси, допуск `RECOGNITION_DEPTH_CM = 0.01`). Рисование стен ограничением коллизий не охвачено (`wall-collision`: «Рисование не ограничивается»).
- `Drawing` хранит содержимое плана `measure` в `walls`, `dimensions`, `doorways`; `mounting` и `demolition` — отдельные поля. История — по планам (`planHistory`), снимок — `Scene` (`src/history.ts`). Набор инструментов плана — `PLAN_TOOLS` (`src/plans.ts`), тип `Tool` — `src/doorway/openings-group.ts`.
- Группа «Проёмы» (`openings-group.ts`, `index.html`, `main.ts`) — образец группы кнопок; числа на холсте правятся через `editable-numbers.ts` и `openNumberEditor`.
- Поведение определено в `specs/communications` и дельтах существующих спецификаций; этот документ описывает только реализацию.

## Goals / Non-Goals

**Goals:**
- Модель, расчёт расстояний и инвариант коммуникаций — чистые функции без DOM, отдельный модуль.
- Единая проверка «тело стены не налагается на коммуникацию» для всех путей, где создаётся или меняется стена.
- Повторное использование образцов: группа кнопок, ввод чисел, призрак, история, подложка только для чтения.

**Non-Goals:**
- Поворот воздуховода; привязка размеров и линейки к граням коммуникаций; вычитание площади из помещений; подпись размера коммуникации в PDF; размещение и правка на планах «Демонтаж» и «Монтаж»; мультивыделение коммуникаций.

## Decisions

**D1. Модель.** В `types.ts` — `Riser` (`kind: "riser"`, `id`, `x`, `y`, `diameterCm`) и `Duct` (`kind: "duct"`, `id`, `x`, `y`, `widthCm`, `depthCm`), объединение `Communication`. Поле `Drawing.communications?: Communication[]` (необязательное, не дописывается при загрузке, версия документа 3 прежняя). Всё прочее — в новом каталоге `src/communications/`.
Альтернатива — хранить коммуникации внутри `Scene` плана `measure` и внутри `walls`: отвергнута, потому что объект общий для всех планов и не относится ни к одному плану.

**D2. Тело и пересечения.** Тело стояка — круг, тело воздуховода — прямоугольник по осям. Проверки: круг–прямоугольник стены (повёрнутый), прямоугольник–прямоугольник, круг–круг, круг–прямоугольник воздуховода. Глубина наложения (мера «нарушения») определяется как наибольшая глубина проникновения; допуск 0,01 см общий с `RECOGNITION_DEPTH_CM`. Это функция `overlapDepth(a, b)`, на ней строятся и инвариант, и «нарушение не растёт» для загруженных документов.

**D3. Расстояние до ближайшей стены.** `slideDistance(c, dir, walls)` — максимальный сдвиг тела вдоль оси `dir`, при котором нет наложения: для каждой стены вычисляется расстояние сдвига до касания (аналитически для прямоугольник–прямоугольник; для круга — минимум по контактам с гранью и с углом прямоугольника), берётся минимум, `null` если препятствий нет. Расстояние влево и вправо — по оси X, вверх (к меньшему `y` на экране) и вниз — по оси Y. Стены с телом, уже наложенным на коммуникацию (нарушение из документа), в расчёт идут с расстоянием 0.
Размерная линия рисуется по точке первого касания: функция возвращает `{distance, contact: Point}`.

**D4. Ограничение движения.** Единая функция `limitAlongSegment(from, to, valid)` ищет последнее допустимое положение на отрезке: проверка `valid` в конце, при нарушении — двоичный поиск по параметру с точностью 1e-4 см, затем при необходимости аналитическое уточнение по касанию (`slideDistance`). Используется для перетаскивания, ввода расстояния и для остановки свободного конца рисуемой стены. Для призрака — перебор сдвигов вдоль осей в четырёх сторонами на `slideDistance`-величины, выбирается наименьший допустимый (`ghostPosition`).

**D5. Ввод размера.** Диаметр, ширина, глубина: максимальный допустимый размер при фиксированном центре находится как «радиус/полуразмер до касания»: для стояка `r_max = min(по всем стенам и коммуникациям расстояние от центра до препятствия)`, для воздуховода — отдельно по каждой оси (`widthCm` — по X, `depthCm` — по Y) через `slideDistance` в направлениях ±X и ±Y: `maxWidth = 2·min(left + w/2, right + w/2)`, аналогично глубина.

**D6. Защита стен.** Новый `communicationGuard(walls, communications)` с тем же интерфейсом `holds(positions)`, что у `doorwayGuard`; подключается в `EditMode` (`communications?: readonly Communication[]`) и в `limit(...)` как ещё одно условие рядом с `doorways`. Правило «не хуже исходного»: нарушение после правки (максимум `overlapDepth` по коммуникациям, затронутым изменяемыми стенами) не превышает нарушения до правки и допуска. `thicknessAllowed`, фильтр привязки и `wall-merge` расширяются проверкой наложения коммуникаций на тело новой/изменённой стены. Общий вход для них — `violatesCommunications(before, after, communications)` по образцу `violatesDoorways`.
В отличие от `doorwayGuard` (его нарушение — «недопустимость без нормали», остановка без скольжения), охранник коммуникаций ДОЛЖЕН возвращать нормаль касания (ось и знак первого контакта по `slideReach`/`wallOverlapDepth`), чтобы `limit(...)` мог выполнить скольжение вдоль коммуникации, как требует спецификация `wall-collision` «Стены не налагаются на коммуникации». Поэтому интерфейс охранника расширяется: `check(positions)` → `Verdict` (`ok` / `{ok:false, normal}`), а `holds` остаётся обёрткой для мест, где нормаль не нужна (толщина, привязка, merge).
Альтернатива — встроить коммуникации в `collisionContext` как «стены»: отвергнута, у неё иные исключения (стыки и привязка к оси), а у коммуникаций исключений нет.

**D7. Рисование стены.** Начальный квадрат установки проверяется по `overlapDepth`; при наложении клик начала не фиксирует. Свободный конец проходит через `limitAlongSegment` по телу стены (прямоугольник вдоль оси шириной в толщину, от начала до конца); результат подставляется в предварительный сегмент и в клик. Нулевая длина — стена не ставится. Тело стены у стыков — по прямоугольнику вдоль оси (как в `wall-collision`), углы-блоки в проверке не участвуют; это совпадает со спецификацией.

**D8. План «Монтаж».** Собственные стены монтажа редактируются теми же функциями с набором `walls` = остатки + собственные; `communications` передаются в `EditMode` так же. Коммуникации в `mountingScene`, остатки и собственные объекты не входят.

**D9. Инструменты и интерфейс.** `Tool` получает значения `"riser"` и `"duct"`; `PLAN_TOOLS.measure` включает их (кнопка группы «Коммуникации» показывается по `toolsOf(plan)`); `mounting` и `demolition` не включают. Группа повторяет `openings-group.ts` (отдельный модуль `communications-group.ts`, не расширение `openings-group` — это другая семья). Иконка группы — в стиле остальных (вид сверху: окружность и прямоугольник с диагональю). Числа на холсте правятся через существующий `editable-numbers` и `openNumberEditor`: добавляются зоны (`distance` по направлению, `diameter`, `width`, `depth`) и применение через чистую функцию `applyCommunicationNumber(scene, id, zone, value) → {communications, applied}`.
Выделение: новый вид выбора в `pressPick` (`src/doorway/press-pick.ts`) с приоритетом после чисел и маркеров, до стен; на планах без инструментов коммуникаций выбор отключён по плану (`activePlan !== "measure"` → не участвует в `pressPick`, `hit` ластика и рамке).

**D10. Отображение.** Модуль `communications-render.ts` рисует контур цветом контура стен текущей палитры (`theme.ts`), без новых цветов палитры; на экране — после тел стен, до подписей элементов; в PDF — на каждой странице теми же функциями с контекстом jsPDF. Числа и размерные линии — только на экране (`drawCommunicationNumbers`), как размеры проёма. На плане «Демонтаж» рисуются поверх серой подложки обычным цветом. Габариты PDF (`wallsBBox` и аналоги страниц) учитывают коммуникации на каждой странице; экспорт остаётся недоступным без стен.

**D11. Хранение и история.** `storage.ts`: проверка элемента по одному, неверные отбрасываются, поле не создаётся при загрузке. `Scene` расширяется необязательным `communications`; отсутствие поля в записи истории при отмене и повторе оставляет список как есть. Операции коммуникаций пишут запись истории плана `measure` через `record`. Параметры новых коммуникаций — переменная сеанса в `main.ts` (по образцу `inherit` новых элементов), не в документе и не в истории.

**D12. Значения по умолчанию.** Стояк Ø 11 см, воздуховод 30 × 20 см — предположение (типичные размеры); правится спецификацией без изменений кода структуры.

## Risks / Trade-offs

- **Объём касания стен.** Ограничение должно сработать во всех путях правки стен (marker drag, group drag, arrows, ввод длины, толщина, merge, snap, рисование, монтаж). Риск пропустить путь: тесты по каждому пути из списка спецификации, а общая функция `violatesCommunications` используется во всех.
- **Круг и угол стены.** Сдвиг круга до касания с углом прямоугольника нетривиален; тесты на угловой контакт и на касание круга боком обязательны.
- **Скольжение.** Для коммуникаций (перетаскивание, ввод расстояния) скольжения вдоль препятствия нет — только остановка в касании; у стен правки сохраняют существующее скольжение.
- **Расстояния и проёмы.** Тело стены считается сплошным (проёмы не учитываются): расстояние до стены через проём «упирается» в тело. Решение принято в спецификации.
- **Подложка на планах.** Фильтр по плану должен стоять в `pressPick`, рамке, ластике и Delete; без DOM-стенда проверяется вручную (как для остальных проводок `main.ts`).
- **Производительность.** Расстояния пересчитываются при каждой отрисовке выделенной коммуникации по всем стенам: O(N) на объект; приемлемо.
- **Загруженные документы.** Наложение из документа допустимо, не углубляется (`overlapDepth` до/после).

## Migration / Compatibility

Миграции нет: новое поле необязательное, версия документа и документа истории не меняются. Старые документы открываются без коммуникаций; записи истории без поля коммуникаций не трогают список.
