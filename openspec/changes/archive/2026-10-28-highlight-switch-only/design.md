## Context

Подсветка связанных объектов считается чистой функцией `linkedObjects` (`src/switching/line-links.ts`); `main.ts` передаёт её результат в отрисовку (`linkedLightIds`, `linkedExhaustIds`, `linkedLineIds`, `linkedSwitchIds`). Мотивация — `proposal.md`, требования — дельта-спека `line-highlight`.

Сейчас для выделенного носителя функция возвращает остальные носители линии, их метки и выключатели. Нужны только выключатели.

```
 схематично, не в масштабе; выделен светильник [S] "L3"

 сейчас                                  после правки
   (+)L3 *   (+)L3 *   [S]L3               (+)L3     (+)L3     [S]L3
   (o)L3,L4 *  (o)L4                       (o)L3,L4 *  (o)L4
   * = подсвечено                          * = подсвечено (только выключатель)
```

## Goals / Non-Goals

**Goals:**
- Выделен носитель или метка: `carrierIds` и `lineIds` пусты, `switchIds` как сейчас.
- Выделен выключатель: результат не меняется.

**Non-Goals:**
- Отрисовка, `main.ts`, форма `LinkedObjects` не меняются: пустые множества уже означают «не подсвечивать».

## Decisions

**D1. Правка только в `linkedObjects`.** Для выбранного носителя или метки возвращать пустые `carrierIds` и `lineIds`; ветка выключателя остаётся прежней. Альтернатива — убрать поля `carrierIds`/`lineIds` из результата для этой ветки через новый тип: отвергнуто, форма результата и потребители остаются одни, а пустые множества дёшевы.

**D2. Выделенный носитель по-прежнему определяет набор имён по показанной метке.** Так выключатели ищутся тем же правилом «имя есть хотя бы в одной клавише», а неотображаемые метки не участвуют.

## Risks / Trade-offs

- [Существующие тесты закрепляют подсветку остальных светильников] → по правилу проекта тесты не подгоняются под код: они меняются по дельта-спеке в отдельной задаче, каждое изменение объясняется ссылкой на сценарий.
