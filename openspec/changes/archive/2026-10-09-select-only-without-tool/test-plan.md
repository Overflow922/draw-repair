# Test Plan

## Scope

Правила режима «выделение только без инструмента» (спецификации `canvas-app`, `wall-selection`, `dimension-selection`, `multi-selection`, `doorway`, `door`, `window`, `wall-drawing`, `ruler-tool`) на уровне чистого модуля `src/tool-mode.ts` (design D8): `selectionAllowed`, `escapeAction`, `afterPlace`. Обработчики DOM в `main.ts` юнит-тестами не покрываются; их проверяет ручная браузерная проверка по сценариям из раздела «Integration Cases» (память: browser-manual-checks).

Тесты описывают наблюдаемое поведение функций по сценариям спецификации, не реализацию. Существующие тесты change deselect-tool-on-element-select не меняются в рамках этого плана; те, что противоречат новым сценариям, перечислены в «Out of Scope» и идут через test-change-request.

## Boundary Cases

| Case | Input | Expected |
|---|---|---|
| TM-SEL-1 | `selectionAllowed(t)` для каждого из `wall`, `dimension`, `doorway`, `door`, `window`, `eraser`, `ruler` | `false` |
| TM-SEL-2 | `selectionAllowed("none")` | `true` |
| TM-ESC-1 | `escapeAction` при каждом активном инструменте (все 7), нет жеста, нет черновика, нет выделения | `deactivate-tool` |
| TM-ESC-2 | `escapeAction`: идёт жест стены (инструмент «Стена»); затем состояние после его отмены | `end-gesture`, затем `deactivate-tool` |
| TM-ESC-2b | `escapeAction`: есть черновик размера (инструмент «Размер»); затем без черновика | `cancel-dimension-draft`, затем `deactivate-tool` |
| TM-ESC-3 | Последовательность Esc → `selectionAllowed` на состоянии после `deactivate-tool` (инструмент = `none`) | `true` |
| TM-ESC-4 | `escapeAction` без инструмента, выделение есть | `clear-selection` |
| TM-ESC-4b | `escapeAction` без инструмента, ничего нет | `none` |
| TM-ESC-5 | `escapeAction` при инструменте группы «Проёмы» с открытой панелью (инструмент `door`) | `deactivate-tool` |
| TM-PLACE-1 | `afterPlace("doorway"/"door"/"window", group)` | `tool = "none"`, `group.panelOpen = false`, `group.active = "other"` |
| TM-PLACE-2 | `afterPlace` с `group.current = "door"` | `group.current` остаётся `"door"` (текущий инструмент группы сохраняется) |
| TM-PLACE-3 | `afterPlace("wall", group)`, `afterPlace("dimension", group)`, `afterPlace("eraser"|"ruler"|"none", group)` | состояние не меняется |

## Negative Cases

| Case | Expected behavior |
|---|---|
| Esc при активном инструменте и одновременно есть выделение (невозможное состояние, но защита) | `deactivate-tool` не должен теряться: приоритет — жест/черновик, затем снятие инструмента; выделение снимает `setTool` (проверяется как порядок приоритета) |
| Esc при активном инструменте «Стена» без жеста возвращает `none`, а не `clear-selection` | `deactivate-tool` (ловит старую реализацию, где «Стена» не снималась) |
| Установка элемента не должна менять выбор «Стена» | `afterPlace("wall", …)` = без изменений |
| `afterPlace` не должна открывать панель группы | `group.panelOpen = false` независимо от входа |

## Invariants

- `selectionAllowed(t)` истинно ровно для `"none"`: нет инструмента, кроме `none`, при котором выделение разрешено.
- `escapeAction` детерминирована и не зависит от порядка полей состояния; для каждого активного инструмента без незавершённых действий возвращает `deactivate-tool`.
- Два последовательных Esc из любого активного инструмента с одним незавершённым действием приводят к `none` (инструмента нет).
- `afterPlace` идемпотентна: повторное применение к результату не меняет его.
- `afterPlace` не меняет `group.current`.

## Integration Cases

Ручная проверка в браузере (dev-сервер на `/draw-repair/`, память browser-manual-checks) после реализации:
1. Инструмент «Стена» → клик по телу существующей стены → стена не выделена, панель стены закрыта; Esc → инструмент снят; клик по стене → выделена.
2. Инструмент «Линейка» → клик по стене и протягивание рамки → ничего не выделено, рамки нет; Esc → линейка снята.
3. Инструмент «Размер» → клик по размеру и перетаскивание размера → без выделения, вынос не меняется; Esc (дважды при начатом размещении).
4. Инструмент «Дверь» → клик по свободному месту стены → дверь поставлена и выделена, инструмент снят, панель группы закрыта; клик по числу ширины → поле ввода; клик в зону направления → направление изменилось одной записью истории.
5. Инструмент «Окно»/«Проём» → то же; клик по существующему элементу не выделяет.
6. Без инструмента: клик, рамка, перетаскивание маркеров и размера работают как раньше; Esc снимает выделение.
7. Комната, нарисованная стена за стеной (память check-multi-step-sequences): после рисования Esc, Esc → выделение работает, перемещение стен без побочных эффектов.

## Mutation Targets

- `selectionAllowed`: замена `=== "none"` на `!== "eraser"` или список «исключений» — TM-SEL-1 должен падать для каждого из 7 инструментов (каждый инструмент проверяется отдельно, не одним общим `every`).
- `escapeAction`: порядок приоритетов (жест → черновик → выделение → инструмент); отсутствие ветки для `wall` (старый баг) — TM-ESC-1 для всех инструментов по отдельности.
- `afterPlace`: потеря `group.current`, оставление `panelOpen = true`, изменение инструмента `wall`/`dimension`.

## Out of Scope

- Существующие тесты change deselect-tool-on-element-select (`src/doorway/element-select-tool.test.ts`, `src/doorway/popups-ui.test.ts`, часть `src/doorway/selection-editing.test.ts`), противоречащие новым сценариям: пересматриваются через test-change-request при реализации, не в этом плане.
- Геометрия стен, привязки, история, PDF — не затронуты.
