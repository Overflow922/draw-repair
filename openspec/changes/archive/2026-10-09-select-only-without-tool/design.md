## Context

Состояние «инструмент» и состояние «выделение» сейчас смешаны в `src/main.ts`:

- `pointerdown` (строки ~761–838): правка выделенного на месте (`selectionEditing.pressNumber/pressZone`, не для ластика), затем `pressPick` с флагами по инструменту (`middleMarker`, `dimensions`, `elements` включены почти во всех инструментах), затем перетаскивание маркеров, смещение размера, `pressDoorway`, `startGroupMove`, начало рамки (`marqueePending`).
- `click` (~946–991): выделяет стену/размер/элемент во всех инструментах, кроме ластика и «Размер»; в «Стена» тело стены выделяется через `wallClickAction`.
- Esc (~1455): цепочка → черновик размера → снятие выделения → снятие инструмента, но только для ластика, «Размер», «Линейка» и инструментов установки; «Стена» не снимается.
- `afterElementPress` (`src/doorway/openings-group.ts`) и `leavePlacing` (`main.ts`) выводят инструмент установки из режима после выделения элемента (change deselect-tool-on-element-select).

`setTool` уже снимает выделение и сбрасывает жесты при смене инструмента, поэтому выделение при активном инструменте возникает сегодня только из-за самих нажатий.

## Goals / Non-Goals

**Goals:**
- Одно правило: состояние «Без инструмента» (`tool === "none"`) — единственное, где нажатия и жесты выделяют и правят существующие объекты.
- Esc снимает любой активный инструмент, предварительно отменив незавершённое действие.
- Инструменты установки («Проём», «Дверь», «Окно») после установки одного элемента деактивируются, элемент остаётся выделенным.
- Удалить код, ставший недостижимым (`afterElementPress`, `leavePlacing`).

**Non-Goals:**
- Не менять действия самих инструментов (ластик удаляет, «Размер» ставит точки, «Стена» рисует, «Линейка» измеряет).
- Не менять правила привязки, геометрию, историю, хранение и PDF.
- Не добавлять новых кнопок и элементов интерфейса (правило `ui.md`): режим выделения — это существующее состояние «Без инструмента».

## Decisions

**D1. Один предикат вместо флагов по инструментам.** В `pointerdown` и `click` вводится единственная проверка «выделение допустимо» (`tool === "none"`), от неё зависят: правка на месте, `pressPick` с маркерами/размерами/элементами, перетаскивание, `pressDoorway`, начало рамки. Флаги `middleMarker`, `dimensions`, `elements` в `pressPick` для активного инструмента становятся ложными; ветка ластика остаётся как есть. Альтернатива — править каждый инструмент отдельно: отвергнута, правило тогда размазано и легко ломается при добавлении инструмента.

**D2. Установка элемента — единственный путь выделить при инструменте.** `ElementTool.place` уже выделяет поставленный элемент (`host.select`). Добавляется переход в `tool = "none"` сразу после установки: призрак сбрасывается, панель группы «Проёмы» закрывается, текущий инструмент группы сохраняется — ровно та же смена состояния, что делал `leavePlacing`, но без повторной установки выделения. Поэтому `leavePlacing` переиспользуется под этот переход (переименовывается по смыслу), а `afterElementPress` и его ветки в `pointerdown`/рамке удаляются.

**D3. Клик по существующему элементу при инструменте установки.** `hover` над существующим элементом даёт `ghost = null`, `place` без призрака вызывает `host.clearSelection()` — выделение не появляется. Дополнительной логики не требуется; поведение зафиксировано сценариями спецификации.

**D4. Инструмент «Стена».** Ветка выделения тела стены в `click` (`wallClickAction` → `select`) убирается; клик в тело стены ничего не делает (квадрат установки и так лежит снаружи тел). Выбор вершины/квадрата не меняется.

**D5. Esc.** Порядок: цепочка/жест → черновик размера → (без инструмента) снятие выделения → иначе `setTool("none")` для любого активного инструмента, включая «Стена». Ветка «снять выделение, не снимая инструмент» исчезает: при активном инструменте выделения нет. Условие `placingTool()` в списке снимаемых инструментов заменяется на `tool !== "none"`.

**D6. Рамка.** `marqueePending` ставится только при `tool === "none"`. Курсор и подсветка: никаких новых стилей.

**D7. Названия сценариев.** В delta-спецификациях `door`, `window`, `wall-drawing` три сценария сохраняют прежние названия («Клик по окну в инструменте «Дверь» выделяет окно» и т.п.), хотя поведение обратное: проверка `openspec validate` требует сохранять названия сценариев изменяемого требования. Переименование — отдельная правка (в TODO.md).

**D8. Чистый модуль правил (тестируемость).** Обработчики `main.ts` не покрыты юнит-тестами, поэтому правила выносятся в чистый модуль `src/tool-mode.ts` (без DOM), по образцу `src/doorway/openings-group.ts`:
- `selectionAllowed(tool: Tool): boolean` — `true` только для `"none"` (D1);
- `escapeAction(state: EscapeState): EscapeAction` — дискриминированный union `"end-gesture" | "cancel-dimension-draft" | "clear-selection" | "deactivate-tool" | "none"` по состоянию (идёт жест стены, есть черновик размера, есть выделение, активный инструмент) (D5);
- `afterPlace(tool: Tool, group: GroupState): { tool: Tool; group: GroupState }` — переход после установки элемента (D2; заменяет `afterElementPress`).
`main.ts` только вызывает эти функции и применяет результат. Тип `Tool` и `GroupState` остаются в `openings-group.ts` (импортируются).

## Risks / Trade-offs

- **Эргономика**: чтобы поправить стену во время рисования, нужен Esc. Это сознательное решение пользователя (explore-сессия).
- **Устаревшие тесты**: тесты change deselect-tool-on-element-select (`src/doorway/element-select-tool.test.ts`, `popups-ui.test.ts`, часть `selection-editing.test.ts`) описывают снятое поведение и подлежат пересмотру через test-change-request; тесты Esc/выделения в других модулях проверить против новых сценариев.
- **Частичная проверка в тестах**: логика в `main.ts` (DOM-обработчики) слабо покрыта юнит-тестами; для условий «tool !== none» нужны либо выделенные чистые функции (предикат допустимости выделения, переход Esc), либо e2e по существующим test-utils. Решает test-plan.
- **Совместимость**: сохранённые чертежи не затрагиваются — изменение только в обработке ввода.
