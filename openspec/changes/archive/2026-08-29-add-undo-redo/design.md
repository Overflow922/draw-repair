## Context

Vanilla-TS + Vite приложение: все мутации стен происходят в `src/main.ts` напрямую (`walls.push`, `moveWall`/`moveEndpoint`, правки полей выделенной стены), автосохранение по флагу `dirty` пишет весь `DrawingStore` в localStorage (`src/storage.ts`, ключ `draw-repair:drawing`). `moveWall`/`moveEndpoint` смещают также примкнутые стены — сопряжения по общим точкам. `selectedWall`, `wallMove`, `endpointDrag`, `chainStart` держат ссылки на объекты внутри `walls`. Размеры: стена в JSON ≈ 81 байт, снимок 100 стен ≈ 8,3 КБ, квота localStorage ≈ 5 МБ.

## Goals / Non-Goals

**Goals:**
- Полный откат любого действия над стенами, включая сопряжённую геометрию.
- Переживание перезагрузки страницы; возврат закрытых чертежей.
- Строго per-чертёжные истории: undo на одной вкладке никогда не трогает другую.

**Non-Goals:**
- Undo для зума/панорамирования, переименования, создания чертежа.
- Дерево версий (ветвящиеся futures).
- Коалирование ввода полей в один шаг.

## Decisions

### Снимки стен вместо обратимых команд
Каждая запись истории — глубокий снимок массива `Wall[]` на момент ДО действия. Альтернатива (команда + обратная операция) отклонена: `moveWall`/`moveEndpoint` тянут сопряжённые стены, и обратная операция обязана запоминать весь затронутый набор — это по сложности сравнимо со снимком, но легко ошибиться. Снимок честно фиксирует всю связанную геометрию и стоит копейки.

Модель стека — стандартная двухстековая:

```
past: [W0, W1, W2]   walls: W3   future: []
undo:  past.pop -> walls, walls -> future
redo:  future.pop -> walls, walls -> past
новое действие: past.push(walls), future = []
```

### Per-чертёжные истории + корзина (решение пользователя)
Истории в разрезе чертежей убирают весь класс кросс-вкладочных проблем: undo всегда применяется к активному чертежу, никаких «перелётов» между вкладками. Отклонённая альтернатива — один глобальный стек: он единственный давал достижимую отмену закрытия, но требовал UX «undo переключает вкладку».

Закрытие без отдельной «мусорки»: чертёж вместе со своей историей уезжает в `trash`, а запись о закрытии кладётся в историю чертежа, активного сразу после закрытия (покрывает и закрытие активной, и фоновой вкладки одним правилом). Undo записи достаёт чертёж из корзины, вставляет на исходный индекс и активирует его.

Ограничение принято осознанно: redo повторного закрытия достижим только из стека-наблюдателя — после возврата чертежа и активации на нём кнопка «Повторить» управляет уже его собственной историей.

### Формат хранения
Новый ключ `draw-repair:history` рядом с `draw-repair:drawing`:

```
{ version: 1,
  histories: { [drawingId]: { past: Wall[][], future: Wall[][] } },
  trash: [ { index: number, drawing: Drawing } ] }
```

Конверт `DrawingStore` не меняется: история — расходный кеш, её порча или отсутствие не должна затрагивать чертежи. Валидация по тем же правилам, что в `storage.ts`: битый JSON или чужая структура → пустые истории; версия новее поддерживаемой → работаем без истории и не перезаписываем документ (reuse флага readOnly-режима).

### Границы шагов
- Драг стены/конца: снимок на `pointerdown`, одна запись на `pointerup`, только если стены изменились (сотни `pointermove` = один шаг).
- Клик цепочки: один клик, добавивший стену = один шаг.
- Поля (толщина, длина, тип): каждое фактическое изменение значения = один шаг, без коалирования — решено с пользователем («важен сам факт изменения»).
- Зум/пан, «+», переименование: не пишутся.

### Интеграция в main.ts
- Восстановление снимка подменяет `drawing.walls` целиком → после undo/redo сбрасывать `selectedWall`, `chainStart`, активные жесты (тот же ресинк, что в `activate()`).
- Undo/redo игнорируются во время активного жеста (`wallMove`/`endpointDrag`/`panDrag`).
- Кнопки: disabled при пустых стеках; клавиши Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y.
- Сохранение истории — через существующий механизм `dirty` (один проход, два ключа).

### Кап и квота
50 шагов на чертёж, вытеснение старейших (FIFO). Худший случай — 10 вкладок по 100 стен с полными стеками ≈ 4,1 МБ, в пределах квоты. Запасная сетка — существующий try/catch вокруг записи в localStorage: при QuotaExceeded история просто не сохраняется (черты не страдают).

## Risks / Trade-offs

- [Тихая потеря истории при переполнении квоты] → приемлемо: кеш расходный, чертежи пишутся отдельно; кап 50 удерживает типичные объёмы далеко от лимита.
- [Redo повторного закрытия недостижим с восстановленного чертежа] → документированное ограничение; редкий сценарий.
- [Полная перезапись документа истории на каждый шаг] → объёмы малы (десятки–сотни КБ), сериализация на каждом шаге незаметна; при деградации — throttling через уже существующий dirty-цикл.
- [Вытеснение старейших шагов при 50+ действиях] → ожидаемое поведение, как в большинстве редакторов.

## Migration Plan

Миграции нет: ключ `draw-repair:history` на существующих установках отсутствует → истории стартуют пустыми, основной конверт не трогается. Откат изменения — удаление ключа.

## Open Questions

Нет — все развилки (per-чертёжные истории, корзина закрытых, гранулярность полей, кап 50) решены в исследовании.
