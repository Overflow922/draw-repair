## Context

Метка линии (`LightLine`: `id`, `targetId`, `name`) хранится в `current().switching.lines`; клавиша выключателя хранит
список имён (`LightSwitch.keys[].lines`). Связь только по имени (`light-switch` «Выключатель и клавиши»).
Светильник и вытяжка выделяются своими инструментами (`lightTool`, `exhaustTool`), метка — `lineTool`, выключатель —
`switchTool`; панель «Линия освещения» сейчас открывается только выделением метки (`linePanelOpen`, `syncLinePanel` в
`src/main.ts`). Рендер: `drawSwitchingScene` красит один выделенный id светильника (`selectedLightId`), вытяжки, метки и
выключателя. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**
- править линию выделенного светильника или вытяжки в уже существующей панели «Линия освещения»;
- подсвечивать объекты, связанные по имени с выделенным, без изменения данных.

**Non-Goals:**
- привязка кликом (выключатель → лампы), мультивыделение, подсветка в PDF;
- правка линий клавиш в панели (остаётся на месте на холсте);
- новый цвет подсветки и новые виджеты.

## Decisions

### D1. Связь вычисляется чистой функцией, ничего не хранится

`linkedObjects(selection, lines, switches, lights, exhausts)` в `src/switching/line-links.ts` возвращает
`{ carrierIds, lineIds, switchIds }` (наборы). Выделение — дискриминированный union
`{ kind: "switch" | "carrier" | "label"; id }`. Набор имён: для выключателя — объединение имён клавиш; для светильника,
вытяжки, метки — имя их показанной метки (через `visibleLines`, поэтому скрытые метки не участвуют). Функция вызывается
при каждой отрисовке из `main.ts`, как `visibleLines`; данных на планах не появляется.

Альтернатива — хранить связи в данных: отвергнута, связь по имени уже спецификация, второй источник правды ни к чему.

### D2. Подсветка тем же цветом выделения, набором id в рендере

В `CeilingView` добавляется необязательное `linkedLightIds?: ReadonlySet<string>`, в `SwitchingView` —
`linkedExhaustIds`, `linkedLineIds`, `linkedSwitchIds`. Светильники красятся тем же кольцом `palette.selection`, что и
выделенный; вытяжки, метки и выключатели — тем же `highlight` (`palette.selection`). Эрасер главнее (порядок проверки:
erasing → selected → linked). Новый цвет не вводится: палитра и PDF не меняются. Страница PDF поля не передаёт, поэтому
подсветки там нет.

Отличать связанные от выделенного можно только по тому, что выделенный один; при необходимости позже — отдельный цвет
(не сейчас).

### D3. Панель «Линия освещения» при выделении светильника или вытяжки

Выделение светильника/вытяжки (`lightTool.press`, `pressExhausts`) выставляет `linePanelOpen` и «носителя панели» —
id выделенного светильника или вытяжки; снятие выделения закрывает панель (в `resetLines` и местах снятия). `syncLinePanel`
показывает номер метки носителя (`visibleLines`), либо пустое поле. Обработчик `change` поля: если выделена метка —
прежнее поведение (`setSelectedName`); если выделен носитель — новый метод `lineTool.setLineOf(carrierId, n)`
(имя `L<n>`/`LV<n>` строится по виду носителя), внутри `setLine` (уже есть: ставит или меняет, возвращает тот же массив при совпадении имени → шага истории нет).
Префикс по виду носителя (`L`/`LV`) и датчик (`canCarryLine`) — те же правила, что у `place`. Значение
`lineNumberCurrent` (для новых меток) при этом не трогается.

Поле пустое у носителя без метки (а не со значением панели): иначе ввод «1» при показанной «1» не вызывает `change`
и метку `L1` нельзя поставить.

Альтернатива — класть метку при выделении автоматически: отвергнута, меняет данные без действия пользователя.

### D4. Где вычисляется выделение для подсветки

В `main.ts` рядом со сборкой `SwitchingView` (около `selectedLightId: hoveredLight ?? lightTool.selectedId()`)
выбирается единственное выделение: выключатель → метка → вытяжка → светильник (выделения взаимоисключающие по
существующим `reset*`). Hover инструмента «Линия освещения» подсветку связей НЕ включает: только выделение.

## Risks / Trade-offs

- [Панель одновременно служит двум режимам (метка и носитель)] → одно состояние «цель панели» (метка или носитель),
  не две отдельные переменные; покрыто тестами панели.
- [Кольцо на связанных светильниках неотличимо от выделенного] → выделенный один, остальные — связанные; при жалобах
  вводится второй оттенок отдельным change.
- [Пересчёт связей на каждой отрисовке] → линейный по числу объектов плана, как `visibleLines`; кэш не нужен.
