## Context

План «Потолки и освещение» (`src/ceiling/`) хранит натяжные потолки в `Drawing.ceiling: CeilingContent` (`ceilings`, выноски, примечания), строит сцену `ceilingScene` поверх `reconstructionScene` и рисует её `drawCeilingScene`. В проекте уже решены почти все части будущих объектов освещения:

- тела чистовых граней — `furnitureReachBodies(base)` (`src/furniture/item-wall-reach.ts`): стены подложки, «Монтажа», гипсокартон, действующая штукатурка как `Shape`-многоугольники; проём грань не прерывает;
- проход фигуры по направлению до касания — `sweep` / `penetration` (`src/communications/shape.ts`);
- числа на месте — `ItemNumber`, раскладка размерной линии `dimGeometry`, поле правки (`src/furniture/item-number*.ts`, `src/doorway/editable-numbers.ts`);
- группа инструментов с панелью кнопок — «Коммуникации» (`canvas-app` «Панель группы «Коммуникации»»);
- легенда PDF — `src/export/legend.ts`, `legend-draw.ts`.

Рисунок знаков — `references/lighting.png` (образец пользователя, условные обозначения листа освещения).

## Goals / Non-Goals

**Goals:**
- пять видов объектов освещения на плане «Потолки и освещение», их постановка, выделение, перемещение, удаление, история, хранение;
- постоянно видимые расстояния до чистовых граней на холсте и в PDF, правка на месте;
- записи легенды PDF.

**Non-Goals:**
- высота монтажа бра и другие атрибуты (мощность, группа, выключатели) — выноской;
- прореживание и цепочки размеров при сетке светильников;
- привязка бра к стене (бра не следует за сдвинутой стеной);
- смена вида у поставленного объекта (удалить и поставить заново).

## Decisions

### D1. Модель: дискриминированное объединение по виду

```ts
type CeilingPointKind = "spot" | "smoke-detector" | "chandelier" | "lighting-outlet"
type LightFixture =
  | { id: string; kind: CeilingPointKind; x: number; y: number }
  | { id: string; kind: "sconce"; x: number; y: number; angleDeg: number }
```

`CeilingContent` получает необязательное `lights?: LightFixture[]` (пустой список не пишется — старые документы байт в байт прежние). Бра хранит угол наружной нормали грани (направление дуги). Центр — целые сантиметры, как у коммуникаций; округление при постановке, перетаскивании и вводе.

Альтернатива — отдельное поле `Drawing.lighting`: отвергнута, объекты принадлежат плану `ceiling`, его история и хранение уже читают `CeilingContent`.

### D2. Расстояния — лучи по `furnitureReachBodies`

Новый чистый модуль `src/ceiling/light-reach.ts`. Для точки и направления `d` — ближайшее пересечение луча с гранями тел (многоугольники): параметр `t` первого входа луча в тело, тела, содержащие начальную точку, пропускаются (спека: «тело, внутри которого лежит центр, не учитывается»).

```
 точка освещения: 4 луча, по оси берётся меньший (равенство -> влево / вверх)

        ^ top
        |
 left <-*-> right        результат: { axis: "x", t, to } и { axis: "y", t, to }
        |
        v bottom

 бра: 2 луча вдоль грани, начало смещено на 0,1 см по нормали в помещение

   #################  <- тело стены, на грани которого стоит бра
   <------ /X\ ------>     (луч не задевает своё тело)
```

Можно было бы переиспользовать `itemWallReach` с вырожденным предметом 0 × 0, но у него семантика стороны и «полосы позади» — для точки это лишнее; луч проще и прямо выражает спеку. `sweep` для отрезка нулевой ширины тоже избыточен.

### D3. Прилипание бра

`snapSconce(cursor, bodies, maxCm)`: для каждого ребра каждого тела — ближайшая точка ребра к курсору; берётся ближайшая с расстоянием ≤ `40 px / k`, при условии что курсор вне всех тел. Нормаль — перпендикуляр ребра в сторону курсора; центр округляется до целого см вдоль ребра (проекция на ребро, затем округление координат). Ребро, лежащее внутри другого тела (стык стены и штукатурки), отбрасывается проверкой «середина отрезка от точки к курсору вне тел».

```
 вид сверху, схематично. Штукатурка P на грани стены W

   WWWWWWWWWWWWWWWW
   PPPPPPPPPPPPPPPP   <- граница W|P внутри: не кандидат
   ----------------   <- наружная грань P: бра прилипает сюда
          x  курсор
```

### D4. Знаки — постоянный размер

Отрисовка знака — функция `drawLightSymbol(ctx, fixture, px, palette)`, где `px` — пикселей (на холсте) или пунктов (в PDF) на «единицу знака»; размеры знаков заданы в миллиметрах на бумаге (3 / 5 / 8 / 2 / 2,5 мм…) и пересчитываются: на холсте `4 px/мм` (3 мм → 12 px, как в спеке), в PDF — 1 мм. Один рисунок на холст и PDF (как рисунки мебели через общий контекст). Геометрия бра в локальных осях (центр диаметра — начало, дуга в сторону +n): полукруг радиуса r = 2 мм; крест «X» — два отрезка, соединяющие точки дуги под 45° и 135° с точками диаметра на ±r/2, пересекающиеся на оси симметрии. Точная форма сверяется с `references/lighting.png` в браузере; тесты проверяют только размеры (ограничивающий прямоугольник) и направление дуги.

```
 бра в локальных осях, схематично, не в масштабе

        .-'''-.
      .' \   / '.        дуга радиуса r в сторону помещения (+n)
     /    \ /    \
    |      X      |
   -+-----/-\-----+-     диаметр на грани стены, центр = середина
         -r/2 +r/2
```

### D5. Числа — та же раскладка, что у мебели

Числа строятся как `ItemNumber` с новым `field: { kind: "light-distance", lightId, ray }` и `geom = dimGeometry(from, to, 0)`, текст `formatLength`. Ноль — число у центра без линии. На холсте рисуются для всех объектов (не только выделенного), подчёркивание и клик-правка — только у выделенного (у остальных клик выделяет). PDF рисует те же `geom` в мм тем же кодом, что размеры страницы.

Ввод: `target = from + d · value` (у бра — вдоль ребра); новый центр = старый + d · (value − t), округление; отказ, если центр внутри тела.

### D6. Слои и hit-test

Холст: … подписи потолков → размерные линии и числа освещения → знаки → выноски/примечания. Hit-test без инструмента: выноска → число освещения → знак (обратный порядок постановки) → подпись потолка. Ластик: выноска → знак → потолок; числа ластик игнорирует.

### D7. Инструмент и группа

Группа «Освещение» — копия механики группы «Коммуникации» (кнопка группы помнит вид, панель только с кнопками), но постановка инструмент не снимает (как «Натяжной потолок»). Призрак — тот же объект с расстояниями, рисуется полупрозрачно цветом призрака схемы.

### D8. Цвета

В палитру схем (`src/theme.ts`) — `lightingRed` (светлая `#e01b1b`, тёмная `#ff5c5c`) и `lightingOrange` (`#e8771e` обе); перекрестие люстры — `wall` (контуры). PDF берёт светлую палитру. Внутренняя окружность ДПС — цвет фона (на заливке потолка — фон бумаги, не смешанный; допустимо, знак маленький).

### D9. История и хранение

Снимок истории плана расширяется списком `lights`; запись без поля при отмене не трогает текущий список (как коммуникации). Валидация `lights` при загрузке — по одному, некорректные отбрасываются.

## Risks / Trade-offs

- [Нагромождение чисел при сетке светильников] → вне объёма; отмечено в Non-Goals, к обсуждению после первых чертежей.
- [Бра «повисает», если стену сдвинули на нижнем плане] → число бра считается от его сохранённого центра; пользователь перетаскивает бра заново. Автоследование — отдельное изменение.
- [Размерная линия проходит через знак другого светильника] → знаки рисуются поверх линий, знак читается; линия под ним не перечёркивает.
- [Луч ровно по ребру тела (касательная)] → касание без входа не считается пересечением; допуск 1e-6 см, как в `item-wall-reach.ts`.
- [Знак бра на наклонной стене] → поворот по `angleDeg`, проверяется сценарием прилипания к наклонной грани в тестах.

## Open Questions

Открытых вопросов, меняющих объём, нет. Высота монтажа бра отложена (Non-Goals): пока пишется выноской; хранить ли её числом у бра — решение для отдельного изменения.
