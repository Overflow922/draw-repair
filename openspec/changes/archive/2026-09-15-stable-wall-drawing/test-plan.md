# Test Plan: stable-wall-drawing

(Раунд 2 — переработан по итогам test-validation.md, VERDICT: FAIL от 2026-09-14.)

## Scope

Проверяется чистая геометрия инструмента «Стена» и отображения стыков через канонический API из `src/wall-geometry.ts` (design D1): `snapRadiusCm`, `snapVertex`, `displayPolygons`, `hitWall`. Рендер на Canvas и DOM-взаимодействие не тестируются юнит-тестами — проверяются их источники данных (позиции вершин, полигоны, попадание).

Слой UI (квадрат как рисуемый объект, подсветка, превью на холсте) покрыт косвенно: спецификационные сценарии о нём сводимы к проверке возвращаемых позиций и полигонов. Прямая пиксельная проверка — вне юнит-области (см. Out of Scope).

## Boundary Cases

| Case | Input | Expected |
|---|---|---|
| Курсор в 0.1 см внутри/снаружи радиуса грани | faceDist = R ± 0.1 | прилипает / сетка |
| Наклон 90.3° (внутри допуска 0.5°) | стык 90.3° | прямоугольная трактовка, габарит без вылета |
| Наклон 91° (за допуском) | стык 91° | косая трактовка: торец остаётся косым (вершина над гранью), НЕ срез заподлицо |
| Расстояние радиус+0.1 от всех стен | faceDist > radiusCm | источник — сетка |
| Сетка/стена одновременно в радиусе | курсор у грани и у узла | стена |
| Орто ровно 15° и за пределами | dy = tan(15°)·dx и +0.1 | притяжение («не более чем» — включительно) / свободно |
| |d| от оси ровно полутолщина в зоне конца | торец (продолжение); +0.001 за полосой — угол |
| Два кандидата на одном расстоянии | симметричные грани двух стен | стена раньше в массиве; реверс массива меняет выбор |
| Вырожденная стена (a == b) | wall с нулевой длиной | игнорируется, без ошибок |
| Толщины не равны у углового примыкания | сосед 40, новая 10 / 60 | вершина на полутолщине НОВОЙ стены от торца |

| Case | Expected behavior |
|---|---|
| hitWall вне всех полигонов | null |

## Invariants

- Чистота: `snapVertex` / `displayPolygons` / `hitWall` не меняют входной массив стен (INV-PURE-1, deep-freeze).
- Согласованность: для произвольной точки зоны стыка `hitWall(p, walls, tol)` возвращает стену w тогда и только тогда, когда p ∈ displayPolygons(w) и w — верхняя из накрытых (HIT-CONS-1, сеточная развёртка 150 точек).
- Габарит: на прямом угле ни одна точка полигонов стены не отстоит от её оси дальше полутолщины (JOINT-RIGHT-2/3); коллинеарное сведение зазора не выходит из полосы граней (JOINT-COLLIN-1).
- Ранняя стена неизменна: полигоны ранней стены идентичны её собственному прямоугольнику при любом соседе (JOINT-RIGHT-1, JOINT-LEGACY-1, JOINT-COLLIN-1, JOINT-OBLIQUE-2/4).
- Владелец зоны стыка = позиция в массиве: реверс массива меняет владельца и обрезку (JOINT-OBLIQUE-2/4).
- Детерминизм: одинаковые (курсор, сцена) → одинаковый результат (SNAP-DET-1/2).

## Integration Cases

- Превью и зафиксированная стена дают идентичные полигоны при одинаковой сцене — 3 сцены (перпендикулярное T, T 60°, угловое) (JOINT-PREVIEW-1).
- hitWall согласован с displayPolygons на плотной сетке точек вокруг стыка (HIT-CONS-1) — единственный источник формы (design D1).
- Радиус инструмента выводится только из `snapRadiusCm(zoom)` (SNAP-RADIUS-PX-1) — main.ts не вычисляет радиус сам.

## Mutation Targets

- Порядок параметров `snapVertex` (радиус/сетка/толщина) — SNAP-GRID-1 даёт характерный сдвиг.
- Знак/направление нормали при прилипании к грани — SNAP-FACE-1 (обе стороны).
- Радиус привязки: в обе стороны для грани (SNAP-RADIUS-1: 5/7 см, SNAP-FACE-2: R±0.1); для торца/продолжения — SNAP-END-2/CONT-1 (ломаются при радиусе < ~3).
- Допуск прямого угла: верхняя сторона — защищена (JOINT-91-1: при допуске ≥1° стык 91° трактуется как прямой, торец срезается заподлицо, вершины над гранью в зоне стыка исчезают — тест проваливается); нижняя сторона юнит-невыразима: при 90.3° области «клин» и «срез по грани» совпадают, различие только в линии шва (render-уровень, см. Out of Scope). Точное значение 0.5° внутри допустимого интервала тестами не фиксируется.
- Порог вершины стыка (полунаибольшая толщина): JOINT-MULTI-1 и SNAP-END-3 по разные стороны порога.
- Приоритет «поздней» стены: JOINT-OBLIQUE-2/4 — реверс массива меняет владельца и обрезку.
- Приоритеты привязки: SNAP-PRIO-1 (стена против сетки: (49,10) vs (50,10)) и SNAP-PRIO-2 (стена против орто+сетка: (49,10) vs (50,0)) — точки результатов различны.
- Гриддинг после орто: SNAP-ORTHO-FIXED-1 убивает мутанта «гридить обе координаты» (дефект нынешнего snap()).
- Границы 15° (включительно) и |d| = полутолщина: SNAP-ORTHO-5, SNAP-END-3.

Мутационное тестирование инструментом не выполняется: в проекте нет mutation-тулинга (только vitest/tsc). Роли играет сеточная развёртка HIT-CONS-1 (150 точек) и пары граничных сценариев.

## Out of Scope

- Пиксельный рендер Canvas: штриховка/фаза линий, толщина контура и **линия шва** (подавление ребра контура у однотипных стен, отображение у разнотипных — сценарии «Разные типы — прямой шов»/«Один тип — непрерывный контур»/«Материал клина»). Геометрия полигонов одинакова для обеих трактовок шва — различие только в рисуемых линиях; защищается код-ревью реализации на этапе apply/verify (render.ts потребляет displayPolygons).
- **Вызов снаппера в main.ts** (`updateWallCursor`): тесты фиксируют контракт `snapVertex` + `snapRadiusCm`, но не могут доказать, что main.ts вызывает их с орто-флагом и радиусом из `snapRadiusCm` для обеих вершин цепочки. Компенсация: тест-файл — контракт; разводка проверяется на этапе verify-change (ручной сценарий) и код-ревью. Осознанное ограничение юнит-области.
- **Комбинация с точной длиной** (поле длины → строго осевой сегмент): ввод длины живёт в main.ts; направление зафиксировано SNAP-ORTHO-*, длина — существующими тестами resizeSelected.
- Перемещение стен и групп (`moveEndpoint`/`moveWall`/`moveWalls`) — покрыты существующими тестами `geometry.test.ts`, семантика не меняется.
- Существующие тесты `geometry.test.ts` не изменяются; их совместимость с новым `hitWall` защищена HIT-BAND-1.
