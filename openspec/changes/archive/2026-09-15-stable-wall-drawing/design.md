# Design: stable-wall-drawing

## Context

Сегодня форма стены вычисляется тремя независимыми путями: заливка/штриховка — `wallDisplayPolys` (клип выпуклых кусков), контур — `wallShape` + `subtractCovered` (полный прямоугольник с параметрически скрытыми участками), попадание — `hitWall` (своя логика полосы и покрытия). Классификатор стыка `jointAt` при 2+ соседях в вершине возвращает `null` — стык исчезает. Радиус прилипания квадрата в инструменте «Стена» равен полтолщины (`findVertexSnap(p, walls, thicknessCm/2)`), орто-привязка к цепочке не применяется (мёртвая ветка + неиспользуемая `snapVertex`), вторая вершина цепочки не прилипает к сетке.

Ограничения: модель данных (`Wall` — ось + толщина + материал, порядок в массиве), формат хранения, история (undo/redo) и легаси-чертежи не меняются. По правилам проекта реализация адаптируется к утверждённым тестам, а не наоборот. Стек без библиотек: Canvas 2D + чистые функции.

## Goals / Non-Goals

**Goals:**

- Один канонический расчёт отображаемой формы стены — единственный источник для заливки, штриховки, контура, подсветки, попадания курсора и превью.
- Единый детерминированный снаппер инструмента «Стена» (радиус 12 экранных px, приоритет стены → орто → сетка).
- Тотальная классификация стыков: классификатор не имеет «отказа»; допуск прямого угла 0.5°; 2+ соседа в вершине → плоские торцы.
- Действующая орто-привязка в цепочке с сеткой поверх неё.

**Non-Goals:**

- Изменение модели данных, формата хранения, undo/redo, легаси-миграция.
- Семантика перетаскивания концов, группового перемещения, выделения рамкой (кроме как потребителей попадания по канонической форме).
- Гистерезис/дебаунс привязки.
- Инструмент «Размер» (кроме потребления общей геометрии граней, если потребуется).

## Decisions

### D1. Канонический модуль `src/wall-geometry.ts`

Вся логика формы и привязки стен собирается в один модуль; `geometry.ts` сохраняет то, что не относится к форме стен (вид, размеры, перемещение), либо поглощается. Публичные обязанности:

```
snapVertex(p, walls, radiusCm, gridStepCm, newWallThicknessCm, orthoFrom?) -> { point, source: 'wall' | 'grid' }
    единый классификатор: грань/торец/продолжение > орто-ось > узел сетки;
    детерминированно: ближайший кандидат, при равенстве — меньший индекс в массиве.
    Толщина новой стены нужна для прилипания к торцу: вершина ставится на
    полутолщину НОВОЙ стены от плоскости торца (наружные грани совмещены
    заподлицо при любой паре толщин — квадрат = толщина из панели);
    прилипание к грани: вершина на грани, независимо от толщин.

snapRadiusCm(zoom) -> number
    единственная точка вывода радиуса: SNAP_RADIUS_PX / (PX_PER_CM * zoom);
    main.ts радиус не вычисляет сам.

displayPolygons(wall, walls) -> Polygon[]
    каноническая форма: на каждый конец — классификация соседей;
    прямой угол (<= 0.5°) / коллинеарность -> прямоугольный контакт,
    иначе -> клин поздней стены; 2+ соседа в пороге -> плоский торец

hitWall(p, walls, toleranceCm) -> Wall | null
    попадание по displayPolygons (позже в массиве — выше), полосный
    допуск оси сохраняется для совместимости с wall-selection
```

Потребители: `render.ts` (заливка/штриховка — клип по полигонам; контур — рёбра тех же полигонов с подавлением шва однотипных; подсветка — заливка тех же полигонов), `main.ts` (`updateWallCursor`, `commitPoint`, ластик, выделение), превью цепочки (тот же `displayPolygons` для временной стены, добавленной последней).

Альтернатива, которую отклонили: оставить три расчёта и синхронизировать их константами — именно это пять раз ломалось в истории коммитов.

### D2. Классификация стыков тотальна

На каждый конец стены собираются все соседи в пороге вершины (полунаибольшая толщина, как сейчас): 0 соседей → свободный плоский торец; 1 → угловой/T-стык; 2+ → плоский торец (требование «Особые конфигурации вершин»). Случай «нет классификации» исчезает как класс ошибок.

### D3. Классификация угла константой

Угол между осями: |Δ| от 90° ≤ 0.5° → перпендикуляр; |Δ| от 0°/180° ≤ 0.5° → коллинеарность; иначе косой стык (клин). Константа `RIGHT_ANGLE_TOL_DEG = 0.5` в одном месте модуля.

### D4. Радиус привязки — экранные пиксели

`SNAP_RADIUS_PX = 12` пересчитывается в мировые единицы чистой функцией `snapRadiusCm(zoom)` — единственной точкой вывода радиуса; используется и для прилипания квадрата, и для сетки; внутренние пороги от полутолщины (условия `2*hCm`, `sC`-клампы в `findVertexSnap`) убираются. Ничто в привязке не читает толщину стены, кроме самой геометрии грани/торца и параметра толщины новой стены в `snapVertex` (для заподлицо у торца).

### D5. Точка применения орто

Орто применяется в снаппере `snapVertex` для каждой вершины цепочки, когда не сработала привязка к стене: направление притягивается к оси (15°), затем подвижная координата — к сетке. Точная длина в поле применяется вдоль итогового направления (блокировка стеной → орто → свободное). Превью строится из тех же вычислений, поэтому вид до клика = результат клика.

### D6. Порядок стен как приоритет

«Поздняя» стена = больший индекс в `walls` на момент отрисовки; превью добавляется последним. Клин принадлежит поздней стене, ранняя остаётся нетронутым прямоугольником. Это фиксирует уже существующую семантику, теперь явно и в одном месте.

## Data Flow

```
walls[], preview? ──> snapVertex ──> позиции вершин/квадрата (main.ts)
   │
   └──> displayPolygons(wall, walls) ──> render: fill/hatch/contour/highlight
                             └────────> hitWall: ластик, выделение
```

Один вызов на стену за кадр; сложность O(стен²) в худшем случае — на практике десятки стен, сопоставимо с текущим кодом.

## Risks / Trade-offs

- **Существующие тесты.** `geometry.test.ts` кодирует нынешнее поведение `snap`/перемещения. Если замороженные новые тесты конфликтуют со старыми (например, по радиусу привязки), конфликт решается через test-change-request — старые тесты не ослабляются молча.
- **Производительность.** Пересчёт полигонов на каждый кадр для всех стен; при росте чертежей добавляется мемоизация по (концы, толщины, порядок) — сейчас не нужна.
- **Плавающая точка на допуске 0.5°.** Стены, уложенные прилипанием под «ровно 90°», могут отличаться на ~1e-12°; сравнение углов делаем через разность направлений с запасом EPS, классификация монотонна по углу.
- **Легаси-чертежи.** Оси, сходящиеся в общей вершине, классифицируются порогом полутолщины как и сейчас — требование «данные не мигрируют» сохраняется; канонический пайплайн обязан обрабатывать пересекающиеся оси без общей вершины (уже записано в спеке).

## Migration

Миграция данных не требуется. Изменяется только вычисление отображения и привязки; сохранённые файлы, история и легаси-чертежи читаются как есть.
