# Test Plan

## Scope

Проверяется наблюдаемое поведение из спек change `add-callout` (`callout`, `canvas-app`, `drawing-plans`, `drawing-storage`, `drawing-history`, `demolition-plan`, `mounting-plan`, `pdf-export`). Тесты — `vitest run` без DOM (окружение `node`, как у остальных тестов проекта): чистые функции, записывающий контекст канваса (`recorder` из `src/doorway/doorway.test-utils.ts`), сериализация хранилища и истории, сборка страниц PDF, чтение `index.html`. Тесты не знают о внутреннем устройстве (D1–D11 design), только о входах и результатах из раздела «Контракт для тестов».

Файлы (ID вида `C-<область>-<n>`), каталог `src/callout/`:
- `callout-store.test.ts` — STORE: списки выносок по планам.
- `callout-text.test.ts` — TXT: нормализация введённого текста.
- `callout-actions.test.ts` — ACT: создание, правка, удаление, перенос точки (чистые операции над списком).
- `callout-layout.test.ts` — LAY: выравнивание, раскладка строк, линия, стрелка.
- `callout-pick.test.ts` — PICK: попадание курсора (выделение, ластик).
- `callout-render.test.ts` — RND: отрисовка на холсте, зум, выделение, подсветка ластика, «Демонтаж».
- `callout-tool.test.ts` — TOOL: наборы инструментов, Esc, режим выделения, кнопка в `index.html`.
- `callout-storage.test.ts` — STO: документ; `callout-history.test.ts` — HIS: история.
- `callout-pdf.test.ts` — PDF: страницы, границы, отрисовка без служебных элементов.
- `callout-plans.test.ts` — PLN: независимость планов (сквозной сценарий через store/actions/history/storage).
- `callout.test-utils.ts` — сцены и конструкторы (`callout(id, target, at, text)`, фиксированный измеритель `measure = (line) => line.length * 7`).

Не покрыто тестами (нет DOM-окружения, фиксируется в `TODO.md` при завершении change): `openTextEditor` (`textarea`, клавиши, blur), проводка событий в `src/main.ts` (клики, Esc, перетаскивание, переключение плана), реальная ширина текста `ctx.measureText`.

## Контракт для тестов

Тесты вызывают только перечисленные ниже публичные функции и поля; реализация обязана их предоставить (это уточнение design D1–D11, не изменение поведения). Подписи — для типов; поля, не названные здесь, тесты не читают.

- `src/types.ts`: `Callout { id: string; target: Point; at: Point; text: string }`; `Drawing.callouts?: Callout[]` (обмер), `MountingContent.callouts?: Callout[]`, `Drawing.demolitionCallouts?: Callout[]`.
- `src/callout/callout-store.ts`: `calloutsOf(drawing, plan): Callout[]` — `[]`, если списка нет; `withCallouts(drawing, plan, list): Drawing` — новый чертёж, исходный не изменён, списки других планов и прочие поля не затронуты; для «Монтажа» остальное содержимое `mounting` сохраняется, при отсутствии `mounting` создаётся `{ walls: [], dimensions: [], callouts }`.
- `src/callout/callout-text.ts`: `normalizeCalloutText(raw: string): string` — `\r\n`→`\n`; убирает пробельные символы и пустые строки в начале и конце всего текста; внутренние строки (включая пустые) и пробелы внутри строк не меняет; пустой или пробельный текст → `""`.
- `src/callout/callout-actions.ts` (чистые, список не мутируют, идентификатор передаётся снаружи):
  - `commitCallout(list, edit, rawText): { list: Callout[]; changed: boolean }`, где `edit = { kind: "new"; id; target; at } | { kind: "edit"; id }`. Текст нормализуется `normalizeCalloutText`. `new`+непустой → выноска добавлена в конец; `new`+пустой → список без изменений, `changed: false`; `edit`+другой текст → текст заменён, порядок и точки прежние; `edit`+тот же текст (после нормализации) → без изменений, `changed: false`; `edit`+пустой → выноска удалена, `changed: true`; `edit` неизвестного id → без изменений, `changed: false`.
  - `moveCalloutPoint(list, id, which: "target" | "at", p: Point): { list; changed }` — без привязок и округления; та же точка или неизвестный id → `changed: false`.
  - `removeCallout(list, id): { list; changed }` — неизвестный id → `changed: false`.
- `src/callout/callout-layout.ts`: `type Measure = (line: string) => number` (ширина строки в px); `calloutLayout(c: Callout, view: View, m: RenderMetrics, measure: Measure): CalloutLayout` с полями: `align: "left" | "right"`; `lines: { text: string; x: number; y: number }[]` (экранные px: `x` — левый край строки, `y` — нижняя кромка строки; строки в порядке ввода); `box: { x: number; y: number; w: number; h: number }` — прямоугольник подложки, содержащий прямоугольники всех строк (строка занимает `[x, x + measure(text)] × [y − m.labelPx, y]`); `lineStart: Point` — начало линии; `arrowTip: Point`. Экранные координаты — как у `toScreen` рендера: `(p − view.pan) · PX_PER_CM · view.zoom`.
- `src/callout/callout-pick.ts`: `pickCallout(list, p: Point /* мир */, view, m, measure, radiusCm): Callout | null` — ближайшая к курсору выноска из попавших; при равенстве расстояний — последняя в списке.
- `src/render.ts`: `RenderOptions` получает `callouts?: readonly Callout[]`, `selectedCallout?: string | null`, `erasingCallout?: string | null`; `drawScene` рисует выноски, `drawDemolitionScene` — через `DemolitionScene.callouts?`, `selectedCalloutId?`, `erasingCalloutId?` (те же значения).
- Отрисовка выноски (уточнение по результатам валидации): подложка, линия, стрелка и маркеры выделения рисуются путями холста (`beginPath` + `moveTo`/`lineTo`/`rect`/`arc` + `fill`/`stroke`), а не `fillRect`/`strokeRect`; текст — `fillText(строка, x, y)`, где `x`, `y` согласованы с установленными на момент вызова `textAlign` и `textBaseline` и с раскладкой `calloutLayout` (тесты принимают любые допустимые значения `textAlign`: left/start, center, right/end и `textBaseline`: alphabetic/bottom, middle, top/hanging); линия выноски — толщиной `RenderMetrics.hatchPx`; после отрисовки состояние холста (шрифт, цвета, толщина, выравнивание) не изменено.
- `src/history.ts`: `HistoryEntry` получает `{ kind: "callouts"; callouts: Callout[] }`; `recordCallouts(history, callouts)`, `undoCallouts(history, current): Callout[] | null`, `redoCallouts(history, current): Callout[] | null` — работают только если верхняя запись соответствующего стека имеет вид `"callouts"`, иначе возвращают `null` и не меняют стеки; записи — глубокие копии; `recordCallouts` очищает `future` и подчиняется `HISTORY_LIMIT`. Существующие `undoEntry`, `redoEntry`, `undoMarks`, `redoMarks`, `undoDemolition`, `redoDemolition` НЕ ДОЛЖНЫ забирать запись вида `"callouts"`: стеки не меняются, возврат `null`.
- `src/storage.ts`: `isCallout(x: unknown): x is Callout`; `parseStore` / `serializeStore` читают и пишут `callouts`, `mounting.callouts`, `demolitionCallouts`; запись истории `"callouts"` проверяется `isCallout` в `parseHistory`.
- `src/doorway/openings-group.ts`: `Tool` включает `"callout"`. `src/plans.ts`: `toolsOf`. `src/tool-mode.ts`: `EscapeState.calloutDraft?: boolean` (необязательное поле: существующие тесты создают состояние без него); `EscapeAction` включает `"cancel-callout-draft"`.
- `src/export/pdf.ts`: страницы из `pagesOf(drawing)` содержат `callouts?: Callout[]` — выноски своего плана; `pageBounds(page, scale)` учитывает их.
- `index.html`: кнопка `id="tool-callout"`, `title="Выноска"` в `div.tool-anchor` с `data-tools="callout"`, по порядку документа после `tool-dimension` и перед `tool-ruler`; своей панели у неё нет.

Сцены (общие): `W` — стена `(0,0)-(500,0)` t20; вид `VIEW` (масштаб 1, 2 px на см); `A` — выноска `a` с `target (300,100)`, `at (100,100)`, текст «Монтаж радиатора\nв нишу» (точка стрелки правее текста — выравнивание вправо); `B` — выноска `b` с `target (50,100)`, `at (150,200)`, текст «Тест» (стрелка левее — выравнивание влево). Все эталоны выводятся из спеки и геометрии сцен, не из продакшн-модулей.

## Invariants

- Операции списка (`commitCallout`, `moveCalloutPoint`, `removeCallout`, `withCallouts`) не мутируют входные данные (C-INV-4, проверяется глубоким сравнением до/после).
- После любой операции `commitCallout` в списке нет выносок с пустым после нормализации текстом (C-INV-5; перебор по набору входов).
- Привязок нет: после `moveCalloutPoint` точка равна переданной ровно, прочие поля неизменны (C-ACT-7, C-INV-1).
- Выноски одного плана не влияют на списки других планов ни в `withCallouts`, ни в хранении, ни в истории (C-PLN-1..3).
- Размер шрифта выносок равен `m.labelPx` при любом зуме (C-RND-3) и совпадает с размером числа размера на экране и в PDF (C-RND-1, C-PDF-4).
- Выноски не читаются расчётом помещений и коллизий: результат `rooms`/площадей и допустимости стены одинаков для чертежа с выносками и без (C-INV-2, C-INV-3) — защита от случайной зависимости.
- Раскладка: прямоугольник каждой строки лежит внутри `box`; линия не заходит внутрь `box` (C-LAY-6, C-LAY-7).

## Integration Cases

- C-PLN-1: через `withCallouts`/`calloutsOf`, `serializeStore`/`parseStore` и `pagesOf` выноски трёх планов проходят полный путь независимо: на каждой странице PDF и в каждом списке свои.
- C-PLN-2: `recordCallouts` в историях разных планов (`planHistory`) — отмена на одном плане не трогает другой.
- C-PLN-3: ластик-эквивалент (`removeCallout`) в списке плана не меняет остальные объекты плана (стены, пометки сноса, собственные объекты «Монтажа») при сборке чертежа `withCallouts`.
- C-PLN-4: пересчёт остатков «Монтажа» (`mountingScene`) от изменения пометок сноса не меняет список `mounting.callouts`.
- C-PDF-3: `buildPdfPages` передаёт в `drawScene` / `drawDemolitionScene` на каждой странице выноски именно этого плана и никогда — `selectedCallout`/`erasingCallout`.
- C-RND-11: `drawDemolitionScene` рисует выноски поверх подложки и пометок.

## Mutation Targets

Мутации, которые должны быть убиты тестами:

- выравнивание: `<` ↔ `<=` в сравнении `target.x` и `at.x` (C-LAY-3, C-LAY-3b); обратное выравнивание; выравнивание всегда влево;
- правый край: `x = anchor.x` вместо `anchor.x − measure(text)` у выравнивания вправо (C-LAY-1);
- межстрочный интервал: разный или нулевой, строки в обратном порядке, строки идут вверх (C-LAY-4, C-LAY-5);
- `lineStart` внутри текста / на другой кромке / на другом краю (C-LAY-6, C-LAY-7);
- `box` не охватывает все строки или только первую (C-LAY-8);
- перевод в экран: пропущен `pan` или зум (C-LAY-9, C-LAY-10);
- размер шрифта зависит от зума, берётся из PDF-метрик на экране или наоборот (C-RND-1, C-RND-3, C-PDF-4);
- курсив включён (C-RND-2); стрелка не нарисована или другого размера (C-RND-4); подложка пропущена или нарисована после текста (C-RND-5);
- маркеры выделения рисуются всегда / не рисуются у выделенной (C-RND-7, C-RND-8); подсветка ластика рисуется без `erasingCallout` (C-RND-9);
- `normalizeCalloutText`: не убирает пустые строки по краям, убирает внутренние пустые строки, не меняет `\r\n` (C-TXT-1..4);
- `commitCallout`: пустой текст создаёт выноску; правка без изменений даёт `changed: true`; стирание не удаляет; новая выноска вставляется в начало списка; правка меняет порядок или точки; неизвестный id удаляет первую выноску (C-ACT-*);
- `moveCalloutPoint`: двигает обе точки, двигает не ту точку, округляет или привязывает к сетке (C-ACT-7, C-ACT-8);
- `pickCallout`: `<` ↔ `<=` на радиусе; выбирает первую вместо ближайшей; игнорирует линию или текст (C-PICK-*);
- `withCallouts`: пишет в список не того плана, затирает остальное содержимое `mounting`, мутирует исходный чертёж (C-STORE-*, C-INV-4);
- `isCallout`: не проверяет пустой текст, NaN, идентификатор (C-STO-5..7); загрузка дописывает пустой список (C-STO-4);
- история: запись без глубокой копии (мутация после записи меняет снимок); `redo` не кладёт текущее состояние в `past`; `undoEntry` забирает запись `"callouts"`; не очищается `future` при записи (C-HIS-*);
- `toolsOf`: `callout` не там по порядку или не на каком-то плане; `escapeAction`: приоритет `calloutDraft` выше `gestureActive`/`dimensionDraft` или `deactivate-tool` при черновике (C-TOOL-*);
- PDF: страница получает выноски всех планов; выноски в границах не учтены; `selectedCallout` попадает в PDF (C-PDF-*).

## Out of Scope

- `openTextEditor` и всё, что требует DOM: поле ввода, Enter/Esc/blur, фокус, остановка всплытия клавиш, размер `textarea`.
- Проводка `src/main.ts`: клики и двойной клик инструмента, превью резинки, перетаскивание маркеров и порог «клик против протяжки», переключение плана/вкладки при вводе, приоритет ластика над стеной и пометкой, автосохранение. Проверяется вручную в браузере (память «browser manual checks») и записывается в `TODO.md`.
- Реальные метрики шрифта: на экране `ctx.measureText` sans-serif, в PDF метрики PTSans; тесты используют фиксированный измеритель, сравнение экрана и PDF — по порядку строк и выравниванию, не по пикселям.
- Мультивыделение, рамка и групповой перенос выносок (non-goal design).
- Существующие одобренные тесты с точными наборами инструментов (`src/plan-tools.test.ts`, `src/mounting-plans.test.ts`, `src/communications/plans.test.ts`, `src/battery/battery-tool.test.ts` B-TOOL-7, 7b, 7c) устареют из-за нового инструмента: они не правятся здесь, оформляются как `test-change-request.md` (правило 5), новые ожидания зафиксированы в `callout-tool.test.ts` (C-TOOL-1..3).
