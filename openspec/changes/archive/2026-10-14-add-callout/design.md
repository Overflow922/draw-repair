## Context

Выноска — новый вид объекта без привязок, поэтому она устроена проще размера. Уже есть всё нужное для её частей:

- Размещение по кликам с черновиком и превью — у «Размера» (`dimDraft`, `dimRubber`, `src/main.ts`), отмена по Esc через `escapeAction` (`src/tool-mode.ts`).
- Ввод на месте — `openNumberEditor` (`src/doorway/doorway-tool.ts`): `input` поверх холста, фокус после mousedown, Enter коммитит, Esc закрывает без коммита, blur закрывает. Для выноски нужно многострочное поле с другим поведением клавиш.
- Размеры шрифта и стрелки — `RenderMetrics` (`labelPx`, `dimArrowPx`) с отдельным набором для PDF (`src/render.ts`), PDF строится тем же рендером.
- Хранение объектов планов: обмер — поля `Drawing`, «Монтаж» — `Drawing.mounting` (`MountingContent`), «Демонтаж» — `Drawing.demolition` (только пометки). История — `Scene` и записи `HistoryEntry` в `src/history.ts`, у планов «Демонтаж» и «Монтаж» свои виды записей.
- Набор инструментов плана — `PLAN_TOOLS` в `src/plans.ts`, тип `Tool` в `src/doorway/openings-group.ts`.

## Goals / Non-Goals

**Goals:**
- Выноска как самостоятельный объект плана с минимальной связностью с остальной геометрией.
- Предметная логика (выравнивание, раскладка текста, поиск по курсору) — чистые функции в модуле `src/callout/`, без DOM; `main.ts` только подключает их.
- Один механизм хранения и истории на три плана.
- Чтение старых документов и историй без миграции.

**Non-Goals:**
- Привязки точек, следование за стенами, рамка и мультивыделение выносок, групповой перенос вместе со стенами.
- Курсив, настройки размера шрифта, выбор стороны или формы линии (полка, излом).
- Перенос по ширине (word wrap): число строк задаёт пользователь через Enter.

## Decisions

### D1. Модель данных и хранение

`Callout { id, target: Point, at: Point, text: string }` в `src/types.ts`; `text` — строки через `\n`, без начальных и конечных пустых строк. Списки выносок:

| План | Где лежит |
|---|---|
| обмер | `Drawing.callouts?` |
| монтаж | `MountingContent.callouts?` |
| демонтаж | `Drawing.demolitionCallouts?` |

Отсутствие поля читается как пустой список и не дописывается при загрузке (как у `communications`, `batteries`). Версия документа остаётся 3. Валидатор — по образцу `isDimension` в `src/storage.ts`: идентификатор, конечные числа координат, непустой текст после trim; неверная выноска пропускается, остальное грузится.

Альтернатива — единый список с полем `plan`. Отвергнута: все остальные объекты хранятся по планам, а правила истории, «Монтажа» (`hiddenDimensions`, `mounting-workspace`) и PDF уже разложены по планам.

### D2. Один интерфейс над тремя списками

Модуль `src/callout/callout-store.ts` отдаёт `calloutsOf(drawing, plan)` и `withCallouts(drawing, plan, list)` — единственное место, знающее, где какой план хранит выноски. Остальной код (рендер, инструмент, ластик, PDF, история) работает со списком выносок активного плана и не ветвится по планам.

### D3. История

Операции над выносками — отдельный вид записи `{ kind: "callouts"; callouts }` в `HistoryEntry`: снимок списка выносок плана до операции. Отмена и повтор подставляют снимок и не трогают остальные объекты, поэтому правка стены не откатывает выноску и наоборот (`Выноски в истории`). Запись — в стек истории того плана, чей это список (ключи историй планов не меняются), поэтому поле плана в записи не нужно. Существующие функции отмены и повтора (`undoEntry`, `undoMarks`, `undoDemolition` и парные) записи этого вида не забирают; для выносок есть свои `recordCallouts`, `undoCallouts`, `redoCallouts`. Версия документа истории остаётся 2; запись проверяется валидатором из D1; история до введения выносок читается без изменений, так как новый вид записи в ней просто не встречается.

Жест переноса — одна запись, как перетаскивание размерной линии. Создание — одна запись при завершении ввода (не при втором клике: пустая выноска не создаётся и шаг не нужен). Правка текста — одна запись при снятии редактирования, если текст изменился.

Альтернатива — расширить `Scene` полем `callouts`, как `batteries`. Отвергнута: у «Демонтажа» и «Монтажа» своё представление сцены, и пришлось бы менять три пути снимков; отдельный вид записи изолирует change.

### D4. Размещение и состояние инструмента

Черновик выноски — состояние в `main.ts` по образцу `dimDraft`: `{ target: Point | null }` плюс состояние редактора. Шаги: пусто → точка стрелки задана → редактор открыт. `EscapeState` получает `calloutDraft`, `escapeAction` — действие `cancel-callout-draft` с приоритетом того же уровня, что у размера. Открытый редактор сам перехватывает Esc (как `openNumberEditor`), поэтому Esc в поле не доходит до `escapeAction`. Привязок нет, поэтому в размещении нет поиска снапа — точки берутся из позиции клика.

### D5. Редактор текста

Новый `openTextEditor` в `src/callout/text-editor.ts` на образце `openNumberEditor`: `textarea` поверх холста с тем же приёмом отложенного фокуса. Отличия: Enter вставляет перевод строки (поведение по умолчанию), Esc коммитит, blur коммитит (в `openNumberEditor` blur только закрывает). Вызов коммита один раз за жизнь редактора. `keydown` останавливает всплытие, чтобы Delete/стрелки/Ctrl+Z не действовали на чертёж. Поле выравнивается и растёт вместе с раскладкой (D6): шрифт и межстрочный интервал равны холстовым, выравнивание — по D6. Размер поля по содержимому пересчитывается на `input`.

Общий код с `openNumberEditor` не выделяется: у них разные правила клавиш и коммита, общего только создание `input` и фокус — это меньше, чем стоимость общей абстракции.

### D6. Раскладка текста и выравнивание

Чистая функция `calloutLayout(callout, metrics, measure)` возвращает: выравнивание (`"left" | "right"` по знаку `target.x − at.x`; `<=` 0 — влево), позиции строк, прямоугольник подложки, точку начала линии у ближнего к стрелке края первой строки на уровне нижней кромки. Ширину строк даёт переданная `measure` (в экранной среде — `ctx.measureText`, в PDF — метрики шрифта PDF), поэтому функция остаётся чистой и тестируемой с поддельным измерителем. Межстрочный интервал — константа в долях `labelPx`.

Геометрия считается в экранных пикселях от мировых точек: мировая точка `at` переводится в экран, текст и стрелка не масштабируются с зумом. Для попадания курсора (выделение, ластик, подсветка) используется та же раскладка — прямоугольник текста и отрезок линии, плюс радиус привязки.

### D7. Отрисовка

`drawCallouts` в `src/callout/callout-render.ts` вызывается из общего рендера с `RenderMetrics`: линия и стрелка — тем же примитивом стрелки, что у размеров (`dimArrowPx`), текст — `${labelPx}px ${font}`, без курсива; подложка цвета фона под текстом; цвета из темы. Для PDF вызывается тем же кодом с `PDF_METRICS` (шрифт PTSans уже содержит кириллицу). Маркеры выделения и подсветка ластика рисуются только при соответствующих опциях рендера, которых в PDF нет.

### D8. Выделение, перенос, правка

Только без инструмента (`selectionAllowed`). Нажатие на выноску: попадание по D6; маркеры у точки стрелки и точки текста — зоны перетаскивания. Нажатие на текст выделенной выноски — ожидание: если до отпускания курсор прошёл меньше порога жеста, открывается редактор, иначе жест — перенос `at`. Пока выноска выделена, остальные объекты не выделены; выбор выноски сбрасывает выделение стен и других объектов и наоборот (одно выделение на холсте). Delete удаляет выделенную выноску, если фокус не в поле ввода.

### D9. Ластик и приоритеты

Поиск выноски под курсором — функция `pickCallout(list, p, radiusCm, layout)` из D6; в обработчике ластика она вызывается первой (приоритет выноски, как у размеров по `fix-dimension-press-priority`). На «Демонтаже» и «Монтаже» ластик получает такую же ветку для выносок своего плана, остальные ветки не меняются.

### D10. PDF

Страница плана получает список выносок плана (`src/export/pdf.ts`, сборка страницы), рисует их `drawCallouts` с `PDF_METRICS` и добавляет их габариты в границы содержимого страницы вместе с остальными объектами (по образцу учёта батарей в границах). Габариты — прямоугольник подложки и точки линии. Условие «чертёж пуст» для экспорта учитывает выноски.

### D11. Изменения в других модулях

- `Tool` — значение `"callout"`; `PLAN_TOOLS` всех планов получают `callout` (после `dimension`, на демонтаже после `demolition`); кнопка и значок в тулбаре `src/main.ts` и стили `src/style.css` — по образцу кнопки «Размер», без панели.
- Esc/Enter-обработка: открытое поле ввода выноски исключено из общих горячих клавиш.
- Переключение плана и вкладки: размещение сбрасывается, редактор коммитит по blur (его закрытие уже происходит при смене DOM).

## Risks / Trade-offs

- **Blur и клик вне поля.** Клик по холсту закрывает поле по blur и одновременно может сработать как первый клик другого инструмента или выбор объекта. Нужно, чтобы клик, закрывающий редактор, только коммитил текст и не начинал новое действие; `pointerdown` обработчик холста должен проверять признак «редактор был открыт». Риск ловится сценарием «клик вне поля при активной «Выноске»» (`callout`, «Инструмент «Выноска» и размещение»).
- **Эквивалентность экрана и PDF.** Ширина строк на экране (`measureText` шрифта sans-serif) и в PDF (метрики PTSans) разная; выравнивание по краю и подложка могут чуть различаться. Допустимо: PDF считает свою раскладку тем же кодом с другим измерителем; сравнение тестами — по порядку строк и выравниванию, не по пикселям.
- **Три места хранения.** Выноски демонтажа — новое поле плана, которого раньше не было (`demolition` хранит только пометки). Миграции нет, но каждый код, который собирает документ по планам (`mounting-workspace`, сохранение вкладок, закрытие вкладки), должен переносить выноски вместе с остальными данными; пропуск ловится тестом сохранения и истории.
- **Клик против протяжки.** Порог между «клик по тексту» (правка) и «перенос» должен совпадать с порогом, принятым у других жестов, чтобы не вводить второе значение.
- **Выноска без привязок и стены.** Если пользователь двигает стену, выноска остаётся и может указывать в пустоту; это принятое поведение (`callout`, «Данные выноски»).
- **Объём PDF-границ.** Многострочная выноска у края чертежа расширяет границы и может уменьшить подобранный масштаб — как любое другое содержимое страницы.
