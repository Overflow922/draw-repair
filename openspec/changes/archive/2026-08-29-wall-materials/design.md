## Context

`gost-walls` (заархивирован) дал категории с плотностной штриховкой в мировых см. По ГОСТ 2.306-68 обозначение в сечении задаётся материалом; шаг нормируется в мм «на бумаге». Спек `wall-types` сейчас описывает категории — дельта `wall-materials` переписывает оба требования.

## Goals / Non-Goals

**Goals:**

- Единственный типовой атрибут стены — материал (4 значения); паттерны штриховки по ГОСТ 2.306-68.
- Экранная метрика: шаг и толщины линий в px/мм экрана, инвариантны к зуму; линейные штриховки строго 45°.
- Один источник паттернов для холста и свотчей; образцы-«легенда» с подписями материалов.

**Non-Goals:**

- Масштаб листа (1:50/1:20), цветные стили, переключатель стилей, атрибут «категория», штриховка торца древесины (удалена по решению пользователя).

## Decisions

- **`MATERIALS` в `types.ts`**: `brick` «Кирпич», `concrete` «Бетон», `reinforced` «Железобетон», `wood-long` «Дерево (вдоль)». `Wall.type` остаётся строкой (формат хранилища прежний, версия 1). `normalizeMaterial`: валидные id проходят, всё прочее (в т.ч. все legacy-типы и `wood-cross`, удалённый после первой итерации) → `brick`.
- **Экранная система координат для паттернов.** Рендер стены: полигон стены переводится в CSS-px (`(w - pan) * k`), затем `clip` и паттерн рисуются в экранной системе (после `ctx.restore()` мировой трансформации, transform = только dpr). Все метрики паттерна — px: шаг `MM(3) ≈ 11.34px` (`96/25.4`), штрихи/точки, амплитуды волн — константы экрана. Это даёт инвариантность к зуму и строгие 45° к рамке (единственная альтернатива — мировые см — отвергнута требованием «как на бумаге»).
- **Линейные штриховки 45°**: семейство линий `y = x + c` (экран), `c` с шагом `spacing / sin(45°)` по диапазону bbox полигона. `lineWidth` 1px.
  - кирпич: сплошные.
  - бетон: `setLineDash([3.5mm, 1.2mm, 0.3mm, 1.2mm])` — штрих-зазор-точка-зазор.
  - железобетон: соседние линии чередуются сплошная/штрихпунктирная (штрихпунктир `[2.5mm, 1mm, 0.3mm, 1mm]`), шаг между соседними 3мм.
- **Дерево (вдоль)**: ось стены `u` (экран, единичный), нормаль `n`; линии-волокна на смещениях `n * (−t..t)` с шагом 3мм; каждая — полилиния вдоль оси с поперечным синусоидальным смещением (амплитуда ~0.6мм, длина волны ~8мм), под клипом.
- **Контур** полигона — единая основная линия 2px `#333` для всех материалов; `drawOutline` выделения и alpha 0.4 превью переводятся в ту же экранную систему.
- **Свотчи-легенда**: внутри каждой кнопки мини-канвас 36×14 + текстовая подпись материала; при старте канвасы рисуются теми же функциями паттернов на прямоугольнике — единственный источник отрисовки; CSS-градиенты удалены.
- **Селектор стиля отображения**: нативный `<select id="render-style">` первым элементом нижней панели, единственный пункт «ГОСТ»; без JS-логики — визуальный каркас будущих переключаемых стилей (при появлении второго стиля — реестр стилей и обработчик change).
- **`main.ts`**: `wallMaterial = "brick"`; обработчики свотчей (`data-material`), стрелки циклируют `MATERIALS`; синхронизация канвасов свотчей не нужна (статичны).

## Risks / Trade-offs

- [Волокна дороже линейной штриховки при каждом redraw] → Полилинии умеренного счёта (десятки на стену); при деградации — кэш оффскрин-паттерна.
- [Штрихпунктир фазы «плывут» между линиями] → Фаза задана началом каждой линии от верхней кромки bbox — визуально приемлемо, ГОСТ фазу не нормирует.
- [Экранный шаг при сильном отдалении плотнее 1px] → Шаг 3мм ≈ 11px — всегда читаем; нижняя граница ГОСТ 1мм не достигается.
- [Потеря категорий для существующих данных] → Осознанное решение пользователя; все legacy-типы → «Кирпич», реверса к категориям через данные нет.

## Migration Plan

Одно применение: types/storage/render/UI/main.ts + тесты. Хранилище совместимо: значения материалов — строки, старые значения нормализуются при чтении. Откат — revert.
