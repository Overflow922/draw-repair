## Context

См. proposal.md. Текущее состояние: у размеров есть скрытый drag offset (`dimDrag` в `main.ts`, работает во всех инструментах, кроме ластика), но нет состояния выделения (`selectedWall` существует, выделения размера нет), нет подсветки, Delete на размеры не действует, панель свойств отсутствует. Точки замера (`from`/`to` типа `DimPoint`) после создания неизменяемы — путей правки нет, это сохраняем.

Выделение стены — прецедент: `selectedWall`, клик выделяет (вне цепочки/ластика/инструмента «Размер»), панель `#wall-panel` у кнопки инструмента, Delete удаляет, Esc/клик мимо снимают, подсветка + маркеры в `render.ts`.

## Goals / Non-Goals

**Goals:**

- Явное состояние выделения размера с видимыми откликами: подсветка, захваты, панель.
- Точный ввод выноса (offset) с клавиатуры; read-only значение размера.
- Delete для выделенного размера; полный набор сбросов выделения.
- Приоритет «размер над стеной» при нажатии, зафиксированный в спеках.

**Non-Goals:**

- Правка точек замера (from/to) — остаются неизменяемыми.
- Независимое смещение концов размерной линии (offsetA/offsetB) — модель данных не меняется.
- Hover-подсветка размеров вне ластика.
- Мультивыделение.

## Decisions

- **Состояние — runtime-only** (`selectedDimension: Dimension | null` в `main.ts`). Не сохраняется в хранилище, историю и чертёж — как `selectedWall`. Альтернатива (хранить id в `Drawing`) отклонена: выделение — временное состояние UI.
- **Нажатие выделяет и сразу разрешает drag**: `pointerdown` по размерной линии/числу (вне ластика) выделяет размер и продолжает существующий `dimDrag`; клик без движения оставляет выделенным. Альтернатива (выделение только чистым кликом, drag отдельно) отклонена — расходится с моделью стен и удваивает ветвления.
- **Захваты — индикаторы, не отдельные ручки**: маркеры рисуются на концах размерной линии (p1/p2), но перетаскивание работает от любой точки линии и числа и меняет общий offset (решение пользователя «двигать размерную целиком»). Маркеры намеренно не ставятся на точках замера, чтобы не обещать их правку.
- **Панель — `.tool-panel` у кнопки «Размер»** (обёртка `.tool-anchor`, по образцу панели стены): поле «Вынос» (число в текущей единице, знак = сторона оси; запятая/точка равнозначны; нечисловые значения игнорируются, 0 допустим) и read-only «Значение» (расстояние между точками замера). Поле обновляется live при drag; ввод применяется сразу (как поле толщины). Панель размера и панель стены взаимоисключающи.
- **Порядок Esc**: цепочка → черновик размера → **снять выделение размера** → выключить инструмент (ластик/размер) → снять выделение стены. Выделение размера снимается раньше выключения инструмента, т.к. размер можно выделить в любом инструменте, кроме ластика.
- **Delete** — только Delete (без Backspace), по прецеденту стен; путь удаления тот же, что у ластика (`deleteDimension` с записью истории). Работает при выделенном размере в любом инструменте.
- **Сбросы**: `setTool`, `activate` (вкладка), `resetEditing` (undo/redo) гасят выделение; `deleteWall` после каскадной фильтрации размеров снимает выделение, если выделенный размер был отфильтрован.
- **Подсветка**: выделенный размер перерисовывается акцентным цветом (механизм как у `hoverDim` ластика, другой цвет) + маркеры в стиле маркеров стены на p1/p2. В ластике выделения не существует — конфликта красной hover-подсветки нет.
- **Дельта в `wall-selection`**: требование «Выделение стены» дополняется правилом приоритета — клик по размеру выделяет размер, а не стену под ним (иначе спеки противоречат друг другу при наложении размера на стену).

## Risks / Trade-offs

- [Клик по существующему размеру в инструменте «Размер» не ставит точку замера] → существующее поведение (перехват drag/выделением); фиксируем его в спеке явно как ожидаемое.
- [Маркеры на концах линии читаются как «можно тянуть конец отдельно»] → поведение одинаково отовсюду (общий offset); расхождение только визуальное, принимаем.
- [Отрицательный/нулевой вынос из поля ввода] → допустимы и воспроизводимы drag-ом; отдельной валидации нет.
- [main.ts и render.ts не покрыты юнит-тестами] → проверка сборкой (`tsc`/`vite build`) + браузерная верификация, как в предыдущих изменениях.

## Migration Plan

Без миграции: схема хранилища и история не меняются. Откат — revert коммита.

## Open Questions

Нет — ключевые развилки (общий offset, состав панели, инструменты) решены с пользователем в explore-сессии.
