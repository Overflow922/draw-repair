## Context

Мотивация и состав изменения — в `proposal.md`, требования — в дельта-спецификациях (`room-explication`, `room-areas`, `pdf-export`, `drawing-storage`, `drawing-history`).

Текущее состояние:
- `findRooms(walls)` (`src/room-area.ts`) вычисляет помещения при каждой отрисовке и возвращает контур, острова, площадь и точку подписи `labelAt`. Идентификатора у помещения нет; `room-areas` запрещает хранить помещения.
- Подпись площади рисуется в `src/render.ts` (`drawRoomLabels`) только вне подложки; в PDF рисуется тем же кодом.
- Область чертежа (`drawingArea` в `src/export/sheet-layout.ts`) и ширина легенды (`legendWidthMm`) общие для всего документа; подбор масштаба (`src/export/fit-scale.ts`) использует эту область.
- Объекты плана «Монтаж» хранятся в `drawing.mounting`; у каждого плана своя история.
- Образцы правки на холсте: числа правятся на месте (`.claude/rules/ui.md`), текст выноски — полем на месте; панели инструментов содержат только кнопки (`canvas-app`).

## Goals / Non-Goals

**Goals:**
- Сохранить принцип «помещения вычисляются»: хранится только пользовательская надстройка над ними.
- Номера стабильны, пока помещение существует; отмена и повтор восстанавливают их вместе со стенами.
- Таблица экспликации и блоки получают данные из одного источника — списка помещений с привязанными данными.

**Non-Goals:**
- Блоки и таблицы на планах «Обмерочный план» и «Демонтаж» и на новых планах (данные уже общие, отображение — отдельными changes).
- Ручная смена номера, ручное положение блока, удаление помещения пользователем.
- Таблица экспликации на холсте.
- Общая таблица для нескольких планов.

## Decisions

### D1. Запись помещения привязана опорной точкой, помещение не хранится
В `Drawing` добавляется необязательный `rooms?: RoomRecord[]` с `RoomRecord { number, name, heightMm, anchor: Point }`. Помещение по-прежнему из `findRooms`; привязку делает единая чистая функция `reconcileRooms(rooms, records)` в `src/room-explication.ts` (сопоставление и согласование — одна операция, отдельной привязки без согласования нет): запись относится к помещению, в контуре которого (вне островов) лежит `anchor`. Результат — список `{ room, record }`.

Альтернативы: хранить помещения явно (нарушает `room-areas`, нужна синхронизация) и нумеровать по порядку обхода (любое новое помещение перенумеровывает остальные и сдвигает названия). Отвергнуты.

### D2. Согласование записей — чистая функция при фиксации шага
`reconcileRooms(walls, records) → records` — чистая функция домена без DOM: сопоставляет, отбрасывает записи исчезнувших помещений и дубликаты (в одном помещении остаётся запись с меньшим номером), создаёт записи новым помещениям с наименьшим свободным номером, названием «» (выводится как «Комната») и высотой 3000, обновляет `anchor` на точку внутри помещения (`labelAt`). Вызывается при фиксации каждого шага истории плана «Монтаж», менявшего стены, а также при загрузке (результат не записывается обратно, `drawing-storage`), и не вызывается во время жеста. Во время жеста для рисования блоков используется `bindRooms` без создания записей; новое помещение, которое появилось в жесте, рисуется с номером, который получила бы запись при фиксации (наименьший свободный).

Записи входят в снимок шага истории плана «Монтаж» вместе со стенами, поэтому отмена и повтор восстанавливают их атомарно.

Порог экспликации 1 м² (`room-explication` «Помещения экспликации»): `findRooms` не меняется (порог 0,1 м² у заливки и подписей остаётся), `reconcileRooms` получает только помещения с `areaCm2 >= 10000` — константа `EXPLICATION_MIN_AREA_CM2` рядом с `MIN_AREA_CM2`, сравнение с запасом `AREA_EPS` как в существующем пороге. Малые помещения не получают записей, блоков и строк таблицы.

### D3. Номера не переиспользуются, пока помещение существует; освобождаются при исчезновении
Следует из вопроса, согласованного в explore: исчезновение помещения на фиксации шага удаляет запись, номер свободен. Отмена возвращает запись из снимка.

### D4. Блок — отдельный рисуемый объект плана «Монтаж», не часть заливки
Блок рисуется функцией в `src/render.ts` или новом модуле `src/room-block.ts` после стен и размеров и перед выделением. Размеры блока на холсте — константы в экранных пикселях, в PDF — в миллиметрах бумаги (по образцу `legend.ts`). Блок не входит в габариты чертежа и подбор масштаба (как подпись площади). Подпись площади на плане «Монтаж» отключается параметром отрисовки, на остальных планах прежняя.

### D5. Выделение — состояние `selectedRoomNumber` рядом с остальными выделениями
Попадание курсора в блок проверяется после стен, размеров, элементов и батарей (меньший приоритет). Выделенный блок подсвечивается и переходит в состояние редактирования на месте: поле названия над блоком и поле высоты поверх правой ячейки (по образцу правки чисел и текста на месте; панель инструмента не открывается, потому что `canvas-app` допускает в панелях только кнопки — решение принято при реализации с пользователем). Применение значения — один шаг истории плана «Монтаж» (по образцу правки параметров выделенного объекта). Логика попадания и валидации высоты — чистые функции, DOM только в `main.ts`.

Единый принцип «объект выделяется и переходит в состояние редактирования» записывается в `.claude/rules/ui.md`; существующие объекты не переделываются, поскольку они ему уже соответствуют.

### D6. Нижняя полоса листа — общая высота документа
Как ширина столбца легенды, высота нижней полосы общая для документа: `bottomBandMm(pages) = max(TITLE_BLOCK_H_MM, tableHeightMm(rooms))`. `drawingArea` получает этот параметр рядом с `legendMm`; `legendArea` заканчивается там же, где область чертежа; `fit-scale` считает по тем же значениям. Таблица стоит в левом нижнем углу рамки, не касается основной надписи. Высота таблицы считается чистой функцией по записям: заголовок, шапка, строки (с переносом названий по образцу `wrapLabel`), итог.

Альтернатива — своя область на каждой странице — отвергнута: масштаб печати общий, а страницы с разной областью усложняют подбор без выигрыша; общая область уже принята для легенды.

### D7. Площадь в таблице — по точным площадям
Строка таблицы форматируется функцией `formatAreaOneDecimal(areaCm2)` (м², запятая, один знак), итог — форматированная сумма точных `areaCm2`. Формат подписи с двумя знаками (`formatArea`) не меняется.

### D8. Порядок строк
По возрастанию номера. Помещение без записи (в экспорте записи есть всегда после согласования) выводится как новое помещение по правилам D2.

## Risks / Trade-offs

- [Перемещение стены сдвинуло опорную точку в соседнее помещение, и название «переезжает»] → `anchor` обновляется на `labelAt` после каждого шага; жест не пересматривает привязку; принято на этапе explore.
- [Резкое изменение за один шаг (например, перемещение нескольких стен) оставляет опорную точку вне помещения, запись теряется] → помещение получает новый номер; данные можно вернуть отменой. Принято.
- [Общая нижняя полоса уменьшает область чертежа на всех страницах, масштаб печати мельче] → осознанный компромисс D6.
- [Таблица не помещается при большом числе помещений на малом формате] → высота полосы растёт, подбор масштаба и формата страницы учитывает её (`fit-scale-ui`: предупреждение о нехватке места, как для чертежа).
- [Неточность текущего образца `legend` «над основной надписью»] → при синхронизации спецификаций формулировку легенды привести к «по высоте области чертежа» (в дельте `pdf-export` это уже отражено в области чертежа).

## Migration Plan

Формат документа и истории не меняется: новые необязательные поля. Старые документы открываются без `rooms`; записи создаются при первой фиксации шага плана «Монтаж» или не создаются вовсе (экспорт и холст используют `reconcileRooms` без записи на диск). Откат — удаление поля `rooms`, остальные данные не затронуты.
