# Test Plan

## Scope

Поведение точек замера на откосах элементов стены (`dimension-tool` «Точки замера на откосах элементов стены»,
«Удаление элемента удаляет размеры на его откосах», изменённые «Инструмент «Размер»» и «Привязка размеров к
стенам»; `drawing-storage` «Формат документа») через чистые функции интерфейса design D8:
`dimPointPoint`, `nearestDimAnchor`, `dimHitDistance`, `deleteObjects`, `isDimension`/`copyDimension`,
`cloneScene`/`parseHistory`, а также рендер (`render`) и PDF-экспорт на сценах без DOM. `main.ts` (маршрутизация
событий, DOM) модульными тестами не покрывается — см. «Out of Scope».

Тесты выводят ожидания из спецификации и геометрии сцен (независимые эталоны координат), а не из продакшн-кода.
Эталоны считаются вручную (см. «Сцены»).

### Сцены (эталоны)

Нормаль грани — `(−d.y, d.x)` оси a → b; `face: 1` лежит на её стороне (для горизонтальной стены a → b вдоль +x
это `y = +t/2`). Откос `a` — меньшая координата вдоль оси, `b` — большая.

## Boundary Cases

| Case | Input | Expected |
|---|---|---|
| Откос на торце стены | R1: курсор в (10, 10) в радиусе | `anchor.kind` не `"jamb"` (вершина контура), `point` = (10, 10) (DA-5) |
| Равенство расстояний в 1e-9 | курсор строго посередине между вершиной и откосом на расстоянии ≤ 1e-9 от равных | побеждает вершина (DA-5b) |
| Откос ближе вершины на 0.5 см | курсор у откоса, вершина дальше | побеждает откос (DA-6) |
| Радиус привязки | курсор ровно на `radius` от откоса / на `radius + 0.01` | точка найдена / `null` (DA-7b) |
| Окно на всю длину стены | элемент t 0…len | откосы совпадают с торцами; вершина побеждает у торцов (DA-5c) |
| Ширина элемента → минимальная | ширина 1 см | откосы различимы: `a` и `b` по разные стороны, расстояние 1 (DA-10b) |
| Откос и вершина в разных стенах | R2 | каждая точка разрешается в своей стене (DA-1b) |
| Диагональная стена | FD | эталоны точек с нормалью (−0.8, 0.6) (DA-14) |
| Нулевая длина | обе точки на одном откосе | `dimGeometry(...)` → `null`, размер не создаётся (DA-21) |
| Пустой список элементов | `elements = []` | точки-откосы → `null`, граневые точки как прежде (DA-22) |

## Negative Cases

| Case | Expected behavior |
|---|---|
| Точка ссылается на удалённый элемент | `dimPointPoint` → `null`, рендер и PDF пропускают размер без исключения (DA-32, DA-36) |
| Элемент есть, стены-хозяина нет (остаток «Монтажа») | `dimPointPoint` → `null` (DA-37b) |
| Откос на `jamb: "c"` / `face: 0` / `face: "left"` | размер отбрасывается при загрузке, остальные данные целы (DA-31) |
| Вырожденная опорная стена (нулевой длины) | `dimPointPoint` → `null`, нет `NaN` (DA-39) |
| Курсор рядом с откосом элемента на ДРУГОЙ грани за пределами радиуса | точка не задаётся (DA-7c) |
| Курсор у откоса, а `elements` не передан | точка откоса не предлагается (DA-40; защищает от пропуска передачи списка в вызове) |
| Клик вне вершин и откосов | `nearestDimAnchor` → `null` (DA-7, DA-8) |
| Удаление не связанного элемента | размеры других элементов и граневые размеры не меняются (DA-26) |
| Удаление элемента без размеров | `deleteObjects` не меняет список размеров (DA-26b) |

## Invariants

- Позиция точки-откоса = `hostPoint`-эталон сцены при любых допустимых правках: сдвиг, смена ширины, смена привязки,
  перенос, удлинение, поворот стены (DA-9…DA-15); координаты в размере не хранятся — тесты не читают их из данных.
- `jamb: "a"` всегда имеет меньшую координату вдоль оси, чем `jamb: "b"`, для любого элемента и любой привязки (DA-11).
- Две грани одного откоса отстоят на толщину стены вдоль нормали (DA-2).
- Расстояние между откосами одной грани равно разности координат вдоль оси (DA-1, DA-16).
- После `deleteObjects` ни один оставшийся размер не ссылается на удалённый элемент или удалённую стену (DA-23…DA-27).
- Сериализация и разбор размера — взаимно обратны для обоих видов точек (DA-28, DA-33); граневая точка не
  приобретает поле `kind` (DA-30).
- `cloneScene` не меняет исходную сцену и не теряет поля откоса (DA-17).
- Вызовы со старой сигнатурой (без `elements`) дают прежний результат (DA-22) — регрессия на утверждённые тесты.

## Integration Cases

- Последовательность стен: комната рисуется стена за стеной (4 порядка) с окном на первой стене; размер между
  откосами окон остаётся на откосах при добавлении последующих стен, меняющих контуры (DA-41).
- Составная стена FC: окно на втором участке, затем удлинение первого участка (DA-16b).
- Размер «откос окна ↔ вершина контура соседней стены» (DA-3b) следует при повороте этой соседней стены.
- Сохранение → загрузка → рендер: размер с откосами, сохранённый и загруженный, рисуется там же (DA-34, DA-28).
- Удаление стены каскадом → undo → redo: элементы и размеры к откосам возвращаются и удаляются одним шагом (DA-25, DA-24).
- План «Монтаж»: размеры и элементы плана хранятся и читаются так же, как на обмере (DA-29, DA-37).
- Совместность с `auto-dimensions`: автоматические размеры стены с элементами не меняются (проёмы на них не
  влияют) — регрессия (DA-42).

## Mutation Targets

Мутации, которые тесты обязаны ловить (ручные мутанты на эталонной реализации валидатора; инструмента Stryker в
проекте нет):

- откосы `a`/`b` перепутаны (инверсия `jambsT` индекса) — DA-1, DA-2, DA-11;
- `face` инвертирован или не учитывается (обе грани дают одну точку) — DA-2, DA-4;
- вместо `thickness / 2` используется `thickness` или 0 — DA-2;
- для привязки `b` откосы считаются как для `a` (игнорируется `anchor`) — DA-11, FB;
- координата откоса сохранена в размере при создании (не следует за элементом) — DA-9…DA-15;
- кандидаты откосов не участвуют в снапе / участвуют только откосы a — DA-4, DA-7;
- равенство расстояний решается в пользу откоса — DA-5;
- проверка «вершина при равенстве» заменена на `<` без допуска 1e-9 — DA-5b;
- `deleteObjects` не вычищает размеры по откосам при явном удалении элемента — DA-23;
- `deleteObjects` вычищает только `from`, не `to` (одна из двух точек) — DA-23 (оба порядка), DA-25;
- каскад по опорной стене не удаляет размеры по откосам её элементов — DA-25;
- `deleteObjects` удаляет размеры всех элементов, а не только удаляемого — DA-26;
- `cloneScene` теряет `kind`/`elementId` (пересобирает `{a, b}`) — DA-17, DA-24;
- `isDimension` принимает откос без `elementId` / с `jamb` вне `a`/`b` / с `face` вне ±1 — DA-31;
- `isDimension` отвергает граневую точку без `kind` — DA-30;
- `copyDimension` пропускает `face` или `jamb` — DA-28;
- загрузка отбрасывает размер с отсутствующим элементом (проверка существования вместо формата) — DA-32;
- `dimPointPoint` возвращает не `null`, а `{x: NaN}` на вырожденной стене — DA-39;
- читатель размеров не получает элементов (рендер/PDF/hit-test) — DA-34, DA-35, DA-38.

## Out of Scope

- DOM-маршрутизация `main.ts` (клики, отметка снапа на canvas, Esc/двойной клик) и ручные UI-проверки в браузере —
  выполняются вручную на этапе verify по `memory/browser-manual-checks` и покрываются через чистые функции,
  которые вызывает `main.ts` (`nearestDimAnchor`, `deleteObjects`).
- Автоматические размеры с элементами (не меняются).
- Подсветка элемента под курсором (открытый вопрос design; пока только отметка снапа).
- Мутационное тестирование инструментом (в проекте нет Stryker); вместо него ручные мутанты валидатора.
- Существующие утверждённые тесты не меняются и не дублируются; их полный прогон — часть валидации
  (`validate-against-full-suite`): валидатор прогоняет новые и все существующие тесты на эталонной реализации.
