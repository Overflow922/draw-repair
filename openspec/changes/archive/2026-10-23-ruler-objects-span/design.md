## Context

Требования — в `specs/ruler-tool/spec.md` этого change; мотивация — в `proposal.md`.

Сейчас `rulerReading(p, walls)` (`src/ruler.ts`) строит формы стен через `displayPolygons`, ищет стену под курсором (`wallUnder`) и иначе бросает лучи (`span`) по рёбрам этих форм. Пять `draw*Plan` в `src/main.ts` вызывают её с рабочим списком стен плана `walls`, а `drawRuler` (`src/render.ts`) рисует результат как размерные линии цветом `palette.angle`.

Объекты хранятся по-разному и привязаны к разным данным:

| Объект | Данные | Форма в плане |
|---|---|---|
| Батарея | `Battery` + стена-хозяин (`wallId`) | `batteryRect(b, host)` — четыре угла |
| Воздуховод | `Duct` | прямоугольник по осям |
| Стояк | `Riser` | круг |
| Предмет мебели | `FurnitureItem` | `itemCorners(t)` — повёрнутый прямоугольник |

Рядом уже есть `obstaclesOf` (`src/furniture/overlap.ts`), но он решает другую задачу: вырезает проёмы из стен, добавляет полосы штукатурки и приближает круг 48-угольником. Для линейки эти три свойства неверны (луч через проём упирается в стену, штукатурка не препятствие, стояк должен давать точный радиус), поэтому переиспользуются только его «кирпичики» (`batteryRect`, `shapeOfCommunication`, `itemCorners`), а не сам `obstaclesOf`.

## Goals / Non-Goals

**Goals:**
- Пролёт и замер объекта считаются в чистом модуле `ruler.ts` без DOM и без знания о планах.
- Каждый план передаёт линейке ровно те объекты, которые нарисованы на нём.

**Non-Goals:**
- Не менять определение помещений и углы (`room-areas`).
- Не вырезать проёмы из препятствий и не учитывать полотно двери и дугу открывания.
- Не вводить общий реестр «объектов чертежа»: одна функция-сборщик на вызов, без хранения.

## Decisions

### D1. Объект линейки — ориентированный прямоугольник или круг

В `src/ruler.ts` объявляется дискриминированный тип:

```ts
export type RulerObject =
  | { kind: "rect"; center: Point; u: Point; widthCm: number; depthCm: number } // u — единичная ось ширины, ось глубины v = (−u.y, u.x)
  | { kind: "circle"; center: Point; diameterCm: number }
```

Все четыре вида объектов приводятся к нему: мебель, воздуховод и батарея — к `rect`, стояк — к `circle`. Плюсы: один код для пролёта и для замера объекта; круг остаётся точным (`rect` с 48-угольником дал бы расхождение около 0,1 мм у стояка диаметром 10 см и сломал бы «ближайшая точка окружности»).

Рассмотрено и отклонено: передавать готовые `Shape` из `communications/shape.ts`. У него нет осей и размеров, а замер объекта их требует.

### D2. Адаптеры — отдельный модуль `src/ruler-objects.ts`

Чистые функции, превращающие данные чертежа в `RulerObject[]`:

- `furnitureRulerObject(item)` — центр, ось `u` из `angleDeg`, ширина и длина;
- `ductRulerObject(duct)` — ось `u = (1, 0)`, ширина и глубина;
- `riserRulerObject(riser)` — круг;
- `batteryRulerObject(battery, host)` — углы из `batteryRect`: центр — среднее четырёх углов, `u` — вдоль стены, ширина — длина батареи, глубина — толщина; без хозяина объект не создаётся (как в `obstaclesOf`);
- `rulerObjectsOf({ walls, batteries, communications, items })` — собирает список в фиксированном порядке: батареи, коммуникации, мебель.

Порядок списка задаёт «стоящий раньше» при равенстве расстояний до центров. `ruler.ts` ничего не знает о `Battery`, `FurnitureItem` и т. д.: зависимость идёт от адаптеров к типу `RulerObject`, а не наоборот.

### D3. Подпись `rulerReading(p, walls, objects)`

Третий параметр — `readonly RulerObject[]`. Порядок решений внутри: сначала `wallUnder` (стена главнее объекта), затем `objectUnder` (ближайший центр, при равенстве — раньше в списке), иначе `space`.

`RulerReading` получает вариант `{ kind: "object"; measures: Span[] }`. Тип `Span` (`from`, `to`, `lengthCm`) уже подходит; отдельный тип для линии объекта не нужен.

### D4. Пролёт — рёбра форм стен + рёбра прямоугольников + круги

`span` принимает рёбра (из стен и из `rect`) и круги отдельно. Пересечения лучей с рёбрами считаются как сейчас. Для круга луч по оси `axis` на высоте `d = p[across] − c[across]` пересекает окружность при `|d| < r` в точках `c[axis] ± sqrt(r² − d²)`. Берутся ближайшее слева и ближайшее справа от `p` — те же `lo` и `hi`, что у рёбер. Касательный луч (`|d| = r`) пересечением не считается.

Курсор внутри объекта до `span` не доходит (приоритет в D3), поэтому проверки «внутри» для лучей не нужны.

### D5. Замер объекта — линии через курсор, у круга — диаметр

Для `rect` с центром `c`, осями `u`, `v` и точкой курсора `p`: пусть `a = (p − c)·u`, `b = (p − c)·v`. Линия ширины идёт от `c + b·v − u·widthCm/2` до `c + b·v + u·widthCm/2` (длина `widthCm`), линия глубины — от `c + a·u − v·depthCm/2` до `c + a·u + v·depthCm/2` (длина `depthCm`). Обе проходят через `p` и упираются в грани. Так линии следуют за курсором, а подписи двух линий (середины отрезков) разведены. Для `circle` — одна горизонтальная линия от `c − (r, 0)` до `c + (r, 0)`: показывается диаметр, а не хорда через курсор (так требует спека).

Рассмотрено и отклонено: обе линии через центр объекта. Их подписи (посередине) совпали бы в центре.

### D6. Какие объекты передаёт каждый план

Каждый вызов в `main.ts` собирает `rulerObjectsOf(...)` из тех же списков, которые план передаёт в рендер:

| План | Стены (как сейчас) | Объекты |
|---|---|---|
| Обмер | `walls` | `batteries`, `communicationsOf()` |
| Демонтаж | `walls` | `batteries` (в том числе помеченные к сносу: они нарисованы), `communicationsOf()` |
| Монтаж | `walls` | `batteries`, `communicationsOf()` |
| Черновые работы | `s.base.walls` | `s.base.batteries`, `communicationsOf()` |
| Реконструкция | `walls` | `batteries`, `communicationsOf()` |
| Мебель | `walls` | `batteries`, `communicationsOf()`, `items` |

Четыре повторяющихся вызова сворачиваются в одну локальную функцию `rulerOf(cursorWalls, cursorBatteries, withItems)` в `main.ts`, которая содержит условие `tool === "ruler" && cursor && !gestureActive()`. Новая функция заменяет пять копий условия, а не добавляет шестую.

### D7. Отрисовка

`drawRuler` (`src/render.ts`): список линий — `ruler.measures` для вида `object`, остальное без изменений. Углы рисуются только для `space`. Цвет, засечки, подложка, постоянные экранные размеры — те же, что у замера стены; новых элементов UI нет (`.claude/rules/ui.md`), картинка-образец для нового вида объекта не нужна (формы объектов не меняются).

## Risks / Trade-offs

- [Батарея без стены-хозяина в списке `walls`] → объект пропускается (как в `obstaclesOf`); тест на сцену с удалённой хозяйкой.
- [Объекты и стены в одной точке: луч упирается в «шов»] → берётся ближайшее пересечение, лишней логики для сшивки нет; тест «батарея вплотную к стене».
- [Пересечение предметов мебели между собой] → мебель может перекрываться (подсвечивается как пересечение); замер берёт предмет с ближайшим центром, а пролёт — ближайшую грань любого.
- [Круг в `span` даёт иррациональные точки] → числа форматируются существующим `formatLength`; тест допускает 0,001 см.

## Migration Plan

Миграции данных нет: замеры не хранятся. Откат — возврат старой сигнатуры `rulerReading(p, walls)`.
