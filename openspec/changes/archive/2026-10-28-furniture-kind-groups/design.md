## Context

См. proposal.md — Why. Сейчас вся мебель — один инструмент `furniture` (`Tool` в `src/doorway/openings-group.ts`), один выбранный вид `furnitureKind` и одна панель `#furniture-panel` со списком кнопок видов, который `main.ts` строит циклом по `FURNITURE_KIND_ORDER`, и полями ширины, длины, угла (у унитаза — свои). Состояние кнопки группы и её панели — общий `GroupState<T>` с переходами `groupButtonClick` и `groupPick`, по нему работают «Проёмы», «Коммуникации», «Освещение» и «Мебель».

Картинки из `references/` не нужны: меняется меню, а не рисунок объекта. Иконки кнопок групп берутся из иконок видов каталога.

## Goals / Non-Goals

**Goals:**
- четыре кнопки групп видов на первом уровне панели инструментов вместо одной;
- в панели каждой группы только кнопки её видов и поля активного вида;
- никаких новых элементов интерфейса: структура, поведение и стили — как у существующих групп (`ui.md`).

**Non-Goals:**
- менять инструмент `furniture`, хранение, историю, пересечения, рисунки, PDF;
- переупорядочивать каталог (порядок задаёт плашку пересечений и легенду PDF);
- пользовательские группы, сворачивание, поиск по видам.

## Decisions

**D1. Группа — поле записи каталога.** `FurnitureKindEntry.group` принимает одно из четырёх значений (`room`, `bedroom`, `kitchen`, `bathroom`); список групп с названиями и иконками лежит рядом с каталогом, а состав группы получается фильтрацией `FURNITURE_KIND_ORDER`. Так «новый вид — новая запись» остаётся верным: к записи добавляется одно поле, а скилл `add-furniture-kind` получает шаг «выбрать группу». Альтернатива — отдельная таблица «группа → виды» — отвергнута: вид можно забыть в таблице, а поле группы тип обязывает заполнить.

**D2. Инструмент один, групп четыре.** `Tool` не меняется, группа — только способ выбрать вид и открыть панель. Кнопка группы активна, когда `tool === "furniture"` и вид активного инструмента принадлежит этой группе. Альтернатива (четыре инструмента) отвергнута: завязаны план, PDF, ластик, история, а поведения это не меняет.

**D3. Текущий вид каждой группы.** Состояние группы — `GroupState<FurnitureKind>` по `current` на группу (по умолчанию первый вид группы), а `active` — вид активного инструмента, если он из этой группы, иначе `"other"`. Клик по кнопке группы и выбор вида в панели идут через те же `groupButtonClick` и `groupPick`. Открыта панель не больше чем одной группы: открытие панели одной закрывает остальные.

**D4. Панель и поля.** Поля «Ширина / Длина / Угол» и поля унитаза остаются как есть (пункт 2 решений исследования: «пока оставить где есть»). Чтобы не размножать поля и их `id`, панели групп делят один блок параметров: он остаётся единственным экземпляром в разметке, а панель каждой группы — это контейнер кнопок видов группы; блок параметров показывается внутри панели открытой группы. Способ (перенос узла блока или единая оболочка панели с заголовком-группой) выбирает реализация, если соблюдены сценарии спеки; ни одного нового вида контрола он не вводит.

**D5. Выделение.** Выделение предмета открывает панель группы его вида (закрыв панель другой группы) и показывает его значения; текущий вид группы при этом не меняется, как не менялся `furnitureKind` раньше. Установка предмета оставляет открытой панель группы поставленного вида.

**D6. Иконки групп.** «Комната» — иконка «Диван», «Спальня» — «Кровать», «Кухня» — «Кухонный шкаф», «Санузел» — «Унитаз». Своих рисунков не вводим.

## Risks / Trade-offs

- [Панель инструментов становится выше: четыре кнопки вместо одной] → на плане «Мебель» других кнопок пять («Размер», «Выноска», «Линейка», «Примечания», «Ластик»), в сумме девять — столько же, как на обмерочном плане; проверить вручную на невысоком окне.
- [Кухня остаётся самой большой группой: 11 видов] → это решение пользователя (стиральная и сушильная машины остаются на кухне); при росте каталога группа делится по тому же полю.
- [Спеки ссылаются на «панель группы «Мебель»» и считают кнопки в ней] → сценарии каталога про «двадцать пять»/«двадцать семь кнопок» заменены сценариями по группам (дельта-спека `furniture-plan`).
- [Разметка: общий блок полей между панелями] → реализация проверяется тестом `furniture-ui`: поля одни, значения вида и выделенного предмета те же, что до изменения.
