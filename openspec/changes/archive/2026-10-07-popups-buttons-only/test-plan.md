# Test Plan

## Scope

Поведение change `popups-buttons-only`:

- инвариант панелей: в разметке вспомогательных панелей только кнопки, панели есть только у «Стена» и группы
  «Проёмы»; выделение не трогает группу (`canvas-app`);
- правимые числа выделенного элемента стены: раскладка, попадание, подчёркивание, применение по цели
  (`doorway` «Ввод чисел размеров проёма», `window` «Правка подписи окна»);
- параметры новых элементов: начальные значения, наследование от правки, независимость видов, что их не меняет
  (`doorway`/`door`/`window` «Инструмент … и параметры новых …»);
- сторона открывания призрака двери по курсору с мёртвой зоной (`door` «Инструмент «Дверь» и параметры новых
  дверей»);
- зоны направления выделенной двери: геометрия, приоритеты нажатия, история, наследование петель, штриховые
  альтернативы (`door` «Направление выделенной двери»);
- история: правки на месте и смена направления — шаги, параметры новых — нет (`drawing-history`);
- размер без панели (`dimension-selection`).

Уровни: модульные тесты чистых функций (D9) и адаптеров `createElementTool` / `createSelectionEditing` с
фейковым хостом (как `door-tool.test.ts`); тесты отрисовки на записывающем контексте (как
`door-render.test.ts`); тесты разметки по `index.html` (как `openings-group.test.ts` GR-09…GR-10).
Единица в тестах — см, если не сказано иное; сцены — `sceneF()` (свободная стена W `(0,0)–(500,0)`, толщина 20)
и раскладка с углами L, R (`doorway.test-utils.ts`).

## Boundary Cases

| Case | Input | Expected |
|---|---|---|
| мёртвая зона стороны открывания | `s = ±deadCm` | прежняя сторона (включительно) |
| мёртвая зона — чуть дальше | `s = deadCm + 0.01` | сторона по знаку |
| мёртвая зона зависит от зума | zoom 1 и zoom 2 (`PX_PER_CM = 2`) | zoom 1: `deadCm = 2`; zoom 2: `deadCm = 1` |
| граница зоны вдоль оси | `x = 145` (середина двери 100…190) | точка принадлежит обеим половинам; выбирается любая, но не `null` — тест проверяет только не-null и сторону |
| граница зоны поперёк | `y = 10` (грань), `y = 100` (грань + w) | внутри зоны `right`; `y = 100.5` и `y = 9.5` — вне |
| подоконник 0 | ввод «0» | применяется, запись есть |
| высота 0 | ввод «0» | не применяется |
| запятая | «2,5» при единице м | 250 см |
| нулевое расстояние в цепочке | «0» у откоса | правимое число (PB-EN-01b), подчёркнуто (PB-RN-01b) |
| подчёркивание числа цепочки | выделенный проём | размерная линия под числом штриховая (design D2) — PB-RN-01 |
| ширина ограничена инвариантом | 200 при свободных 180 | элемент 180, `inherit` получает 180 |
| ввод без изменения | то же значение | записей 0, `inherit` не вызван |

## Negative Cases

| Case | Expected behavior |
|---|---|
| клик по подписи невыделенного проёма | `pressNumber` → `false` |
| клик по числам призрака | `pressNumber` → `false` (нет выделения) |
| выделение проёма + стены | `pressNumber` → `false`, подчёркиваний нет |
| `pressZone` у выделенного проёма или окна | `false`, элемент не изменён |
| `pressZone` при ластике | адаптер не вызывается: проверка в PB-INT-02 по порядку в `pointerdown` (исходник: ветка `tool !== "eraser"`) |
| нечисловой ввод в любое правимое число | элемент прежний, записей 0 |
| Esc / blur в редакторе | элемент прежний, записей 0, `inherit` не вызван |
| выделение, перемещение, стрелки, установка | `inherit` не вызван ни разу |

## Invariants

- `inherit` вызывается только после применённой правки на месте или смены направления и только с фактическим
  элементом после ограничения инвариантом.
- Параметры одного вида не меняются правкой элемента другого вида.
- Сторона открывания никогда не входит в параметры новых дверей.
- Подчёркивания и зоны существуют только при одиночном выделенном элементе своего вида и только на экране.
- Правимые числа главнее зон; зоны главнее элементов, стен и размеров под ними.
- Раскладка правимых чисел подписи совпадает с отрисованной подписью: центр «H=…» у проёма — центр рамки
  подписи (PB-EN-04 сверяет с `elementLabelLayout`).
- Чистые функции не мутируют вход (`inheritFrom`, `setDirection`, `ghostSwing`).

## Integration Cases

- PB-INT-01: `main.ts` хранит одно значение параметров новых элементов вне данных вкладок и истории.
- PB-INT-02: порядок нажатия в `pointerdown` вне ластика — `pressNumber` → `pressZone` → `pressPick` (исходник без комментариев).
- PB-INT-03: хост элементов в `main.ts`: `params` возвращает одно значение из `initialParams()`, `inherit` присваивает ему `inheritFrom(значение, e)`; `inheritFrom` вызывается один раз.
- PB-TL-*: инструменты читают параметры из `host.params()`; два инструмента с общим хостом видят правки
  друг друга по своему виду и не видят чужие.
- Разметка: `index.html` после change не содержит удалённых идентификаторов (PB-UI-02).

## Mutation Targets

- `ghostSwing`: `≤` ↔ `<` на границе мёртвой зоны; знак нормали; `deadCm` без деления на `k`.
- `doorZoneAt`: середина двери вместо откоса; `w` ↔ толщина; сторона `left`/`right` перепутана; петли `a`/`b`
  перепутаны.
- `inheritFrom`: обновление не того вида; перенос `swing` в параметры; потеря `sillCm`.
- `createSelectionEditing`: `inherit` до ограничения инвариантом; `inherit` при `unchanged`/`rejected`;
  запись истории при `unchanged`; приоритет зоны над числом.
- `editableNumbers`: пропуск нулевого расстояния; цель `height` у части «H под.»; правимые числа при
  мультивыделении.
- Отрисовка: подчёркивание при отсутствии выделения или в PDF.

Инструмента мутационного тестирования в проекте нет (`package.json`); мутации проверяются вручную валидатором.
