# Test Plan

## Scope

Проёмы в стенах: новая возможность `doorway` и дельты `wall-collision`, `wall-drawing`, `wall-deletion`, `multi-selection`, `drawing-storage`, `drawing-history`, `pdf-export`, `room-areas`.

В проекте нет DOM-окружения тестов (`vitest` в node, без jsdom): обработчики указателя и клавиш в `main.ts` автоматически не тестируются. Поэтому поведение проверяется через **чистые публичные функции** (design D3–D10) и через `drawScene` с записывающим контекстом (как `room-area-render.test.ts`, `ruler-e2e.test.ts`). Решения, которые иначе жили бы в `main.ts` (каскад удаления, попадание и приоритеты, рамка, стрелки), выносятся в чистые функции модулей `src/doorway/` — это часть контракта тестов. То, что остаётся только в DOM (поле ввода на месте числа, панель, фокус), — ручные проверки в браузере (раздел «Ручные проверки»).

### Сцены (см, толщины — `t`)

- **F** — свободная стена W `(0,0)-(500,0)` t20.
- **R** — комната: W `(0,0)-(500,0)`, R `(500,0)-(500,400)`, B `(500,400)-(0,400)`, L `(0,400)-(0,0)`, все t20, углы с общими вершинами; помещение со стороны `y > 0` у W, грань W `y = +10` — внутренняя. Сторона грани `side` = знак `cross(d, p − a)` для точки `p` грани: у W (`d = (1,0)`) грань `y = +10` — `side = +1` (сторона нормали `(−d.y, d.x)`; на экране с осью y вниз это **справа** от `a → b`, а «слева на экране» — сторона `(d.y, −d.x)`, см. spec doorway «Отображение проёма»), грань `y = −10` — `side = −1`.
- **RP** — R + перегородка P `(300,10)-(300,390)` t10 (торцы на внутренних гранях W и B).
- **D0** — проём на W: `anchor a`, `offset 100`, `width 90`, `height 210`.
- **RT** — две комнаты: R + перегородка Q `(250,10)-(250,390)` t10, проём на Q `anchor a`, `offset 100`, `width 90`.
- **UO** — R с проёмом на W вплотную к L: `anchor a`, `offset 10`, `width 90` (внутреннее расстояние 0).

Допуски: координаты и расстояния `toBeCloseTo(x, 3)`; «касание» — `|x − эталон| ≤ 1e-3`.

## Invariants

- После любой операции `doorway-edit` с `applied` → `doorwayHolds(result, walls) === true` (DE-*, свойство проверяется в каждом тесте).
- После любой ограниченной правки стен с проёмами → все проёмы `doorwayHolds` (если до правки держались) — проверка «по всем проёмам» после каждого DG-теста.
- Ширина при вводе расстояния и при перемещении не меняется; высота не меняется ничем, кроме поля H.
- `anchor` меняется только вводом расстояния.
- Каноническая форма стены не зависит от проёмов (DL-11).
- Правки стен не меняют данные проёмов (`offset`, `anchor`, `width` — те же объекты/значения); положение — только через геометрию стены.
- Каскад: после `deleteObjects` нет проёмов, ссылающихся на удалённые стены.
- Расстояния двух граней различаются ровно на геометрию стыков, ширина одна (`a + width + b` = длина свободного участка на каждой грани).

- `moveWallsBounded` / `moveEndpointBounded` / `resizeWallBounded` с `EditMode.doorways` — DG-01…DG-14: ограничение + D5 + следование данных (D1) вместе.
- `planEdit` орто-растяжение через ограничитель с проёмом (DG-10).
- `snapWithSource` + `violatesDoorways` (DD-01…DD-04).
- `drawScene` → записанные операции: вырез, серые линии, подпись, размеры (DL-*), PDF через `buildPdf` (DP-*).

## Mutation Targets

Инструмента мутационного тестирования в проекте нет; ниже — ручные мутации, которые валидатор применяет локально (и откатывает) для проверки силы тестов:

- `doorway-faces`: знак `ε` у внутренней/наружной пробной линии; `≤`/`<` в инвариант; `t0`/`t1` перепутаны; сторона грани (`side`) перевёрнута.
- `jambsT`: ветка `anchor b` (`L − offset − width`).
- `doorway-edit`: смена `anchor` в `setDistance`; фиксированный откос в `setWidth`; `Math.round` → `Math.floor`; ограничение по участку текущего положения vs всей стене; допуск 0.5° в `arrowSlide`; знак направления стрелки.
- `doorway-guard`: пропуск стен-соседей (только изменённые); игнор `thickness`; разрешение «не углублять» как «разрешить всё».
- `wall-edit`: проверка проёмов только в конце пути.
- `doorway-layout`: приоритет размер/проём/стена; рамка по оси между откосами vs по всей стене.
- `storage`/`history`: отсутствие `doorways` → повреждённый документ; фильтр сирот.

## Out of Scope

- Дверное полотно, дуга, окна; ручные размеры к откосам.
- Точная экранная раскладка (отступы цепочек и подписи в пикселях) — открытый вопрос design; тесты проверяют сторону и наличие, не пиксели.
- Производительность ограничителя — замер вручную на чертеже ~100 стен (design Risks), не автотест.
- Поведение поля ввода при зуме/панораме — открытый вопрос design.
