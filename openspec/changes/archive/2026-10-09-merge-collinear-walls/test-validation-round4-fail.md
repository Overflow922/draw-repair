## Резюме

63 теста закрыли все находки раунда 3: из 220 мутантов (136 новых + 84 перенесённых из раундов 2-3, с пересечением) существующий набор убивает все, кроме 21 + 3. Из выживших 20 эквивалентны или вне объёма (список ниже). Остался один мутант, входящий в объём:

- F1: проверка нарушения проёма выполняется для «E без удлинения + новая стена» вместо удлинённой стены (мутант M180, он же M93 этого раунда). Это естественная ошибка реализации (вызвать обычную проверку постановки на сцене, где новая стена добавлена отдельно). Спека требует: «нарушение проёма ДОЛЖНО проверяться для удлинённой стены, и тогда слияние НЕ ДОЛЖНО выполняться». Тело удлинённой E и пара «E + N с митром стыка» дают разные нарушения проёма на наклонной стене; мутант объединяет и оставляет в чертеже нарушенный проём. Ни один из 63 тестов этого не различает (MW-12 и MW-32 используют перпендикулярную V, где обе проверки согласны). Раунд 3 записал M180 как «нет расхождений на чистых сценах»; направленный перебор показал расхождения на допустимых (до слияния проём не нарушен) сценах, см. F1.

Вердикт: FAIL, вернуть в Test Writing (один тест MW-36).

## Находки

### F1. Проверка проёма идёт по удлинённой стене (MW-36)

Предложение спецификации: «нарушение проёма ДОЛЖНО проверяться для удлинённой стены, и тогда слияние НЕ ДОЛЖНО выполняться и стена НЕ ДОЛЖНА фиксироваться»; сценарий «Продолжение нарушает проём другой стены»; инвариант размещения проёма сохраняется (doorway, «Элементы остаются на месте»). Мутант M180 заменяет проверку на `violatesDoorways(scene.walls, [...scene.walls, wall], doorways)`.

Достижимость: в направленном переборе 17920 сцен (допустимая сцена до слияния) эталон возвращает `blocked`, а M180 возвращает `merged` в 186 сценах из 16759, и во всех 186 итоговая сцена M180 нарушает проём (`doorwayHolds = false`, нарушение 1.68 см при 0 до слияния). Типичный случай: тонкая наклонная стена с проёмом пересекает ось E у свободного конца; удлинённое тело E заходит в проём на доли сантиметра. Фаззинг первого этапа показал 7 допустимых расхождений из 6000. Пользователь может нарисовать такое продолжение, и в чертеже останется нарушенный проём.

Тест (добавить в `src/wall-merge.test.ts`, использует `Scene`, `door`, `w`, `mergeContinuation`, `doorwayHolds`; все импорты в файле уже есть). Числа выведены из геометрии: F толщины 10 через `(-60, 0)` под 75 градусов, длина 400, проём шириной 60 на 130..190 см от `a` лежит в `y` от `-67.6` до `-9.6`, тело удлинённой E (`|y| <= 10`) заходит в него на 0.4 см:

```ts
it("MW-36: удлинённая стена врезается в проём наклонной стены, хотя отдельная стена не врезалась бы — blocked", () => {
  const c = Math.cos((75 * Math.PI) / 180)
  const s = Math.sin((75 * Math.PI) / 180)
  const f = w(-60 - c * 200, -s * 200, -60 + c * 200, s * 200, "F", 10)
  const el = door("F", "a", 130, 60)
  const scene: Scene = { walls: [w(0, 0, 500, 0, "E"), f], dimensions: [], doorways: [el] }
  expect(doorwayHolds(el, scene.walls, scene.doorways ?? [])).toBe(true)
  for (const tipX of [-67, -65, -60, -58]) {
    const before = snapshot(scene)
    expect(mergeContinuation(scene, w(-10, 0, tipX, 0, "N")).kind, `tipX=${tipX}`).toBe("blocked")
    expect(snapshot(scene)).toBe(before)
  }
})
```

Проверено в копии: проходит на эталоне; падает на M180 (`tipX=-67: expected 'merged' to be 'blocked'`). Тест не зависит от того, какой кандидат выбран, и не фиксирует числа нарушения. Таблицу покрытия в `test-plan.md` и `test-suite.md` нужно дополнить MW-36 (делает Test Writer).
