## Сводка

Из 257 мутантов выжили 35. Почти все они эквивалентны или вне объёма. Три выживших нарушают предложения спецификации, которые пользователь может воспроизвести, а тест на них не стоит. ## Находки (в объёме)

### F1. Проверка проёмов не покрывает элементы самой удлиняемой стены

Spec (wall-drawing): «нарушение проёма ДОЛЖНО проверяться для удлинённой стены, и тогда слияние НЕ ДОЛЖНО выполняться». Spec (doorway): после слияния «инвариант размещения проёма сохранён». MW-12, MW-32 и MW-36 проверяют только элементы другой стены V.

Мутант: `violatesDoorways(scene.walls, walls, doorways.filter((d) => d.wallId !== e.id))` проходит все 64 теста. Достижимая сцена, на которой он даёт неверный результат (проверено на эталоне и мутанте):

- E: `(0,0)-(500,0)`, 20 см, кирпич;
- F: `w(515, 10, 645, 85, "F", 30)`: стена 30 см, начинается рядом с торцом, торец E свободен;
- проём на E: `door("E", "b", 5, 90)`; до слияния `doorwayHolds` истинно;
- продолжение: `w(501, 0, 602, 0, "N")`.

Эталон: `blocked`. Мутант: `merged`, и после него `doorwayHolds` ложно: удлинённая E упирается в F внутрь собственного проёма. На 4 зёрнах VALID-fuzz мутант отличается от эталона в 2 сценах из ~13 500 слияний.

Что добавить, тест MW-37 (перед ним сцена):
1. Сцена выше → `mergeContinuation(...).kind` равно `"blocked"`, `JSON.stringify(scene)` не изменился.
2. Контроль: тот же набор, проём `door("E", "b", 100, 90)` → `"merged"`.
3. Вариант у конца a (проверено на эталоне): F = `w(-15, 10, -145, 85, "F", 30)`, проём `door("E", "a", 5, 90)`, продолжение `w(-1, 0, -102, 0, "N")` → `"blocked"`; с расстоянием 100 → `"merged"`.

### F2. Нулевое расстояние привязки (граница «не меньше 0»)

Spec допускает расстояние привязки 0 (элемент вплотную к концу), а storage его принимает. Ни один тест не ставит элемент на расстояние 0. Мутанты P1 и P2 (`el.offsetCm === 0 ? el : ...`, то есть элемент вплотную к удлиняемому концу «едет» вместе с концом) проходят все 64 теста; fuzz различается в ~460 сценах.

Что добавить, тест MW-38: на E из MW-1 элементы `door("E", "b", 0, 90, 210, "p")`, `win("E", "b", 0, 100, 150, 85, "q")` и `dr("E", "b", 0, "a", "right", 90, 210, "r")` (откосы `x = 410..500`). После `merged(..., N(510, 0, 900, 0))` каждый должен иметь привязку `a` и расстояние 410; `expectSameElement` для каждого. Зеркально у конца a: те же элементы с привязкой `a` и расстоянием 0 (откосы `x = 0..90`), продолжение `N(-10, 0, -400, 0)`, ожидание: привязка `b`, расстояние 410. Контрольная часть: элементы с расстоянием 0 у конца, который остаётся на месте (привязка `a` при слиянии у `b`), результат `toEqual` исходному и вид `merged`.

### F3. Свободность конца при стене другого материала

Spec: конец свободен, если плоскость торца «не закрыта телом другой стены, и в конце E не сходятся оси других стен»; материал занимающей стены не важен. Все тесты MW-8..8j используют кирпич. Мутант `wallEndOccupied(e, end, scene.walls.filter((x) => x.type === e.type))` проходит все тесты (в fuzz различий нет: он однотипный).

Что добавить, тест MW-8k: сцена `[E(), { ...w(500, 0, 500, 300, "F"), type: "concrete" }]` → `none`; то же с тройником (`{ ...w(500, -100, 500, 100, "G"), type: "concrete" }`) → `none`; то же у конца a (`{ ...w(0, 0, 0, 300, "F"), type: "concrete" }`, продолжение `N(-10, 0, -400, 0)`) → `none`.
