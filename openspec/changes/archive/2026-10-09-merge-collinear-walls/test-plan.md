# Test Plan

## Scope

Поведение слияния продолжения со стеной (specs `wall-drawing` «Продолжение стены удлиняет существующую» и `doorway` «Элементы остаются на месте при удлинении опорной стены»). Тесты проверяют наблюдаемый результат чистой функции `mergeContinuation(scene, wall)` из `src/wall-merge.ts` (design D1): результат `none` / `blocked` / `merged` и сцена после слияния — стены, элементы, размеры. Положение откосов элементов проверяется независимо от формул привязки — через `jambsT` на результирующей стене и сравнением с числами из спецификации в мировых координатах. Привязка начала к торцу (`snapStartVertex`) отдельно не тестируется: тесты подают стену с вершиной `a`, как её даёт привязка (на полтолщины за торцом), и с вершиной ровно в конце оси.

Вне автоматических тестов: подключение в `commitPoint` (`src/main.ts`) — проверяется вручную в браузере (цепочка: два отрезка по одной прямой, отмена/повтор, продолжение у проёма), результат записывается в `test-suite.md` и в TODO.md (нет автотеста обвязки, как у `auto-wall-dimensions`).

## Negative Cases

| Case | Expected behavior |
|---|---|
| Другая толщина или материал | `none`, сцена не меняется |
| Конец E занят стыком, T-примыканием, концом внутри контура | `none` |
| Обратное направление нового отрезка | `none` |
| Угол 90°, 45° к оси | `none` |
| Продолжение нарушает проём другой стены | `blocked`, `none` как результат слияния отсутствует |
| Несколько стен подряд: продолжается только та, чей конец свободен | `merged` для неё, остальные не меняются |

## Invariants

- Число стен после `merged` равно прежнему; после `none` и `blocked` вход не меняется.
- `id`, `thicknessCm`, `type` и положение в массиве удлинённой стены не меняются; направление оси `a → b` сохраняется (скалярное произведение нового и старого направлений положительно, векторы сонаправлены).
- Конец E, к которому не примыкает новая стена, не сдвигается.
- Новая вершина лежит на прямой оси E (расстояние ≤ 1e-9).
- Для каждого элемента: положения откосов в мировых координатах до и после слияния совпадают (≤ 1e-6), ширина, высота и прочие поля не меняются; `doorwayHolds` для каждого элемента истинно после слияния.
- Тело удлинённой стены покрывает тело E и тело нового отрезка (площадь контура = сумма площадей с промежутком, без щелей).
- `merged` ⇒ нет нарушения проёма (`violatesDoorways` ложно).

## Integration Cases

- Сцена с проёмом, окном и дверью на E; слияние у `b` и у `a`; затем `jambsT`, `doorLeaf`, `openingLines` на результате дают прежние места.
- Сцена из двух отрезков по одной прямой подряд (три вызова: стена 1 ставится, стена 2 сливается, стена 3 сливается): итог — одна стена, длина равна сумме длин и зазоров.
- Угловая комната: четыре стены цепочкой с углами — слияний нет, число стен прежнее.
- Размер длины, привязанный к торцу `b` (ребро 3), после слияния измеряет стену до нового конца.
- Хранение: `serializeHistory`/`parse` не требуют изменений — формат сцены после слияния проходит `isWall`/`isWallElement`.

## Mutation Targets

Правдоподобные ошибки, которые поверхностно верная реализация пропустит:
- допуск `0 ≤ s ≤ jointTol` заменён на `s ≥ 0` (сливает далёкие стены) или на `s > 0` (теряет вершину ровно в точке оси);
- проверка толщины пропущена или сравнивает с допуском; проверка материала пропущена;
- проверка свободного конца пропущена (сливает с T-примыканием, углом);
- направление не проверено: возврат назад «сливается»;
- допуск прямой 0.5 заменён на угол, проверяется только одна вершина нового отрезка;
- новая вершина берётся равной `wall.b` вместо проекции (нарушение «ось на прямой»);
- при слиянии у `a` меняется `b` (и наоборот); направление оси переворачивается;
- `blocked` возвращается как `none` (нарушающая проём стена ставится отдельно);
- элементы у удлинённого `b` не переприкрепляются (едут вместе с концом) — заметно только по откосам в мире;
- переприкрепление считает расстояние от нового конца вместо ближнего откоса (ошибка на ширину);
- удлинённая стена уходит в конец массива (меняется форма стыков);
- вход мутируется (история теряет прежнюю запись);
- слияние применено ко всем подходящим концам E, а не только к тому, у которого лежит начало;
- сравнение материала по ссылке/регистру.

## Out of Scope

- Слияние моста и слияние по концу новой стены (отдельное изменение).
- Объединение уже существующих стен при открытии и отдельной командой.
- Привязка начала к торцу (покрыта тестами `wall-snap`).
- Подключение в `main.ts` — вручную; автотест обвязки — TODO.md.
