## Context

См. proposal.md. Сейчас у страницы PDF нижняя полоса состоит из основной надписи (справа) и таблицы экспликации (слева, только «Монтаж»); её высота общая для документа (`bottomBandMm` в `src/export/explication.ts`), область чертежа считается из неё (`drawingArea` в `sheet-layout.ts`), страницы собираются `pagesOf` в `pdf.ts` как `PlanPage`.

Данные планов лежат так: обмер — поля `Drawing`, «Демонтаж» — `demolition*`-поля `Drawing`, «Монтаж» — `Drawing.mounting`. Для выносок этот разнобой уже закрыт функциями `calloutsOf`/`withCallouts` (`src/callout/callout-store.ts`). История — стек записей с видами (`kind`), у выносок свой вид `"callouts"` (`src/history.ts`); у каждого плана своя история (`historyKey`).

## Goals / Non-Goals

**Goals:**
- Примечания плана хранятся, правятся и выводятся в PDF по существующим паттернам (выноски, экспликация), без новых механизмов.
- Раскладка блока — чистая функция в миллиметрах, тестируется без DOM.

**Non-Goals:**
- Блока на холсте нет; нет шаблонов, форматирования текста, общих примечаний «на весь чертёж».
- Нумерация не хранится; ручные номера и вложенные пункты не поддерживаются.

## Decisions

**D1. Хранение: по образцу выносок.** Три поля `notes` в тех же местах, где лежат выноски плана (`Drawing.notes`, `Drawing.demolitionNotes`, `MountingContent.notes`); доступ через пару `notesOf(drawing, plan)` / `withNotes(drawing, plan, list)` в новом модуле `src/notes/notes-store.ts`. Тип — `string[]`. Загрузка: `loadNoteList` нормализует (массив, строки, обрезка, ограничения 15×300), отсутствие поля не дописывается; версия документа не меняется. Альтернатива — одно поле `notes: Record<PlanId, string[]>`: чище, но ломает единообразие с выносками и требует нового места в `mounting`.

**D2. Нормализация в одном месте.** Чистая `normalizeNotes(text: string): string[]` (разбить по строкам, обрезать, выбросить пустые, срезать по 300 и 15) используется и при применении правки в панели, и при загрузке (`loadNoteList` делает то же для массива). Так вход из UI и из хранилища не расходятся.

**D3. История: вид записи `"notes"`.** Снимок списка плана (копия массива) по образцу `"callouts"`: `recordNotes`, `undoNotes`, `redoNotes`; прежние функции отмены/повтора записи `"notes"` не забирают (как у `"callouts"`), `main.ts` в `undo`/`redo` диспетчеризует по верхней записи. Проверка снимка в `isEntry` — массив строк. Версия документа истории не меняется.

**D4. Панель — инструмент `notes` без жестов на холсте.** Копируем структуру существующих инструментов с панелью (кнопка + панель справа, повторный клик переключает панель, `canvas-app` «Вспомогательная панель инструмента»). Новый инструмент добавляется в `PLAN_TOOLS` всех трёх планов после «Линейки»; инструмент плана по умолчанию не меняется. Содержимое панели — `<textarea>`; это **осознанное исключение** из правила «в панели только кнопки», зафиксированное MODIFIED-дельтой `canvas-app` (в `ui.md` для текста «на месте» предписан холст, но у примечаний нет места на холсте — блок существует только на листе). Клавиши в textarea не пробрасываются в горячие клавиши холста — как у поля толщины стены. Применение: `blur`, закрытие панели, смена инструмента/плана, Esc; один шаг истории и только если `normalizeNotes(text)` отличается от текущего списка.

Альтернативы: (a) панель-переключатель, не меняющая активный инструмент, — проще для ввода посреди рисования, но это новый паттерн, `ui.md` запрещает без согласования; (b) блок на холсте с правкой на месте — две геометрии (мир и лист), отвергнуто с пользователем.

**D5. PDF: раскладка в `src/export/notes.ts`, рисование в `notes-draw.ts`** (рядом с `explication*.ts`, по тому же разделению). `notesLayout(items): { lines: {number?: string; text: string; y: number}[]; heightMm: number }` — перенос по пробелам по ширине 170 мм той же оценкой ширины текста, что `wrapName` в экспликации (общую функцию переноса выносим из `explication.ts` с параметром ширины и кегля, не дублируем). `notesRect(format, heightMm)` — правый нижний угол рамки над основной надписью, ширина 185 мм. `PlanPage` получает `notes?: readonly string[]`; `pagesOf` заполняет его из `notesOf` только когда список не пуст.

**D6. Высота нижней полосы.** `bottomBandMm` становится `max(titleH + max(notesHeight страниц), explicationH)`. Остальной код области чертежа (`drawingArea`, `legendArea`, `fitsFormat`, `placeOnPage`) уже принимает `bandMm` и менять не нужно. Блок примечаний стоит на основной надписи независимо от высоты экспликации, поэтому при высокой экспликации (`explicationH` > `titleH + notes`) над блоком остаётся свободное место — это допустимо.

**D7. Выгрузка без стен.** Кнопка экспорта сегодня отключена, если нигде нет стен и выносок (`main.ts`, `fit-scale.ts` — «заполненная» страница). Примечания сами по себе страницу «заполненной» не делают и экспорт не разрешают: примечания — приложение к чертежу.

**D8. Предел размера блока.** Максимум 15 пунктов и 300 символов в пункте ограничивает высоту блока (на A4 при 15 пунктах в одну строку ≈ 3+5+67,5+2 = 77,5 мм; с переносами выше). Если блок настолько высок, что область чертежа получается нулевой или отрицательной высоты, экспорт ведёт себя как при слишком большом чертеже (масштаб 1:1000 по `drawing-scale` «Масштаб не вычисляется сверх ряда»). Особой защиты сверх лимитов не вводим.

## Risks / Trade-offs

- [Исключение из правила «в панели только кнопки» закрепляет второй прецедент] → оформлено явно в `canvas-app`, дельта-спека и сценарий «Поле только в панели «Примечания»».
- [Общая высота полосы сжимает область чертежа на страницах без примечаний] → то же поведение, что у экспликации; нужно для единого масштаба документа (`drawing-scale`).
- [Правка применяется по blur: незавершённый ввод при закрытии вкладки браузера теряется] → применяем также на `pagehide`; иначе поведение как у выносок («Ввод текста на месте»).
- [Лимиты 15×300 выбраны без данных] → значения вынесены в константы; изменение — правка спеки `plan-notes`.
- [Оценка ширины текста при переносе приблизительна (как у экспликации)] → запас: ширина переноса 170 мм при блоке 185 мм; тест на «ни одна строка не шире блока» по реальной метрике jsPDF.

## Migration Plan

Миграции нет: поля необязательны, версия документа и истории не меняется, старые документы читаются как «без примечаний». Откат — удаление полей игнорируется читающим кодом без ошибок.
