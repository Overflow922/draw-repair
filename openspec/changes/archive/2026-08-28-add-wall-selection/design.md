## Context

Приложение — canvas-планировщик стен: `main.ts` держит состояние (`walls`, `chainStart`, `thicknessCm`, `wallType`, `view`), `geometry.ts` — чистая геометрия и привязки, `render.ts` — отрисовка. Модель `Wall { a, b, thicknessCm, type }` уже хранит толщину и тип, отдельного цвета нет (цвет определяется типом). Клик по холсту сейчас всегда фиксирует вершину цепочки; pan — средняя кнопка, зум — колесо. Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Выделение стены кликом без конфликта с рисованием цепочки, pan и зумом.
- Перетаскивание концов выделенной стены с существующими привязками (стены → оси 90° → сетка).
- Переиспользование поля толщины и образцов типа для правки выделенной стены без новой разметки.

**Non-Goals:**
- Перемещение всей стены, мультивыделение, удаление, undo/redo.
- Отдельный цвет стены вне типов.

## Decisions

### Состояние выделения — индекс стены в `main.ts`
`selectedWall: Wall | null` (ссылка на элемент `walls`). Клик по пустому месту снимает выделение и продолжает работу как раньше (начало цепочки); Esc снимает выделение, если цепочка не рисуется. Альтернатива — хранить индекс: хуже при возможных будущих операциях удаления/переупорядочивания; ссылка устойчива.

### Hit-test и маркеры концов — чистые функции в `geometry.ts`
- `hitWall(p, walls, toleranceCm): Wall | null` — расстояние от точки до осевой линии сегмента ≤ `max(thicknessCm / 2, toleranceCm)`; при перекрытии выбирается ближайшая. Переиспользуются существующие приватные `distance`/`projectOnSegment`.
- `endpointAt(p, wall, radiusCm): "a" | "b" | null` — попадание в конец стены.
- Допуски в экранных пикселях (`SNAP_RADIUS_PX`) конвертируются в см через `PX_PER_CM * view.zoom`, как в `toSnappedPoint` — поведение стабильно на любом зуме.

Альтернатива — проверять попадание только в габаритный прямоугольник: неточно для диагональных стен.

### Перетаскивание конца — pointerdown/move/up с мутацией стены
Drag начинается pointerdown левой кнопкой на маркере конца выделенной стены (`setPointerCapture`), только когда стена уже выделена. На каждом move: `snap(cursor, wallsWithoutDragged, GRID_STEP_CM, SNAP_RADIUS_PX / k, oppositeEnd)` — из кандидатов привязки исключается сама перетаскиваемая стена (иначе конец липнет к своему сегменту), `orthoFrom` = противоположный конец даёт осевую привязку 90° как при рисовании. Обновление конечной точки — прямая мутация стены и `redraw()` (подпись длины обновляется существующим рендером). Если snapped-точка совпадает с противоположным концом (`pointsEqual`) — обновление пропускается, так что нулевая длина невозможна и на release ничего откатывать не нужно. Реализация через иммутабельное превью с коммитом на release дала бы дублирование рендера без выгоды.

### Разделение клика и drag — флаг `suppressClick`
После drag конца браузер генерирует и `click`; он не должен ни выделять, ни фиксировать вершину. Флаг выставляется на drag и сбрасывается в обработчике `click`. Обработка `click`: если `chainStart` активен — существующий `commitPoint`; иначе `hitWall` → выделение (без начала цепочки) или `commitPoint` (снятие выделения + начало цепочки).

### Отображение — расширение сигнатуры `render`
`render(canvas, walls, preview, unit, view, selected?: Wall)`. Выделенная стена: обводка — тот же сегмент, отрисованный более широкой полупрозрачной линией контрастного цвета под стеной. Маркеры концов: круги постоянного экранного размера (радиус `HANDLE_PX / k`) с белой заливкой и тёмной обводкой, рисуются в мировых координатах. Стиль — код в `render.ts` без новых CSS-сущностей.

### Правка свойств — ветвление в существующих обработчиках
- `input` поля толщины: при `selectedWall` валидное значение пишется в `wall.thicknessCm` и одновременно в `thicknessCm` (дефолт), иначе — только в `thicknessCm` как сейчас. Некорректное значение не применяется никуда.
- `setWallType`: при `selectedWall` дополнительно `wall.type = t`; дефолт `wallType` обновляется как сейчас.
- При выделении: `syncThicknessBox` показывает толщину стены, `setWallType(wall.type)` подсвечивает образец.
- `syncThicknessBox` источником значения берёт `selectedWall?.thicknessCm ?? thicknessCm`, поэтому конвертация при смене единицы работает для обоих режимов без отдельной ветки.
- После снятия выделения ничего не сбрасывается — последние значения остаются дефолтами для новых стен.

### Стыки — чистая функция `moveEndpoint` в `geometry.ts`
`moveEndpoint(walls, wall, end, pos)` присваивает концу новую позицию и ту же позицию всем концам других стен, совпадавшим со старой (`pointsEqual`). Используется и в drag, и в клавиатурном ресайзе — сварка стыков едина. Альтернатива — двигать соседа только вдоль оси перетаскиваемой стены: сложнее и ломает диагональные стыки.

### Клавиатурное изменение длины — конец a неподвижен, ввод применяется немедленно
При выделенной стене `updateLengthBox` показывает живую длину стены (как превью при рисовании); ввод в поле через `typedLengthCm` немедленно перемещает конец b вдоль текущего направления (a неподвижен) через `moveEndpoint` — консистентно с «немедленным» превью при рисовании; механика `lengthDirty` переиспользуется (пока пользователь печатает, живое значение не затирает ввод), при выделении и снятии выделения `lengthDirty` сбрасывается. Альтернатива — применять по Enter: дополнительное состояние и расхождение с поведением при рисовании. Принятый недостаток: длина «прыгает» на промежуточных символах ввода.

### Привязка к продолжению линии — `snap` без зажима проекции
Кандидат привязки к стене не зажимается пределами отрезка: при следе проекции за концом кандидатом является конец стены, пока он в радиусе, иначе — продолжение линии. Без этого при конфигурациях с углом >90° (след за пределом соседней стены) привязка к стене не срабатывала вовсе — воспроизведено до исправления (конец падал на сетку). Правило едино для рисования и drag — оба используют один `snap`.

### Орто-привязка — флаг `ortho` и кнопка-переключатель
`ortho = false` по умолчанию (выключена); кнопка расположена в блоке размеров (`#size-box`) и стилизована собственным правилом `#ortho-toggle` в габаритах кнопок единиц. Флаг лишь запрещает передачу `orthoFrom` в `snap` (`ortho ? origin : undefined`) в двух местах — `toSnappedPoint` (рисование) и drag конца; привязки к стенам и сетке не затронуты. Без персистентности — приложение не хранит состояние между сессиями.

### Тесты — чистая геометрия в `geometry.test.ts`
Юнит-тесты vitest на `hitWall`, `endpointAt` и `moveEndpoint` (внутри полосы толщины, вне, приоритет ближайшей, допуск в см, протяжка стыка). Интеракция (`main.ts`) покрывается вручную — canvas-DOM в vitest не настроен.

## Risks / Trade-offs

- [Клик по стене в зоне привязки вершины при неактивной цепочке теперь выделяет, а не начинает цепочку] → Это заданное поведение: рисование начинается кликом по пустому месту; при активной цепочке клики по стенам работают как раньше.
- [Мутация стены во время drag при будущем появлении undo] → Появится необходимость хранить снапшот на drag start; сейчас задача undo вне скоупа.
- [Обводка выделения под стеной на близких цветах может быть малозаметна] → Контрастный цвет обводки (например, циан/#0891b2) с полупрозрачностью; проверить визуально на трёх типах стен.

## Migration Plan

Изменение локально для фронтенда, данных и персистентности нет (стены существуют только в памяти сессии). Откат — revert коммита.
