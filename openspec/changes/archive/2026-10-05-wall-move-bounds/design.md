## Context

Правки положения и длины стен в `src/main.ts` применяют вектор, полученный привязкой, без ограничений:

| Правка | Без орто | С орто |
|---|---|---|
| перемещение / группа (`groupMove`) | `moveWalls(walls, group, target − pressed.a)` — **приращение** на каждом `pointermove` | `restoreWalls(snapshot)` + `planOrthoStretch` / `applyStretch` полным вектором |
| перетаскивание конца (`endpointDrag`) | `moveEndpoint(walls, wall, end, next)` — приращение, сварка соседей | снимок + план `end` |
| стрелки | `moveWalls(walls, selected, ±step)` | план `walls` |
| ввод длины (`resizeSelected`) | `moveEndpoint(walls, wall, "b", end)` | план `end: b` |

Существующие примитивы описывают **правила следования** и покрыты одобренными тестами (`geometry.test.ts`, `move-tee-stretch.test.ts`, `ortho-stretch.test.ts`, `face-corner-margin.test.ts`):
- `moveWalls` / `followingEnds` — какие концы несдвигаемых стен следуют (без орто);
- `moveEndpoint` / `attachedEnds` — сварка концов при перетаскивании (без орто);
- `planOrthoStretch` / `applyStretch` — орто-растяжение;
- `teeEndAttached(end, w, wall)` — T-примыкание конца к оси или грани; `jointedWalls`, `faceCornerTol` — стыки.

Отображаемая форма стены — `displayPolygons(wall, walls)` (`wall-geometry.ts`), выпуклые куски; `coveredInterval` / `mergeIntervals` — покрытие отрезка кусками.

Мутационного тестирования в проекте нет (только `vitest`).

## Goals / Non-Goals

**Goals:**
- Ограничение правки — отдельный слой над примитивами: примитивы и их одобренные тесты не меняются (D1).
- Одна модель для всех пяти правок: «правка как функция вектора» + ограничитель (D2, D5).
- Границы примкнутой стены (D3) и запрет прохождения сквозь стены (D4) согласованы: скольжение у препятствия не отрывает примкнутую стену.
- Итог перетаскивания не зависит от пути указателя и при выключенном орто (D6).

**Non-Goals:**
- Точный поиск «ближайшего допустимого» положения в невыпуклых карманах (см. D5, Risks).
- Исправление наложений в сохранённых чертежах.
- Ограничение рисования новых стен.
- Изменение правил следования связанных стен, кроме следования ножки за изменённой опорной (D2a).

## Decisions

### D1. Слой ограничения над примитивами

Новые модули:

```
src/edit-plan.ts      правка как функция вектора: положения изменяемых стен для v (чисто)
src/tee-bounds.ts     примкнутые концы, опорные стены, диапазоны, проекция вектора (чисто)
src/wall-collision.ts тела стен, глубина и площадь наложения, проверка допустимости, ограничитель (чисто)
src/wall-edit.ts      публичные правки с ограничениями — используются main.ts и тестами
```

Публичный API (`src/wall-edit.ts`). Текущая геометрия `walls` — исходное положение правки (начало жеста); функции мутируют `walls` и возвращают фактический результат:

```ts
// snappedAxis — стена, к линии оси которой привязан перетаскиваемый конец (перетаскивание конца)
// или опорный конец a нажатой стены (перемещение); источник — snapWithSource (D4)
type EditMode = { ortho: boolean; snappedAxis?: Wall }

// перемещение за средний маркер, группа, стрелки; возвращает применённый вектор
function moveWallsBounded(walls: Wall[], group: readonly Wall[], v: Point, mode: EditMode): Point

// перетаскивание конца; target — точка после привязки; возвращает итоговое положение конца
function moveEndpointBounded(walls: Wall[], wall: Wall, end: WallEnd, target: Point, mode: EditMode): Point

// ввод длины; возвращает итог: применена ли правка и фактическая длина
type ResizeResult = { kind: "applied"; lengthCm: number } | { kind: "rejected"; reason: "both-ends-attached" | "no-change" }
function resizeWallBounded(walls: Wall[], wall: Wall, lengthCm: number, mode: EditMode): ResizeResult
```

`moveWalls`, `moveEndpoint`, `planOrthoStretch` остаются примитивами без ограничений. `main.ts` переходит на функции `wall-edit.ts`.

**Альтернатива:** встроить ограничения в `moveWalls` / `moveEndpoint`. Отклонено: одобренные тесты этих функций фиксируют поведение без ограничений (например, ножка T, уходящая с грани), их пришлось бы менять — это запрещено. Кроме того, ограничение нужно и для орто-плана, общий слой убирает дублирование.

### D2. Правка как функция вектора

`edit-plan.ts` строит по **исходной** геометрии план правки и возвращает чистую функцию положений:

```ts
interface Segment { a: Point; b: Point }
interface EditPlan {
  changed: readonly Wall[]                                      // все стены, которые правка может изменить
  positions: (v: Point) => ReadonlyMap<Wall, Segment>           // новые оси изменяемых стен; без мутации
}
function planMove(walls, group, v, mode): EditPlan              // без орто — followingEnds; с орто — planOrthoStretch(dir(v))
function planEndpoint(walls, wall, end, v, mode): EditPlan      // без орто — attachedEnds (сварка); с орто — plan "end"
```

Для фиксированного направления `v` положения линейны по величине: концы, помеченные планом, смещаются на `v`. Без орто сварка соседей при перетаскивании конца ставит их концы в позицию конца (`base + v`). Для перебора допустимых `v` с другим направлением план с орто строится заново: он зависит от направления (D2 change ortho-stretch-move).

**Следование ножек за опорной (D2a).** `positions(v)` после базового плана обрабатывает исходные T-примыкания (`findAttachments`, D3). Если опорная стена есть в результате и изменилась, а примкнутый конец базовым планом не смещён, конец ставится в новую систему опорной: исходное поперечное смещение `lat` и исходное расстояние вдоль оси от неподвижного конца опорной. Неподвижный конец — тот, чьи координаты не изменились. Если изменились оба, расстояние отсчитывается от `a`. Ножка со свободным вторым концом (свободен — как в `followingEnds`: нет стыка и примыкания) смещается целиком на смещение конца, иначе смещается только конец. Обработка повторяется для ножек, примкнутых к изменившимся при следовании стенам. Каждая стена меняется один раз, связи определяются по исходной геометрии. Положения нелинейны по `v` (поворот опорной), поэтому ограничитель по-прежнему проверяет каждую точку пути.

При орто опорная только растягивается вдоль себя или смещается целиком. При растяжении расстояние от неподвижного конца сохраняет ножку на месте, а при смещении целиком ножка уже увлечена орто-планом. Поэтому поведение орто не меняется.

Чтобы `planMove` / `planEndpoint` не дублировали правила следования, `followingEnds` и `attachedEnds` экспортируются из `geometry.ts` без изменения логики; `moveWalls` / `moveEndpoint` не меняются.

### D3. Границы примкнутой стены (`tee-bounds.ts`)

**Поиск.** По исходной геометрии для каждой стены S, сдвигаемой целиком (seed правки), и каждого её конца e: опорная стена H — несдвигаемая стена, для которой `teeEndAttached(S[e], S, H)` и нет углового стыка (`faceCornerTol`). Результат — `Attachment { wall: S; end; host: H; lat }`, где `lat` — исходное поперечное смещение конца от оси H (0 — на оси, ±h_H — на грани).

**Диапазон.** Сторона ножки — знак поперечного смещения второго конца S относительно оси H. Линия грани — параллель оси H на `h_H` в сторону ножки. Покрытие проверяется по линии, смещённой от грани на 0.05 см внутрь H: интервал, покрытый отображаемыми кусками (`displayPolygons`) самой H и стен, образующих с концами H угол, объединяется. Угол — стык по `jointedWalls`, где оси расходятся больше чем на 15° от коллинеарного продолжения (порог почти коллинеарного стыка `wall-joints`). Коллинеарное продолжение H другой стеной диапазон не расширяет: по спецификации ножка остаётся на «той же» опорной стене. Интервалы объединяются (`mergeIntervals`), берётся связный интервал `[lo, hi]`, содержащий исходную точку конца. Так наружный угол включается: угол закрыт телом H или угловой стены, — а свободный торец H ограничивает. Внутренний угол этим интервалом не ограничивается, его даёт D4: угловая стена не связана с S и останавливает её тело в касании.

Половина следа тела S на грани: `f = h_S / |sin θ|`, где θ — угол между осями S и H. Допустимая продольная координата конца: `[lo + f, hi − f]`. Если исходная точка уже вне этого отрезка (старые чертежи), отрезок расширяется до неё: стене можно вернуться в диапазон, но не уйти дальше.

**Проекция вектора перемещения.** Для seed-стен с примкнутыми концами:
- один примкнутый конец (или несколько с параллельными опорными стенами): `v' = (v · d_H) d_H`, продольная составляющая ограничивается пересечением диапазонов;
- опорные стены не параллельны (угол больше 0.5°): `v' = 0`;
- при орто: если `v'` не параллелен оси орто (|cross| > `RIGHT_SIN`) — `v' = 0`.

Конец ставится в координатах опорной стены (продольная координата + исходное `lat`), чтобы примыкание не терялось из-за погрешности (`teeEndAttached` проверяет грань с допуском 1e-6).

**Проекция для конца.** При перетаскивании примкнутого конца target переводится в систему H: продольная координата ограничивается диапазоном с θ, пересчитанным для нового положения конца. Поперечная — `lat`. При орто точка — пересечение линии `lat` с осью орто через противоположный конец. Ось орто — горизонталь или вертикаль через противоположный конец, если target отклоняется от неё не более чем на 15° (как в `snap`). Иначе орто не срабатывает, и проекция выполняется как без орто. Для перемещения ось орто так же определяется по запрошенному `v`. Если пересечения нет или оно вне диапазона, конец остаётся на месте.

**Инвариант для всех примыканий.** Правка может изменить ножку, не являющуюся seed (соседи, орто-план), или саму опорную стену: например, опорная поворачивается вслед за стыком или укорачивается при перетаскивании её конца. Проекция эти случаи не покрывает. Поэтому в D4 к проверке допустимости добавляется условие: каждое исходное примыкание, у которого правка изменяет ножку или опорную стену, после правки сохраняется. «Сохраняется» здесь — по спецификации, а не через `teeEndAttached`: в системе новой оси опорной стены поперечное смещение конца равно исходному `lat` (допуск 1e-6), а продольная координата лежит в диапазоне `[lo + f, hi − f]`, пересчитанном для нового положения. Диапазон может выходить за конец оси опорной у наружного угла, где `teeEndAttached` уже даёт `false`. Если ножка и опорная сдвигаются целиком одним вектором, проверка тривиальна.

Примыкание у наружного угла после такой правки может попасть в допуск углового стыка на грани (`faceCornerTol`). Тогда при следующих правках стены классифицируются как угловой стык и следуют по правилам стыков: это исходные определения спецификации, ограничение их не меняет (см. Risks).

### D4. Тела и допустимость (`wall-collision.ts`)

- Тело — прямоугольник оси шириной в толщину (не `displayPolygons`): так быстрее и однозначно по спецификации.
- Глубина наложения двух выпуклых прямоугольников — минимальное перекрытие проекций по четырём осям (SAT). Пересечение — глубина > 0.01 см. Нормаль контакта — ось минимального перекрытия.
- Площадь наложения — отсечение одного прямоугольника полуплоскостями другого (`clipHalfPlane`) + `polygonArea`.

Пары исключаются по исходной геометрии: связанные стыком (`jointedWalls`) или примыканием (`teeEndAttached` любого конца одной к другой).

**Исключение по привязке к оси** — только при `mode.snappedAxis = X`, то есть когда привязка действительно поставила конец на линию оси X. Для пары (стена конца, X) тело стены проверяется не целиком, а без участка у привязанного конца длиной `h_X / |sin θ|` вдоль оси стены, где θ — угол между осями. Это наложение конца в пределах полутолщины X от её оси. Остальная часть тела с X пересекаться не должна. Положение на оси, полученное без привязки (например, по сетке), исключения не даёт. Если стена параллельна X (`|sin θ| ≤ RIGHT_SIN`) или вырезаемый участок не короче самой стены, исключения нет и тело проверяется целиком: параллельная стена вдоль оси — не T-примыкание (найдено при проверке пользователем: стена, привязанная к оси параллельной соседней, входила в неё целиком).

Источник `snappedAxis` — новая функция `snapWithSource(cursor, walls, gridStepCm, radiusCm, orthoFrom?)` в `geometry.ts`: возвращает `{ point, axisWall: Wall | null }`, где `axisWall` — стена, к линии оси которой выполнена привязка (проекция на линию стены или её продолжение; не конец стены и не сетка). `snap()` становится обёрткой `snapWithSource(...).point`, поведение и одобренные тесты `snap` не меняются.

Существующее наложение: пара, у которой в исходном положении глубина > 0.01 см и нет исключения, проверяется условием «площадь(v) ≤ площадь(0) + 1e-6 см²» вместо глубины.

`admissible(plan, v)`: для всех пар (изменяемая стена, любая другая стена), кроме исключённых, — условие глубины или площади. Плюс инвариант примыканий из D3.

### D5. Ограничитель

`limit(planFor, vReq, project)`:
1. **Путь по прямой.** `pathOk(v)` — `admissible` в точках `t·v`, `t ∈ (0, 1]`. Шаг такой, чтобы ни одна точка изменяемых стен не смещалась больше чем на четверть толщины самой тонкой стены чертежа (`минимальная полутолщина / 2`) за шаг. Тело, проходящее сквозь стену толщины t, в каком-то шаге налагается на неё не меньше чем на t/4, что больше порога распознавания. Дополнительно проверяется `t = 1`. Так нет туннелирования через тонкие стены.
2. Если `pathOk(vReq)` — результат `vReq` (наложение до 0.01 см включительно допустимо и не исправляется).
3. **Касание.** Порог 0.01 см только распознаёт пересечение, остановка — в касании. Ищется наибольшее `t*`, при котором на пути `[0, t*]` нет наложения глубже 1e-6 см с не исключёнными парами, а для исходно налагающихся пар площадь не растёт. Поиск — перебор шагами, затем бисекция до 1e-5 см. Получается `vc = t*·vReq`. Стена, уже стоящая в касании, при запросе вглубь получает `t* = 0`.
4. **Скольжение** (кроме ввода длины). `n` — нормаль контакта блокирующей пары в `t* + δ`. Остаток `r = vReq − vc`, касательная часть `rt = r − (r·n)n`. Кандидат — `project(vc + rt)`, проекция D3. Если путь к кандидату свободен по критерию шага 3 (касание без углубления), результат — кандидат. Иначе бисекция по `s ∈ [0, 1]` для `project(vc + s·rt)`, результат — наибольшее допустимое.
5. Одна итерация скольжения. Если в кармане встречается второе препятствие, стена останавливается в последней допустимой точке.

Для правок с орто `planFor(v)` строит план по направлению `v` (D2). Скольжение при орто даёт касательную часть только вдоль оси орто: `project` обнуляет поперечную, и при поперечной нормали скольжения нет.

Ввод длины: `v = û·(L − L₀)` вдоль стены от подвижного конца. Только шаги 1–3, без скольжения. Итоговая длина — `L₀ + t*·(L − L₀)`.

### D6. Применение от снимка при любом орто

Чтобы «путь по прямой от начала жеста» был определён, перетаскивание (группа, конец) при **выключенном** орто тоже применяется как в D3 change ortho-stretch-move: на каждом `pointermove` `restoreWalls(snapshot)`, затем правка полным вектором от исходной опорной точки. Сварка соседей (`moveEndpoint` без орто) по снимку даёт тот же итог, что и приращения, кроме случаев накопленного дрейфа — их спецификация и так требует устойчивости к протяжке.

### D7. Ввод длины

`resizeWallBounded`:
1. Подвижный конец по спецификации: b, если b не примкнут (D3, поиск), иначе a, если a не примкнут; иначе `rejected: both-ends-attached`.
2. Новая позиция подвижного конца — вдоль текущего направления от неподвижного.
3. Ограничитель D5 без скольжения. Если итог совпал с текущей длиной — `rejected: no-change`.

`main.ts`: при `rejected` запись истории не создаётся, поле длины возвращается к текущей длине (`updateLengthBox`). При `applied` поле показывает `lengthCm`.

### D8. Точки интеграции в `main.ts`

- `groupMove`, `pointermove`: `restoreWalls(snapshot)` (оба режима), привязка через `snapWithSource` (те же `others` / `stretchSnapWalls`), затем `moveWallsBounded(walls, group, target − baseA, { ortho, snappedAxis: axisWall })`.
- `endpointDrag`: `restoreWalls(snapshot)`, привязка через `snapWithSource`, затем `moveEndpointBounded(…, next, { ortho, snappedAxis: axisWall })`.
- Стрелки: `moveWallsBounded(walls, selected, ±step, { ortho })`. `pushRecord` выполняется только при ненулевом применённом векторе: первое нажатие, давшее сдвиг, открывает серию.
- `resizeSelected`: `resizeWallBounded`, затем история и поле по D7.
- Запись истории при отпускании кнопки — как сейчас: при неизменном положении не создаётся.

### D9. Размеры, история, формат

Размеры привязаны к рёбрам (`EdgeRef`) и следуют автоматически. Формат файла не меняется, миграции нет.

## Risks / Trade-offs

- **«Ближайшее допустимое» приближённо.** D5 даёт касание и одно скольжение. В невыпуклых карманах (угол между двумя препятствиями) стена останавливается раньше теоретически ближайшей точки. Сценарии спецификации (касание, скольжение вдоль одной стены, возврат) выполняются точно.
- **Источник привязки.** Исключение по оси зависит от `snapWithSource`: если привязка к стене и к сетке дают одну точку, источником считается стена (у привязки к стенам приоритет). Попадание на ось только по сетке исключения не даёт, стена останавливается у грани.
- **Наружный угол становится угловым стыком.** Ножка, доведённая до наружного угла, может попасть в допуск углового стыка на грани. Последующие правки тогда следуют правилам стыков, и ножка увлекает конец опорной. Это следствие существующих определений, а не нового правила.
- **Инвариант примыканий и правки соседей.** Проверка на реальном чертеже при реализации показала, что без следования ножек за опорной большинство правок без орто блокировалось до нуля: сдвиг стены комнаты поворачивал боковую из-под перегородки. Решение пользователя — D2a: ножка следует за опорной. Ограничение остаётся только там, где опорная укорачивается из-под ножки за пределы диапазона.
- **Производительность.** На `pointermove` — до ~сотни шагов × пары изменяемых и остальных стен, SAT на прямоугольниках. Для чертежей в десятки стен это доли миллисекунды. Число шагов ограничивается (не больше 2000); бисекция скольжения — 20 итераций.
- **Диапазон по отображаемой форме.** Диапазон зависит от `displayPolygons` опорной и угловых стен. Особые формы стыков (клинья, легаси) могут сдвинуть границу на доли сантиметра. Защита от наложения при этом остаётся за D4.
- **Переход на снимок без орто (D6).** Меняет способ применения без орто. Поведение должно совпасть, это проверяется существующими тестами протяжки и e2e-сценариями.

## Migration

Нет: формат данных не меняется; существующие наложения остаются и обрабатываются по D4.
