### Независимая проверка геометрии

**C-12g** (`src/wall-collision-snap.test.ts:10-18`) — дословно сценарий спецификации.
- N: ось y = 0, t20 → тело y ∈ [−10, 10], x ∈ [0, 400]. W: ось y = 40, t20 → тело y ∈ [30, 50], x ∈ [100, 300]. Проекции по x перекрываются на [100, 300], значит при сдвиге вверх тела сходятся по y.
- Касание: нижняя грань W `40 + v_y − 10 = 10` → `v_y = −20`. Эталон `(0, −20)` верен.
- Исходно N и W не связаны: концы W в 40 см от оси N, вне грани и далеко от концов N; стыка и T-примыкания нет. Исключение «по положению до правки» не применяется.
- Скольжение (D5 шаг 4) ничего не добавляет: нормаль контакта (0, 1) коллинеарна запросу, касательная часть остатка нулевая. Поэтому `|v.x| ≤ 1e-9` корректно, а ближайшее к запросу положение касания — ровно `(0, −20)`.
- Опорный конец W.a после запрошенного сдвига — `(100, 0)` на оси N, то есть `snappedAxis: N` соответствует сценарию.

**C-12h** (`src/wall-collision-snap.test.ts:20-27`).
- X: x ∈ [150, 400], тело y ∈ [190, 210]. M: x ∈ [0, 100], t10, тело y ∈ [195, 205]. Стены коллинеарны (`sin θ = 0`).
- Исходно не связаны: зазор M.b–X.a = 50 см, а `faceCornerTol(X, M) = max(1.25·10, hypot(10, 5) + FACE_CORNER_MARGIN) + EPS` ≈ 12.5 см. M.b `(100, 200)` лежит на линии оси X, но вне её отрезка, T-примыкания нет.
- Касание: тело M доходит до торца X при `b.x = 150`. Эталон `(150, 200)` верен.
- `faceCornerTol` после правки на ответ не влияет: по спецификации связь пары определяется по положению до правки. В точке касания M.b совпадает с X.a — это точный стык, а в точке запроса `(200, 200)` M.b стоит на оси X внутри отрезка, то есть T-примыкание. Поэтому реализация, которая (ошибочно) пересчитывает связь по новому положению, исключит пару и вернёт 200. C-12h этот дефект убивает.
- Скольжения нет: нормаль контакта (−1, 0) противоположна запросу. Строгое `p.y` toBe(200) при осевой геометрии выполнимо: проекция D3 для несвязанного конца — тождество, касательная часть равна 0.

**C-12i** (`src/wall-collision-snap.test.ts:29-35`) — перпендикулярная пара, геометрия C-12b. С привязкой исключение даёт `(−100, 0)` и M = `(200,200)-(300,200)`. Без исключения получилось бы касание `(−90, 0)` (как в одобренном C-12b). Контроль верен.

### Мутационная проба (копия `src` в scratchpad, мутирован `trimmedRect`; прогон snap + collision + tee + invariants)

| Вариант `trimmedRect` | Результат |
|---|---|
| Исходный (без исправления) | C-12g, C-12h падают |
| Правильное исправление: `sin ≤ RIGHT_SIN` (0.5°) или `trim ≥ len` → полное тело | C-12g/h/i и все collision/tee проходят |
| Исключение отключено полностью | C-12i, C-12, C-12b падают |
| Параллельная → укорочение на `h_X` (как при `sin = 1`) | C-12h падает (касание при b.x = 160) |
| Параллельная → укорочение на `len/2` | C-12h падает |
| Только «`trim ≥ len` → полное тело», без порога угла | выживает |
| Порог параллельности 10° вместо 0.5° | выживает |

Рассуждением (одна точка `trimmedRect` общая, поэтому инъекцией не проверялось):
- исправление только для перемещения убивает C-12h, только для перетаскивания конца — C-12g;
- «исправление» отказом от правки (`v = 0`, конец на месте) убивают C-12g (`v_y = −20`) и C-12h (`p.x = 150`);
- остановка с зазором (по порогу 0.01 см или раньше касания) убивается допуском 1e-4 по обоим эталонам;
- пересчёт связи пары по новому положению убивает C-12h (см. выше).

Замечание о среде: в `wall-edit-invariants.test.ts` и в проекте, и в копии (без мутаций) воркер vitest падает («Worker exited unexpectedly», 2 passed из 3). Это предсуществующее поведение, к раунду 7 отношения не имеет (N-9).

## Findings

**Блокирующие**

Нет.

- C-12g верен: дословно сценарий `spec.md:66-68`, касание при `v = (0, −20)` подтверждено (тела y ∈ [−10, 10] и [30, 50]), исходной связи нет.
