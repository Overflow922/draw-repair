## Context

Текущая раскладка: `#main` — flex-строка из прибитого слева `#toolbar` (56px, рамка на всю высоту) и `#canvas-wrap`; `#tabbar` — полоса на всю ширину. Референс парящего блока уже есть — `#size-box`: `position: absolute`, отступ 12px, `border-radius: 8px`, тень. Идентификаторы элементов (`#thickness`, `#wall-types`, `#thickness-unit` и т.д.) используются в `main.ts`; стрелки ↑/↓ глобально переключают тип стены, если фокус не в поле толщины.

## Goals / Non-Goals

**Goals:**

- Полноэкранный холст; все блоки — абсолютные острова поверх него с общим стилем.
- Общий класс `.panel` вместо копирования стилей `#size-box` между блоками.
- Механизм вспомогательных панелей, обобщённый на будущие инструменты (сейчас — только «Стена»).

**Non-Goals:**

- Удаление элементов чертежа (отложено отдельным change).
- Изменение поведения вкладок, инструментов, истории, хранения.
- Темы, анимации, мобильная раскладка.

## Decisions

- **Канвас — подложка, блоки — оверлеи.** `#canvas-wrap` растягивается на всё окно (`#main` без flex-соседей), острова позиционируются `position: absolute` внутри него. Альтернатива — `position: fixed` у блоков и отдельный слой: отвергнуто, т.к. абсолюты внутри общего контейнера проще и не ломаются при будущих вложенных слоях. Клик по острову не попадает в `canvas` (слушатели на элементе canvas), отдельный перехват не нужен.
- **Один стиль `.panel`** (фон, рамка, скругление 8–10px, тень) — из рецепта `#size-box`; `#size-box` переводится на класс, дубликаты стилей удаляются.
- **Подпанель — часть разметки острова инструментов, а не отдельный всплывающий слой.** Контейнер инструментов — flex-строка: колонка кнопок + абсолютная панель, привязанная к активной кнопке (`left: 100%`), выравнивание по кнопке. Видимость — класс-модификатор; состояние в переменной `main.ts` (`wallPanelOpen`), а не только в CSS, т.к. авто-открытие приходит из логики выделения.
- **Правила видимости панели «Стена»** (по решению с пользователем): клик по кнопке — toggle; выделение стены — авто-открытие; снятие выделения — состояние не меняется; ручное закрытие при выделенной стене держит панель закрытой до нового выделения. Реализация: флаг `wallPanelOpen`, авто-открытие ставит его в `true` в месте присвоения `selectedWall`.
- **Толщина и тип переезжают в подпанель с сохранением id** (`#thickness-label`, `#thickness`, `#thickness-unit`, `#wall-types`). Обработчики `main.ts` не переписываются; меняются только запросы, если структура обёрток изменилась.
- **Стрелки ↑/↓ остаются глобальными** — переключение типа работает при закрытой панели (требование `wall-types`); guard на фокус в `#thickness` сохраняется.
- **Состояния кнопок первого уровня** — hover/нажатие и кольцо открытой подпанели — чистым CSS; кольцо через `:has(.tool-panel.open)` у якоря инструмента, без JS, автоматически обобщается на будущие инструменты.
- **Вкладки — тот же `.panel`**, позиционирование `top/left: 12px`; поведение (`drawing-manager`) не трогается.

## Risks / Trade-offs

- [Острова перекрывают холст — рисовать «под» блоком нельзя] → Приемлемо (так работают все островные UI); блоки компактные, отступы 12px.
- [Подпанель смещается вместе с кнопкой при росте числа инструментов] → Панель привязана к своей кнопке, а не к острову целиком; при добавлении инструментов привязка сохраняется.
- [Полноэкранный холст меняет прямоугольник `getBoundingClientRect`] → Координаты уже считаются от rect канваса (`toWorld`), отдельной правки не требуется; проверить pan/zoom после переноса.
- [Регрессии в визуально богатом UI без юнит-тестов] → Проверка сценариев спеков вручную в браузере (в т.ч. стрелки при закрытой панели, авто-открытие при выделении).

## Migration Plan

Одношагово: разметка + стили + точечные правки `main.ts` в одном применении; откат — revert применения. Данные (`drawing-storage`) не затрагиваются.
