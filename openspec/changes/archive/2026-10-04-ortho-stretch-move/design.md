## Context

Правки положения стен в `src/main.ts`:

| Правка | Привязка | Применение |
|---|---|---|
| перемещение стены и группы (`groupMove`) | `snap(baseA + drag, others, …, ortho ? baseA : undefined)` | `moveWalls(walls, group, target − pressed.a)` — **приращение** на каждом `pointermove` |
| перетаскивание конца (`endpointDrag`) | `snap(cursor, walls − wall, …, ortho ? other : undefined)` | `moveEndpoint(walls, wall, end, next)` — приращение |
| сдвиг стрелками | — | `moveWalls(walls, selected, ±step)` |
| ввод длины (`resizeSelected`) | — | `moveEndpoint(walls, wall, "b", end)` |

`snap()` (`src/geometry.ts:42`): сначала привязка к стенам (проекция на линию или конец в радиусе), затем орто-фиксация одной координаты, затем округление **обеих** координат к сетке. Отсюда утечки, проверенные на сценах:
- конец при `y = 15` уходит на `y = 20`, и стена наклоняется на 1.1°;
- привязка к стене игнорирует орто.

`moveWalls` и `moveEndpoint` сдвигают только стыковой конец соседа. Это источник поворотов соседей: угол комнаты на +30 см даёт 5.7°.

## Goals / Non-Goals

**Goals:**
- При включённом орто точка привязки строго на оси (D1).
- Орто-растяжение связанных стен по спеке (D2), не зависящее от пути указателя (D3).
- Поведение без орто не меняется: `moveWalls`, `moveEndpoint` и их тесты остаются как есть.

**Non-Goals:**
- Исправление поворотов, уже сохранённых в чертежах.
- Изменение рисования цепочки (`chainSegment` / `snapOnRay` уже держат ось).
- Ограничение правок, при которых растягиваемая стена проходит через ноль длины (поведение как у текущих правок, см. Risks).

## Decisions

### D1. Привязка на оси орто

В `snap()` при `orthoFrom` сначала определяется ось: горизонталь или вертикаль через `orthoFrom`, если отклонение ≤ 15°. Если ось определена:
- кандидаты привязки к стенам — точки на оси: пересечение оси с линией каждой стены (не параллельной оси) и проекции концов стен на ось; берётся ближайший к курсору в пределах радиуса;
- иначе — округление к сетке **только** координаты вдоль оси; координата поперёк оси берётся ровно от `orthoFrom`.

Если ось не определена (отклонение > 15°) или `orthoFrom` нет, поведение прежнее.

**Альтернатива:** сохранить приоритет стен над орто, как в текущей спеке. Отклонено: это прямой источник боковой составляющей, которая и наклоняет стены.

### D2. План орто-растяжения — чистая функция

Новый модуль `src/ortho-stretch.ts`:

```ts
type StretchSeed =
  | { kind: "walls"; walls: Wall[] }               // перемещение, группа, стрелки
  | { kind: "end"; wall: Wall; end: "a" | "b" }    // перетаскивание конца, ввод длины

interface StretchPlan { moved: ReadonlyMap<Wall, { a: boolean; b: boolean }> }

function planOrthoStretch(walls: readonly Wall[], seed: StretchSeed, v: Point): StretchPlan
function applyStretch(plan: StretchPlan, v: Point): void   // сдвиг отмеченных концов на v
```

Алгоритм — обход в ширину по очереди стен, сдвигаемых целиком:
1. Начальная очередь: стены seed (`walls`) или пусто, с одним смещаемым концом (`end`).
2. Для смещаемого конца P и каждой стены W вне плана проверяется связь:
   - конец W в допуске стыка с P: `faceCornerTol` — допуск углового стыка, он же больший из допусков привязки конца, как в `moveWalls`;
   - для стены, сдвигаемой целиком, — ещё T-примыкание конца W к её оси или грани. Используется покончевая проверка `teeEndAttached(end, w, wall)`, экспортируемая из `geometry.ts`: плану нужен конкретный примкнутый конец. Прежняя `teeAttached` построена на ней и не меняет поведения.
3. Связанная W параллельна `v` (`|cross(û_W, v̂)| ≤ RIGHT_SIN`) — помечается её связанный конец. Иначе W помечается целиком и ставится в очередь.
4. Стена с обоими помеченными концами — целиком (сдвиг один раз) и ставится в очередь, как любая стена, сдвигаемая целиком: её T-примыкания и стыки обрабатываются (ST-18). Стена, уже помеченная целиком, не пересматривается.
5. Связи считаются по **исходной** геометрии (до сдвига), сдвиг применяется после построения плана.

Ножка T не увлекает стену: T-проверка идёт только от стены, сдвигаемой целиком, к концам других стен, не наоборот.

Для `end`-seed сама стена seed помечается одним концом. Её T-примыкания не распространяются: стена не сдвигается целиком.

`RIGHT_SIN` экспортируется из `wall-geometry.ts`, там уже есть допуск прямого угла 0.5°.

**Альтернатива:** доработать `moveWalls` флагом `ortho`. Отклонено: функция и её одобренные тесты описывают поведение без орто. Отдельная чистая функция плана проще тестируется и не трогает существующее.

### D3. Применение от снимка, а не приращениями

С орто-растяжением результат зависит от направления `v`: параллельный сосед растягивается, поперечный сдвигается. Если применять приращения на каждом `pointermove`, путь указателя (сначала вбок, потом вверх) менял бы итог. Поэтому при включённом орто правка с перетаскиванием на каждом `pointermove` делает так:
1. восстанавливает координаты стен из снимка начала жеста (`groupMove.snapshot`, `endpointDrag.snapshot`; объекты стен остаются теми же, копируются только `a` / `b`);
2. считает полный вектор `v` от исходной опорной точки;
3. строит план по исходной геометрии и применяет его.

Без орто остаётся текущее применение приращениями. Сдвиг стрелками и ввод длины — одиночные действия: план на текущей геометрии.

Это также выполняет существующий сценарий «Угловой стык устойчив при протяжке» при орто: итог равен перемещению одним шагом.

### D4. Точки интеграции в `main.ts`

- `groupMove`: при `ortho` — D3 с seed `walls: group`; `others` (исключение из привязки) — стены плана для текущего `v`. Чтобы не было зацикливания «план зависит от привязки, а привязка от плана», исключаются стены плана, построенного по направлению оси привязки (`v` единичный по оси орто) до привязки.
- `endpointDrag`: при `ortho` — D3 с seed `end`, `v = next − base`. Из привязки так же исключаются стены плана по направлению оси (спека: увлекаемые правкой стены не участвуют в привязке) и сама перетаскиваемая стена. Иначе перетаскивание угла прилипало бы к прежней линии соседа, который смещается целиком. Общий помощник — `stretchSnapWalls` в `main.ts`.
- Стрелки: при `ortho` — план с seed `walls: selected` и `v = ±step`.
- `resizeSelected`: при `ortho` — план с seed `end: b`, `v = newB − b`.
- История: снимок начала жеста, как сейчас (одна запись).

### D5. Размеры

Размеры привязаны к рёбрам стен (`EdgeRef`) и пересчитываются от их геометрии, поэтому следуют автоматически.

## Risks / Trade-offs

- **Каскад по плану.** Растяжение может сдвинуть много стен (вся комната при сдвиге стены вдоль себя). Это ожидаемая семантика «сохранить прямые углы», она отражена в сценариях. Каждая стена сдвигается один раз, обход конечен.
- **Нулевая и отрицательная длина.** Растяжение параллельного соседа может довести его до нуля или «вывернуть». Текущие правки этого тоже не ограничивают. Ограничение — отдельное решение, сейчас не вводится.
- **Допуск параллельности 0.5°.** Сосед, уже повёрнутый больше чем на 0.5° (например, после старых правок), считается непараллельным и сдвигается целиком. Его поворот сохраняется, но не усиливается.
- **Исключение из привязки.** План для исключения строится по направлению оси, а не по итоговому `v`. При смене оси во время жеста набор исключений пересчитывается.

## Migration

Нет: формат данных не меняется; уже сохранённые повороты остаются.
