## Context

Размеры пометки строит `markDimensions(span, walls, mode, unit, k, labelPx)` (`src/demolition/mark-dimensions.ts`) поверх `markChains`: режим `"chain"` — три размера на каждой грани, режим `"width"` — один размер ширины на грани `+1`. Нулевое расстояние сейчас возвращается как размер с `geom: null` и числом «0» (`MarkDimension.spot`).

Потребители:

- `drawDemolitionScene` (`demolition-render.ts`): цепочка только у выделенной пометки и у превью, `width` — по флагу `widths` (PDF).
- `markDimensionExtent` → `export/pdf.ts:152`: габариты страницы по размеру ширины.
- `demolition-tool.ts:180`: попадание клика в число цепочки выделенной пометки (`markNumberAt`).

Поведение определяют delta-спеки; здесь только способ реализации.

## Goals / Non-Goals

**Goals:**
- Одна и та же цепочка у каждой действующей пометки на экране и в PDF; выделение влияет только на подчёркивание и правку.
- Нулевой размер не порождает ни геометрии, ни числа.
- Габариты PDF-страницы охватывают все выносные линии, размерные линии и числа цепочки обеих граней.

**Non-Goals:**
- Не менять расчёт `A / W / B` и стыков (`markChains`), слияние участков, правку чисел.
- Не вводить учёт соседних пометок при расчёте цепочки.
- Не менять формат хранения: размеры не сохраняются.

## Decisions

1. **Нулевые размеры отбрасываются в `markDimensions`**, а не в рендере: из результата исчезает ветка `geom: null`, `MarkDimension.geom` становится обязательным, рендер больше не рисует «числа без линий» (`drawNumber` в `demolition-render.ts` нужен только для подчёркнутого числа внутри размера — проверить при реализации, возможно упрощается). Альтернатива (фильтр в рендере) оставила бы нулевые числа кликабельными в `demolition-tool.ts`, что противоречит спецификации.
2. **Режим `"width"` удаляется**: PDF использует тот же `"chain"`, что и экран. Флаг `widths` в `DemolitionOptions` заменяется отсутствием различия: цепочка рисуется у всех пометок, `underline` — только у выделенной. Альтернатива (оставить режим) сохранила бы два пути для одного и того же.
3. **Габариты PDF** (`markDimensionExtent`) строятся по всей цепочке: концы выносных линий за размерной линией и четыре угла каждого числа, по обеим граням.
4. **Правка прижатого к стыку участка**: число «0» исчезло, поэтому участок правится противоположным числом (`B` двигает участок с сохранением ширины, см. сценарий «Участок у стыка правится другим числом»). Отдельного способа выбрать нулевую цель не вводится.
5. **Публичная поверхность для тестов** (имена сохраняются, меняется только поведение):
   - `markDimensions(span, walls, "chain", unit, k, labelPx)` возвращает только размеры ненулевой длины; у каждого `geom` непустой; порядок прежний (грань `+1`: `gapA`, `width`, `gapB`; затем грань `−1`). Режим `"width"` удаляется.
   - `drawDemolitionScene` / `renderDemolition` рисуют цепочку у каждой действующей пометки и у превью; поле `widths` в `DemolitionOptions` удаляется. Подчёркивание — только у `selectedId`.
   - `markDimensionExtent(span, walls, k, metrics)` возвращает точки всей цепочки обеих граней (концы выносных линий за размерной линией и четыре угла каждого числа); для пометки без ненулевых размеров или на вырожденной стене — пустой список.
   - `markNumberAt` / правка чисел (`editNumber`) не меняются; нулевых целей клика нет, потому что нулевых размеров нет.
6. **Независимость цепочек** — следствие того, что `markChains` берёт только стены, а не соседние пометки; кода для этого не требуется, только сценарий «Две пометки одной стены».

## Risks / Trade-offs

- **Загромождение**: цепочки обеих граней у каждой пометки плотнее, чем прежняя ширина на грани `+1`. Принято пользователем; размерные линии разных пометок одной стены могут пересекаться по вертикали у общих выносных линий — допустимо, спецификация требует независимости.
- **Теряется клик по «0»**: участок, прижатый к стыку, нельзя вернуть кликом по нулю; правится числами `B`/`W` (решение 4).
- **Существующие тесты** (`demolition-sizes-render`, `demolition-dimensions-render`, `mark-dimensions`, `mark-numbers`, `demolition-dimensions-pdf`, `mark-numbers-faces`) закрепляют прежнее: нулевое число, `width`, отсутствие размеров у невыделенных. Они меняются через test-writer по спецификации, не подгоняются под реализацию.
- **Дрейф документации**: формулировка «ширину участка числом рядом с ним» в требовании PDF «Страница демонтажа» (`pdf-export`) устарела после этого изменения; не входит в delta, заносится в TODO.md.

## Migration

Не требуется: размеры пометок не хранятся, формат чертежа не меняется.
