## Context

Мотивация — в `proposal.md`, требования — в `specs/`. План «Мебель» повторяет устройство плана «Реконструкция» (change `reconstruction-plan`), поэтому почти вся инфраструктура уже есть:

- каталог планов и их инструментов — `src/plans.ts` (`PLANS`, `PLAN_TOOLS`);
- подложка — живая производная, считается чистой функцией: `reconstructionScene(drawing)` даёт подложку «Черновых работ», куски штукатурки (`pieces`), стены гипсокартона (`own`), видимые размеры плана;
- рабочий набор плана — `reconstruction-workspace.ts` (`openReconstruction`, `storedReconstruction`): инструменты правят смешанный список стен, а в чертёж пишется только хранимое;
- отрисовка плана и PDF — одна функция `drawReconstructionScene` (`src/reconstruction/reconstruction-render.ts`);
- история плана — снимки собственных объектов под ключом `<id>:<plan>`, проверка записи при загрузке (`src/history.ts`);
- хранилище — необязательное поле чертежа, битые элементы отбрасываются по одному (`src/storage.ts`, `loadReconstruction`);
- группа с панелью — `src/doorway/openings-group.ts` (`GroupState`, `groupButtonClick`, `groupPick`).

Новое: объект с углом поворота (стол), расчёт пересечений и индикация пересечений (подсветка и плашка). Блокирующей проверки (`wall-collision`) нет: пересечение не запрещает правку, а только показывается.

Сетка координат — абсолютные сантиметры чертежа, ось Y вниз; углы по часовой на экране, поэтому поворот на θ — стандартное вращение холста (x' = x·cosθ − y·sinθ, y' = x·sinθ + y·cosθ).

## Goals / Non-Goals

**Goals:**
- Дать первый инструмент плана «Мебель» — стол — и заложить структуру для следующих инструментов группы «Мебель».
- Пересечения считаются по текущему состоянию, не хранятся, не мешают правке и не попадают в PDF.
- Не дублировать код: подложка, размеры, ластик, выноски, примечания, история и хранение используют существующие механизмы.

**Non-Goals:**
- Блокировка, прилипание, скольжение по препятствию, ограничение угла и размера.
- Привязка размеров к столам и измерение линейкой по столам (размеры и линейка работают по подложке).
- Область открывания двери (дуга полотна) как препятствие: препятствие — проём в пределах толщины стены (см. D4); дверное полотно — отдельное решение позже.
- Другие виды мебели, группы столов, копирование столов.
- Отметка пересечения в PDF, в таблице или в файле: только на экране.

## Decisions

### D1. Каталог и инструменты (`drawing-plans`)

`PLANS` получает `{ id: "furniture", label: "Мебель" }` последним; `PlanId` расширяется автоматически. `PLAN_TOOLS.furniture = ["table", "dimension", "callout", "ruler", "notes", "eraser"]`; `Tool` (в `openings-group.ts`) получает `"table"`. Инструмент «Стол» входит в группу «Мебель»: состояние группы — `GroupState<"table">` из `openings-group.ts` (тот же код, что у «Проёмов»; параметр `T` там уже есть). Отдельной кнопки «Стол» нет: кнопка группы «Мебель» вызывает `groupButtonClick`, список группы пока из одного элемента, но расширяется добавлением значения в `FurnitureGroupTool`.

*Альтернатива:* одиночная кнопка «Стол» без группы, группа позже. Отклонено пользователем: инструментов будет много, группа нужна сразу.

### D2. Модель данных (`src/types.ts`)

```ts
export interface Table {
  id: string
  x: number          // центр, см
  y: number
  widthCm: number    // вдоль оси X при угле 0
  lengthCm: number   // вдоль оси Y при угле 0
  angleDeg: number   // [0, 360), по часовой на экране
}

export interface FurnitureContent {
  tables: Table[]
  dimensions: Dimension[]
  callouts?: Callout[]
  notes?: string[]
}
// Drawing.furniture?: FurnitureContent
```

Центр, а не угол прямоугольника, потому что поворот идёт вокруг центра (решение пользователя): поворот не меняет `x, y`. Угол нормализует `normalizeAngle(deg)`: `((deg % 360) + 360) % 360`, поэтому 360→0, −90→270, 450→90; нечисло отвергается до вызова. Размеры плана — тот же `Dimension`, что на «Реконструкции». Вариант «объединить `Table` и будущую мебель в `FurnitureItem` с `kind`» отклонён как спекулятивный (одна разновидность): добавится дискриминатор `kind`, когда появится вторая.

*Хранение:* `Drawing.furniture` необязательно, при загрузке не дописывается (как `reconstruction`). Подсветка и плашка не хранятся.

### D3. Подложка и рабочий набор

`furnitureScene(drawing)` — чистая функция по образцу `reconstructionScene`: берёт `reconstructionScene(drawing)` (подложка, штукатурка, стены ГКЛ) и добавляет собственные столы и видимые размеры `drawing.furniture`. Размер считается видимым, пока обе опорные точки разрешимы по стенам подложки и гипсокартона (то же правило `resolvable`; общий помощник выносится из `reconstruction-scene.ts` и используется обоими планами — не копируется).

Рабочий набор `openFurniture(drawing)`: `walls` — подложка и стены ГКЛ (все только для чтения: идентификаторы целиком в `readOnlyIds`), виртуальные стены штукатурки как препятствия (`plasterObstacles`), `dimensions` — размеры плана. Благодаря этому инструменты «Размер», «Линейка» и «Ластик» работают без изменений, а подложка не выделяется. Стол в `walls` не входит: это отдельный список `tables`, потому что столы не стены (нет `a/b`, нет стыков).

В `main.ts` добавляется ветка `loadWorking` для `furniture` рядом с веткой `reconstruction`; `commitFurniture` пишет `drawing.furniture` и, как остальные планы, не создаёт поле, пока в нём пусто.

### D4. Препятствия и пересечения (`src/furniture/overlap.ts`, домен)

Чистая функция `tableOverlaps(table, obstacles): Overlap[]`, где `Overlap = { kind: ObstacleKind; region: Point[] }`, `ObstacleKind = "wall" | "drywall" | "plaster" | "opening" | "door" | "window" | "battery" | "communication" | "table"`.

Препятствия приводятся к многоугольникам:

| Источник | Многоугольник |
|---|---|
| стена подложки (обмер, «Монтаж») | `displayPolygons(wall, walls)` (то, что нарисовано, с вырезами проёмов) |
| стена гипсокартона | то же, по списку стен ГКЛ |
| штукатурка | прямоугольник виртуальной стены из `plasterObstacles(pieces)` |
| проём, дверь, окно | тело в пределах толщины хозяйской стены и ширины элемента (`kind` — `opening`, `door`, `window`) |
| батарея | `batteryRect(b, wall)` |
| стояк | правильный 48-угольник по окружности (ошибка площади < 0,3 %) |
| воздуховод | прямоугольник `widthCm × depthCm` |
| другой стол | его четырёхугольник |

Пересечение — отсечение многоугольника препятствия четырьмя полуплоскостями прямоугольника стола (`clipHalfPlane` из `wall-geometry.ts`, Sutherland–Hodgman: годится и для невыпуклого препятствия, выпуклым должен быть только отсекающий прямоугольник). Результат — подсвечиваемая область. Распознавание «глубже 0,01 см» (как `RECOGNITION_DEPTH_CM` в `wall-collision`): прямоугольник стола сжимается на 0,01 см с каждой стороны; пересечение есть, только если сжатый прямоугольник даёт область площадью > 1e-9 см². Касание граней даёт нулевую область и не считается. Подсвечивается область от несжатого прямоугольника.

```
 вид сверху, схематично, не в масштабе

   препятствие P (многоугольник)     стол T (прямоугольник, повёрнут)
   отсекаем P четырьмя сторонами T:

        P ###########
          ###########      T  /\
          ######xxxxx\      /  \
          ######xxxxxxx\   /    \     xxx = clip(P, T) — область подсветки
          ###########\ \  /      /
                      \_\/_____/
```

Стол и стол: подсветка один раз на пару (идентификаторы упорядочены), чтобы область не рисовалась дважды; плашка перечисляет вид «стол» без повторов.

Производительность: столов единицы, препятствий — сотни; расчёт на каждый кадр перетаскивания допустим (отсечение четырёхугольником — O(вершин)). Предварительный отсев по ограничивающим прямоугольникам делается внутри функции; кэш ключуется версией сцены, как `reconCache` в `main.ts`.

Порядок видов в плашке: стена, гипсокартон, штукатурка, проём, дверь, окно, батарея, коммуникация, стол — константа `OBSTACLE_ORDER`.

### D5. Поворот и размеры (`src/furniture/table.ts`)

`tableCorners(t)`: полуширина `hw = widthCm/2`, полудлина `hl = lengthCm/2`, ось ширины `u = (cosθ, sinθ)`, ось длины `v = (−sinθ, cosθ)`; углы `c ± hw·u ± hl·v`. Поворот полем «Угол» — присваивание `angleDeg = normalizeAngle(value)`; центр не меняется. Путь вращения (короткая дуга) не нужен: пересечения не блокируют правку, достаточно итогового угла.

Размеры: `widthCm` и `lengthCm` — положительные числа; `parseLengthField` из `drywall-params.ts` переиспользуется для разбора в текущих единицах (общая функция вынесется в нейтральный модуль, если окажется, что модуль `reconstruction` не должен зависеть от `furniture` — зависимость идёт от `furniture` к общему помощнику, не наоборот).

### D6. Жесты (`src/furniture/table-edit.ts`, `main.ts`)

- *Постановка:* клик при инструменте `table` → `newTable(id, p, params)` → `tables.push`, `record`, выделение стола, `tool = "none"`, панель остаётся открытой (D7). Призрак — превью стола полупрозрачным (как `preview` стены ГКЛ), пересечения призрака считаются тем же `tableOverlaps`.
- *Выделение:* hit-test по несжатому четырёхугольнику в локальных координатах стола (точку переводим в систему стола обратным поворотом и сравниваем с полуразмерами), допуск — пиксели экрана → см. Работает только без инструмента (`canvas-app` «Выделение и правка только без инструмента»). Из-за этого клик по столу при активном «Столе» не выделяет, а ставит новый: постановка никогда не отказывает, и действует общее правило приложения.
- *Перетаскивание:* смещение указателя в мировых координатах применяется ко всем выделенным столам, без привязки; один жест — одна запись истории; нулевое смещение записи не создаёт.
- *Стрелки:* 10 см, с Shift 1 см; серия — одна запись (механизм серий, как у стен).
- *Рамка:* пересекает четырёхугольник стола с рамкой по тому же правилу, что для стен (реализация сверяется с `wall-selection`).

### D7. Панель группы «Мебель»

Разметка в `index.html` по образцу `openings-panel` и `drywall-panel`: заголовок, ряд кнопок группы («Стол»), три поля «Ширина», «Длина», «Угол» (ширина и длина — в текущих единицах, подпись — как у панели «Гипсокартон» с `UNIT_LABEL[unit]`; угол — «Угол, °»). Логика значений — `src/furniture/table-params.ts` по образцу `drywall-params.ts` (`TABLE_DEFAULTS = { widthCm: 80, lengthCm: 160, angleDeg: 0 }`, `panelValues(params, selected)`, `editParams(params, selected, patch)`): при ровно одном выделенном столе поле меняет стол (одна запись истории), иначе — значения для новых.

### D8. Индикация пересечений

- **Подсветка:** область заливается полупрозрачным красным, цвет задаёт схема: функция `conflictColor(theme)` рядом с `tableColors(theme)` в `src/furniture/furniture-render.ts` (как `drywallColors` у «Реконструкции»; поле в `Palette` не вводится, чтобы не менять палитру ради одного плана). Рисуется в слое поверх столов и подложки (в том числе коммуникаций), до размеров. В PDF области пересечений не передаются, поэтому подсветки там нет. Слой столов встраивается в отрисовку «Реконструкции» через необязательный обратный вызов `above` в `ReconstructionView` (после стен гипсокартона, перед размерами).
- **Плашка:** DOM-элемент `#furniture-warning` в `index.html`, `position: absolute; top: 12px; right: 12px`, `pointer-events: none`, класс-остров по образцу `.panel`, цвета — уже существующие в `style.css` переменные `--popup-text`, `--popup-bg`, `--popup-border` (светлая и тёмная схемы заведены, использовались попапами, удалёнными в `popups-buttons-only`). Текст: «Стол пересекается: » + виды через запятую. Показывается только на плане «Мебель» и пока `overlaps.length > 0`; скрывается при смене плана и вкладки.
- Новых библиотек и состояний нет: плашка — производная от текущего расчёта, обновляется в той же функции перерисовки, что и панели.

*Альтернативы:* попап рядом со столом (отклонено: позиционирование у краёв холста, новое поведение); модальное окно (противоречит `ui.md`: «никаких диалогов»).

### D9. Хранение и история

- `storage.ts`: `loadFurniture(raw)` по образцу `loadReconstruction`: стол — непустой `id`, числа `x`, `y`, положительные `widthCm`, `lengthCm`, конечный `angleDeg` (приводится `normalizeAngle`); негодные отбрасываются по одному; размеры, выноски и примечания — теми же функциями, что у соседних планов.
- `history.ts`: ключ `<id>:furniture`, суффикс `FURNITURE_SUFFIX`; запись снимка — `{ kind: "furniture", tables, dimensions }`; проверка записи при загрузке (`isFurnitureHistory`), запись с негодным столом делает документ повреждённым. `cloneScene` не затрагивается (в нём стены; столы копируются отдельной функцией `copyTables`).
- Отмена и повтор: восстанавливают `tables` и `dimensions`, подсветка вычисляется заново.

### D10. PDF и легенда

`PdfPage` получает слой `furniture?: { pieces; drywall; tables }`; для `plan === "furniture"` страница строится из `furnitureScene(drawing)`, рисуется `drawFurnitureScene` (внутри — `drawReconstructionScene` для подложки и ГКЛ, затем столы), без подсветки и плашки. Габариты (`roughExtent`) расширяются углами повёрнутых столов. Легенда: `legend.ts` — запись «Стол» после «Гипсокартон» (`page.furniture.tables.length > 0`), «Штукатурка» и «Гипсокартон» — также при `furniture` (по подложке); `legend-draw.ts` — образец стола цветом стола. Страница «Мебель» может дать 11 записей (пять материалов, батарея, стояк, воздуховод, штукатурка, гипсокартон, стол): требуется проверка помещения на A3–A0 (спека «Легенда страницы «Мебель» при всех записях»).

### D11. Размещение модулей (`.claude/rules/architecture.md`)

```
src/furniture/
  table.ts             домен: Table, tableCorners, normalizeAngle, hitTable, newTable
  overlap.ts           домен: приведение препятствий к многоугольникам, tableOverlaps
  table-params.ts      параметры панели (по образцу drywall-params)
  table-edit.ts        правка: переместить, сдвиг, размеры, угол, удаление (чистые функции над массивом столов)
  furniture-scene.ts   подложка + столы + видимые размеры
  furniture-workspace.ts  openFurniture / storedFurniture
  furniture-render.ts  отрисовка столов и подсветки; общая функция для холста и PDF
```

Домен (`table.ts`, `overlap.ts`) не зависит от DOM, хранилища и `main.ts`. `main.ts` только связывает жесты, панель и плашку — тонкая обвязка.

## Risks / Trade-offs

- **Стол не блокируется, пользователь может поставить мебель в стену и не заметить** → красная подсветка и плашка; PDF намеренно без них (сигнал редактирования, не часть чертежа).
- **Невыпуклые препятствия при отсечении Sutherland–Hodgman дают вырожденные «мостики» в области** → площадь верна, заливка может нарисовать лишний тонкий мостик; в тестах проверяем площадь, а при визуальной проверке — отсутствие артефактов; запасной путь — разбивать многоугольник на выпуклые.
- **Окружность стояка заменена 48-угольником** → ошибка площади < 0,3 %, видимой разницы нет; порог 0,01 см определяется по полигону, а не по окружности.
- **Легенда страницы «Мебель» из 11 записей может не поместиться на A3** → проверка при реализации (задача 6.3); если не помещается, это выявится тестом спеки, а не молча.
- **Правило «выделять только без инструмента» делает клик по столу при активном «Столе» постановкой нового стола** → поведение единообразно с проёмами и дверями; если неудобно, меняется на уровне `canvas-app`, а не столов.
- **Плашка в правом верхнем углу может перекрыться с другим плавающим блоком** → проверить в браузере (большие вкладки, узкое окно); блок `pointer-events: none`, клики не перехватывает.
- **Общий помощник `resolvable` и `parseLengthField` выносятся из `reconstruction`** → маленький рефакторинг на двух планах; тесты «Реконструкции» не меняются и должны проходить без правок.

## Migration Plan

Миграции нет: поле `furniture` необязательно, версия документа остаётся 3, старые чертежи открываются с пустым планом. Откат — удаление плана из каталога: поле `furniture` в документе игнорируется загрузчиком прежней версии, остальные данные читаются.

## Open Questions

- Область открывания двери как препятствие (дуга полотна) — отдельное решение; в этой работе только проём в стене (см. Non-Goals). Не меняет спеки, структуру и задачи.
- Нужна ли привязка размеров к столам (расстояние от стены до стола): частая потребность, но не входит в эту работу; записывается в `TODO.md` в разделе Out of scope.
