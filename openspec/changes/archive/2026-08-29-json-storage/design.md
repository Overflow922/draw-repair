## Context

Всё состояние чертежа — модульные переменные в `src/main.ts` (`walls`, `view`, настройки инструмента); персистенции нет. Модель данных канонична: координаты и `thicknessCm` — в сантиметрах, единицы отображения (`м/см/мм`) — чисто презентационные. Тесты — vitest (`geometry.test.ts`), среда по умолчанию node (DOM-глобалов нет).

## Goals / Non-Goals

**Goals:**

- Автосохранение текущего чертежа после каждой мутации без команды пользователя и без `beforeunload`.
- Восстановление при загрузке страницы, включая вид (зум/пан).
- Безопасное поведение на битых данных и на документе будущей версии.
- Шов для будущего менеджера чертежей: смена схемы хранения локализована в одном модуле.

**Non-Goals:**

- Несколько чертежей / вкладки (отдельное изменение `drawing-manager`).
- Экспорт/импорт файлов, облако, синхронизация, история версий.
- Сохранение состояния инструментов (толщина/тип по умолчанию, unit) — это не данные документа.

## Decisions

- **localStorage, а не IndexedDB.** Синхронное API, ~5 МБ против килобайт реального чертежа, ноль асинхронной обвязки. Альтернатива IndexedDB отклонена: асинхронность и сложность неокупаются масштабом данных.
- **Формат v1 `{ version, walls, view }`, зеркальный рантайм-модели.** Координаты в см, тип стены — id из `WALL_TYPES`; конверсий нет, сериализация тривиальна и не может «поплыть». Вербоузная форма (`{a:{x,y},...}`, а не компактные массивы) — файл читаем и правится руками; цена — килобайты, не мегабайты.
- **`version` в документе с первого дня.** Единственная дешёвая возможность эволюционировать формат (двери, комнаты) без ручного разбора старых данных.
- **Сериализация — чистые функции в `src/storage.ts`, localStorage — тонкая обвязка.** `serializeDrawing`/`parseDrawing` не касаются DOM/хранилища → тестируются в node-среде без jsdom по образцу `geometry.test.ts`. Альтернатива — тестировать сам localStorage — потребовала бы jsdom и моков.
- **Сохранение по dirty-флагу в `redraw()`, а не вызовы save из ~7 точек мутаций.** `redraw()` и так вызывается после каждой мутации; флаг страхует от забытой точки вызова при будущих правках. `redraw()` на голом движении мыши (превью цепочки) флаг не ставит — сохранения не происходит.
- **Валидация `parseDrawing`:** битый JSON или структурное несоответствие (не массив стен, стены без конечных точек/толщины/типа, нечисловые координаты) → `null` → пустой чертёж, дальше сохраняем нормально. `version > 1` → режим «только чтение»: приложение работает в памяти, но `saveDrawing` блокируется до очистки хранилища. Граница системы — внешние данные — поэтому проверка обязательна, но неглубокая: типы и наличие полей, без геометрических инвариантов.

## Risks / Trade-offs

- [Правки пользователя при документе будущей версии не сохраняются молча] → Осознанно принято для v1: альтернатива (писать поверх) уничтожает чужие данные необратимо. Сценарий редкий (даунгрейд сборки), потеря — только текущая сессия.
- [localStorage недоступен (приватный режим/квота)] → `saveDrawing` оборачивается в try/catch: приложение работает без сохранения, без аварийного завершения.
- [Хранимый вид (зум/пан) — не «данные», а удобство] → Храним: после перезагрузки пользователь видит то же место. Если когда-нибудь мешает — выпадает из формата без миграции.

## Migration Plan

Не требуется: данных в хранилище ещё нет, формат вводится с нуля. Откат — просто перестать вызывать `storage.ts`.
