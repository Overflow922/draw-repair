# Test Plan

## Scope

Наблюдаемое поведение change `new-wall-materials`:

- каталог материалов, миграция старых типов, образцы и переключение стрелками (`wall-types`);
- штриховки пяти материалов на холсте (записанные операции 2D-контекста), в превью образцов и в PDF (операторы страницы jsPDF через `pdf-ops.test-utils`);
- непрерывность штриховки и узора через стыки, фаза и размер при панораме и масштабе (`wall-joints`);
- запрет сноса «Бетона», действие пометок, миграция `reinforced` (`demolition-plan`, `mounting-plan`, `drawing-storage`);
- состав, порядок и ширина легенды PDF (`pdf-export`).

Уровни: unit (каталог, нормализация, предикат сноса, генератор линий, тайл), integration (рисование стены → операции контекста / пути PDF; загрузка документа → стены и пометки; страница PDF → легенда), UI (панель «Стена» и стрелки в стиле существующих UI-тестов, например `fit-scale-ui.test.ts`, `tool-mode.test.ts`). Мутационного инструмента в проекте нет (`package.json`) — раздел «Mutation Targets» описывает вручную проверяемые мутации.

Числа штриховок (шаг, множители толщины, период тайла) — детали design; тесты проверяют соотношения и границы из спеки, а не конкретные константы: шаг «Блоков» < шага «Кирпича», толщина «Блоков» < толщины «Кирпича», шаг в диапазоне 1–10 мм листа, углы 45°/135° с допуском.

## Boundary Cases

| Case | Input | Expected |
|---|---|---|
| Шаг линий «Блоков» | PDF, штриховка блока | расстояние между соседними линиями ≥ 1 мм и < шага «Кирпича» |
| Шаг линий «Кирпича» | PDF | шаг ≤ 10 мм и > шага «Блоков» |
| Угол линий | стена под 0°, 30°, 90°, 137° | линии «Блоков/Кирпича/Бетона» 45°, «ГКЛ» — 45° и 135°, допуск 0,01 рад |
| Миграция | `type: "reinforced"` / `"wood-long"` / `"partition"` / `""` / `"unknown"` / не строка | `concrete` / `wood-long` / `brick` / `brick` / `brick` / `brick` |
| Цикл стрелок | активен первый / последний материал | вверх с первого → «Дерево», вниз с последнего → «Блоки» |
| Легенда на A4–A0 | 5 материалов + пометка сноса (6 записей) | вертикально помещается на каждом формате |
| Пометка на бетонной стене | `fromCm/toCm` в пределах стены | пометка в хранилище есть, действующей нет |
| Стена `canDemolish` | вырожденная стена любого материала | не сносится (поведение сохраняется) |
| Тайл «Дерева» | стена шире/уже периода, начало не в нуле | узор покрывает всю стену без пустот |
| Фаза при большом смещении | `pan` ≈ 1e6 px | узор и линии сохраняют шаг, без плывущей фазы |

## Negative Cases

| Case | Expected behavior |
|---|---|
| Стена из «Бетона», протяжка «Демонтажем» | пометка не создана, шага истории нет, инструмент не снят |
| Тип `reinforced` в документе | стена читается как `concrete`, не как `brick`; пометка не действует |
| Тип `wood-long` в документе | остаётся `wood-long`, подпись «Дерево» |
| Неизвестный/пустой тип | `brick` |
| Старые подписи «Железобетон», «Дерево (вдоль)» | нигде не появляются: ни в панели, ни в легенде |
| Стрелки при выделенной стене/размере или в поле толщины | материал не меняется |
| Смена материала выделенной стены | другие стены не меняются |
| «Бетон» на странице PDF | заливка не уходит за контур стены и не закрывает штрихи и контур |
| Узор «Дерева» у стены под углом | не поворачивается вместе со стеной |

## Invariants

- Каталог — единственный источник состава, порядка и подписей: порядок панели = порядок стрелок = порядок легенды.
- `normalizeMaterial` идемпотентна и всегда возвращает материал каталога; `normalizeMaterial(id)` для id из каталога возвращает его же.
- Штриховка не выходит за полигон стены (клип) ни на холсте, ни в PDF.
- Каждая точка зоны стыка заштрихована один раз.
- Фаза штриховки и узора привязана к чертежу: `pan` и масштаб её не меняют; шаг на экране в мм постоянен.
- Толщина линий: «Блоки» < «Кирпич» при любых метриках (экран и PDF).
- Формат документа остаётся версии 3; пометки сноса не теряются при миграции материала.
- Красная штриховка сноса остаётся под 135° с шагом 3 мм (регрессия от общего генератора линий).

## Integration Cases

- Нарисовать стены всех пяти материалов → записанные операции показывают разные паттерны (количество линий, углы, заливка, пунктир) (WM-H1).
- Экспорт PDF двух стыкующихся стен одного материала под произвольным углом → линии лежат на общих прямых (WM-J1, WM-J2), узор совпадает на стыке (WM-J6).
- Загрузка документа с `reinforced`, `wood-long` и старыми типами, затем экспорт PDF → легенда «Бетон»/«Дерево»/«Кирпич» (WM-S1, WM-L4).
- Документ с пометкой на `reinforced`-стене → после загрузки пометка есть, на плане «Демонтаж» стена не снесена, на «Монтаже» без вычета (WM-S2, WM-D4, WM-D7).
- Тёмная схема: записанные цвета заливки и штрихов «Бетона» различимы между собой и с `paper` (WM-H9, контраст по WCAG в `theme.test-utils`).
- Подложка «Демонтажа» с бетонной и снесённой стенами: серые штрихи подложки (`muted`), серая заливка бетона, красная штриховка 135° с шагом 3 мм — на холсте и в PDF (WM-D8; шаг красной штриховки закрыт новыми тестами, поскольку его ловят только они).
- Статическая разметка панели образцов `index.html` против каталога: состав, порядок, подписи, превью 36×14, активный по умолчанию «Кирпич» (WM-U1, WM-U2, WM-U8) — тест без DOM, читающий файл.

## Mutation Targets

Мутации, которые тесты обязаны ловить (пройти «поверхностно правильной» реализацией не должны):

- `reinforced` → `brick` вместо `concrete` в `normalizeMaterial` (ловят WM-C2, WM-S2, WM-L4, WM-D2).
- `canDemolish` продолжает сравнивать с `"reinforced"` или не сравнивает вообще (WM-D1, WM-D2, WM-D3).
- Порядок каталога перепутан (например, «ГКЛ» перед «Бетоном») — ловят WM-U2, WM-U4, WM-L2.
- «ГКЛ» рисуется одной серией линий или двумя серий в одну сторону (WM-H5 проверяет оба угла и одинаковый шаг).
- Угол «ГКЛ» не 135° (а, скажем, 45° дважды) или шаг серий разный (WM-H5, WM-H6).
- Пунктир «Бетона» пропущен (сплошные линии) или заливка нарисована поверх штрихов (WM-H3, WM-H4: порядок операций заливка → штрихи → контур).
- Заливка «Бетона» одного цвета на светлой и тёмной схемах, либо совпадает с `paper`/`ink` (WM-H9).
- Узор «Дерева» привязан к оси стены (вращается) или к началу стены (смещается на стыке) вместо привязки к чертежу (WM-H7, WM-J6, WM-J4).
- Фаза `anchorC` не учитывается для 135° (сетка «ГКЛ» сдвигается на стыке) (WM-J2).
- Толщина «Блоков» равна толщине «Кирпича» (WM-H2).
- Шаг «Блоков» не меньше шага «Кирпича» (WM-H2).
- Старое значение подписи «Дерево (вдоль)» осталось в легенде/панели (WM-C1, WM-L2, WM-L3).
- Красная штриховка сноса сменила шаг или угол после объединения генераторов линий (WM-D8).
- В PDF рисуется заливка «Бетона» без клипа по стене (выходит за контур) (WM-H4).

## Existing tests invalidated by the specification

Спека меняет поведение намеренно, поэтому часть существующих тестов не соответствует ей и должна быть переписана Test Writer'ом (не реализацией) до реализации; изменение — отдельный шаг, а не подгонка под код:

- `src/types.test.ts` — `normalizeMaterial("reinforced")` теперь `concrete`; каталог из пяти материалов.
- `src/export/legend.test.ts`, `src/export/legend-pdf.test.ts` — порядок и подписи записей легенды (нет «Железобетон», «Дерево (вдоль)»; есть «Блоки», «ГКЛ», «Дерево»); тесты на ширину колонки по подписи «Железобетон» (LG-9, LG-15) привязать к самой длинной подписи нового каталога.
- Тесты запрета сноса, использующие тип `reinforced` как несносимый (`demolition/*.test.ts`, `mounting/*.test.ts`, `export/demolition-*.test.ts`, `mark-storage.test.ts`): теперь несносимый материал — `concrete`; `marks.test.ts` DM-27 (`it.each(["brick","concrete","wood-long"])` — «стена из материала %s сносится») ложится на новую спеку и должен потерять `concrete` и получить `blocks`, `brick`, `gkl`, `wood-long`.
- `src/export/plan-title-strip.test.ts`, `src/export/fit-scale.test.ts`, `src/wall-seam.test.ts`, `src/wall-merge.test.ts` — используют литерал `reinforced` как тип `Material`; после выхода типа из каталога заменяются на `concrete` или подходящий материал, сохраняя смысл проверки.
- `src/mounting/mounting-live.test.ts` MP-31 («смена материала и толщины стены обмера видна в остатках») — стена `concrete` с пометкой больше не даёт двух остатков; материал заменяется на сносимый (`wood-long`), смысл проверки сохраняется (находка валидатора F1).
- `src/theme-render.test.ts` PATTERN-DARK-1 и PATTERN-LIGHT-1 — требовали, чтобы все операции превью имели цвет `ink`; заливка «Бетона» (цвет схемы, не `ink`) их нарушает. Проверка делится: штрихи — `ink`, заливка — отдельно (только у `concrete`, не бумага и не `ink`) (F2).
- `src/theme.test.ts` LIGHT-EXACT-1 и DARK-KEYS-1 — пиннят точный набор ключей палитры; новый ключ `concreteFill` (design D5) добавляется в ожидаемый набор, значение заливки не пиннится (формат цвета проверяется), остальные цвета светлой палитры сверяются как раньше (F3).
- Тесты, которые читают штриховку по числу линий и шагу, а не по id (если есть), проверить на независимость от старых констант `strokeHatch45`.
- Хелперы выбора образца легенды (`inColumn`, `inChart` в `legend-pdf.test.ts`): принадлежность столбцу или чертежу — по середине штриха, а не по всем точкам; штриховка и тайлы с запасом за образец (их обрезает клиппинг) не должны менять результат (F5).

Новые тесты не должны ослаблять эти проверки: покрытие «несносимости» переносится на `concrete` один в один.

## Out of Scope

- Подбор точных числовых значений шага и толщины линий и точного внешнего вида узора «Дерева» (приёмка глазом заказчика; тест только на соотношения и бесшовность).
- Производительность отрисовки тайла «Дерева» на холсте (профилирование — вручную).
- Пиксельное сравнение с эталонными картинками.
- Миграция документов версий 1 и 2 (не затрагивается).
