## Context

Рендер чертежа — чистый Canvas 2D (`src/render.ts`): полигоны стен через `wallShape()`, штриховки материалов `setLineDash` + clip, контур, повёрнутые подписи длины. Все метрики (толщины линий, шаг штриховки, кегль подписей) — экранные px-константы. Рантайм-зависимостей у проекта нет. Мотивация — см. proposal.md (Why).

## Goals / Non-Goals

**Goals:**
- Векторный PDF текущей вкладки без дублирования логики черчения.
- Формат страницы A0–A4 по выбору пользователя, авто-ориентация, вписывание с полями.
- Кириллица в подписях длины.

**Non-Goals:**
- Фиксированный масштаб (1:50, 1:100), рамка и штамп по ГОСТ 2.301.
- Разбиение на несколько страниц, экспорт всех вкладок, другие форматы (SVG, PNG).
- Экспорт сетки, выделения, ручек, превью — экранные сущности.

## Decisions

### D1. Вектор через jsPDF + `doc.context2d` (шим Canvas API)
Альтернативы: растр (`toDataURL` + `addImage` — мыло и мегабайты); pdf-lib/свой слой операторов (переизложение `drawWall`/штриховок ~150 строк дублирования); полностью свой писатель PDF (плюс ручное встраивание шрифта — дороже всех). Шим позволяет подать `pdf.context2d` в существующие функции рендера. jsPDF — первая рантайм-зависимость проекта: принято сознательно, она дешевле альтернатив кодом.

### D2. Спайк шима до реализации
Проверяем на примере текущего рендера: `setLineDash` со штрих-пунктиром (бетон/ж/б — смысл ГОСТ-штриховки), clip по полигону, `translate/rotate`, повёрнутый `fillText`. **План Б** при провале: свой слой PDF-операторов поверх низкоуровневого API jsPDF (`pushOperators`: `m/l/S/d/W n`) — геометрия (`wallShape`, `sameTypeJoint`) переиспользуется, переизлагаются только примитивы рисования.

### D3. Кириллический TTF-шрифт
Базовые шрифты PDF кириллицу не умеют. Встраиваем один OFL-шрифт (Roboto Regular или аналог) ассетом, `addFileToVFS` + `addFont`; jsPDF сабсетит при выводе — PDF не тащит весь шрифт. Альтернативы: экспорт без подписей (теряются размеры — отклонено), текст как векторные пути (лишняя зависимость и сложность).

### D4. Метрики рендера как параметр
Экранные px-константы (`CONTOUR_PX`, `HATCH_STEP`, кегль 14px) на странице в мм дают неверные веса (контур 2мм, подписи 14мм). `render.ts` получает объект метрик с умолчаниями = текущие экранные; экспорт передаёт страничные (контур ~0.6мм, штриховка ~0.25мм, подписи ~3.5мм) — ГОСТ-веса без ветвлений в логике черчения. Сетка/выделение для экспорта отключаются флагом (сетка сейчас рисуется безусловно).

### D5. Подгонка страницы — чистая функция
`fitToPage(bbox, pageMm, marginMm) -> { scale, orientation, offset }`: ландшафт при шире-чем-выше bbox; масштаб = min по осям; покрытие тестами. Форматы A4..A0 (мм): 210×297, 297×420, 420×594, 594×841, 841×1189. Оси Y не переворачиваем: спайк (1.1) показал, что пространство `doc.context2d` канвасоподобное (y вниз, origin сверху-слева) — страничные мм используются как обычные экранные.

### D6. Имя файла — чистая функция
`<имя>_<ГГГГ-ММ-ДД_ЧЧ-мм-сс>.pdf` по локальному времени; символы `\/:*?"<>|` из имени чертежа удаляются. Секунды — чтобы повторные экспорты не коллизились. Скачивание: `Blob` → object URL → `a[download]` → revoke.

## Risks / Trade-offs

- [Шим `context2d` врёт на штрих-пунктире/clip/повороте] → спайк первым делом (D2); план Б не меняет спеки и разбивку задач.
- [Ассет шрифта ~100–300КБ] → один OFL-шрифт, сабсет на стороне jsPDF; принято.
- [Первая рантайм-зависимость] → компромисс осознан (D1); попытка «своего писателя» оценена дороже.
- [Крупный чертёж на A4 → мелкий масштаб] → свойство вписывания, а не дефект; пользователь выбирает больший формат.
- [Пустой чертёж] → экспорт недоступен (кнопка неактивна), PDF пустой страницы не создаём.
